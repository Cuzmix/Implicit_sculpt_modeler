Workspaces: the top bar's tabs

The fixed Sculpt, Model and Render spaces become the person's own workspaces: named layouts they make, rename, reorder, colour and delete. Sculpt, Model, Paint and Render ship as starting workspaces, tied to the tools that bring them (the Model tool still brings Model). A workspace someone makes switches only from its tab unless they tie a tool to it. Each keeps a desktop and a tablet layout. The saved-layout stamps go.

Each mock runs in a browser: switch between Desktop and Tablet, Mouse and Finger (a finger needs a long press before a drag, as in the app), pick tools on the right to try the ties, change the layout to see the amber dot, and add four workspaces to see what happens when the tabs no longer fit.

A. Tabs and one menu recommended

Today's tabs, each a workspace, then +. The lit tab, a right-click or a long press opens its menu: rename, duplicate, colour, the tools that bring it, Reset layout, Delete. Tabs drag to reorder; what does not fit folds into a chevron list.

  • One tap switches; no new kind of control
  • Destructive actions stay off the bar
  • Overflow reuses the top bar's give-way steps
  • The menu is the only place ties are shown

B. Browser tabs and a sheet

Each workspace its own pill; a double tap renames in place; the lit pill's ⋯ opens a Workspace sheet with name, colour, tools and a picture of both layouts. + makes a copy at once. Pills scroll sideways.

  • The clearest place to see and set ties and both layouts
  • Double tap and ⋯ on a pill are mouse habits on a tablet
  • Sideways scrolling hides workspaces with no hint of how many

C. One chip and a switcher card

The bar holds only the current workspace's chip; a tap opens tiles, each a picture drawn from its layout, dragged to reorder, ⋯ for the rest, + first.

  • Smallest bar; scales to twelve workspaces on any screen
  • Pictures say what each workspace holds
  • Two taps to switch instead of one

What is the same in every direction

PartBehaviour
SwitchA tap, or Ctrl+1…9 by position. A tied workspace gives back its tool; an untied one keeps the tool in hand.
TiesSix: Sculpt brushes, Paint brush, Curve, Insert, Model and Look tools. Each is held by one workspace; ticking it elsewhere moves it. Picking a tool switches only when its tie changes, so brushes picked in an untied workspace never throw you to Sculpt. Move keeps whatever was in front.
Look toolRender's "a press turns the view" becomes a tool (the tool decides the hands; the workspace only the layout).
Amber dot, ResetThe dot shows a layout differs from where it started (a starter's shipped layout, or the copy it was made from); Reset layout puts that back, for the screen in use.
DeleteThe last one cannot go. Deleting the current one shows its left neighbour first. The toast says which tools now bring nothing, and Undo puts it back.
Desktop and tabletTwo layouts per workspace, chosen by the device (iPad and Android are Tablet), with an override in Settings > Interface. Switch Screen in the mock to see each kept apart.
