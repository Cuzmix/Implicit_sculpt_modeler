# PR 6 design: the corpus script and `bench --quadremesh`

Part of the Remesh / Quad Remesh roadmap (report https://claude.ai/artifact/Y7oLGn8QV2MmegNP2uYWgV, sections 7 and 8,
PR 6), approved by Bolt 2026-10-30 07:09. The last PR of the series; the full gate follows it.

## What exists when it is done
One command, `python scripts/remesh_check.py`, generates the report's synthetic corpus as OBJ files, runs **Remesh**,
**Remesh with Quads** and **Quad Remesh** on each through the headless app (`--import`, `--script`, `--export`,
`--check-mesh`), measures each result and writes one markdown table (`build/remesh_check/report.md`, also printed) with
a PASS/FAIL against the report's acceptance column, exiting 1 on a failure a closed fixture should not have. `bench
--quadremesh` times Quad Remesh's engine per size, as `bench --remesh` times Remesh. README gets both.

## Design (`scripts/remesh_check.py`, stdlib only, ~350 lines, Windows and Linux)
- Fixtures, generated by the script into `build/remesh_check/fixtures/` (90 lines of generators, deterministic, no
  randomness): `sphere` (icosphere 5), `torus`, `overlap` (two overlapping spheres), `gap` (two spheres 0.02 apart
  along an oblique axis, the crevice PR 5b fixed), `rod` (a sphere with a 0.03-radius rod), `cylinder` (open, no caps),
  `pieces` (three disconnected spheres of different sizes), `nonmanifold` (two cubes sharing an edge plus a fin),
  `bumpy` (icosphere 6 displaced by a sum of sines, the dense organic case), `invalid` (a duplicate triangle, a flipped
  triangle and a NaN position: must be refused, never crash). `--real PATH` adds a real sculpt (the Female export in the
  project files), run with Quad Remesh's Close first off and on, the report's own pair of a test.
- Runs: for each fixture and each tool one app process, `--import=<obj> --script="<set lines>; <verb>" --frames=2
  --export=<out.obj> --check-mesh`; Remesh is `set rebuild_even V; rebuild`, Quads adds `set remesh_quads on`, Quad
  Remesh is `set retopo_quads Q; retopologize` (`set retopo_close_first on` for the real sculpt's second run). `--export`
  writes the selected object, which is the remeshed one or the Quad Remesh's new object, as quads where the object has
  them. The time comes from the result line in the log ("Remeshed X: 20,004 vertices (130 ms)", "Quad remeshed X: 1,608
  quads (AutoRemesher), UVs in 12 charts, 226 ms"); a run without one is a refusal, and its last warning is the note.
  The app's exit stats gain `peak_rss_mb=` (Linux and Android from `/proc/self/status`'s VmHWM, 0 elsewhere), which the
  script shows as the memory column, since nothing portable measures a child's peak from Python.
- Metrics, from the exported OBJ read back as polygons: vertices, faces, quad share and non-quad count, four-valent share
  (polygon adjacency), boundary and non-manifold edges and closedness (edge counts over the polygons), signed volume
  (fans), and the deviation from the input: each output vertex's distance to the nearest input triangle (a grid hash over
  the input's triangles, closest point on a triangle), max and mean as a share of the input's bounding diagonal.
- Acceptance (the report's table): for a closed fixture Remesh must be closed and manifold with the volume within 2 % of
  the input's (sphere: 1 %) and the count within 5 % of the request; Remesh with Quads the same plus every face a quad;
  Quad Remesh quads ≥ 99 % of faces and no non-manifold edges, four-valent ≥ 95 % on the sphere, torus and bumpy sphere,
  faces within −25 % / +10 % of the request. Open, non-manifold and invalid fixtures stay in the table with what they
  did (a refusal is a PASS where the report expects one). `--only NAME`, `--vertices N` (20,000), `--quads N` (2,000),
  `--app PATH`, `--keep` (the OBJ outputs).
- Environment: the script inherits the environment and sets `SDL_ASSERT=abort`; on Linux without a display it sets
  `SDL_VIDEODRIVER=offscreen` unless set, on a Linux without a display. It never starts GitHub Actions.

## Design (`src/bench/quadremesh.odin`, ~90 lines)
`--quadremesh`: at each size the stretched sphere `--remesh` uses, decimated to Quad Remesh's input cap (1M triangles,
as `quad_remesh_compute` does before the engine), then `quadmesh.remesh` at 20,000 quads, adaptivity 0, every pool
thread: decimate ms, quad remesh ms, faces, quad share, four-valent share, peak RSS. On a platform without the engine
(`!quadmesh.AVAILABLE`) one line says so. `bench` already stays clear of `render` and `app`; `quadmesh` is a geometry
package, so the boundary check holds. README's Quad Remesh section gets the table from this VM.

## Out of scope
Running the corpus in `gate.py` (minutes; it is a tool for a remesh change, named in the sm-cad skill), RSS on Windows,
a real sculpt in the repository (the Female export stays in the project files), the 10M geodesic sphere as a fixture (the
bench covers size).

## Review and as built (2026-10-30)
The architect's review (Revise) was taken: a run that exits 2 is a warned run (the app writes no export then), not a
crash; Remesh's time comes from its own log line (`remesh: N vertices in M ms`, which the result line leaves out under
50 ms); the one "invalid" fixture became three (a NaN position, a doubled triangle, a flipped one); the thresholds are
the report's section 7 word for word (Remesh volume 1 %, Quad Remesh 2 %, no boundary edge at all, the torus 100 %
four-valent, every vertex within 0.6 of the lattice spacing); the deviation reads every vertex (every k-th past 100k);
`--stability` runs each tool again on one thread and compares the files byte for byte; `--check-mesh` is not passed
(the script measures the OBJ itself); the bench takes its input count before the mesh is destroyed. Departures from the
note: the spacing check is its own check, "near", on the closed solids only, since an open cylinder's caps are 20 % of
the diagonal off its input surface by design; the distance grid searches outward until a ring holds a triangle and the
next could not hold a nearer one, so a far vertex gets its true distance rather than infinity.

The corpus found two faults on its first run, both now fixed in geom with a test
(`remesh_mends_a_doubled_or_turned_triangle`): a sphere with one triangle doubled remeshed non-manifold (134 edges)
and its Quads run tripped an assert in the sculptor, and one flipped triangle left the result's cap 0.27 off. The
cause is one: either puts the x rays' winding out by two behind the triangle, `mesh_edges_paired` is false but
`mesh_close_holes` finds no hole to cap, so the lattice saw a surface that was neither closed nor open. Remesh now
runs `mesh_fix` first when the edges do not pair (the double dropped, the turned one turned), reports `mended` and
the result line says "N triangles mended first". With that, 34 of the 36 rows pass with `--stability` (every
serial result equals its parallel one); the two FAILs are AutoRemesher's and kept honestly: the thin rod (48 faces
inside out, so the built-in engine answers) and the bumpy sphere's 1,492 faces for 2,000 (−25.4 %, a shade past the
−25 % bar). `bench --quadremesh` at 500k, 1M and 5M: the engine takes about 10 s on its capped million-triangle
input whatever the sculpt's size, about 11k quads for 20,000 asked (its count is a guide), 99.8 % four-valent, 1.8 GB
peak at 5M (the decimation's). The app gained `peak_rss_mb` in its exit stats (VmHWM on Linux and Android, 0
elsewhere) so the script's memory column needs no profiler.
