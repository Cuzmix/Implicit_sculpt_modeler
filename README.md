# Sculpt

A performance-focused sculpting prototype in Odin, using SDL3 + SDL_GPU for rendering and its own interface kit (`src/ui`) for everything around the viewport.

## Layout

| Path | Owns |
| --- | --- |
| `src/app` | Entry point, frame loop, scene of sculptable objects, Move, Brush, Curve and Insert tools, brush alphas (the built-in ones and loaded images, which way each dab's image faces), the interface's panels (`new_ui.odin`, `kit_*.odin`), keys and pointer from SDL (`device.odin`), fingers and the pen (`touch.odin`), who owns each touch and drag and what the camera does with it (`navigate.odin`) and routing into `Viewport_Input` (pen pressure and tilt included), the Settings panel (`kit_settings.odin`), the viewport overlay and the brush pie, the History timeline and time-lapse, the menu's file actions (scene save and open, mesh import and export, file dialogs) |
| `src/render` | Every GPU object the app creates: device, pipeline, viewport target, mesh buffers (16 bytes a vertex: float3 position, octahedral normal), per-mesh indirect draws of the visible chunks, simplified copies of far chunks drawn from a second index buffer while the view moves, partial redraws (while the camera and objects stay put, the last frame is kept and only the screen rectangle around what changed is cleared and redrawn), shaders |
| `src/geom` | CPU sculpt geometry (structure-of-arrays triangle mesh, BVH, test spheres, mesh simplification that keeps patch borders), view-culling math (chunk bounds and normal cones, frustum and back-face tests) and the choice of simplified groups to draw, OBJ and PLY reading and writing with cleanup of what is read, quad retopology, UV layout and normal and displacement map baking, response curves (the pen pressure curve); no rendering or UI imports |
| `src/camera` | Orbit camera math (Free and Turntable orbits that go all the way round, roll, snapping to square views, zoom toward a point), including how a leaning pen turns the brush in the view; no rendering or UI imports |
| `src/gizmo` | Move gizmo math: projection, handle picking, axis and view-plane drags; no rendering or UI imports |
| `src/sculpt` | Brush dabs on a `geom.Mesh`: mesh split into nodes that own contiguous vertex ranges, parallel brushes (Draw, Smooth, Clay, Flatten, Inflate, Pinch, Crease, Grab) with X/Y/Z symmetry, pen tilt and alphas (a grey image that shapes each dab), a per-vertex mask, per-frame normal updates, dirty vertex ranges for upload, stroke undo/redo that saves only the nodes a stroke touched (512 MB cap per object), simplified copies of groups of nodes rebuilt between strokes, subdivision levels, HD detail sculpted a window at a time above the top level, dynamic topology (brushes split and collapse edges as they go), levels in and out of the scene file |
| `src/ui` | The interface kit: immediate-mode containers and widgets (buttons, segmented controls, switches, sliders, values to drag, text fields, selects, brush tiles, list rows, areas to draw into), hit testing, the gesture arena that settles whether a finger's press is a tap, a drag or a scroll, multi-finger gesture measurement (`fingers.odin`), antialiased shapes tessellated on the CPU, text in Inter and icons in Lucide through fontstash; it imports neither SDL nor the renderer, so its tests run headless |
| `src/jobs` | Persistent worker pool (`parallel_for`) used by sculpt and mesh setup |
| `src/bench` | Headless sculpt benchmark at chosen mesh sizes (no window or GPU) |
| `src/sdf_trial` | Standalone SDF/voxel comparison spike (not linked into the app) |
| `src/dart_trial` | Standalone Odin vs Dart comparison of the Draw brush's hot loops (not linked into the app) |

The 3D viewport is rendered by `render` into an offscreen texture that the interface draws under its panels. Strokes undo and redo with Ctrl+Z and Ctrl+Shift+Z (or Ctrl+Y), also the buttons at the top left; the order runs across objects. Changes that rebuild an object undo the same way: remesh, dynamic topology on or off, Delete higher and Delete lower, and adding, importing or deleting (Delete key) an object. Before such a change the object is kept as the scene file stores it (every level as positions, the mask, dynamic topology); undo rebuilds it from that and keeps the object it replaces, so redo works too. That costs about 37 bytes a base vertex plus 12 a vertex of each level above (about 370 MB for a 10M-vertex object), up to 1.5 GB in all, past which the oldest go; the Stats panel shows the total. The object's strokes from before such a change can no longer be undone one by one, and HD detail is not kept (the HD steps are). Undoing a remesh takes about 0.1 s at 100k vertices and 0.24 s at 1M on the test VM (release build). The interface never owns sculpt state: panels read and edit `App` fields through pointers each frame, and what the viewport saw reaches the camera and the active tool as a plain struct. Each object keeps its mesh in local space with a transform (position, uniform scale, rotation), so moving or turning an object never rewrites its vertices; the brush works in the object's local space, and so do symmetry and Mirror and weld. The Object tab's Transform turns the selected object (degrees about X, then Y, then Z); scenes save it (scene file version 2, which still opens version 1 files).

## Linux

```sh
# once: system packages are listed at the top of the script
./scripts/setup_deps.sh

./build.sh            # debug build with allocation tracking -> build/sculpt
./build.sh release    # optimized build
./build.sh test       # unit tests (geom, camera, sculpt, jobs, gizmo, png_write, ui, app)

./build.sh run -- --vertices=10000000
./build.sh smoke      # 300 frames in GPU debug mode; non-zero exit on assert, GPU error or leak
./build.sh bench      # headless sculpt benchmark at 500k, 1M, 5M, 7M, 10M vertices
./build.sh gpubench   # GPU and CPU frame times while orbiting and sculpting, same sizes
./build.sh computebench # Smooth all on the CPU against a GPU compute shader, same sizes
./build.sh wincheck   # compile app and bench for Windows x64 (no link) to catch Windows-only errors
```

Headless (CI or containers): run under `Xvfb` with Mesa's llvmpipe Vulkan driver (`mesa-vulkan-drivers`).


(`./build.sh android` and `./build.sh androidrun` on Linux, with the SDK in `~/Android/Sdk` or `ANDROID_HOME`; `./build.sh androidcheck` compiles the Odin side for Android without the SDK.) Both find Android Studio's SDK (`%LOCALAPPDATA%\Android\Sdk`) and Java (`%ProgramFiles%\Android\Android Studio\jbr`) unless `ANDROID_HOME` and `JAVA_HOME` say otherwise. Opening `android/` in Android Studio works too: Run builds, installs and starts it. ## Benchmark

`build/bench [vertex counts...] [--meshes=N] [--threads=N] [--node=N] [--prefault=MB]` builds a sphere of each size (N of them with `--meshes`, only the first sculpted; with no sizes given it also runs 10M with a second idle sphere), prepares it for sculpting, runs the same 77-dab stroke with a large (r=0.13) and a small (r=0.04) brush, and prints a markdown table, including the undo memory of each stroke and the time to undo and redo it. A frame is 4 dabs plus the normal update and is what the app does per frame during a fast stroke. The normal update recomputes every normal of the nodes whose triangles moved, but only the border vertices of their neighbours; the normal cones that back-face culling uses wait until the stroke ends (until then those chunks are simply not back-face culled), and "Stroke end ms" is the frame where that work starts, at most 512 nodes a frame. A second table culls the sculpted sphere from three cameras (whole sphere, close-up, detail) and reports the share of triangles that would be drawn, the number of indirect draw commands, and the CPU time to cull. On cloud VMs, pass `--prefault=3000` so the VM's slow first touch of fresh memory does not dominate setup times.

`build/bench --lod [vertex counts...]` prints a table for simplified drawing instead: at each size, the time to build every group's copy as the app does (a batch a frame), the copies' memory, the triangles drawn and the CPU time to choose them from the culling table's three cameras at full detail and with copies at most 1 px off (on a 1000 px tall viewport), and the time to rebuild what the large-brush stroke made stale.

`build/bench --brushes [vertex counts...]` prints a table with one row per brush instead: the main table's stroke with the large brush, for every brush kind, then Draw with X symmetry, Draw over a sphere masked on one side and Draw with the Noise alpha (see Brushes, masking and symmetry and Brush alphas below).

`build/bench --masks [vertex counts...]` prints a table for the mask commands instead: at each size, each command on a sphere masked on one side, with how many vertices it changed and its undo (see Brushes, masking and symmetry below).

`build/bench --remesh [vertex counts...]` prints a table for voxel remesh instead: at each size, a sphere with one Grab move that pulls a wide spike out of it, remeshed back to the same vertex count (see Voxel remesh below).

`build/bench --dyntopo [vertex counts...]` prints a table for dynamic topology instead: at each size, the main table's stroke with the large brush on the usual layout, then with dynamic topology on, once with nothing to split, once refining and once more over what it refined, with undo, redo and the time to turn it on and off (see Dynamic topology below).

`build/bench --files [vertex counts...]` prints a table for files instead: at each size, a sphere written as OBJ and as PLY and parsed back, cleaned up and made ready to sculpt as Menu > Import mesh... does, then saved and read back as a scene; and a second table for scenes with subdivision levels, laid out as `--levels` lays them out (see Files below). It works in memory, without the disk.

`build/bench --hd [vertex counts...]` prints a table for HD detail instead: at each size, a sphere as the top level with an HD level one and then two steps above it. It times opening a window of about 4M vertices at the front, the small-brush stroke in it (median frame), storing it on leaving and opening the window again with the stored detail, and gives the window's memory and what the stroke stored. Then the regular levels the HD level stands in for: their memory (estimated past 16M vertices), and while they stay under that, the time to build them and the same stroke on their top level.

`build/bench --levels [vertex counts...]` prints a table for subdivision levels instead: at each size, a base sphere of at most 40k vertices with as few levels above it as reach that size. It times building the levels (all of them, and the top one alone), the same stroke on the top level, stepping down to the base (carrying the stroke down, then the base's normal update), the stroke on the base, and stepping back up (carrying that up through every level, then the top level's normal update, with the megabytes the app would upload).

## Big meshes (20M to 50M)

The sculpt core scales with what a stroke touches, not with the mesh: a brush of the same size on screen touches more vertices on a denser mesh, and the frame grows with those, while a brush of the same vertex count costs the same at 10M and at 50M. `build/bench 20000000 50000000` (4 threads, this repo's cloud VM):

| Vertices | Setup s | Mesh MB | Peak RSS MB | Frame ms, large brush (verts a dab) | Frame ms, small brush (verts a dab) | Undo ms, large |
| --- | --- | --- | --- | --- | --- | --- |
| 10M | 1.0 | 888 | 2267 | 1.34 (39k) | 0.29 (3.5k) | 8.0 |
| 20M | 3.0 | 1776 | 2700 | 2.37 (78k) | 0.45 (7k) | 14.9 |
| 50M | 9.0 | 4442 | 6751 | 6.20 (194k) | 0.99 (18k) | 39.3 |

What did grow with the mesh was culling: every frame tested each chunk (about one per 600 triangles) against the view, about 1 ms at 50M even when the view held a few hundred of them, and a stroke's partial redraw paid it every frame. Chunks now also come in groups of 64 neighbours (`CHUNK_GROUP`, in the chunks' order, which follows the BVH), each with bounds and a normal cone holding its chunks'; a group outside the view or wholly facing away is skipped without looking at its chunks, and the rest are tested one by one as before, so the same chunks are drawn. The sculptor remakes a group only when one of its chunks changed (`sculptor_chunk_groups`); under dynamic topology, whose chunks come and go, chunks are tested one by one. Culling CPU ms, chunk by chunk and by groups:

| Vertices | Whole sphere | Close-up | Detail |
| --- | --- | --- | --- |
| 10M | 0.35 → 0.19 | 0.23 → 0.05 | 0.19 → 0.014 |
| 20M | 0.80 → 0.38 | 0.50 → 0.07 | 0.36 → 0.019 |
| 50M | 2.07 → 0.95 | 1.39 → 0.12 | 1.11 → 0.03 |

Saving reserves the object's size up front instead of growing the buffer a doubling at a time, which at 50M (about 1.7 GB an object) means it never holds a second, larger copy while the buffer grows. In the app a 30M sphere is ready to sculpt in about 5 s, saves to a 1 GB .sculpt file in about 8 s and opens again in about 4.5 s on the VM, whose disk and first touches of memory are slow; a 40M top level built with `--vertices=40000 --subdivide=5` takes 11 s and about 9.5 GB with every level and the GPU's copy. To time a real GPU at these sizes: `build.bat gpubench --vertices=20000000` (or 50000000; give the GPU 2 GB of free memory at 50M).

## GPU benchmark and frame timing

`build.sh gpubench` (or `build.bat gpubench`) builds the release app and runs it on one sphere at 500k, 1M, 5M, 7M and 10M vertices (only one size with `--vertices=N`). At each size it runs six cases: the camera orbiting once around the sphere with everything on, with simplified drawing off, and with view culling off too, and a brush stroke with partial redraw and culling both on, partial redraw off, and both off. The stroke drags the 60 px Draw brush back and forth across the sphere at 30 px a frame (two dabs a frame, like a fast real stroke) and is undone after each case. Each case runs 30 warm-up frames and then measures 120; stroke cases count only the frames that sculpted. It prints three markdown tables, GPU time of the 3D viewport and CPU time per frame (p50 / p99) and triangles drawn per frame, and writes them to `build/gpubench.md`. It needs a display, and only a real GPU gives meaningful numbers. Vsync is turned off during the run where the display allows it.

The Stats panel shows the same timings live:

- **Frame**: the whole frame, waits included. With VSync on this is the display's refresh interval whenever the frame is ready in time, so it does not show what a speed setting saves; compare CPU and GPU instead, or turn VSync off.
- **CPU**: the frame minus its waits.
- **GPU (3D)**: the GPU time of the 3D viewport's uploads and drawing, shown while "Time GPU work" is on. The 3D work goes in its own command buffer; with timing on, the app waits for the previous frame first and then for this one, so the time from submit to its fence is the GPU's alone. Frames then no longer overlap, so leave it off when not measuring.
- **Display wait**: time spent waiting for the display, at the start of the frame and while presenting.
- **VSync**: off uses mailbox where the display offers it (no tearing), else immediate (may tear). The app reads input after the wait at the start of the frame, so a driver that makes the app wait there for the next screen image no longer delays that frame's input. Drivers that wait while presenting instead (Mesa does) still add up to a refresh interval of lag with VSync on; turning it off removes that.

## Smooth all and the GPU compute trial

Smooth all (Object tab, Deformation) smooths the whole selected object, as ZBrush's Deformation > Smooth: each step moves every vertex toward the average of its triangles' corners (the step the Smooth brush takes) by the Smooth strength, for the Smooth steps given. Masked areas stay (partly masked ones move part of the way), it is one undo step, and it is not offered with dynamic topology on. The Deformation section shows how long the last one took.

It is also the trial of moving a heavy sculpt operation onto the GPU. Sculpting runs on the CPU, across every core, and the GPU only draws; with "On the GPU" on, Smooth all runs instead as a compute shader (`src/render/shaders/smooth_all.comp`, `src/render/smooth_compute.odin`): the app uploads the positions, triangles, the vertex-to-triangle lookup and each vertex's weight, dispatches one pass a step between two position buffers, and reads the result back into the CPU mesh, which then updates normals, bounds, undo and the drawn mesh the usual way. The CPU path stays the default, and the fallback when the device refuses the compute pipeline. The shader does the CPU's arithmetic in the CPU's order (`precise` stops it fusing multiplies and adds), so the results match: on llvmpipe they are bit-identical, and on other GPUs they may differ in the last bits of a division.

`build.sh computebench` (or `build.bat computebench`) builds the release app and times Smooth all at 1 and 10 steps on a rough sphere at 500k, 1M, 5M, 7M and 10M vertices (only one size with `--vertices=N`), on the CPU and on the GPU, and writes the table to `build/computebench.md`. The GPU time is split into upload, compute and readback, each including the wait for the GPU. "Cold" uploads the triangles and lookup with the positions, as a press of Smooth all does; "warm" keeps them on the GPU from the run before, so only positions and weights travel, which shows what keeping the mesh on the GPU between commands would save. The last column is the largest difference between the GPU's result and the CPU's. Undo saving and normals are the same either way and are left out. It needs a display; only a real GPU gives meaningful GPU numbers.

The SDF/voxel comparison spike from step 3 builds separately: `deps/odin/odin build src/sdf_trial -o:speed -collection:deps=deps`.

The Odin vs Dart spike times the Draw brush's hot loops (finding the nodes a dab reaches, the area normal, moving the vertices, the per-frame normals) written the same way in both languages over the same cube-sphere and stroke, with one thread and with every core (Dart through worker isolates sharing the mesh in native memory). It answers whether the sculpt core could move to Dart; at 10M vertices on the 4-core cloud VM the Odin frame was 1.7 to 2.1 ms on 4 threads and the Dart frame 6.5 ms, and on one thread 2.6 to 3.3 ms against 6.4 to 10.6 ms. The checksum column agrees to about six digits: Dart does its arithmetic in doubles and rounds to floats on store.

## Idle objects

Only the selected object is sculpted or moved, so the viewport draws every other object once into a cached colour + depth image and reuses it while the camera and those objects stay put (all through a brush stroke). Each frame then costs a screen-sized copy plus the selected object's triangles, however many idle objects there are. Orbiting, panning, zooming, selecting another object or changing an idle one redraws the cache. On the CPU side idle objects already cost nothing per frame (`build/bench` with `--meshes=2`).

## Simplified drawing while the view moves

While the camera orbits, pans or zooms, or an object moves, far parts of each mesh are drawn from simplified copies, then everything is drawn at full detail once the view has stayed put for a quarter of a second. The chunks a mesh is split into for culling are grouped along its BVH, four to six at a time, then groups of groups, up to one group for the whole mesh. Each group has a copy of the triangles under it with about a quarter of them, made from its children's copies by collapsing edges into existing vertices, cheapest first by quadric error. A copy never moves a vertex on its group's border, so any mix of copies and chunks meets without cracks. Each frame, the renderer draws a group's copy instead of what lies under it when the copy strays less than "Largest error" (1 px by default) from the full mesh, as seen from the camera; nearby chunks stay at full detail. On a 10M vertex sphere seen whole this draws about 500k triangles instead of 8.6M (`build/bench --lod`).

Copies are built a few milliseconds a frame, for one object at a time and never during a stroke, so a new 10M vertex mesh takes a few seconds to get all of them; until then, and for the groups an edit made stale until they are rebuilt, the chunks under them are drawn instead. Meshes under 262,144 triangles get no copies. The Stats panel turns it off ("Simplify while moving"), sets the largest error, shows how many groups are left to build and the build time per frame.

## Subdivision levels

As in ZBrush, an object can have up to 8 subdivision levels: its base mesh and finer copies, each made from the one below by one step of Loop subdivision, which splits every triangle into four and smooths the result. Each level is a whole mesh with its own sculpt data and GPU buffers, so sculpting on a level costs what it costs on a plain mesh of that size, and only the current level is drawn. Every vertex above the base stores its offset from where subdivision puts it, in a frame that turns with the surface of the level below. When the current level changes, the levels are brought up to date with the edits made on the one being left: levels above are rebuilt from their offsets, so fine detail rides on a coarse change, and levels below move each vertex by half its own change plus half the average change around it, so they follow the large shapes of a fine edit while the detail stays on top. Only the parts of each level an edit reached are visited.

Ctrl+D (or Subdivide in the Object tab's Subdivision levels) adds a level above the top one and goes to it; D and Shift+D (or Higher and Lower there) go up and down a level. The section shows how many vertices and how much memory the next level would take (Subdivide is refused past 12 GB), the memory all levels use, and how long the last level change took. Delete lower makes the current level the base; Delete higher drops the levels above it; both are undo steps (that object's earlier strokes can no longer be undone one by one). Undo and redo walk back across levels, switching the object to the level each stroke was made on.

## HD detail

As with ZBrush's HD geometry, an object can be sculpted up to 3 Loop steps finer than its top level without building those levels. Divide HD in the Object tab adds an HD level (on a closed mesh), and A over the object opens a window: the finer subdivision of the top-level chunks nearest the pointer, up to the window size (4M vertices by default; the section's Window slider sets 1 to 16M). The window sculpts like any level and is drawn in place of the chunks it covers; A again (or Leave HD) stores what changed and closes it. Detail is stored per top-level chunk, only for chunks that were sculpted, as each vertex's offset from where subdivision of the top level puts it, in a frame that turns with that surface, so it rides on later changes to the top level and the levels below. Outside a window it is kept but not shown, as in ZBrush.

The window's border stays where the top level is drawn around it. Brushes fade out over the last 8 top-level edges toward it, so a stroke across it leaves a slope rather than a cliff, and flat seal triangles close the join between the two meshes so it draws without pinholes. Strokes in the window undo one by one; closing it stores them and drops them from the undo history, and undoing an older stroke closes the window first. Subdivide is refused while an HD level exists (Delete HD first), Delete higher drops it with the top level, and Remesh drops it.

## Sculpt layers

Sculpt layers work as ZBrush's: the Object tab's Layers section lists the selected object's layers on its current level, newest on top. New layer adds one at full strength and starts it recording (its record button lit): while a layer records, every stroke, Smooth all and Clip also goes into the layer, as the displacement it made. Its Strength slider then dials that work from -1 (reversed) through 0 (gone) to 2 (doubled), the eye button hides or shows it, and its name can be typed over; sculpting outside the layer (record off), or in another layer, stays where it is whatever the slider does, since the surface is always the work outside the layers plus each layer's displacement times its strength. Only one layer records at a time; Recording on a layer shown at another strength first sets it to full (an undo step), and moving the recording layer's slider stops the recording. Delete takes the chosen layer's work off the surface (the select under the rows chooses it); Bake keeps it as plain sculpting and drops the layer. Adding, deleting, baking, hiding and showing are undo steps, a slider drag is one undo step however far it goes, and undoing a recording stroke takes it out of the layer too. A layer keeps 12 bytes a vertex for the nodes it moved, and nothing elsewhere; a slider change moves only those vertices. Layers belong to a subdivision level: work on other levels reaches the level as always, under its layers. They are saved with the scene (every level's, with names, strengths and visibility; files from before layers open without any). Not in HD windows or with dynamic topology; turning dynamic topology on, and anything that rebuilds the mesh (remesh, decimate, mirror and weld, slice), bakes them. 10M vertices (`build/bench --brushes`, VM): a Draw frame while recording is the same as without (1.2 against 1.3 ms); the stroke's end adds it to the layer in 2.3 ms, and a slider change on that stroke's layer takes 4.6 ms plus 3.5 ms for normals. Flag: `--layer` adds a recording layer to the first object before starting.

## Brushes, masking and symmetry

Fourteen brushes, picked in the dock, the brush browser (the grid button at its end) or the brush pie, the first ten with keys 1 to 9 and 0 in this order:

| Key | Brush | What it does (Ctrl inverts) |
| --- | --- | --- |
| 1 | Draw | Pushes the surface out along the average normal under the brush (in). |
| 2 | Smooth | Moves each vertex toward the average of its neighbours. Shift smooths with any brush. |
| 3 | Clay | Builds up toward a plane just above the surface, moving only what lies below it, so dips fill first and strokes leave flat-topped layers (digs). |
| 4 | Flatten | Pulls toward the plane through the area under the brush (pushes away from it). |
| 5 | Inflate | Pushes each vertex along its own normal, so shapes swell evenly (shrinks). |
| 6 | Pinch | Pulls the surface together toward the brush's centre, along the surface (pushes apart). |

| 9 | Mask | Paints the mask (erases it). |

| | Snake hook | Pulls the surface out after the pointer for horns, tentacles and fingers: the point the stroke has reached follows the pointer in the plane facing the camera, and each step of the way, at most a quarter radius, drags what is under the brush along by its falloff. A Morph dab costs a little less than a Draw dab (10M: 0.22 against 0.31 ms in the same run). Flag: `--store-morph`.

## Polypaint and polygroups

**Polypaint** works as ZBrush's: each vertex has a colour, painted with the Paint brush in the colour picked in the Brush tab (with the Paint brush) or the Object tab's Polypaint section (Surface page), at full mesh detail (no textures or UVs). A colour has a coverage too: unpainted vertices show the material's clay, the brush lays paint over it as far as its strength and falloff reach (paint over bare clay is the paint colour from the first touch, so stroke edges fade into the clay without a dark fringe), and Ctrl takes coverage off again. The mask, hiding and Front faces only hold it back as they do any brush. Fill with colour paints everything that is not masked or hidden; Clear paint takes it off the same part. Strokes and both commands are undo steps (4 bytes a vertex of what they reach). Each subdivision level keeps its own colours: changing level carries what was painted since the level became current to the level you go to (a vertex continuing one below takes its colour, an edge vertex the average of the edge's ends, and going down a vertex takes the one above it), so a look at a coarser level and back leaves fine paint as it was, and a new level takes the colours of the one below. Colours are saved in scene files (for the current level) and exported: PLY as `red`, `green` and `blue` vertex properties, OBJ as three more numbers on each `v` line, both as the paint over white as far as it covers. On the GPU each vertex has 8 more bytes (colour and group) in a storage buffer the mesh shader reads, made only once an object has paint or groups. 10M vertices (bench, VM): a Paint stroke frame takes 1.0 ms against Draw's 1.3. Not in HD windows (whose detail leaves when they close) or with dynamic topology on (turning it on drops colours and groups; it is an undo step).

**Polygroups** split a mesh into parts, as ZBrush's do: a group number per triangle, shown in flat colours with View > Polygroups (Shift+W). Ctrl+W groups the masked part as one new group and clears the mask, or with nothing masked makes what is shown one new group (with nothing hidden, the whole object becomes one group), as in ZBrush. The Object tab's Polygroups section (Select page) has the same as buttons (Group visible, Group masked), Groups by creases (a group for each part of the surface between edges sharper than the Crease angle, 35 degrees by default: a cube's six faces, a hard-surface import's panels) and Clear groups. A Ctrl + Shift click on a group shows only that group; a second Ctrl + Shift click on it when it is all that shows hides it and shows everything else; with Alt as well, the click masks the group instead. A Ctrl + Shift click on empty space, or on an object without groups, still shows everything. Every change is an undo step, groups follow level changes as colours do (a triangle going up takes the group of the triangle it was cut from, going down the group of the middle one of its four), and they are saved with the scene. Drawing them costs no triangle data: each vertex carries one group to the GPU and each triangle is drawn starting from a corner that carries its own group, whose value a flat shader input takes, so borders are sharp; a triangle none of whose corners can carry its group shows a neighbour's colour (none in the tests; at most one in a thousand is allowed). While the view moves, far parts drawn from simplified copies may show ragged group borders. Flags: `--groups=creases|visible|masked`, `--show-groups`, `--paint-color=R,G,B` (0 to 1), `--fill-paint`, and `--brush=paint`.

Masking works as in ZBrush: each vertex has a mask from 0 to 255, and every brush moves it only by what the mask leaves (a fully masked vertex never moves). Masked areas are drawn darker. In the Object tab's Mask section, Clear (Alt+M), Invert (Ctrl+I) and Mask all change the whole mask at once; mask strokes and these commands are undo steps like any stroke. Blur, Sharpen, Grow and Shrink move the mask's edge, as ZBrush's BlurMask, SharpenMask, GrowMask and ShrinkMask and Blender's mask filters do, a step at a time: each vertex takes from the corners of its triangles their average (Blur), their highest value (Grow) or their lowest (Shrink), so a step reaches one ring of triangles further, and Sharpen pushes each partly masked vertex toward masked or unmasked against half a Blur step, which narrows a soft edge to a sharp one that stays smooth along the triangles. Mask cavities masks the creases and dents, as ZBrush's Mask By Cavity does: each vertex is masked by how far it sits below the average of its neighbours along its normal, measured against their distance, so grooves and pores go dark and flat or bulging parts stay free; Blur after it softens the result. Steps sets how many steps a press takes (3 by default): since a step is a ring of triangles, a denser mesh needs more for the same distance. The section shows what the last command did and how long it took. The mask is carried when the object changes subdivision level (a vertex that continues one of the level below takes its mask, a new edge vertex the average of the edge's ends), so it holds on every level. An HD window starts unmasked and its mask is dropped when it closes. The mask costs no GPU memory or upload: it rides in the low 4 bits of each of the two 16-bit halves of the vertex's packed normal, which still places the normal within 0.1 degrees.

Mask shapes work as ZBrush's: with the Brush tool, Ctrl and a left drag that starts on empty space (not on an object) draws a rectangle, or a lasso when the Mask section says so, and letting go masks everything of the selected object inside it, through to the back side; with Alt held too it unmasks. Each shape is an undo step. The polygon is filled into a 1024 x 1024 coverage grid first, so a lasso of any length costs a lookup per vertex: at 10M vertices a shape takes about 25 ms on the test VM, 2 ms at 1M (`build/bench --masks` has the rows). A drag that starts on an object is a stroke as before, and Alt + left drag without Ctrl still orbits.

Ctrl + Shift and a left drag with the Brush tool runs the gesture tool chosen in the Object tab's "Hide, clip and slice" section (remembered between runs): Hide rectangle (the default, as ZBrush's SelectRect), Hide lasso, Clip or Slice. A Ctrl + Shift click without a drag shows everything again, whichever is chosen, or on a polygroup isolates it (see Polypaint and polygroups).

Hiding works as ZBrush's: the hide tools draw a rectangle or a lasso (green), and letting go keeps only the triangles whose middle is inside it shown, through to the back; hold Alt as you let go to hide what is inside instead (red). Ctrl+H (or Show all) shows everything and Ctrl+Shift+H (or Invert) swaps hidden and shown; it never hides every triangle. Hidden triangles are not drawn and no brush, mask, mask command or clip moves a vertex all of whose triangles are hidden, and the brush and picking look through them; vertices on the edge of a hidden part still move. Each hiding change is one undo step. Each subdivision level keeps its own hidden part. Hidden parts are not saved in scene files, and hiding is refused in an HD window or with dynamic topology on (turning dynamic topology on shows everything); an HD window does not open while anything is hidden. On the test VM (release build) hiding half of a 10M-vertex sphere takes about 0.3 s. Flag: `--hide=y` keeps only the - side of the first object's Y plane shown (`-y` the + side; also x or z), after `--slice`.

Slicing works as ZBrush's SliceCurve but makes separate objects: the Slice tool draws a line (cyan) across the viewport, and letting go cuts the selected object in two along the plane through the line and the view direction, through to the back (`geom.mesh_slice`, `src/geom/slice.odin`). Each part is closed with a cap of evenly sized triangles (as long as the edges the cut crossed, up to 100,000 triangles a cap), so both stay closed and can be sculpted, remeshed or exported; holes and several separate cuts (a torus cut through) are filled correctly. The part on the right of the drag becomes a new object beside it; the other stays selected. It works on the level the object is on and rebuilds it like a remesh: levels, HD detail, mask and hiding go, and symmetry is not used. One Ctrl+Z undoes both parts. On the test VM a 1M-vertex sphere slices in about 0.4 s and a 10M one (20M triangles) in about 6 s plus 2.4 s to set the two objects up. Flag: `--slice=x` slices the first object across the middle of its bounds along x (or y, z) before starting, after `--mirror`.

Clipping works as ZBrush's Clip Curve: with the Clip tool chosen, Ctrl + Shift and a left drag draws a line across the viewport, shading the side to the right of the drag (hold Alt to take the other side instead; what is held when you let go counts). Letting go flattens every vertex of the selected object on the shaded side onto the plane through the line and the view direction, through to the back, so the part past the line becomes a flat cut face. Nothing is deleted: the triangles stay, lying in the plane (Remesh selected afterwards to tidy the cut). It mirrors with the brush's symmetry, leaves masked and hidden areas (partly masked ones move part of the way), and is one undo step. Not with dynamic topology on. On the test VM a clip takes 35 ms at 10M vertices for a small cap and about 150 to 250 ms when it cuts away half the mesh, most of it saving 60 MB of positions for undo; the Object tab shows the last one's time.

Stroke (the Brush tab): Dots lays dabs along the path, as above. Drag rectangle, as ZBrush's DragRect, lays one stamp where the drag starts and redoes it as the pointer moves: its radius is how far the pointer is from the start and, with an alpha, the image's top faces the pointer, so an alpha can be placed, sized and turned in one drag. Each redo first puts back what the stroke did so far from the undo copies it already keeps (`sculptor_stroke_restore`), so it stays one undo step and costs one dab a frame. It works with every brush but Grab and Snake hook, and not with dynamic topology, whose strokes change the triangles (those use Dots). Flag: `--stroke=drag_rect`.

Front faces only (a switch in the Brush tab's Options, as ZBrush's BackfaceMask) makes every brush but Grab, and the mask shapes, leave the vertices whose normal faces away from the viewer, with a short fade across the ones seen edge-on, so a stroke on a thin part such as an ear, a fin or a sheet leaves its far side alone and a mask rectangle stops at the visible side. It is per vertex, not a visibility test: a front-facing part hidden behind another is still reached. With symmetry, each mirror image faces the mirrored way. Flag: `--front-only`.

Symmetry (X, Y and Z on the toolbar at the top; the X key toggles X) mirrors every dab across those planes through the object's origin, up to 8 images with all three; Grab drags each image the mirrored way.

## Voxel remesh (DynaMesh)

Remesh in the Object tab (or Ctrl+R, at the object's own vertex count) rebuilds the selected object as an even surface of about the vertex count picked there, as ZBrush's DynaMesh does: stretched triangles from Grab or long strokes become even again, overlapping or self-intersecting parts merge into one closed surface, and anything thinner than the lattice spacing goes. It keeps the shape of the level the object is on; its levels, HD detail and mask go, and Ctrl+Z brings them back (HD detail apart).

How it works (`src/geom/remesh.odin`): the object is laid on a lattice whose spacing gives about the asked-for vertex count (at most 4,096 lattice points along any axis, DynaMesh's top resolution). A ray along each lattice row finds where it crosses the mesh and which way, using exact fixed-point tests so a ray through a shared edge or vertex counts it once, and a lattice point is inside where the winding number is positive. Rays along y and z find where the surface crosses those lattice edges. Marching cubes then joins the crossings, with one rule on ambiguous cube faces that makes the result closed and manifold (every edge between exactly two triangles), and three rounds of relaxation along the surface even out the triangles. Rays, crossings and cells are stored only where the surface is, so memory grows with the surface's area rather than the lattice's volume.

## Project detail

**Project detail** (Object tab), after ZBrush's ProjectAll: the selected object's shown level takes the shape of the object chosen in Project from, and its polypaint too with Polypaint too. Each vertex looks along its normal both ways, as far as Reach (a share of the selected object's size, 0.03 by default), for the other surface, and moves to the nearer hit by Strength; the mask holds vertices back as it holds a brush. Vertices that find nothing stay put. It is one undo step.

By default each object is read in its own space, as baking does, so a copy made by Duplicate or Retopologize, which is put beside the original, projects as if it lay on top of it; As placed uses where the two sit in the scene instead. The usual round trip: duplicate a sculpt, Remesh or Retopologize the copy (the detail goes), subdivide it a level at a time and Project detail at each level from the lowest up, so every level holds what it can of the original. A 100k-vertex retopology projected from a 1M sphere takes about 0.3 s on the VM, the source's BVH included. Not under dynamic topology on the selected object. Flag: `--project` (from the first object onto the selected one; after `--retopo`).

## Curve and insert tools

**Curve** (C, or Curve on the toolbar; its settings fill the inspector's first tab), after ZBrush's curve brushes: drag over any surface and, on release, a new object follows the path. It is made one of three ways. **Tube** sweeps a circle of Sides sides along it, capped at both ends; Lift sets how far its middle sits out from the surface, in radii, so 0 half buries it and 1 rests it on top. **Stitches** sets leaning bars across the path. **Zipper** sets interlocking teeth from alternate sides. Width is a share of the brush's diameter where the path began, so S resizes it. The path is resampled at even steps and smoothed three times, which takes out the hand's wobble. Each part is turned to the path's frame there (along the path, out of the surface and across it), so the result follows the surface's curvature. The result is an ordinary closed object: remesh it to sculpt it, or mark it Union for the booleans.

**Insert** (I), after ZBrush's insert mesh brushes: click a surface to put a shape there at the brush's size, standing on the surface's normal and turned with the view; drag before letting go to size it instead. The shape is any primitive or starter at Vertices (a starter is never under 15,000), or a copy of any object in the scene (Copy of ... in its list), fitted to that size. Sink pushes it into the surface by that share of its half size. **Mark it as** sets its boolean mark as it is made, so a cylinder marked Subtract, with Live boolean on, cuts a hole at once.

Each curve or insert is one undo step. The geometry is in `src/geom/curve_mesh.odin`. Flags: `--curve=tube|stitches|zipper` (a wavy path across the middle of the view) and `--insert=SHAPE` (at the middle of the view).

## Booleans and Extract

**Booleans** (Object tab), after ZBrush's Live Boolean: set "The selected object is" to Union, Subtract or Intersect on any object, and the marked objects apply, in scene order, to the base, the first object left unmarked. With **Live boolean** on, the result is drawn in their place at about Live vertices (200,000 by default) and made again whenever one of them is moved, turned, sculpted or remarked, once the mouse is let go; while you drag or sculpt the selected one it shows as it is. Subtract and Intersect objects are not drawn on their own, so select them in the Scene tab's list to move them. **Make boolean mesh** replaces the base with the result at about Result vertices (1M by default) and deletes the marked objects, all as one undo step. Marks are saved in .sculpt files.

How it works (`src/geom/boolean.odin`): both meshes go through the voxel remesh together, with B's crossings counted 4,096 times A's, so one winding number says whether each lattice point is inside A, B, both or neither, and the operation picks which count as inside. Any two closed meshes therefore combine, overlapping or not, into one closed manifold surface. The voxels round edges off at their spacing, so each vertex is then put back onto the nearer input surface along its normal when one is within a voxel, which brings back the inputs' detail and flat faces; only the seam where they meet stays at voxel resolution. Two 1M-vertex spheres: about 0.35 s for a 1M union on the VM; the live preview at 200k takes about a tenth of that.

**Extract masked** makes a new object from the selected object's masked part (mask over half), as ZBrush's Extract does: a shell Thickness thick (a share of the object's size, 0.02 by default) along the normals, its open edge smoothed so it does not follow the mask's jagged outline, closed where the masked part was one piece. Flags: `--boolean=union|subtract|intersect` (marks every object but the first and moves them onto it; use with `--spheres=2`), `--live-boolean`, `--make-boolean`, `--extract=THICKNESS` (masks the top third of the view first when nothing is masked).

## Retopology, UVs and baking

**Retopologize selected** (Object tab, Retopology and baking) makes a new object of about Quads quads (4000 by default) lying on the selected object's shown level, and puts it next to it, as ZBrush's ZRemesher does: every face a quad, closed where the sculpt is closed, facing out. The way there is simpler than ZRemesher's, and its edge flow does not follow the sculpt's curves: the sculpt is decimated by quadric error (as Decimate does, so more faces go where the shape bends), neighbouring triangles that make a near-square quad without folding pair up (about three in four do), every face is then cut into quads at its middle and its edges' middles, as a Catmull-Clark step cuts, and twelve rounds relax each vertex toward its neighbours' middle along the surface and put it back onto the sculpt along its normal. About four vertices in five end up with four quads around them. The new object is ordinary: it can be subdivided and sculpted, and its base level keeps its quads (drawn and sculpted as two triangles each) for export and baking; deleting its lower levels or turning dynamic topology on drops them. It takes about 11 s from a 10M sphere (mostly the decimation) and under a second from 1M (4 threads, VM).

It comes with **UVs**: the quads are grouped into charts that face within 55 degrees of their first quad, each chart laid flat by projecting it onto the plane facing that quad (so no quad folds over), turned to its smallest box, and the boxes packed in rows into the unit square at the largest scale that fits, with 8 texels of a 4096 map between charts; a sphere gets about a dozen charts filling 70 to 80% of the square. New UVs lays them out again after the shape changed a lot.

**Bake maps...** asks for a folder and bakes the object chosen in Bake from (by default the one the quads came from; its top level) onto the selected quad object's UVs, at Size texels square (512 to 4096, default 2048): each texel's point on the quads casts a ray each way along the quads' smooth normal, as far as Reach (2 average quad edges by default), and the nearer hit gives the displacement (distance along the normal, outward positive) and the sculpt's normal there. It writes `NAME_normal.png` (tangent space with green up, OpenGL's way; the tangent frame comes from the UVs per vertex and chart and is blended across each face, as MikkTSpace does, though not to the bit), `NAME_displacement.png` (16-bit grey: 32768 is the quads' surface, 0 and 65535 the largest distance in and out), `NAME_displacement.txt` (that distance in the OBJ's units) and `NAME.obj` (the quads with their UVs). Charts' edges are grown 8 texels outward so filtering at seams finds no background. Both objects are read in their own spaces, so moving either changes nothing. 10M-vertex sphere onto 5,000 quads at 2048: 3.7 s, with every covered texel finding the surface. Flags: `--retopo=N`, `--bake=DIR` (on exit, from the first object onto the newest), `--bake-size=N`.

## Mirror and weld, duplicate

Mirror and weld in the Object tab (as ZBrush's Mirror And Weld and Blender's Symmetrize) replaces one half of the selected object with a mirror image of the other, across the object's own X, Y or Z plane (the one brush symmetry uses), keeping the + side unless "Keep the - side" is on. Triangles crossing the plane are cut at it and the two halves are welded along the cut (`geom.mesh_symmetrize`, `src/geom/symmetrize.odin`), so a closed object stays closed; vertices within 1/100,000 of the object's size of the plane move onto it so the cut makes no slivers. It works on the level the object is on and rebuilds the object like a remesh: levels, HD detail and mask go, and Ctrl+Z brings them back. 100k vertices take about 0.1 s on the test VM. Flag: `--mirror=x` (or `-x`, `y`, `-y`, `z`, `-z`) does it to the first object before starting.

Duplicate (the Scene tab, or the object list's right-click menu; Ctrl+Shift+D) adds a copy of the selected object beside it, with every subdivision level, the mask and dynamic topology (HD detail is not copied, as in a saved scene), and selects it; Ctrl+Z removes it.

## Decimate

Decimate in the Object tab's Remesh section (as ZBrush's Decimation Master) rebuilds the selected object with about the vertex count picked there while keeping its shape: edges collapse where that moves the surface least (quadric error, `geom.mesh_decimate`, `src/geom/decimate.odin`), so the triangles stay dense where the detail is and go sparse where it is flat, unlike a remesh, which spreads them evenly. It is meant for exporting a sculpt to other programs. A collapse that would fold the surface, pinch it or leave a needle is refused, so a closed object stays closed and sound (`--check-mesh` stays clean); among collapses that change the shape equally, as on a flat area, shorter edges go first. Large meshes are first thinned in parallel, a quarter of the triangles a round in 64 cells whose borders move every other round, then finished as a whole. It works on the level the object is on and, like a remesh, drops levels, HD detail and mask (Ctrl+Z brings them back). The section shows how far the surface strayed at most. On the 4-thread test VM: 1M vertices to 3k in 0.7 s; 5M to 100k in 8 s and to 10k in 3 s; 10M to 100k in 12 s. Flag: `--decimate=N`.

## Dynamic topology

Ctrl+T, or the switch in the Object tab's Dynamic topology section, turns dynamic topology on for the selected object, as Sculptris Pro in ZBrush and dyntopo in Blender do: each dab first splits the edges under the brush longer than Detail pixels on screen and, with Collapse short edges (on by default), collapses the ones shorter than 0.4 of that. The brush makes triangles where it goes, as many as the detail you see needs, so you can start from a coarse ball and pull out horns and folds without stretching anything. Since Detail is in pixels, zooming in makes finer triangles. On a dense mesh seen from afar the edges are already shorter than Detail, and with collapse on the brush coarsens what it touches; lower Detail or switch collapse off to keep the density. Every brush works with it, symmetry too; Grab and Mask leave the triangles as they are, and so do fully masked areas. The object needs a single subdivision level and no HD level, and turning it on or off is an undo step of its own (its earlier strokes can no longer be undone one by one). Remesh selected works on a dynamic object and turns it off.

How it works (`src/sculpt/dyntopo.odin`): the sculptor works per node as it does on a fixed mesh, but each node gets a page of the mesh's arrays (1,280 vertex slots and 2,048 triangle slots) and uses the first of them, so it grows and shrinks in place; unused triangle slots hold zeros, which draw nothing. A node whose page fills up splits in two along its longest axis, and the BVH over the nodes is rebuilt then, in well under a millisecond. Each vertex lists its triangles (up to 16), so splits and collapses only touch what is around them. Splits go longest first and cut each triangle across its longest side (Rivara's bisection): when either triangle beside an edge has a longer one, that splits first, even just outside the brush. Triangles stay well shaped however often an area is refined: no angle went below 24 degrees in our measurements, and a test strokes one ring 160 times and checks for angles under 15 degrees, folds and the whole layout every 20 dabs. A collapse is refused where it would fold or pinch the surface, give a vertex more than 12 triangles, make an edge longer than Detail, or leave its worst triangle thinner than before and under 0.3 on a scale where an equilateral triangle is 1 (2√3 times the area over the sum of the squared sides), so thin slivers do not pile up where the brush coarsens. Surfaces that are not closed work too (an imported scan, say): an edge on the border splits its one triangle, and collapses leave border vertices where they are, so the border keeps its shape. Turning it on is refused on a mesh with an edge shared by more than two triangles or with triangles facing opposite ways across an edge. A dab makes at most 2,048 splits and 2,048 collapses, and the app stops laying dabs for a frame once they have taken 10 ms, so a large brush over a coarse area keeps the frame rate and catches up over the next frames. Undo saves each node a stroke changes, whole, before its first change, and swaps it back. The GPU gets the index pages that changed along with the changed vertices; when the mesh outgrows its buffers, they are made again at the larger size.

`build/bench --dyntopo` (4 threads, this repo's cloud VM). A frame is 4 dabs plus the normal update, as in the main table. Fixed is the large-brush stroke on the usual layout, Plain the same with dynamic topology on but nothing to split, Refine with a detail that splits every edge under the brush once (each triangle into four), which is far more than a stroke on a coarse mesh asks for: from 5M up every dab stops at its 2,048 splits. ## Files

The menu (top left) opens and saves scenes and imports and exports meshes, each through the system's file dialog (SDL's); what the dialog picks runs at the start of the next frame. The outcome shows as a note at the bottom of the window for a few seconds, amber when something failed or needs attention, and goes to the log.

**Scenes** (`.sculpt`: Open scene, Save scene, Save scene as): every object with all its subdivision levels as shown and their sculpt layers, a retopologized object's quads and UVs, the mask, polypaint and polygroups of its current level, dynamic topology if on, its name and place, and the camera. Each level is stored as positions, so it opens exactly as it was saved. Since the vertex numbering changes whenever a level is built, the levels above the base store their vertices in an order the topology alone decides: the vertices that continue the level below first, then those on its edges, by the edge's ends. Opening builds every level above the base again from it, as subdividing does, and moves its vertices where they were, so it takes about as long as subdividing to that size; the base itself keeps its node layout in the file, so it opens without being laid out again (see below). HD detail is not saved, only each object's number of HD steps; the HD section says so while an object has stored detail, and so does the note after saving. Nor is the undo history. Opening reads and uploads the whole new scene before the old one goes, so a damaged file leaves the scene as it was (both are in memory for a moment). Saving writes beside the file and renames over it, so a failed save never leaves a half-written file. The format is little-endian binary with a version number: `scene_save` in `src/app/files.odin`, then per object `levels_write` in `src/sculpt/levels_file.odin`.

**Import** (Import mesh, `.obj` or `.ply`): OBJ `v` and `f` lines (polygons become fans of triangles; negative indices and `v/vt/vn` corners work; everything else is skipped), read in parallel chunks of 4 MB. PLY in ASCII or binary of either byte order, with any vertex properties (x, y and z are kept) and polygon faces. Then a cleanup: vertices at exactly the same place are welded (exporters split vertices along UV seams), triangles left with a repeated corner and vertices no triangle uses are dropped, and a closed surface that faces inward is turned outward. The mesh is centred and sized like a sphere (radius 1) and placed beside the other objects; its place in the file is kept for export. A surface that is not closed sculpts, also with dynamic topology, which keeps its border, but subdivision, HD and remesh need a closed one, and the note says so.

**Export** (Export selected, `.obj` or `.ply` by the name, or by the dialog's filter when the name has none): the selected object's shown level (packed, when dynamic), as OBJ with nine significant digits, which read back as the same floats, or as binary PLY, with polypaint as vertex colours when it has any (Import does not read colours back yet). It goes back where it was in the file it came from, so an imported mesh exported again lines up with the original; Move tool placement is not written.

An object made by Retopologize exports from its base level as quads with their UVs (OBJ only; PLY stays triangles). Normal and displacement maps are baked into a folder from the Object tab (see Retopology, UVs and baking).

The look comes from one set of design tokens (`src/ui/theme.odin`, "Graphite"): surfaces, text, one blue accent and the status colours, three corner radii (6, 8, 12), five type sizes in Inter and the motion durations. The brush pie, the labels over the viewport and the Stats panel use the same tokens and typeface.

Motion (`src/ui/motion.odin`) follows Anime.js: a value eases toward its target over a duration, after an optional delay, and a new target sets off from wherever it is, so nothing jumps. Presses dip and wash, hover fades in, the marker under a chosen tab or brush slides, switches move their knob with a slight overshoot, menus and popovers grow from where they open and fade, groups open by growing, the inspector slides, tooltips wait and fade, and notes rise in one after another. Nothing a stroke, the camera or a drag depends on is animated. Menu > Reduce motion, or `--reduce-motion`, makes every animation arrive at once; it is remembered.

The kit (`src/ui`) is drawn by the renderer's own UI pass (`src/render/ui_pass.odin`, `ui.vert`/`ui.frag`): one vertex and index buffer a frame, a single-channel glyph atlas updated only where it changed, one draw per texture and clip change, with the viewport image drawn as the first quad and the viewport's overlay (the brush outline, the gizmo, the shape being dragged) laid just over it, under the panels, though it is drawn after them, once the tools have run (`ui.layer_mark`). At 1600 x 900 a frame is about 6,500 vertices with the Brush tab open and 9,000 with the Object tab; laying it out, animating and tessellating it takes about 0.65 ms p50 (0.8 ms with the Object tab) in a release build on a 12-thread Windows desktop, at 1M and at 10M vertices alike (`ui_ms_p50`, `ui_ms_p99` and `ui_vertices` on exit). Animations change only the vertices drawn, never the layout, and the tweens live in one table allocated at start. Keys, the pointer and typed text come from SDL's events (`src/app/device.odin`); fingers and the pen come from SDL's touch and pen events (`src/app/touch.odin`, `src/app/navigate.odin`), with SDL's own turning of fingers into the mouse off (see Touch and pen below). Text is Inter (SIL Open Font License) and icons are Lucide (ISC), both embedded; their licences are in `assets/fonts`.

## Command palette

Ctrl+K, `/` (on keyboards where it has its own key; Ctrl+K works on every layout) or the Search button at the top right opens the command palette: a search field over a list of every command the menus, the inspector's buttons and the shortcuts run, one row per brush, view, mask command, paint, group command, remesh or decimate size and New scene shape, plus each Settings tab ("Settings: Touch") and each Help tab ("Help: Gestures"). Type part of a name, or a word another app uses for it (dynamesh, zremesher, subtool, freeze, polygroup, bpr, ...): rows whose name is the text come first, then names starting with it, then names with a word starting with each word typed, then those other words, then, from three letters, names holding the letters in order (`wfr` finds Wireframe). Among equals, a row run recently comes first, then one that can run now. Each row shows its icon, its shortcut, and a check when it is on; one that cannot run now (Duplicate object with nothing selected) is dimmed, does nothing, and its help line below starts "Not now". Up and Down pick a row (the list, eight rows or as many as the window's height leaves room for, scrolls to follow; with no keyboard, typing more narrows it), Enter or a tap runs it and closes the palette, and Escape, Android's Back, Ctrl+K again or a press outside closes it. With nothing typed the list starts with the last eight rows run, which are remembered (`palette_recent`, by name) and cleared by Settings > Reset everything. Two commands that act where the pointer is (A's HD window and R's replay) are not listed.

## Settings

Menu > Settings opens the app's preferences on the right, in the inspector's place, so the model stays in view while a change is tried; every change takes effect at once. Four tabs:
- Interface: the interface size (100% to 150% of what the screen asks for, never smaller, so every target stays at least 48 points), Reduce motion, Lay the brush ring on the surface (on by default; see Controls), Show next steps over the dock (the action bar, on by default; see Interface), Modifier buttons (Off, Left, the default, or Right, above the object's status, for the other hand; see Touch and pen), Show every option (the inspector's sections without their More options folds, off by default; see Interface) and Reset panel positions. They are remembered with the rest (see Remembered settings): saved when the panel closes, when the app goes to the background (Android) and on exit. Brush and tool settings stay with the tool, in the inspector; the drawing switches for comparing speed stay in the Stats panel's Advanced view.

## Statistics

F11, Menu > Stats or Settings > Performance shows the Stats panel at the top left. Simple, the default, says how smoothly the app runs in plain words, in four groups: Performance (frame rate; frame time and interface update time, each typical and in slower moments; the GPU's 3D time when measured), While sculpting (brush work per frame and input to the GPU, once a stroke has run), Mesh (objects, vertices, triangles, triangles drawn last frame) and Memory (the undo history's size; the memory of the whole app is not measured, so it is not shown), then Last operation (what the last remesh, smooth, file action and so on did, and how long it took). Typical is the median (p50) of the last 240 frames: half took less and half more. Slower moments is the 99th percentile (p99): 99 frames in 100 took that long or less; it is not the slowest frame. Interface update is only the time to lay out and draw the panels, one part of a frame. With VSync on, the frame time includes waiting for the screen, so it sits near the refresh time even when the app has time to spare. "What do these numbers mean?" at the bottom says the same. Advanced shows every measurement by its exact name (`frame_ms`, `cpu_ms`, `ui_ms`, `cursor_ms` for laying the brush ring on the surface, ...) with its p50 and p99, the frame-time graph, the drawing switches and what the brush costs; a measurement with no samples yet says so instead of showing 0.

## Screenshots

Menu > Save screenshot (F12) writes the viewport, as the last frame drew it and without the brush outline or gizmo, to a PNG file at the viewport's size. The encoder is this repo's own (`src/png_write`; Odin's `core:image/png` only reads): each row filtered with Sub or Up, deflated with greedy matches and the fixed codes, so a 1214 x 862 viewport is about 200 KB and takes about 25 ms in a release build. `--dump-viewport=PATH` does the same on exit, or writes a binary PPM when the path ends in `.ppm`, which `scripts/ppm.py` reads.

## Pen and brush pie

The Brush tab's Pen section holds what a drawing tablet changes. "Pressure changes strength" and "Pressure changes size" choose what pen pressure scales; a mouse counts as full pressure. The pressure curve below them maps how hard the pen presses (along) to how much that counts as (up): a cubic Bézier from corner to corner whose two handles drag anywhere in the square, so it never falls back. Linear, Soft (light pressure goes far), Firm (it takes a press) and S are presets. A dot on the curve follows the pen. The Tilt slider (0 by default) lets a leaning pen turn the brush: the direction Draw, Clay, Flatten, Pinch and Crease push in leans toward the pen's top, by the pen's lean times the slider, at most 81 degrees, as Blender's tilt does; mirrored dabs lean the mirrored way. With tilt on, a line from the brush circle shows the lean. The readout under it shows the last pressure, what it counts as, and the lean. Tilt costs one small rotation a dab: a 2M stroke took the same brush time with it and without (1.27 to 1.33 ms p50 either way, run to run). SDL reports pen pressure and tilt on Windows (pointer messages) and on Linux (X11 and Wayland); neither is tested on a real tablet yet.

The brush pie puts every brush in a ring around the pointer, in key order clockwise from the top. Hold Space over the viewport, point toward a brush and let go to pick it, so a flick picks without aiming. A tap of Space, or a right click without dragging (a pen's side button sends one), leaves it open: click a brush, or click the middle, press Escape or tap again to close it. While it is open, nothing reaches the tools or the camera. The slice of the brush in use has a band along its outer edge.

## Brush falloff

The Brush tab's Falloff section shows how strongly the brush in use works from its centre (left) to its rim (right). By default it is the built-in smooth falloff, (1 − d²)² for the distance d in radii. Dragging either handle draws your own: a cubic curve read from the rim in, as the pressure curve is drawn, so it is always 0 at the rim and full at the centre. Presets: Smooth (the built-in), Linear (a cone), Sharp (a point in the middle, for creases and pores), Firm (most of the radius at full strength) and Flat (full strength to the rim, a hard-edged stamp). Each brush keeps its own falloff, Grab and Mask included; an alpha replaces it. The sculptor reads a drawn falloff from a 257-entry table over the squared distance, so it costs no square root: a 2M stroke's brush time was 7 to 12% higher with one than with the built-in (0.24 vs 0.25 to 0.27 ms p50, release, test VM). Flag: `--falloff=NAME` starts every brush with that preset.

## Brush alphas

An alpha, as in ZBrush (Blender calls it a brush texture), is a square grey image that shapes each dab in place of the round falloff: white moves fully, black not at all. The Brush tab's Alpha section shows the round brush and every alpha as thumbnails; tap one to use it. Six are built in: Square (flat stamps and edges), Noise (bumps of every size, for skin, stone and bark), Rings, Stripes (ridges along the image's up, so along a stroke they rake parallel grooves), Dots (rivets, scales) and Star. "Load image..." adds a PNG, JPEG, BMP, TGA or QOI file: its brightness times its opacity, padded to a square and averaged down to at most 512 pixels a side, so a grey height map and a white shape on a transparent ground both work. Every brush but Grab uses the alpha; Shift's smoothing stays round.

The image lies on the plane across the area under the brush, its middle on the dab's centre and its sides one radius away, so a stamp sits flat on a curved surface. A vertex takes the image's value where it falls, blended between pixels, and fades as it lies further above or below that plane. Which way the image's top faces is the mode: Follow stroke turns it with the stroke, Fixed keeps it to the screen's up, and Random turns every dab a new way, for texture without a visible repeat; Angle turns it further. The brush outline becomes the image's square, turned as the next dab will be, with a tick at its top. Symmetry mirrors the image too, so a stamp on the left reads backwards on the right as a mirror would show it.

A dab looks for vertices as far out as the image is above 0, measured when it loads: up to the square's corners, 1.41 radii, but no further than the round brush for images that fade out inside their circle, like the built-in ones but Square. With the Noise alpha a dab costs about a fifth more than Draw and a frame under a tenth more (`build/bench --brushes`, the large brush; Draw measured 0.037 and 0.312 ms a dab and 0.27 and 1.91 ms a frame at 1M and 10M in the same run, beside the alpha row in the table above), the extra being three dot products and one image lookup a vertex.

## Viewport materials, flat shading and wireframe

The Scene tab's Material section picks how objects are shaded. The classic presets are Clay (the default, as before), Red wax, White, Grey and Skin: each sets the selected object's colour, a muted one for the others, and the light's ambient, highlight and wrap (wax and skin let the light reach past the shadow line, as scattering does). Below them are physically based materials: Gold, Copper, Chrome and Steel (metals, coloured by measured reflectance), Plastic, Ceramic, Rubber and PBR clay. These use metallic and roughness with GGX highlights from the key and fill lights plus the reflection of a procedural studio (grey sky, dark floor, a softbox behind the key light) that roughness blurs, and a filmic curve so bright reflections roll off; it is all computed in the fragment shader, so they take no memory and cost the same at any vertex count. The colour, Metallic and Roughness sliders under it edit whichever material is in use into Custom, leaving the presets as they are. View > Flat shading, or Shift+G, lights each triangle with its own normal, so the facets show instead of the smoothed normals; the shader takes the triangle's normal from screen-space derivatives of the position, so it needs no extra vertex data and works with every material. While the view moves, far parts drawn from simplified copies show those copies' larger facets. View > Wireframe, or Shift+F as ZBrush's PolyFrame, draws the selected object's triangle edges over it: the same visible chunks again with line fill, pulled toward the eye by a depth bias so they sit on the surface, so it roughly doubles the selected object's draw cost while it is on. Flags: `--material=NAME`, `--flat`, `--wireframe`.

## Brush presets

A preset is a named brush, as in Nomad or Blender: a base brush with its own strength, falloff, alpha (with its mode and angle), stroke kind, lazy mouse, paint colour and cloth mode. Size, the pen settings, symmetry and front faces only stay the same for every brush, so changing brush never changes how big it is. The Brush tab's first section, Preset, names the one the brush is on even while folded ("Preset: Soft clay · changed"). On a plain brush it offers Save as preset (named "Clay 1", "Clay 2", ...), which keeps the brush as it is and puts it on the new preset, and Reset brush, which puts the plain brush's strength and falloff back to a fresh install's. Its list picks any preset, or None for the plain brush. On a preset: its name, to type a new one (Enter or a tap elsewhere renames it; an empty name, another preset's or a brush's own is refused), Save changes and Revert (while it differs from what was saved), Save as new preset (a copy), and under More options Delete preset. The brush's own slots hold the preset's values while it is on one, and leaving it (picking a brush by its key, the dock, the pie or the list) gives the plain brush its own back, so a preset never changes a plain brush and what is remembered for it. The palette finds Save brush as preset, Save preset changes, Revert preset, Delete preset and Reset brush. The brush browser lists the presets under the brushes, each tile the base brush's icon over the preset's name (a long one is cut, and shown whole in its tooltip): a tap picks one, a long press (or right-click) shows its settings with the Preset section open. Each of the dock's seven slots holds a brush or a preset, and a long press (or right-click) on one opens its menu above it: Brush settings (Preset settings on a preset), every brush and preset to put in the slot instead (a tap puts it there), and Reset dock, which gives back a fresh install's seven. The same brush or preset may sit in two slots, and a deleted preset's slots go back to its brush. Up to 24 presets; they and the dock are remembered with the settings, and an alpha is remembered by name, so a loaded image's comes back only when that image is loaded again (the built-in ones always do).

## Remembered settings

An interactive run remembers, for the next one, the brush (which one, its size, each brush's strength and falloff curve), the pen settings (pressure, its curve, tilt), lazy mouse, the stroke, front faces only, symmetry, the dynamic topology detail, the alpha mode and angle, the material (with the Custom one), flat shading, wireframe and orthographic view, the Scene tab's shape and size for new objects, the mask steps and mask shape, and the command palette's recent rows, and the brush presets with the one the brush was on (`preset` and `brush_preset` lines, names escaped as %20), and the dock's slots (`dock <slot> brush <brush>` or `dock <slot> preset <name>`). So do the Settings panel's choices (the interface size, the brush ring, Show every option, how far the first-run tips got, the camera and touch settings with what the view turns about and the safe zone, the Stats panel and VSync; see Settings), and where each panel window was moved to and whether it is folded (`window` lines). They go to `settings.txt` in SDL's per-user folder (`%APPDATA%\Implicit\Sculpt` on Windows, `~/.local/share/Implicit/Sculpt` on Linux) when the app closes, when the Settings panel closes and when the app goes to the background, as plain `key values` lines after a `version` line; delete the file to start from the defaults. Runs with `--frames`, `--gpubench`, `--bench-stroke` or `--no-settings` neither read nor write it (`--settings-file=PATH` reads and writes PATH instead, scripted runs included), so scripted runs and benchmarks stay the same everywhere, and flags given on the command line win over it. Which sections are open is not remembered, nor are the scene, the speed toggles in the Stats panel or Smooth all's "On the GPU" switch.

## Cloth brush

The Cloth brush (no key; in the brush browser and the pie) turns the surface in and around the brush into cloth for the length of a stroke, as Blender's cloth brush does, so it folds and wrinkles instead of stretching. Its mode, in the Brush tab's Stroke section: Drag (what is under the brush follows the pointer on the plane facing the camera, as Grab, and the cloth around it is pulled along into folds), Gravity (the region sags toward the bottom of the screen while the button is held, settling at about half a radius at full strength; Ctrl lifts it), Pinch (gathers the cloth toward the brush into radial folds, easing in over the first 40 frames up to 55% of the way at full strength; Ctrl expands) and Expand (pushes it outward so it buckles into a ring ridge; Ctrl pinches). The simulation (`src/sculpt/cloth.odin`) is position-based dynamics in the object's space: a damped Verlet step with the mode's force, then five Jacobi rounds over every triangle edge of the region that keep the edges at their lengths, puff squeezed cloth out along its starting normals so it folds outward together, and even out each vertex's displacement with its neighbours' (bending), so folds stay smooth on dense meshes. The region's outer 30% is increasingly held where it was, and masked or hidden vertices are held completely, so the cloth stays sewn to the rest of the mesh. It runs every frame while the button is down, even with the pointer still; the stroke is one undo step. Symmetry is not applied, and it does not run with dynamic topology on. Cost on the test VM (4 threads, release): on a 1M-vertex sphere about 2.3 ms a frame with a 60 px brush; at 10M (about 170k simulated vertices) about 18 ms a frame and 50-150 ms to set up at the start of a stroke, so it is a slower brush than the others, which it leaves untouched. Flags: `--brush=cloth`, `--cloth=drag|gravity|pinch|expand`.

## Studio render

View > Studio render (Shift+R, as ZBrush's BPR) builds the viewport up into ambient occlusion and a soft key-light shadow while the view stays still, like a path-traced preview: crevices and creases deepen, and raised forms cast soft shadows onto what is behind them and onto other objects. Each still frame adds one light sample (`src/render/studio.odin`): it renders every object's depth from a direction into a 2048² shadow map, then for every viewport pixel reconstructs the surface point and normal from the viewport's depth and adds whether that light reaches it (3x3 filtered) to a half-float accumulation image. Three samples in four come from directions spread evenly all round the scene (an R2 sequence), weighted by how directly they face the surface, which gives the occlusion; one in four comes from around the shading's key light, jittered over a small disc, which gives its soft shadow. The image shown is the viewport darkened by both, by the Occlusion and Shadow strengths in the Scene tab's Studio render section; it settles within the Samples count (256 by default, at most 1024), after which it costs nothing. That section shows the count while it builds. Any change to the viewport, a stroke, the camera, a resize, starts it over; until the view is still again the plain viewport is copied through, so with it on a stroke costs one screen-sized copy a frame (10M stroke on the test VM: CPU frame p50 3.8-3.9 ms off and 4.8 ms on, where the llvmpipe software GPU makes that copy on the CPU; on a real GPU it is a fraction of a millisecond). Screenshots, `--dump-viewport` and the time-lapse save what the viewport shows. It needs a depth format shaders can read; where the device has none it logs a warning and stays off. Flags: `--studio`, `--studio-samples=N`.

## History timeline and time-lapse

The History panel (the clock button beside undo and redo) opens over the brush dock and lays every undo step on one bar, oldest at the left: a block per step, coloured by what it was (brush strokes gold, mask changes blue, hiding grey, Smooth all and Clip green, rebuilds such as remesh or add and delete orange), dimmed once undone. Press or drag anywhere on the bar to go to that point; resting the pointer on it shows the step's brush or command, its object and how long ago it was made. The outer buttons jump to the start and the newest step, the ones beside them step one at a time, and Play replays the History forward at the Steps a second speed (from the start when it stands at the end). It moves only with undo and redo, as many as it takes, so it is exactly Ctrl+Z or Ctrl+Shift+Z pressed that many times: a stroke made after scrubbing back drops the steps ahead of it, and what the undo memory limits dropped is not on the bar. Scrubbing spends at most 25 ms a frame stepping, so a long drag stays responsive; a stroke undo takes about 2 ms at 10M vertices in a release build on the test VM, so the whole History of 40 strokes there rewinds in well under a second.

Record time-lapse... asks for a folder, rewinds the History to the start, then redoes Steps a frame steps each frame up to where the timeline stood and saves the viewport after each as `frame_00000.png`, `frame_00001.png` and so on, at full detail; with Turn above 0 the camera also turns that many degrees around the scene each frame, as a turntable, and goes back where it was afterwards. Any video tool turns the frames into a film (`ffmpeg -framerate 12 -i frame_%05d.png sculpt.mp4`). A stroke, or Stop recording, ends it early. Flags: `--timelapse=DIR` records once `--bench-stroke` ends (or at the start), and the run lasts until it is done; `--timelapse-steps=N` and `--timelapse-spin=DEG` set Steps a frame and Turn; `--bench-lifts=N` lifts the synthetic pen N times so the stroke becomes N + 1 steps.

## Stroke recorder

The Brush tab's Stroke recorder keeps strokes to play back, as ZBrush's Record and Replay Last do. The app always keeps the last stroke as it was drawn: every frame's pointer samples, pen pressure and tilt, Shift and Ctrl (and the modifier buttons), the camera and viewport size, and the brush settings. Record starts a recording that keeps every stroke until Stop recording. Replay plays the recording, or else the last stroke, back where it was drawn, with the camera it was drawn with, whatever the view is now. R over the viewport plays it so its first stroke starts under the pointer, in the current view and size, which turns a stroke or a set of strokes into a stamp to lay anywhere, on any object (a rivet, a scale, a monogram, a spiral). With Recorded brushes off the path is replayed with the brush as set now: record a path once, then lay it with Clay, then Crease. Instant plays every recorded frame at once instead of one a frame, as drawn. Escape stops a replay, and switching to Move does too.

A replay feeds the recorded frames through the same code a drawn stroke goes through (`src/app/replay.odin`, `sculpt_frame`), so lazy mouse, symmetry, Drag rectangle, Grab, Snake hook and Cloth replay as they were drawn, each replayed stroke is one undo step and shows on the History timeline, and a replay where it was drawn on the same mesh gives the same vertices, bit for bit, as the original strokes (checked frame by frame and Instant on a 200k sphere: three strokes recorded with `--record-strokes`, saved, then replayed on a new sphere, export files identical). Instant brings normals up to date between recorded frames (`sculpt.sculptor_refresh_normals`), as frame-by-frame drawing does. While a replay runs the pointer does not sculpt; the camera still moves.

Save strokes... writes the recording (or else the last stroke) to a `.strokes` file and Load strokes... reads one into the recording, to replay in another scene or share. A file keeps each stroke's brush kind, size, strength, falloff, pressure settings and curve, lazy mouse, Front faces only, stroke mode, symmetry, paint colour and cloth mode; the alpha, pen tilt strength and dynamic topology detail come from the brush as set when it is loaded, since an alpha names an image file that may not be there. Every number in a file is checked (finite, in range) before it reaches a brush, and a damaged file is refused. A frame costs 60 bytes plus 21 a pointer sample in the file and a little more in memory. Version 3 files keep whether a frame's stroke painted the mask through the Mask modifier button; versions 1 and 2 still load. Flags: `--record-strokes`, `--save-strokes=PATH`, `--load-strokes=PATH`, `--replay-shift=DX,DY`, `--instant-replay`.

## Controls

Every shortcut, menu row, brush key and inspector action button runs a command from one table (`src/app/commands.odin`: name, help, icon, whether it can run now, whether it is on), so the shortcut a menu or tooltip shows is always the one that works. A shortcut's modifiers must match exactly: Ctrl+Z undoes and Ctrl+Shift+Z redoes, and a key held with a modifier it does not list does nothing (Ctrl+B, Shift+1 or Ctrl+F are not shortcuts). Each key press keeps the modifiers held when it went down, so two quick shortcuts in one slow frame both work.

Files: Ctrl+O opens a scene, Ctrl+S saves it (where it was last saved or opened, else it asks), Ctrl+Shift+S saves it somewhere else. F12 saves a screenshot.

Tools (also on the toolbar): W picks Move, B Sculpt (the brushes), C Curve and I Insert. Ctrl+K or `/` opens the command palette (see Command palette). Tab shows or hides the inspector, F11 the Stats panel, F1 opens Help (every shortcut, the mouse and touch controls, and a glossary), and Escape (or Android's back gesture) closes whatever menu is open. F points the camera at the selected object; Shift+F shows its wireframe; Shift+G switches flat shading; Shift+W shows polygroups, Ctrl+W groups the masked part (or what is shown). Delete deletes it (Ctrl+Z brings it back). Ctrl+D subdivides the selected object; D and Shift+D go up and down its levels; Ctrl+Shift+D duplicates it. Ctrl+R remeshes it at its own vertex count. Ctrl+T turns dynamic topology on or off for it. A opens an HD window where the pointer is on an object with an HD level, or closes the open one.

Move: click an object to select it (a click on empty space clears it, a drag there turns the view), drag it to move it in the view plane, or drag a gizmo arm (red X, green Y, blue Z) to move along that axis. The Object tab's Transform sets position, turn and scale exactly: drag sideways on a value.

Brush: left drag sculpts the object under the cursor, which becomes selected (Shift smooths, Ctrl inverts; the Mask brush then erases); a left drag that starts on empty space turns the view instead, as in ZBrush, and keeps turning it when it crosses the model (Settings > Touch makes the mouse wait for the model instead). Keys 1 to 9 and 0 pick the first ten brushes, X toggles X symmetry, Alt+M clears the mask and Ctrl+I inverts it. Ctrl + drag from empty space masks a rectangle or lasso (Ctrl+Alt unmasks). Ctrl+Shift + drag runs the chosen gesture tool: hides by rectangle (the default) or lasso (Alt hides the inside), clips along a line (Alt: the other side) or slices along a line; a Ctrl+Shift click shows everything. Ctrl+H shows everything, Ctrl+Shift+H inverts what is hidden. The brush follows every mouse or pen sample, not just where the pointer is once a frame: dabs go along the path the pointer took on screen, a quarter of the radius apart, each where that point meets the surface. Pen pressure scales the strength, and the size too with "Pressure changes size" in the Brush tab's Pen section, through the pressure curve there; a mouse counts as full pressure. Space (hold and let go, or tap) or a right click without dragging opens the brush pie (see Pen and brush pie above). S over the viewport sizes the brush where it is (move away from or toward the circle's middle, then click or press S again; a right click or Escape puts the old size back), and U does the same for the strength; [ and ] step the size, Shift+[ and Shift+] the strength. Each brush keeps its own strength, and Shift-smoothing uses the Smooth brush's. The brush ring turns blue while a press would smooth, red while it would invert and violet while it would paint the mask, from the keys held or the modifier buttons. Lazy mouse makes the brush trail the cursor on a string that many pixels long, for steadier lines. Over the model the brush ring lies on the surface, as in ZBrush: a circle of the brush's size in the plane the surface faces under it (the vertex normals the brush would reach, weighted as a dab weighs them, so it shows the way the brush pushes), seen in perspective, with a short tick out along that normal from its middle; off the model it is a flat circle on the screen (Settings > Interface turns this off). With an alpha (see Brush alphas above) the outline is the alpha's square. R over the viewport replays the recorded strokes (or else the last stroke) starting under the pointer, and Escape stops a replay (see Stroke recorder above).

Scene tab: pick a shape (Sphere, Cube, Cylinder, Cone, Torus, or one of the starters below) and a size (41k to 25M vertices) and Add it; the Object tab's Remesh rebuilds the selected object as an even mesh of about the size picked there that keeps its shape (see Voxel remesh above). Geodesic spheres come in steps of 10f² + 2 vertices; the Scene tab shows the exact count it will build. The cube and torus are even grids, so their triangles follow their edges; the cylinder and cone are voxel remeshed from a smooth outline, which gives even triangles over the caps (their counts land within about a fifth of the one asked). Every shape is closed, so it subdivides and remeshes like a sphere. Flag: `--shape=NAME` starts with that shape instead of spheres.

**Starters** are base meshes to begin a sculpt from, as ZBrush's and Nomad's are: Head, Bust, Figure (A-pose), Hand and Creature (four legs and a tail). They are made in code, so they need no files and carry no licence (`src/geom/starters.odin`): each is a few dozen ellipsoids and tapered tubes, fused into one closed surface by a voxel remesh (as fine as keeps the thinnest part, a finger or the tail, whole) and relaxed so the joins blend, then remeshed again at the size asked and relaxed a little more. Each faces the front (+Z) with +Y up and, all but the hand, is symmetric across X, so X symmetry works on it at once. Added at a size, a starter arrives with subdivision levels: as many as keep its base at 15,000 vertices or more, up to three, so a 1M Head is a 16k base with three levels above it, to step down to for big changes of form and up for detail (the Scene tab says how many levels it builds). A starter is never built under 15,000 vertices. On the test VM a 1M Head takes about 3 s from the tap to sculpting.

**New scene** (Menu > New scene, or the palette's "New scene: Head" and so on) replaces the scene with one Sphere, Head, Bust, Figure, Hand or Creature at the Scene tab's Add size, in the starting view, with an empty History and no file to save to (Save then asks where), as opening a scene does. When the scene has work to lose (any undo step, or more than one object), the first tap only arms that button, which turns red and reads Discard?, with a note; a second tap on it within 4 s goes ahead, and the menu stays open between the two. A palette row needs running twice in the same way.

Orbit, as ZBrush: a left drag on empty space or in the safe zone along the window's edges (see Touch and pen), a right drag anywhere, or Alt + left drag. The view turns about the middle of the last stroke, which stays where it is on screen while everything turns round it, as ZBrush's Local and Blender's Orbit Around Selection do, so the part being worked on stays in view; before any stroke, and after Focus, Frame all or Reset camera, it turns about the selected object's middle, and a point behind the eye is passed over. A small dot marks it while the view turns. Settings > Camera > Turn about can make a drag that starts on the model turn about the spot under it instead (Pointer, as Blender's Auto Depth), or every orbit turn about the middle of the view (Centre). Hold Shift while turning to snap to the nearest view square to the axes (front, back, sides, top or bottom, upright or at a quarter turn of roll), and a drag far enough jumps to the next. Pan: middle drag, or Alt or Shift + right drag. Zoom: mouse wheel, or Ctrl + right drag (up zooms in). The orbit goes all the way round both ways, over the top too, with no jump and no flip at the poles: Free (the default) turns about the screen's axes, Turntable about the model's up axis (Settings > Camera, with the speeds and inverting). P (or keypad 5) switches between perspective and orthographic (parallel) projection, as wide at the orbit centre as the perspective view, so the object keeps its size on screen. Keypad 1, 3 and 7 look from the front, right and top, with Ctrl from the back, left and bottom (also in the Scene tab's Camera section). In orthographic projection the far-chunk simplification while orbiting is off. Flags: `--ortho`, `--view=front|back|right|left|top|bottom`.

## Touch and pen

Fingers and the pen work as in ZBrush for iPad (`src/app/touch.odin`, `src/app/navigate.odin`, with every setting in Settings > Touch):
- One finger on the model sculpts, as the mouse does, once it has been down 90 ms (0.25 s while double taps are on) or moved past the slop, so a second finger landing with it makes a gesture before any clay moves. One finger on empty space turns the view, and keeps turning it over the model. Settings > Touch > On the model > Turns the view leaves sculpting to the pen.
- The pen sculpts on the model with pressure, and on empty space turns the view (or waits for the model). While the pen is near the screen or on it, a single finger does nothing (the hand holding it); the pen coming down cancels a touch in progress.
- Two fingers pan with their middle, zoom as they spread or pinch, toward the point between them, and twist to roll the view once they have turned 10 degrees (Free orbit only). Three fingers drag up and down for the brush size and sideways for its strength, whichever way they go first. A quick tap of two fingers undoes, of three redoes. Held still (landing together, within 0.15 s), two fingers undo again and again: once at 0.45 s, with a ring filling round them from 0.15 s on, then every 0.12 s with a count beside the ring, until a finger moves or lifts; three redo the same way. A hold never starts while the pen is near the screen, and once it undoes the touch neither pans nor zooms.
- Put two fingers down and lift one, and the other turns the view once it moves past the slop, about the same pivot an orbit would use, so a view filled by the model can still be turned with one finger. Only after two fingers that stayed still: the finger left rolling off the end of a pinch turns nothing. A two-finger tap still undoes unless the finger left turned the view.
- A double tap of one finger (the second tap within 0.3 s and 48 points of the first) on empty space frames the selected object, or every object when none is selected. On the model it pins the pivot to that point, with a pulse to show where: every orbit turns about it, whatever Turn about says, until the next stroke ends or the view is framed or reset. Neither tap sculpts: while one finger sculpts, a single tap's dab waits out the 0.3 s for a second tap, then lands as it was tapped (same view, brush and modifier buttons), or at once when anything else comes first (a key, the mouse, the pen, a finger elsewhere or a stroke). Taps in the safe zone along the edges never double-tap, nor do the presses that draw mask or hide shapes. A quick tap's dab keeps the modifier buttons latched or held at its press.
- The modifier buttons at the bottom left (`src/app/modifiers.odin`) do what Shift, Ctrl and Alt do, for a tablet with no keyboard: Smooth smooths (Shift), Invert inverts the brush (Ctrl), Mask paints the mask on the model at the Mask brush's strength and draws the Mask section's rectangle or lasso from empty space (Ctrl from empty space), and Hide runs the gesture tool picked in Hide, clip and slice (Ctrl+Shift): a drag hides, clips or slices, a tap on a polygroup isolates it and a tap off one shows everything. Invert with Mask erases the mask and unmasks shapes; with Hide it flips the gesture as Alt does. With Mask on, where a tap lands chooses a mask command, as ZBrush's Ctrl click and Nomad's taps while Mask is held: off the model it inverts the mask, on a masked part it blurs the mask, on an unmasked part it sharpens it (by the Mask section's Steps), each with a toast that offers Undo; a tap paints no dot, so a mask stroke begins once it moves past the slop or is held 0.25 s. With the mouse, Ctrl and a click on empty space invert the mask too (Ctrl on the model still inverts the brush). A tap on another object selects it first; Invert (or Alt) changes nothing about which command a tap runs. A quick tap that stays within the slop latches a button until it is tapped again (filled); a finger held on one makes it act only while held (outlined), so the other hand sculpts with the pen or a finger and lifting ends it, as Nomad's and 3DCoat's sticky keys. Smooth, Mask and Hide go one at a time; Invert goes with any. A finger on a button is the buttons' alone: it is never the pointer, never part of a gesture, a hand resting there is no palm, and the pen landing leaves it be. A press takes the buttons' state as it goes down and keeps it until it lets go, so lifting the finger mid-stroke changes nothing; a held button beats a latched one, the last held wins, and any of Shift, Ctrl or Alt held at the press leaves the buttons out of it. The mouse and the pen click the buttons, which latches. Where a panel, a menu or a list lies over them, a finger there is the panel's. They sit under the sliders, which shorten on a short window so the two never meet, and rise above the dock on a narrow one; Settings > Interface moves them to the bottom right, above the object's status, or hides them, which lets go of every latch.
- Settings > Touch turns each of these off: Hold two fingers to keep undoing, Lift one of two fingers to turn, Double tap to frame or pin.
- Long press is the secondary action, as in ZBrush for iPad and Nomad (`secondary` in `src/ui/ui.odin`): a finger or the pen held on a control for 0.45 s without moving past the slop does what a right-click on it does (the pen's side button is a right-click too), and a ring fills round the press from 0.15 s on to show it coming. On a control with no such action it shows the control's name and shortcut instead. Either way letting go is no tap, and a press that moves, changes a value or scrolls is no long press. The mouse's left button never long-presses. What each does:
  - Undo and Redo open the History panel (while there is something to undo or redo; the History button beside them always does).
  - A slot in the dock opens its menu, to show its brush's settings or put another brush or preset in it (see Brush presets).
  - A brush or preset in the brush browser picks it and shows its settings in the inspector.
  - The Size and Strength sliders go back to where a new brush starts: 60 px, and the brush's own starting strength. A finger that moves the value while held is adjusting it, not resetting it.
  - The object's status at the bottom right opens its menu above it.
  - An object in the Scene tab opens its menu.
- A finger or the pen changes nothing until it moves more than the slop, 10 points (Android's touch slop is 8 dp, iOS about 10 pt), so a tap never nudges the view; the mouse has none.
- The safe zone, as the SculptNavigation add-on's border: one finger, the pen or the left button pressed within 64 points of an edge of the screen turns the view even over the model, so when it is zoomed in until the model fills the screen there is still somewhere to turn it from. A faint line marks where the zone ends; panels over it keep their presses, and Ctrl keeps it for the mask and hide shapes (so does a finger held on Mask or Hide, though not a latched one). Settings > Camera sets its width (24 to 200 points), hides the line or turns it off.

Every touch, from its first finger down to its last finger up, belongs to where its first finger landed. On a panel the panels have it: that finger presses, drags and scrolls them, and other fingers of the same touch do nothing, so a hand resting on a panel never pinches the view. On the viewport the fingers navigate or sculpt as above, and lifting fingers never turns what is left into another gesture. A touch the system cancels lets go without a click, and a stroke it drew is taken back (Redo has it). Inside a panel that scrolls, a finger or pen press on a control waits to see which way it goes: up or down past the slop scrolls the panel and the control does nothing, sideways a slider takes it, and a tap within the slop is the control's tap; the mouse presses at once and scrolls with the wheel. Touchpads are not touch screens: their fingers never reach the view, and nor do the stand-in fingers SDL can make of the pen and the mouse.

`python scripts/gate.py` runs every check a change must pass (check, test, build, smoke, these scenarios, and the Windows and Android compile checks on Linux) with one line a step. `python scripts/touch_check.py` (after a debug build) drives the app with scripted fingers, pen and mouse through these cases and checks the camera, the dabs, the undo steps and the saved settings on exit: a simulation on the desktop, not a tablet (see the `sm-touch-testing` skill).
