# Sculpt

A performance-focused sculpting prototype in Odin, using SDL3 + SDL_GPU for rendering and its own interface kit (`src/ui`) for everything around the viewport.

## Layout

| Path | Owns |
| --- | --- |
| `src/app` | Entry point, frame loop, scene of sculptable objects, Move, Brush, Curve and Insert tools, brush alphas (the built-in ones and loaded images, which way each dab's image faces), the interface's panels (`new_ui.odin`, `kit_*.odin`), keys and pointer from SDL (`device.odin`), fingers and the pen (`touch.odin`), who owns each touch and drag and what the camera does with it (`navigate.odin`) and routing into `Viewport_Input` (pen pressure and tilt included), the Settings panel (`kit_settings.odin`), the viewport overlay and the brush pie, the History timeline and time-lapse, the menu's file actions (scene save and open, mesh import and export, file dialogs), autosave on its own thread and crash recovery (`autosave.odin`, `kit_recover.odin`) |
| `src/render` | Every GPU object the app creates: device, pipeline, viewport target, mesh buffers (16 bytes a vertex: float3 position, octahedral normal), per-mesh indirect draws of the visible chunks, simplified copies of far chunks drawn from a second index buffer while the view moves, partial redraws (while the camera and objects stay put, the last frame is kept and only the screen rectangle around what changed is cleared and redrawn), shaders |
| `src/geom` | CPU sculpt geometry (structure-of-arrays triangle mesh, BVH, test spheres, mesh simplification that keeps patch borders), view-culling math (chunk bounds and normal cones, frustum and back-face tests) and the choice of simplified groups to draw, OBJ and PLY reading and writing with cleanup of what is read, binary glTF and USD writing with morph targets and blend shapes (`gltf_write.odin`, `usd_write.odin`), quad retopology, UV layout and normal and displacement map baking, response curves (the pen pressure curve); no rendering or UI imports |
| `src/camera` | Orbit camera math (Free and Turntable orbits that go all the way round, roll, snapping to square views, zoom toward a point), including how a leaning pen turns the brush in the view; no rendering or UI imports |
| `src/gizmo` | Move tool gizmo math: projection, handle picking (arms, plane squares, rings, the scale disc), axis, plane, turn and scale drags, snapping, the Euler inverse; no rendering or UI imports |
| `src/sculpt` | Brush dabs on a `geom.Mesh`: mesh split into nodes that own contiguous vertex ranges, parallel brushes (Draw, Smooth, Clay, Flatten, Inflate, Pinch, Crease, Grab) with X/Y/Z symmetry, pen tilt and alphas (a grey image that shapes each dab), a per-vertex mask, per-frame normal updates, dirty vertex ranges for upload, stroke undo/redo that saves only the nodes a stroke touched (512 MB cap per object), simplified copies of groups of nodes rebuilt between strokes, subdivision levels, HD detail sculpted a window at a time above the top level, dynamic topology (brushes split and collapse edges as they go), levels in and out of the scene file |
| `src/ui` | The interface kit: immediate-mode containers and widgets (buttons, segmented controls, switches, sliders, values to drag, text fields, selects, brush tiles, list rows, areas to draw into), hit testing, the gesture arena that settles whether a finger's press is a tap, a drag or a scroll, multi-finger gesture measurement (`fingers.odin`), antialiased shapes tessellated on the CPU, text in Inter and icons in Lucide through fontstash; it imports neither SDL nor the renderer, so its tests run headless |
| `src/jobs` | Persistent worker pool (`parallel_for`) used by sculpt and mesh setup |
| `src/bench` | Headless sculpt benchmark at chosen mesh sizes (no window or GPU) |
| `src/sdf_trial` | Standalone SDF/voxel comparison spike (not linked into the app) |
| `src/dart_trial` | Standalone Odin vs Dart comparison of the Draw brush's hot loops (not linked into the app) |

The 3D viewport is rendered by `render` into an offscreen texture that the interface draws under its panels. Strokes undo and redo with Ctrl+Z and Ctrl+Shift+Z (or Ctrl+Y), also the buttons at the foot of the brush bar on the left; the order runs across objects. Changes that rebuild an object undo the same way: remesh, dynamic topology on or off, Delete higher and Delete lower, and adding, importing or deleting (Delete key) an object. Before such a change the object is kept as the scene file stores it (every level as positions, the mask, dynamic topology); undo rebuilds it from that and keeps the object it replaces, so redo works too. That costs about 37 bytes a base vertex plus 12 a vertex of each level above (about 370 MB for a 10M-vertex object), up to 1.5 GB in all, past which the oldest go; the Stats panel shows the total. The object's strokes from before such a change can no longer be undone one by one, and HD detail is not kept (the HD steps are). Undoing a remesh takes about 0.1 s at 100k vertices and 0.24 s at 1M on the test VM (release build). The interface never owns sculpt state: panels read and edit `App` fields through pointers each frame, and what the viewport saw reaches the camera and the active tool as a plain struct. Each object keeps its mesh in local space with a transform (position, uniform scale, rotation), so moving or turning an object never rewrites its vertices; the brush works in the object's local space, and so do symmetry and Mirror and weld. The Object palette's Transform turns the selected object (degrees about X, then Y, then Z); scenes save it (scene file version 2, which still opens version 1 files). Placing an object anew is an undo step too: each gizmo drag, each drag of a Transform value and Reset transform is one, which undo and redo put back exactly, in its place among the strokes; it outlives the object's strokes when those are dropped (a level renumbered, an HD window closed), and undo waits while a drag is under way.

## Pinned versions

See `scripts/versions.env`: Odin `dev-2026-10`, SDL `3.4.18` (Linux; Windows uses the SDL3 shipped with Odin).

## Linux

```sh
# once: system packages are listed at the top of the script
./scripts/setup_deps.sh

./build.sh            # debug build with allocation tracking -> build/sculpt
./build.sh release    # optimized build
./build.sh test       # unit tests (geom, camera, sculpt, jobs, gizmo, png_write, zip, ui, app)
./build.sh check      # odin check of every package with the strict flags, then the agent-file mirror check (scripts/agents_sync.py)
./build.sh run -- --vertices=10000000
./build.sh smoke      # 300 frames in GPU debug mode; non-zero exit on assert, GPU error or leak
./build.sh bench      # headless sculpt benchmark at 500k, 1M, 5M, 7M, 10M vertices
./build.sh gpubench   # GPU and CPU frame times while orbiting and sculpting, same sizes
./build.sh computebench # Smooth all on the CPU against a GPU compute shader, same sizes
./build.sh wincheck   # compile app and bench for Windows x64 (no link) to catch Windows-only errors
```

Headless (CI or containers): run under `Xvfb` with Mesa's llvmpipe Vulkan driver (`mesa-vulkan-drivers`).

## Windows

With Visual Studio's "Desktop development with C++" workload installed (Odin links with its linker and the Windows SDK) and git and python on PATH, from any command prompt:

```bat

build.bat            :: or: build.bat release | test | run | smoke | bench | gpubench | computebench | check
```

## Android

`android/` is a Gradle project that packages the app for 64-bit ARM tablets (Android 11 or newer, Vulkan): SDL's own Java activity (`SDLActivity`, from the SDL checkout in `deps/sdl3-src`) loads `libSDL3.so`, built from that same source, and `libmain.so`, which holds `src/app` compiled by Odin to one arm64 object (`-target:linux_arm64 -subtarget:android -build-mode:obj`) and linked with stb_truetype and a small C file (`android/app/jni/android_main.c`) that gives SDL its `SDL_main` and stands in for two pthread calls Android lacks. `android/app/jni/CMakeLists.txt` runs Odin itself, so Gradle or Android Studio rebuilds the app whenever a source, shader or font changes; the Odin side is always an optimised build. The app targets API 36, as Google Play requires, links for 16 KB pages and asks for no permissions.

Once, on Windows (Linux: `scripts/setup_deps.sh` already fetched SDL's source):

1. Install [Android Studio](https://developer.android.com/studio). In its first-run wizard keep the standard SDK. Then Settings > Languages & Frameworks > Android SDK > SDK Tools, tick Show Package Details, and install NDK (Side by side) `28.2.13676358` and CMake `3.22.1` (Gradle also fetches them itself on the first build if they are missing).
2. From the repo, after `scripts\setup_deps.bat`: `scripts\setup_android.bat` (clones SDL `release-3.4.18`).
3. On the tablet: Settings > About tablet (on OnePlus: About device > Version), tap Build number seven times; then Settings > System > Developer options > USB debugging on. Plug it in and allow the PC when it asks.

Then:

```bat
build.bat android      :: android\app\build\outputs\apk\debug\app-debug.apk
build.bat androidrun   :: the same, installed on the plugged-in tablet and started
```

(`./build.sh android` and `./build.sh androidrun` on Linux, with the SDK in `~/Android/Sdk` or `ANDROID_HOME`; `./build.sh androidcheck` compiles the Odin side for Android without the SDK.) Both find Android Studio's SDK (`%LOCALAPPDATA%\Android\Sdk`) and Java (`%ProgramFiles%\Android\Android Studio\jbr`) unless `ANDROID_HOME` and `JAVA_HOME` say otherwise. The project uses Gradle 9.8 and the Android Gradle plugin 9.4, which run on Java 17 to 25 (Android Studio 2026.2 ships 25; Gradle 8 stops at 24 with "Unsupported class file major version 69"). Opening `android/` in Android Studio works too: Run builds, installs and starts it. Without a cable, copy the APK to the tablet and open it there (Android asks once to allow installs from the file manager). The log goes to logcat: `adb logcat -s SDL/APP` (adb is in the SDK's `platform-tools`), and the GPU line names the tablet's Vulkan driver.

On the tablet the app is full screen, with the system bars a swipe away, and lays its panels inside the safe area SDL reports (camera cutout, rounded corners, gesture bar). The interface scales by the screen's density, so its 48 point targets are 48 dp. The pen sculpts with pressure and its side button opens the brush pie; fingers sculpt and move the view as in ZBrush for iPad (see Touch and pen). Back closes an open menu and otherwise does nothing, so it can never drop unsaved work; leave with the home gesture. Open, Import, Load image, Run script and stroke recordings go through the system's file picker, which hands back `content://` URIs; the app reads those through SDL's IO, and Import tells OBJ from PLY by the file's first bytes, since such a URI has no extension. Not yet on Android: Save and Export cannot write to a picked `content://` file, and leaving the app does not save the scene to a file; it writes an autosave instead (see Autosave and recovery), which the next start offers back if Android dropped the app in the background. A Google Play build also needs a release signing key and `bundleRelease` (an `.aab`).

## Command scripts

A command script sets a run up from text, the same way the interface would: `--run=FILE` runs a file, `--script=TEXT` one given on the command line with `;` between statements (in `build.bat`, which splits arguments at `;`, `,` and `=`, use `--run=FILE`). It runs once the window has laid out its viewport, before the run's own frames start: `--frames`, the frames of `--ui-events` (none go in before it ends), `--bench-stroke`, `--load-strokes`, `--timelapse` and `--orbit` all count from the frame it ends on. What it did is where the run starts: none of it is in the History or the camera's Previous view, the scene counts as unsaved only if it did before, and the Stats' timings and counts start afresh. Anything done by hand while a `wait` lets frames pass is part of that set-up too. `--gpubench` builds its own scenes and takes no script.

One statement a line (or `;` between them); `#` starts a comment that runs to the line's end, and `"quoted text"` is one word. Names are written in lower case with `_` or `-` between words, in any case.

- A command by its name in the command palette's registry: `remesh`, `subdivide`, `undo`, `frame_all`. One with choices takes one by name: `brush clay`, `view_axis front`, `mask invert`, `deformer lattice`, `remesh_to 500000`, `new_scene head`. One that is on or off takes `on` or `off` and then only changes it when it differs (`wireframe on`, `front_only off`); without either it turns over. Commands that ask for a file, typed text or a pick on screen (open, save, import, export, screenshot, rename, the palette and the pies), and those that depend on what a script cannot know (Replay last stroke at the pointer, Open last autosave), are not for scripts, nor are Record macro, Run macro and Run script, so no script starts another. `new_scene` goes ahead without asking twice.
- `set <setting> <value>`: a remembered setting under its name in the settings file (`set orbit_style turntable`, `set radius_px 80`, `set symmetry xz`, `set paint_color 0.2 0.4 0.9`, `set material "red wax"`, `set new_vertices 1000000` for the size Add object and New scene use), or a value a command reads that is not remembered: `smooth_steps`, `smooth_strength`, `mirror_axis` (0 x, 1 y, 2 z), `mirror_negative`, `extract_thickness`, `boolean_vertices` (Make boolean's Result vertices), `hd_window`, `studio_samples` and `cloth_mode`. So `set rebuild_even 200000; rebuild` remeshes the selected object to 200,000 vertices, as Rebuild > Even does. Bools take on/off, true/false, yes/no or 1/0; a number must be in the setting's range; a count must be whole.
- `wait N` lets N frames pass (to see a change drawn, or let a time-lapse start); `select N` selects the Nth object alone, counting from 1 down the Scene palette's list, the objects in folders included.
- Verbs, for what no command does with a single choice, each doing what its tool or panel does:
  - `move X Y Z` and `rotate X Y Z` set the selected object's place and its turn in degrees about X, then Y, then Z, as the Transform values do;
  - `boolean none|union|subtract|intersect` marks the selected object, as the Booleans section's tabs do;
  - `slice x|y|z` cuts the selected object in two across the middle of its bounds, as a Slice line does;
  - `hide x|y|z` hides the + side of its middle across that axis (`-x`, `-y`, `-z` the - side), as a hide rectangle does;
  - `mask_rect LEFT TOP RIGHT BOTTOM` masks what that part of the view shows, each edge from 0 to 1 across the view from its top left, as a mask rectangle does;
  - `project N` projects the detail of object N onto the selected one, as Project detail does;
  - `draw_curve tube|stitches|zipper` draws a wavy curve across the middle of the view with the Curve tool;
  - `insert_middle sphere|cube|cylinder|cone|torus` inserts that shape where the middle of the view meets the surface, as an Insert click does;
  - `falloff smooth|linear|sharp|firm|flat` gives every brush that falloff preset;
  - `focal N` (-100 to 100) gives every brush that focal shift;
  - `alpha NAME` picks an alpha by name (a built-in's, or `mine/NAME` or `PACK/NAME` from the library), or loads an image file as one for this run (quote a path with spaces);
  - `layer N STRENGTH [hidden]` sets the selected object's layer N (from 1, the bottom one) to that strength, from -1 to 2, shown or with `hidden` hidden, as its slider and eye do, in one undo step;
  - `install_pack PATH` installs a content pack in place, replacing an installed one of the same name and author (see Content packs).

The whole script is checked before any of it runs: an unknown name, a choice or value that does not fit, or an unclosed quote lists every such line (`script: setup.cmd:3: brush takes one of: draw, smooth, ...`), at most 20, and the run exits with code 2 having done nothing. While it runs, a statement that does nothing (a command not available then, an operation that refuses or leaves the scene as it was, `select` past the last object) stops it: a run with `--frames` exits with code 2 saying which line and writes none of its `--export`, `--save`, `--bake` or `--save-strokes` files; an interactive run shows a note and keeps what ran before it as its set-up. An interactive run remembers the settings a script set, as it does those changed in the Settings panel. The exit stats add `script_statements`, `script_ran`, `script_frames` and `script_failed`.

Scripts replace the start-up flags that once mirrored the tools. For example, a 200k remesh then a sculpt layer is `set rebuild_even 200000; rebuild; new_layer`; Decimate is `set rebuild_goal fewer; set rebuild_fewer 20000; rebuild`; Retopologize `set retopo_quads 300; retopologize`; Mirror and weld `set mirror_axis 1; set mirror_negative on; mirror_weld`; Smooth all `set smooth_steps 3; smooth_all`; dynamic topology `dyntopo_toggle on` (and `set detail_px 14`); the morph target `morph_store`; polypaint `set paint_color 0.1 0.5 0.9; paint fill`; the camera `set orbit_style turntable`, `set orbit_pivot centre`, `set edge_orbit off`, `set finger_model orbit`; the brush ring flat on the screen `set surface_ring off`; the pen's tilt `set tilt_strength 0.5`; the alpha's turn `set alpha_mode fixed; set alpha_angle 30`; symmetry `set symmetry xz`; Line and Join strokes `set stroke_line on`, `set stroke_join on`; and the HD window `set hd_window 2000000`. Each was checked against the flag it replaced: the same mesh, scene file and settings, bit for bit. The verbs were checked the same way against theirs, with two differences: a curve or an insert now goes across the view as it is laid out rather than the window size asked for, and a slice no longer reframes the camera on the two parts.

## Macros

Record macro (in Menu > Macros, or search for it in the command palette, or give it a key in Settings > Keys) starts keeping the commands you run, by any route: a key, a button, a menu, the palette or a pie. A red "Recording macro" chip at the top of the viewport counts them and has Stop (Record macro again stops too). Stop asks for a name under the chip ("Macro 1" when left empty): Save keeps it, Discard, Escape or a tap elsewhere drops it. Each command is kept as the line of a command script (see Command scripts above) that does it again: a choice by its name (`brush clay`, `mask invert`), a switch as the state it left (`wireframe on`, so running the macro sets it rather than flips it), Sculpt HD as `hd_sculpt` or `hd_leave`, and a command that reads values from its panel (Smooth all, Rebuild, Mirror and weld, Retopologize, Extract, Make boolean, the mask's Blur to Shrink, Creases groups, Fill with colour, Add object) gets `set` lines for them first, written when they differ from the last the macro set. A command that queues its work for the next frame (Remesh, Subdivide, ...) is kept once that has changed the scene, and one that refused (a warning note) is not kept. Undo while recording takes the newest command out again when the step it undoes is that command's. Strokes, turns of the view, gizmo and slider drags and clicks on objects are not commands and are not recorded, nor are undo and redo, the view commands (axis views, focus, frame all, previous and next view), panels, the palette and the pies; commands that ask for a file, a typed name or a pick on screen (open, save, import, export, screenshot, rename, New scene) are left out and the save note counts them. So a macro acts on whatever is selected when it runs, as ZBrush's do.

A saved macro takes the first of 16 numbered slots and is Run macro N, listed in the palette and Settings > Keys by its name ("Macro: Zebra") only while the slot holds one; like any command it can be given a key, put on a pie or starred, and the binding stays with the slot. Running it runs its lines at the start of the next frame as your own work: each command is its own undo step as if done by hand, nothing is cleared, a line that does nothing stops it with a note naming the line and keeps what ran before it, and a finished run says "Ran macro Zebra: 3 steps". It is not offered while recording, while a script or another macro runs, during a stroke or drag, or while a save or file dialog waits. Each macro is a plain command script, `macro-NN.cmd` (NN the slot) in the `macros` folder beside the settings file (a settings file given with `--settings-file` has its own, `<name>-macros`), whose first line `# Macro: <name>` names it; edit it in any text editor and it is read again at the next start (on Android the folder is the app's private storage). A run that keeps no settings keeps no macros either: a macro saved then lasts until the app closes. Deleting a macro takes Run macro N off every key, pie slot, star, gesture and recent search that ran it, so a macro saved in the slot later starts with none of them.

Menu > Macros (or Search) opens the Macros panel in the tray's place, as Settings and Help open: Record macro (Stop recording while one is on) and Run script at its top, then each macro kept, by name with its keys and gestures under it ("Macro 3, no key" for none), and four buttons: Run, Key (the Assign key popover, as Ctrl+Alt+click on Run gives too), Rename (a field under the row; Enter applies it, and the file's first line changes with it) and Delete, which asks for a second tap on its bin within three seconds ("Tap the bin again to delete it") and then deletes the macro and its file. The note at its foot names the folder the files are in.

Run script (Menu > Macros, or Search) picks a command script file (`.cmd`, or `.txt`) with the system's file dialog and runs it as a macro runs, without keeping it: on what is selected, each command its own undo step, a line that does nothing stopping it with a note, and a file with an error running none of it ("Cannot run bevel.cmd: bevel.cmd:2: no command is named ..."). `wait` and `new_scene` are for start-up scripts only (`--run`), and it is not offered while a recording, a script or a macro runs. The exit stats add `macros`, `macro_recording`, `macro_entries`, `macro_left_out`, `macros_run`, `scripts_run` (script files run) and `macro_steps` (the statements macros and script files ran).

## Benchmark

`build/bench [vertex counts...] [--meshes=N] [--threads=N] [--node=N] [--prefault=MB]` builds a sphere of each size (N of them with `--meshes`, only the first sculpted; with no sizes given it also runs 10M with a second idle sphere), prepares it for sculpting, runs the same 77-dab stroke with a large (r=0.13) and a small (r=0.04) brush, and prints a markdown table, including the undo memory of each stroke and the time to undo and redo it. A frame is 4 dabs plus the normal update and is what the app does per frame during a fast stroke. The normal update recomputes every normal of the nodes whose triangles moved, but only the border vertices of their neighbours; the normal cones that back-face culling uses wait until the stroke ends (until then those chunks are simply not back-face culled), and "Stroke end ms" is the frame where that work starts, at most 512 nodes a frame. A second table culls the sculpted sphere from three cameras (whole sphere, close-up, detail) and reports the share of triangles that would be drawn, the number of indirect draw commands, and the CPU time to cull. On cloud VMs, pass `--prefault=3000` so the VM's slow first touch of fresh memory does not dominate setup times.

`build/bench --lod [vertex counts...]` prints a table for simplified drawing instead: at each size, the time to build every group's copy as the app does (a batch a frame), the copies' memory, the triangles drawn and the CPU time to choose them from the culling table's three cameras at full detail and with copies at most 1 px off (on a 1000 px tall viewport), and the time to rebuild what the large-brush stroke made stale.

`build/bench --brushes [vertex counts...]` prints a table with one row per brush instead: the main table's stroke with the large brush, for every brush kind, then Draw with X symmetry, Draw over a sphere masked on one side and Draw with the Noise alpha (see Brushes, masking and symmetry and Brush alphas below).

`build/bench --masks [vertex counts...]` prints a table for the mask commands instead: at each size, each command on a sphere masked on one side, with how many vertices it changed and its undo (see Brushes, masking and symmetry below).

`build/bench --remesh [vertex counts...]` prints a table for voxel remesh instead: at each size, a sphere with one Grab move that pulls a wide spike out of it, remeshed back to the same vertex count (see Voxel remesh below).

`build/bench --dyntopo [vertex counts...]` prints a table for dynamic topology instead: at each size, the main table's stroke with the large brush on the usual layout, then with dynamic topology on, once with nothing to split, once refining and once more over what it refined, with undo, redo and the time to turn it on and off (see Dynamic topology below).

`build/bench --files [vertex counts...]` prints a table for files instead: at each size, a sphere written as OBJ and as PLY and parsed back, cleaned up and made ready to sculpt as Menu > Import mesh... does, then saved and read back as a scene; and a second table for scenes with subdivision levels, laid out as `--levels` lays them out (see Files below). It works in memory, without the disk.

`build/bench --hd [vertex counts...]` prints a table for HD detail instead: at each size, a sphere as the top level with an HD level one and then two steps above it. It times opening a window of about 4M vertices at the front, the small-brush stroke in it (median frame), storing it on leaving and opening the window again with the stored detail, and gives the window's memory and what the stroke stored. Then the regular levels the HD level stands in for: their memory (estimated past 16M vertices), and while they stay under that, the time to build them and the same stroke on their top level.

`build/bench --levels [vertex counts...]` prints a table for subdivision levels instead: at each size, a base sphere of at most 40k vertices with as few levels above it as reach that size. It times building the levels (all of them, and the top one alone), the same stroke on the top level, stepping down to the base (carrying the stroke down, then the base's normal update), the stroke on the base, and stepping back up (carrying that up through every level, then the top level's normal update, with the megabytes the app would upload).

## Big meshes (20M to 50M)

The sculpt core scales with what a stroke touches, not with the mesh: a brush of the same size on screen touches more vertices on a denser mesh, and the frame grows with those, while a brush of the same vertex count costs the same at 10M and at 50M. `build/bench 20000000 50000000` (4 threads, this repo's cloud VM):

| Vertices | Setup s | Mesh MB | Peak RSS MB | Frame ms, large brush (verts a dab) | Frame ms, small brush (verts a dab) | Undo ms, large |
| --- | --- | --- | --- | --- | --- | --- |
| 10M | 1.0 | 888 | 2267 | 1.34 (39k) | 0.29 (3.5k) | 8.0 |
| 20M | 3.0 | 1776 | 2700 | 2.37 (78k) | 0.45 (7k) | 14.9 |
| 50M | 9.0 | 4442 | 6751 | 6.20 (194k) | 0.99 (18k) | 39.3 |

What did grow with the mesh was culling: every frame tested each chunk (about one per 600 triangles) against the view, about 1 ms at 50M even when the view held a few hundred of them, and a stroke's partial redraw paid it every frame. Chunks now also come in groups of 64 neighbours (`CHUNK_GROUP`, in the chunks' order, which follows the BVH), each with bounds and a normal cone holding its chunks'; a group outside the view or wholly facing away is skipped without looking at its chunks, and the rest are tested one by one as before, so the same chunks are drawn. The sculptor remakes a group only when one of its chunks changed (`sculptor_chunk_groups`); under dynamic topology, whose chunks come and go, chunks are tested one by one. Culling CPU ms, chunk by chunk and by groups:

| Vertices | Whole sphere | Close-up | Detail |
| --- | --- | --- | --- |
| 10M | 0.35 → 0.19 | 0.23 → 0.05 | 0.19 → 0.014 |
| 20M | 0.80 → 0.38 | 0.50 → 0.07 | 0.36 → 0.019 |
| 50M | 2.07 → 0.95 | 1.39 → 0.12 | 1.11 → 0.03 |

Saving reserves the object's size up front instead of growing the buffer a doubling at a time, which at 50M (about 1.7 GB an object) means it never holds a second, larger copy while the buffer grows. In the app a 30M sphere is ready to sculpt in about 5 s, saves to a 1 GB .sculpt file in about 8 s and opens again in about 4.5 s on the VM, whose disk and first touches of memory are slow; a 40M top level built with `--vertices=40000 --subdivide=5` takes 11 s and about 9.5 GB with every level and the GPU's copy. To time a real GPU at these sizes: `build.bat gpubench --vertices=20000000` (or 50000000; give the GPU 2 GB of free memory at 50M).

## GPU benchmark and frame timing

`build.sh gpubench` (or `build.bat gpubench`) builds the release app and runs it on one sphere at 500k, 1M, 5M, 7M and 10M vertices (only one size with `--vertices=N`). At each size it runs six cases: the camera orbiting once around the sphere with everything on, with simplified drawing off, and with view culling off too, and a brush stroke with partial redraw and culling both on, partial redraw off, and both off. The stroke drags the 60 px Draw brush back and forth across the sphere at 30 px a frame (two dabs a frame, like a fast real stroke) and is undone after each case. Each case runs 30 warm-up frames and then measures 120; stroke cases count only the frames that sculpted. It prints three markdown tables, GPU time of the 3D viewport and CPU time per frame (p50 / p99) and triangles drawn per frame, and writes them to `build/gpubench.md`. It needs a display, and only a real GPU gives meaningful numbers. Vsync is turned off during the run where the display allows it.

The Stats panel shows the same timings live:

- **Frame**: the whole frame, waits included. With VSync on this is the display's refresh interval whenever the frame is ready in time, so it does not show what a speed setting saves; compare CPU and GPU instead, or turn VSync off.
- **CPU**: the frame minus its waits.
- **GPU (3D)**: the GPU time of the 3D viewport's uploads and drawing, shown while "Time GPU work" is on. The 3D work goes in its own command buffer; with timing on, the app waits for the previous frame first and then for this one, so the time from submit to its fence is the GPU's alone. Frames then no longer overlap, so leave it off when not measuring.
- **Display wait**: time spent waiting for the display, at the start of the frame and while presenting.
- **VSync**: off uses mailbox where the display offers it (no tearing), else immediate (may tear). The app reads input after the wait at the start of the frame, so a driver that makes the app wait there for the next screen image no longer delays that frame's input. Drivers that wait while presenting instead (Mesa does) still add up to a refresh interval of lag with VSync on; turning it off removes that.

## Smooth all and the GPU compute trial

Smooth all (Object palette, Deformation) smooths the whole selected object, as ZBrush's Deformation > Smooth: each step moves every vertex toward the average of its triangles' corners (the step the Smooth brush takes) by the Smooth strength, for the Smooth steps given. Masked areas stay (partly masked ones move part of the way), it is one undo step, and it is not offered with dynamic topology on. The Deformation section shows how long the last one took.

It is also the trial of moving a heavy sculpt operation onto the GPU. Sculpting runs on the CPU, across every core, and the GPU only draws; with "On the GPU" on, Smooth all runs instead as a compute shader (`src/render/shaders/smooth_all.comp`, `src/render/smooth_compute.odin`): the app uploads the positions, triangles, the vertex-to-triangle lookup and each vertex's weight, dispatches one pass a step between two position buffers, and reads the result back into the CPU mesh, which then updates normals, bounds, undo and the drawn mesh the usual way. The CPU path stays the default, and the fallback when the device refuses the compute pipeline. The shader does the CPU's arithmetic in the CPU's order (`precise` stops it fusing multiplies and adds), so the results match: on llvmpipe they are bit-identical, and on other GPUs they may differ in the last bits of a division.

`build.sh computebench` (or `build.bat computebench`) builds the release app and times Smooth all at 1 and 10 steps on a rough sphere at 500k, 1M, 5M, 7M and 10M vertices (only one size with `--vertices=N`), on the CPU and on the GPU, and writes the table to `build/computebench.md`. The GPU time is split into upload, compute and readback, each including the wait for the GPU. "Cold" uploads the triangles and lookup with the positions, as a press of Smooth all does; "warm" keeps them on the GPU from the run before, so only positions and weights travel, which shows what keeping the mesh on the GPU between commands would save. The last column is the largest difference between the GPU's result and the CPU's. Undo saving and normals are the same either way and are left out. It needs a display; only a real GPU gives meaningful GPU numbers.

The SDF/voxel comparison spike from step 3 builds separately: `deps/odin/odin build src/sdf_trial -o:speed -collection:deps=deps`.

The Odin vs Dart spike times the Draw brush's hot loops (finding the nodes a dab reaches, the area normal, moving the vertices, the per-frame normals) written the same way in both languages over the same cube-sphere and stroke, with one thread and with every core (Dart through worker isolates sharing the mesh in native memory). It answers whether the sculpt core could move to Dart; at 10M vertices on the 4-core cloud VM the Odin frame was 1.7 to 2.1 ms on 4 threads and the Dart frame 6.5 ms, and on one thread 2.6 to 3.3 ms against 6.4 to 10.6 ms. Build and run both (the Dart SDK comes with Flutter): `deps/odin/odin build src/dart_trial -o:speed -no-bounds-check -collection:deps=deps -out:build/dart_trial`, `build/dart_trial [sizes] [--threads=N]`, then in `src/dart_trial/dart` `dart pub get` and `dart compile exe bin/kernel.dart -o ../../../build/dart_kernel`, `build/dart_kernel [sizes] [--threads=N]`. The checksum column agrees to about six digits: Dart does its arithmetic in doubles and rounds to floats on store.

## Deformers

The Object palette's Deformers section (Surface page) bends, twists or tapers the selected object, or pulls it with a lattice (below), as ZBrush's gizmo deformers and Blender's Simple Deform do: the part the mask leaves free (all that is shown, with no mask), along one of the object's own axes (X, Y or Z) over that part's extent, from a fixed end that stays put to the far end that moves most. Bend curves that part into an arc of the same length, turning by the Amount (degrees) toward one of the two other axes (Toward; a negative amount bends the other way), and stops short of folding the inside of the bend over itself, so a thick part bends less far than a thin one (a sphere up to about 109°, a long thin part a whole turn). Twist turns it about the axis, nothing at the fixed end and the whole Amount (up to a turn either way) at the far end. Taper scales it across the axis, from as it is at the fixed end to 1 + Amount at the far end (-95% to +300%). Fixed end picks the - or + end; Auto keeps the end at the mask's soft edge, where a freed limb joins the rest (the - end with no mask). A half-masked vertex takes part of the deformation, so the mask's soft edge eases into it.

Drag Amount: the object deforms live from where the drag began, letting go is one undo step (Bend, Twist or Taper in the History), and the slider springs back to 0 for the next, which deforms the surface as it now is. The note says what it did ("Bent Sphere 1 by 40° along Y toward +X (12 ms)"), and Adjust... on the action bar sets the last one's Amount again from before it, still one step. While Amount is held nothing undoes beneath it, a stroke does not start, and a command ends the drag first as its own step. The palette's Bend, Twist, Taper and Lattice open the section on that deformer. Not in an HD window or with dynamic topology. A deformation at a lower subdivision level moves the levels above with it, and their detail keeps its size (a taper does not shrink it). Each frame of a drag deforms every free vertex again from its start: 7 to 8 ms at 1M and 55 ms (taper) to 70 ms (bend) at 10M on the 4-core VM (release), of which about 15 ms is normals.

Lattice, the section's fourth choice, is a free-form deformation cage, as Blender's Lattice modifier and Maya's lattice are: with the Move tool on (the section's Use the Move tool, or W), a box of points stands round the part the mask leaves free in place of the gizmo, 2, 3 or 4 points a side (Points a side; 3 at first), a little larger than that part. Drag a point with the mouse, a finger or the pen and it follows the pointer across the view, pulling the surface near it smoothly and the rest less the further it is (each point's pull is its Bernstein weight, so the whole surface moves together as the cage bends); letting go is one undo step (Lattice in the History), the point stays where it was dragged, and the next drag, of that point or another, carries on from the cage as it is. A press on a point takes it whatever is under it, so a point off the model drags rather than turning the view; Snap (or Ctrl held) moves it by whole grid steps, as it does the gizmo. Any other step in the History (a stroke, a mask, an undo, a move of the object, another level) makes the cage again at rest round the surface as it then is, and so does Fit the cage again; with nothing free to put a cage round, the gizmo is back. The masked part stays put and a half-masked vertex takes part of each pull. Escape or a second finger cancels a drag, as for the gizmo. Not in an HD window or with dynamic topology. The first drag of a cage notes where each vertex is in it (12 bytes a vertex, let go once the cage is made again or Lattice is no longer picked); each frame of a drag then moves every free vertex again from its start: 5 ms at 1M and 49 ms at 10M on the 4-core VM (release).

## Idle objects

Only the selected object is sculpted or moved, so the viewport draws every other object once into a cached colour + depth image and reuses it while the camera and those objects stay put (all through a brush stroke). Each frame then costs a screen-sized copy plus the selected object's triangles, however many idle objects there are. Orbiting, panning, zooming, selecting another object or changing an idle one redraws the cache. On the CPU side idle objects already cost nothing per frame (`build/bench` with `--meshes=2`).

## Simplified drawing while the view moves

While the camera orbits, pans or zooms, or an object moves, far parts of each mesh are drawn from simplified copies, then everything is drawn at full detail once the view has stayed put for a quarter of a second. The chunks a mesh is split into for culling are grouped along its BVH, four to six at a time, then groups of groups, up to one group for the whole mesh. Each group has a copy of the triangles under it with about a quarter of them, made from its children's copies by collapsing edges into existing vertices, cheapest first by quadric error. A copy never moves a vertex on its group's border, so any mix of copies and chunks meets without cracks. Each frame, the renderer draws a group's copy instead of what lies under it when the copy strays less than "Largest error" (1 px by default) from the full mesh, as seen from the camera; nearby chunks stay at full detail. On a 10M vertex sphere seen whole this draws about 500k triangles instead of 8.6M (`build/bench --lod`).

Copies are built a few milliseconds a frame, for one object at a time and never during a stroke, so a new 10M vertex mesh takes a few seconds to get all of them; until then, and for the groups an edit made stale until they are rebuilt, the chunks under them are drawn instead. Meshes under 262,144 triangles get no copies. The Stats panel turns it off ("Simplify while moving"), sets the largest error, shows how many groups are left to build and the build time per frame.

## Subdivision levels

As in ZBrush, an object can have up to 8 subdivision levels: its base mesh and finer copies, each made from the one below by one step of Loop subdivision, which splits every triangle into four and smooths the result. Each level is a whole mesh with its own sculpt data and GPU buffers, so sculpting on a level costs what it costs on a plain mesh of that size, and only the current level is drawn. Every vertex above the base stores its offset from where subdivision puts it, in a frame that turns with the surface of the level below. When the current level changes, the levels are brought up to date with the edits made on the one being left: levels above are rebuilt from their offsets, so fine detail rides on a coarse change, and levels below move each vertex by half its own change plus half the average change around it, so they follow the large shapes of a fine edit while the detail stays on top. Only the parts of each level an edit reached are visited.

Ctrl+D (or Subdivide in the Object palette's Subdivision levels) adds a level above the top one and goes to it; D and Shift+D (or Higher and Lower there) go up and down a level. When the top level has sculpt layers, they move up to the new level (see Sculpt layers), and that Subdivide is an undo step of its own with a note: Undo puts the levels back with the layers on the old top, but the object's earlier strokes can no longer be undone past it. The section shows how many vertices and how much memory the next level would take (Subdivide is refused past 12 GB), the memory all levels use, and how long the last level change took. Delete lower makes the current level the base; Delete higher drops the levels above it; both are undo steps (that object's earlier strokes can no longer be undone one by one). Undo and redo walk back across levels, switching the object to the level each stroke was made on.

## HD detail

As with ZBrush's HD geometry, an object can be sculpted up to 3 Loop steps finer than its top level without building those levels. Divide HD in the Object palette adds an HD level (on a closed mesh), and A over the object opens a window: the finer subdivision of the top-level chunks nearest the pointer, up to the window size (4M vertices by default; the section's Window slider sets 1 to 16M). The window sculpts like any level and is drawn in place of the chunks it covers; A again (or Leave HD) stores what changed and closes it. Detail is stored per top-level chunk, only for chunks that were sculpted, as each vertex's offset from where subdivision of the top level puts it, in a frame that turns with that surface, so it rides on later changes to the top level and the levels below. Outside a window it is kept but not shown, as in ZBrush.

The window's border stays where the top level is drawn around it. Brushes fade out over the last 8 top-level edges toward it, so a stroke across it leaves a slope rather than a cliff, and flat seal triangles close the join between the two meshes so it draws without pinholes. Strokes in the window undo one by one; closing it stores them and drops them from the undo history, and undoing an older stroke closes the window first. Subdivide is refused while an HD level exists (Delete HD first), Delete higher drops it with the top level, and Remesh drops it.

## Sculpt layers

Sculpt layers work as ZBrush's: the Object palette's Layers section lists the selected object's layers on its current level, newest on top. New layer adds one at full strength and starts it recording (its record button lit): while a layer records, every stroke, Smooth all and Clip also goes into the layer, as the displacement it made. Its Strength slider then dials that work from -1 (reversed) through 0 (gone) to 2 (doubled), the eye button hides or shows it, and its name can be typed over; sculpting outside the layer (record off), or in another layer, stays where it is whatever the slider does, since the surface is always the work outside the layers plus each layer's displacement times its strength. Only one layer records at a time; Recording on a layer shown at another strength first sets it to full (an undo step), and moving the recording layer's slider stops the recording. Delete takes the chosen layer's work off the surface (the select under the rows chooses it); Bake keeps it as plain sculpting and drops the layer. Adding, deleting, baking, hiding and showing are undo steps, a slider drag is one undo step however far it goes, and undoing a recording stroke takes it out of the layer too. A layer keeps 12 bytes a vertex for the nodes it moved, and nothing elsewhere; a slider change moves only those vertices. Layers belong to a subdivision level: work on other levels reaches the level as always, under its layers. Subdivide moves the top level's layers up to the new level, as ZBrush does, each displacement subdivided by the same Loop weights as the surface, so setting a moved layer to 0 gives what subdividing without it gives; the old top keeps its shape, without the layers in its list, and the recording moves up with them. Delete higher carries the deleted levels' layers down to the level it keeps, after its own: each vertex there takes half the displacement of the vertex it became above plus half the mean of that vertex's neighbours', level by level, the same way the levels pass sculpting down, so setting a carried layer to 0 takes off what it put on the kept level (its detail finer than that level goes with the levels above, as their other sculpting does). Past 32 layers on the level the rest are baked, and the note counts them. They are saved with the scene (every level's, with names, strengths and visibility; files from before layers open without any). Not in HD windows or with dynamic topology; turning dynamic topology on bakes them. Rebuilds keep them, as Nomad's layers survive a remesh: Remesh, Decimate, Mirror and weld, Slice (both parts) and Make boolean (the base) give the new mesh the layers of the level they rebuilt from, with their names, strengths, visibility and recording, and each new vertex takes each layer's displacement at the nearest point of the old surface (blended over that triangle's corners), so the shape is unchanged and moving a slider afterwards moves the new mesh as it moved the old one. Mirror and weld gives the mirrored half the kept half's displacement mirrored, and keeps the seam on the plane. A new vertex takes the layers fully within two edge lengths (of the coarser mesh) of the old surface, less the farther it is beyond that, and none beyond four (a boolean's other objects, a slice's cap), so a slider leaves no step at the seam. The layers of the object's other levels go with them, and the note says how many the rebuilt object kept and how many went. Only new vertices near what a layer displaced are searched for on the old surface, so a layer over part of the surface costs little: one over a small patch adds 36 ms to a 1M remesh (0.3 s) and 0.3 s to a 10M one (4 s), and one over the whole surface 0.4 s and 6.6 s, on the 4-core VM. Meanwhile the old level stays in memory beside the new mesh, with the search's tree and 21 bytes a new vertex: roughly 1 to 1.5 GB more at 10M while it runs (an estimate, not measured), only when there are layers. 10M vertices (`build/bench --brushes`, VM): a Draw frame while recording is the same as without (1.2 against 1.3 ms); the stroke's end adds it to the layer in 2.3 ms, and a slider change on that stroke's layer takes 4.6 ms plus 3.5 ms for normals. A script adds one with `new_layer` and sets one with `layer 2 0.5` (or `layer 2 0.5 hidden`). Exported to glTF, the layers become shape keys (see Export).

## Brushes, masking and symmetry

Fifteen brushes, picked in the dock, the brush browser (the grid button at its end) or the brush pie, the first ten with keys 1 to 9 and 0 in this order:

| | History | A local undo, as ZBrush's HistoryRecall brush: brings the surface back toward how it was before an earlier step of the History, half the way a dab at full strength, only where it is brushed (see History brush below). |

History brush: by default it paints back to how the shown level (or HD window) was before the oldest step its History still holds, so in a fresh session it paints back toward what was opened. The Brush palette's History brush section, shown while the brush is held, names that step ("Before: Draw stroke, 4 steps back (the oldest held)"); Earlier and Later move it one step at a time (also in the palette, as History brush: earlier, later and use the oldest), Use the oldest goes back to the default, and a right-click or long press on a step of the History panel's bar chooses that step (see History timeline and time-lapse). A chosen step stays until it is undone or the History drops it; the next History stroke then says so and paints back to the oldest instead. The target is built when Earlier, Later or Use the oldest moves the point, or else at the first History press that finds none (a copy of the positions with the steps' saved positions laid over it, newest first: 12 bytes a vertex; on a 10M-vertex sphere about 0.1 s with four threads, the copy shared between them) and kept while its step is in the History, so the brush's own strokes, ordinary undo steps, do not move it. It reaches back neither through dynamic topology strokes (with dynamic topology on the brush does nothing and says why) nor past a change carried to this level from another (the levels bring each other up to date when the current level changes, and no step of this level holds that change): with nothing in reach it does nothing and says so. One target per level, not saved with the scene.

The Object palette's Morph target: Store keeps the selected object's surface as it is now, Delete drops it. There is one per subdivision level, kept in memory only (12 bytes a vertex: 120 MB at 10M), not saved with the scene, and none while dynamic topology is on, whose strokes add and remove vertices (turning it on drops the target). A Morph dab costs a little less than a Draw dab (10M: 0.22 against 0.31 ms in the same run). Script: `morph_store`.

## Polypaint and polygroups

**Polypaint** works as ZBrush's: each vertex has a colour, painted with the Paint brush in the colour picked in the Brush palette (with the Paint brush) or the Object palette's Polypaint section (Surface page), at full mesh detail (no textures or UVs). A colour has a coverage too: unpainted vertices show the material's clay, the brush lays paint over it as far as its strength and falloff reach (paint over bare clay is the paint colour from the first touch, so stroke edges fade into the clay without a dark fringe), and Ctrl takes coverage off again. The mask, hiding and Front faces only hold it back as they do any brush. Fill with colour paints everything that is not masked or hidden; Clear paint takes it off the same part. Strokes and both commands are undo steps (4 bytes a vertex of what they reach). Each subdivision level keeps its own colours: changing level carries what was painted since the level became current to the level you go to (a vertex continuing one below takes its colour, an edge vertex the average of the edge's ends, and going down a vertex takes the one above it), so a look at a coarser level and back leaves fine paint as it was, and a new level takes the colours of the one below. Colours are saved in scene files (for the current level) and exported: PLY as `red`, `green` and `blue` vertex properties, OBJ as three more numbers on each `v` line, both as the paint over white as far as it covers. On the GPU each vertex has 8 more bytes (colour and group) in a storage buffer the mesh shader reads, made only once an object has paint or groups. 10M vertices (bench, VM): a Paint stroke frame takes 1.0 ms against Draw's 1.3. Not in HD windows (whose detail leaves when they close) or with dynamic topology on (turning it on drops colours and groups; it is an undo step).

**Polygroups** split a mesh into parts, as ZBrush's do: a group number per triangle, shown in flat colours with View > Polygroups (Shift+W). Ctrl+W groups the masked part as one new group and clears the mask, or with nothing masked makes what is shown one new group (with nothing hidden, the whole object becomes one group), as in ZBrush. The Object palette's Polygroups section (Select page) has the same as buttons (Group visible, Group masked), Groups by creases (a group for each part of the surface between edges sharper than the Crease angle, 35 degrees by default: a cube's six faces, a hard-surface import's panels) and Clear groups. A Ctrl + Shift click on a group shows only that group; a second Ctrl + Shift click on it when it is all that shows hides it and shows everything else; with Alt as well, the click masks the group instead. A Ctrl + Shift click on empty space, or on an object without groups, still shows everything. Every change is an undo step, groups follow level changes as colours do (a triangle going up takes the group of the triangle it was cut from, going down the group of the middle one of its four), and they are saved with the scene. Drawing them costs no triangle data: each vertex carries one group to the GPU and each triangle is drawn starting from a corner that carries its own group, whose value a flat shader input takes, so borders are sharp; a triangle none of whose corners can carry its group shows a neighbour's colour (none in the tests; at most one in a thousand is allowed). While the view moves, far parts drawn from simplified copies may show ragged group borders. Script: `group creases` (or `visible`, `masked`), `polygroups on`, `set paint_color 0.2 0.4 0.9` (0 to 1), `paint fill` and `brush paint`.

Masking works as in ZBrush: each vertex has a mask from 0 to 255, and every brush moves it only by what the mask leaves (a fully masked vertex never moves). Masked areas are drawn darker. In the Object palette's Mask section, Clear (Alt+M), Invert (Ctrl+I) and Mask all change the whole mask at once; mask strokes and these commands are undo steps like any stroke. Blur, Sharpen, Grow and Shrink move the mask's edge, as ZBrush's BlurMask, SharpenMask, GrowMask and ShrinkMask and Blender's mask filters do, a step at a time: each vertex takes from the corners of its triangles their average (Blur), their highest value (Grow) or their lowest (Shrink), so a step reaches one ring of triangles further, and Sharpen pushes each partly masked vertex toward masked or unmasked against half a Blur step, which narrows a soft edge to a sharp one that stays smooth along the triangles. Mask cavities masks the creases and dents, as ZBrush's Mask By Cavity does: each vertex is masked by how far it sits below the average of its neighbours along its normal, measured against their distance, so grooves and pores go dark and flat or bulging parts stay free; Blur after it softens the result. Mask hidden (under More options, and Mask it on the action bar while something is hidden) masks every corner of a hidden triangle fully and unmasks everything else, the one mask command that writes hidden vertices: hide a part, Mask hidden, then Show all, and the mask is that part. Steps sets how many steps a press takes (3 by default): since a step is a ring of triangles, a denser mesh needs more for the same distance. The section shows what the last command did and how long it took. The mask is carried when the object changes subdivision level (a vertex that continues one of the level below takes its mask, a new edge vertex the average of the edge's ends), so it holds on every level. An HD window starts unmasked and its mask is dropped when it closes. The mask costs no GPU memory or upload: it rides in the low 4 bits of each of the two 16-bit halves of the vertex's packed normal, which still places the normal within 0.1 degrees.

Selection sets keep masks to bring back, as ZBrush's Selection Sets do (Object palette > Selection sets). Store mask as set (also in the command palette) keeps the selected object's mask under a name, "Set 1" and on, which its row's text field changes; Restore on a row makes that set the mask again, and for the set the list picks, Add to mask takes the more masked of set and mask at each vertex, Subtract takes the set off the mask, and under More options Store over replaces the set with the mask and Delete removes it. A restore is one undo step, like a mask command, and leaves hidden parts' mask as it is; storing, renaming and deleting are not undo steps, as in ZBrush. A set is kept by the level it was stored on and restores on any level, carried there as the mask is when the level changes; deleting levels carries the sets of the deleted ones to the current level. An object keeps up to 16. A remesh or any other rebuild (Decimate, Mirror and weld, Slice, Make boolean) drops them, and its note says how many went (Undo brings them back with the old mesh); turning dynamic topology on drops them too and says so, and they cannot be stored or restored with it on or in an HD window. The palette's Restore selection set 1 to 9 can be given keys (Settings > Keys). Sets are saved in scene files (version 10, which older versions of the app do not open), as runs of equal values where that is smaller, so a mask costs at most a byte a vertex.

Mask shapes work as ZBrush's: with the Brush tool, Ctrl and a left drag that starts on empty space (not on an object) draws a rectangle, or a lasso when the Mask section says so, and letting go masks everything of the selected object inside it, through to the back side; with Alt held too it unmasks. Each shape is an undo step. The polygon is filled into a 1024 x 1024 coverage grid first, so a lasso of any length costs a lookup per vertex: at 10M vertices a shape takes about 25 ms on the test VM, 2 ms at 1M (`build/bench --masks` has the rows). A drag that starts on an object is a stroke as before, and Alt + left drag without Ctrl still orbits.

Ctrl + Shift and a left drag with the Brush tool runs the gesture tool chosen in the Object palette's "Hide, clip and slice" section (remembered between runs): Hide rectangle (the default, as ZBrush's SelectRect), Hide lasso, Clip or Slice. A Ctrl + Shift click without a drag shows everything again, whichever is chosen, or on a polygroup isolates it (see Polypaint and polygroups).

Shapes wait for Apply when drawn with a finger or the pen (Settings > Touch > Shapes, "Mouse at once" by default): a mask rectangle or lasso (Ctrl, or the rail's Mask, from empty space), a hide rectangle or lasso, and a Clip or Slice line stay on screen when the drag lets go, with a bar under them: Apply (Enter), Flip (Unmask, Hide inside, Other side; not for Slice) and Cancel (Escape or Back, once no menu or popover is open). White handles sit on a rectangle's corners and a line's ends, and a ringed one in the middle moves the whole shape; each takes a press within half a touch target, by a finger, the pen or the mouse, and two fingers landing on one still pinch or turn the view, leaving the shape where it was. A press anywhere else does what it always does, so the view can be turned, panned or zoomed under the shape before applying, and Apply uses the view as it is then; a new shape replaces it, and leaving the Brush tool lets it go. A shape drawn with the mouse applies as it lets go, as before. "Always at once" and "Always after Apply" make every pointer the same. Script: `set shape_apply auto` (or `now`, `confirm`).

Hiding works as ZBrush's: the hide tools draw a rectangle or a lasso (green), and letting go keeps only the triangles whose middle is inside it shown, through to the back; hold Alt as you let go to hide what is inside instead (red). Ctrl+H (or Show all) shows everything and Ctrl+Shift+H (or Invert) swaps hidden and shown; it never hides every triangle. Hide masked hides the triangles masked at least half at every corner, and Hide unmasked the others, to work on the masked part alone; the two are exact complements, so from a fully shown object Invert turns one into the other, and what is hidden already stays hidden. Both are in the Hide, clip and slice section and the command palette, with no keys until one is assigned. Hidden triangles are not drawn and no brush, mask, mask command (but Mask hidden) or clip moves a vertex all of whose triangles are hidden, and the brush and picking look through them; vertices on the edge of a hidden part still move. Each hiding change is one undo step. Each subdivision level keeps its own hidden part. Hidden parts are not saved in scene files, and hiding is refused in an HD window or with dynamic topology on (turning dynamic topology on shows everything); an HD window does not open while anything is hidden. On the test VM (release build) hiding half of a 10M-vertex sphere takes about 0.3 s. Script: `hide y` hides the + side of the selected object's middle across Y, keeping the - side shown (`hide -y` the other way; also x or z).

Slicing works as ZBrush's SliceCurve but makes separate objects: the Slice tool draws a line (cyan) across the viewport, and letting go cuts the selected object in two along the plane through the line and the view direction, through to the back (`geom.mesh_slice`, `src/geom/slice.odin`). Each part is closed with a cap of evenly sized triangles (as long as the edges the cut crossed, up to 100,000 triangles a cap), so both stay closed and can be sculpted, remeshed or exported; holes and several separate cuts (a torus cut through) are filled correctly. The part on the right of the drag becomes a new object beside it; the other stays selected. It works on the level the object is on and rebuilds it like a remesh: levels, HD detail, mask and hiding go, and symmetry is not used. One Ctrl+Z undoes both parts. On the test VM a 1M-vertex sphere slices in about 0.4 s and a 10M one (20M triangles) in about 6 s plus 2.4 s to set the two objects up. Script: `slice x` slices the selected object across the middle of its bounds along x (or y, z).

Clipping works as ZBrush's Clip Curve: with the Clip tool chosen, Ctrl + Shift and a left drag draws a line across the viewport, shading the side to the right of the drag (hold Alt to take the other side instead; what is held when you let go counts). Letting go flattens every vertex of the selected object on the shaded side onto the plane through the line and the view direction, through to the back, so the part past the line becomes a flat cut face. Nothing is deleted: the triangles stay, lying in the plane (Remesh selected afterwards to tidy the cut). It mirrors with the brush's symmetry, leaves masked and hidden areas (partly masked ones move part of the way), and is one undo step. Not with dynamic topology on. On the test VM a clip takes 35 ms at 10M vertices for a small cap and about 150 to 250 ms when it cuts away half the mesh, most of it saving 60 MB of positions for undo; the Object palette shows the last one's time.

Stroke (the Brush palette; Dots, Rectangle, Spray, Roll, not shown for Grab, Snake hook and Cloth, which drag what they pick up): Dots lays dabs along the path, as above. Rectangle (Drag rectangle), as ZBrush's DragRect, lays one stamp where the drag starts and redoes it as the pointer moves: its radius is how far the pointer is from the start and, with an alpha, the image's top faces the pointer, so an alpha can be placed, sized and turned in one drag. Each redo first puts back what the stroke did so far from the undo copies it already keeps (`sculptor_stroke_restore`), so it stays one undo step and costs one dab a frame. It works with every brush but Grab and Snake hook, and not with dynamic topology, whose strokes change the triangles (those use Dots). Spray, as ZBrush's Spray, lays a dab every half radius scattered up to the Spread slider's share of the radius from the path on screen (0 to 1.5, default 0.6), each 75 to 100% of the size and 50 to 100% of the strength and, with an alpha, turned its own way, for texture without a visible repeat. Its random numbers come from the stroke's seed and the dab's step (SplitMix64), and the seed comes from a counter each stroke takes the next of, kept by the stroke recorder, so a replayed Spray stroke lands exactly the same dabs. Roll, as ZBrush's Roll, lays a dab every diameter, the first a radius from the press, with the alpha's top along the stroke whatever the alpha's mode, so an alpha tiles like a tape rolled out (stitches, zips, chains); without an alpha it is Dots at that spacing. Shift's Smooth and the rail's Smooth and Mask always stroke as Dots. Presets keep the stroke mode and the spread; settings.txt keeps them as `stroke` and `stroke_spread`. Script: `set stroke spray` (or `dots`, `drag_rect`, `roll`).

Front faces only (a switch in the Brush palette's Options, as ZBrush's BackfaceMask) makes every brush but Grab, and the mask shapes, leave the vertices whose normal faces away from the viewer, with a short fade across the ones seen edge-on, so a stroke on a thin part such as an ear, a fin or a sheet leaves its far side alone and a mask rectangle stops at the visible side. It is per vertex, not a visibility test: a front-facing part hidden behind another is still reached. With symmetry, each mirror image faces the mirrored way. Script: `front_only on`.

Lock plane (a switch in the same Options section, as ZBrush's Original plane and Nomad's lock) keeps the area the stroke's first dab found, its normal and middle, for the whole stroke, so a long Flatten or Clay stroke across changing ground flattens to one plane instead of following it, and a Draw stroke pushes one way throughout; a stroke joining one (Join strokes) keeps its plane, so a long Flatten laid in pieces stays on one. It applies to Draw, Clay, Flatten, Pinch and Crease, and to any brush with an alpha (which lies on that plane); Clay's offset and a leaning pen still apply on top, each mirror image takes the plane mirrored, and the switch greys out on the other brushes. Connected only (as ZBrush's topological auto masking) makes a dab work only on what joins the place it presses (the triangle under its centre) through the shown surface without leaving the brush, so a finger pressed against the next one, the far lip of a thin slit or a separate shell inside the brush stays untouched however near it is in space, and hidden parts join nothing; it holds for every brush but Grab and Cloth (masking and painting included) and greys out for those two. Both are commands too (Lock plane, Connected only and Front faces only in the palette, for a key or a pie), presets keep them, and `.strokes` files store them. Lock plane costs nothing; Connected only finds what is joined on the worker threads, a BVH leaf each, and costs about as much again as the dab: a Clay stroke at 10M vertices takes 1.8 ms of brush time a frame with it against 0.7 without (release, `--bench-stroke=120`, 4-thread VM), and 8 bytes a vertex once first used. Script: `lock_plane on`, `connected on`.

Symmetry (X, Y and Z on the toolbar at the top; the X key toggles X) mirrors every dab across those planes through the object's origin, up to 8 images with all three; Grab drags each image the mirrored way.

## Voxel remesh (DynaMesh)

Rebuild (Object palette, Shape page) replaces the selected object's topology by what it is for, picked on its tabs: Even (this remesh), Fewer (Decimate, below) or Quads (Retopologize, below), each at the count its Density slider sets (1k to 25M vertices, or 100 to 1M quads), and its button runs it. While Density is held, and for 1.5 s after, or while a mouse is over it, the selected object shows a checkerboard of the cells that density gives, as Nomad's resolution preview does: for Even the very lattice the remesh will build on (each cell becomes about one vertex; the line under the slider gives the cells' width), for Quads squares of the mean quad's size. Fewer has none, since decimation is dense where the detail is. Cells smaller than about three pixels fade to an even tint rather than shimmer. The preview measures the object's area once per change of its mesh, spread over frames at about 1 ms a frame (a 10M sphere takes about 90 ms in all on this repo's 4-core VM, so its cells show after a few dozen frames); drawing it is a few instructions in the mesh shader, and it is never in a studio render or a time-lapse. `--density-preview=N` shows it held on, for an even remesh of N vertices.

Remesh (Rebuild's Even, or Ctrl+R at the object's own vertex count) rebuilds the selected object as an even surface of about that many vertices, as ZBrush's DynaMesh does: stretched triangles from Grab or long strokes become even again, overlapping or self-intersecting parts merge into one closed surface, and anything thinner than the lattice spacing goes. It keeps the shape of the level the object is on; its levels, HD detail and mask go, and Ctrl+Z brings them back (HD detail apart).

How it works (`src/geom/remesh.odin`): the object is laid on a lattice whose spacing gives about the asked-for vertex count (at most 4,096 lattice points along any axis, DynaMesh's top resolution). A ray along each lattice row finds where it crosses the mesh and which way, using exact fixed-point tests so a ray through a shared edge or vertex counts it once, and a lattice point is inside where the winding number is positive. Rays along y and z find where the surface crosses those lattice edges. Marching cubes then joins the crossings, with one rule on ambiguous cube faces that makes the result closed and manifold (every edge between exactly two triangles), and three rounds of relaxation along the surface even out the triangles. Rays, crossings and cells are stored only where the surface is, so memory grows with the surface's area rather than the lattice's volume.

`build/bench --remesh` (4 threads, this repo's cloud VM, `--prefault=3000`). Sculpt-ready is the same preparation as any new mesh of that size (BVH, chunks, normals). Edge spread is the 99th percentile and the longest edge over the median edge, before and after:

| 1.00M | 1.00M | 298 | 154 | 3.38 | 1.59 | 4.5 | 1.7 |

## Project detail

**Project detail** (Object palette), after ZBrush's ProjectAll: the selected object's shown level takes the shape of the object chosen in Project from, and its polypaint too with Polypaint too. Each vertex looks along its normal both ways, as far as Reach (a share of the selected object's size, 0.03 by default), for the other surface, and moves to the nearer hit by Strength; the mask holds vertices back as it holds a brush. Vertices that find nothing stay put. It is one undo step.

By default each object is read in its own space, as baking does, so a copy made by Duplicate or Retopologize, which is put beside the original, projects as if it lay on top of it; As placed uses where the two sit in the scene instead. The usual round trip: duplicate a sculpt, Remesh or Retopologize the copy (the detail goes), subdivide it a level at a time and Project detail at each level from the lowest up, so every level holds what it can of the original. A 100k-vertex retopology projected from a 1M sphere takes about 0.3 s on the VM, the source's BVH included. Not under dynamic topology on the selected object. Script: `project 1` projects from the first object onto the selected one (any object's number, counting from 1, down the Scene palette's list).

## Curve and insert tools

**Curve** (C, or Curve on the toolbar; its settings fill the tray's first palette), after ZBrush's curve brushes: drag over any surface and, on release, a new object follows the path. It is made one of three ways. **Tube** sweeps a circle of Sides sides along it, capped at both ends; Lift sets how far its middle sits out from the surface, in radii, so 0 half buries it and 1 rests it on top. **Stitches** sets leaning bars across the path. **Zipper** sets interlocking teeth from alternate sides. Width is a share of the brush's diameter where the path began, so S resizes it. The path is resampled at even steps and smoothed three times, which takes out the hand's wobble. Each part is turned to the path's frame there (along the path, out of the surface and across it), so the result follows the surface's curvature. The result is an ordinary closed object: remesh it to sculpt it, or mark it Union for the booleans.

**Insert** (I), after ZBrush's insert mesh brushes: click a surface to put a shape there at the brush's size, standing on the surface's normal and turned with the view; drag before letting go to size it instead. The shape is any primitive or starter at Vertices (a starter is never under 15,000), or a copy of any object in the scene (Copy of ... in its list), fitted to that size. Sink pushes it into the surface by that share of its half size. **Mark it as** sets its boolean mark as it is made, so a cylinder marked Subtract, with Live boolean on, cuts a hole at once.

Each curve or insert is one undo step. The geometry is in `src/geom/curve_mesh.odin`. Script: `draw_curve tube` (or `stitches`, `zipper`: a wavy path across the middle of the view) and `insert_middle cube` (or another shape, at the middle of the view).

## Booleans and Extract

**Booleans** (Object palette), after ZBrush's Live Boolean: set "The selected object is" to Union, Subtract or Intersect on any object, and the marked objects apply, in scene order, to the base, the first object left unmarked. With **Live boolean** on, the result is drawn in their place at about Live vertices (200,000 by default) and made again whenever one of them is moved, turned, sculpted or remarked, once the mouse is let go; while you drag or sculpt the selected one it shows as it is. Subtract and Intersect objects are not drawn on their own, so select them in the Scene palette's list to move them. **Make boolean mesh** replaces the base with the result at about Result vertices (1M by default) and deletes the marked objects, all as one undo step. Marks are saved in .sculpt files.

How it works (`src/geom/boolean.odin`): both meshes go through the voxel remesh together, with B's crossings counted 4,096 times A's, so one winding number says whether each lattice point is inside A, B, both or neither, and the operation picks which count as inside. Any two closed meshes therefore combine, overlapping or not, into one closed manifold surface. The voxels round edges off at their spacing, so each vertex is then put back onto the nearer input surface along its normal when one is within a voxel, which brings back the inputs' detail and flat faces; only the seam where they meet stays at voxel resolution. Two 1M-vertex spheres: about 0.35 s for a 1M union on the VM; the live preview at 200k takes about a tenth of that.

**Extract masked** makes a new object from the selected object's masked part (mask over half), as ZBrush's Extract does: a shell Thickness thick (a share of the object's size, 0.02 by default) along the normals, its open edge smoothed so it does not follow the mask's jagged outline, closed where the masked part was one piece. Script: with `--spheres=2`, `select 2; boolean union; move 0.9 0 0; select 1; make_boolean` marks the second sphere Union, moves it onto the first and makes the mesh (`live_boolean on` turns Live boolean on); `set extract_thickness 0.05; mask_rect 0 0 1 0.335; extract_masked` masks the top third of the view and extracts it.

## Retopology, UVs and baking

**Retopologize** (Object palette, Rebuild's Quads; baking is in Build > UVs and baking) makes a new object of about Quads quads (4000 by default) lying on the selected object's shown level, and puts it next to it, as ZBrush's ZRemesher does: every face a quad, closed where the sculpt is closed, facing out. The way there is simpler than ZRemesher's, and its edge flow does not follow the sculpt's curves: the sculpt is decimated by quadric error (as Decimate does, so more faces go where the shape bends), neighbouring triangles that make a near-square quad without folding pair up (about three in four do), every face is then cut into quads at its middle and its edges' middles, as a Catmull-Clark step cuts, and twelve rounds relax each vertex toward its neighbours' middle along the surface and put it back onto the sculpt along its normal. About four vertices in five end up with four quads around them. The new object is ordinary: it can be subdivided and sculpted, and its base level keeps its quads (drawn and sculpted as two triangles each) for export and baking; deleting its lower levels or turning dynamic topology on drops them. It takes about 11 s from a 10M sphere (mostly the decimation) and under a second from 1M (4 threads, VM).

It comes with **UVs**: the quads are grouped into charts that face within 55 degrees of their first quad, each chart laid flat by projecting it onto the plane facing that quad (so no quad folds over), turned to its smallest box, and the boxes packed in rows into the unit square at the largest scale that fits, with 8 texels of a 4096 map between charts; a sphere gets about a dozen charts filling 70 to 80% of the square. New UVs lays them out again after the shape changed a lot.

**Bake maps...** asks for a folder and bakes the object chosen in Bake from (by default the one the quads came from; its top level) onto the selected quad object's UVs, at Size texels square (512 to 4096, default 2048): each texel's point on the quads casts a ray each way along the quads' smooth normal, as far as Reach (2 average quad edges by default), and the nearer hit gives the displacement (distance along the normal, outward positive) and the sculpt's normal there. It writes `NAME_normal.png` (tangent space with green up, OpenGL's way; the tangent frame comes from the UVs per vertex and chart and is blended across each face, as MikkTSpace does, though not to the bit), `NAME_displacement.png` (16-bit grey: 32768 is the quads' surface, 0 and 65535 the largest distance in and out), `NAME_displacement.txt` (that distance in the OBJ's units) and `NAME.obj` (the quads with their UVs). Charts' edges are grown 8 texels outward so filtering at seams finds no background. Both objects are read in their own spaces, so moving either changes nothing. 10M-vertex sphere onto 5,000 quads at 2048: 3.7 s, with every covered texel finding the surface. Script: `set retopo_quads 5000; retopologize`. Flags: `--bake=DIR` (on exit, from the first object onto the newest), `--bake-size=N`.

## Mirror and weld, duplicate

Mirror and weld in the Object palette (as ZBrush's Mirror And Weld and Blender's Symmetrize) replaces one half of the selected object with a mirror image of the other, across the object's own X, Y or Z plane (the one brush symmetry uses), keeping the + side unless "Keep the - side" is on. Triangles crossing the plane are cut at it and the two halves are welded along the cut (`geom.mesh_symmetrize`, `src/geom/symmetrize.odin`), so a closed object stays closed; vertices within 1/100,000 of the object's size of the plane move onto it so the cut makes no slivers. It works on the level the object is on and rebuilds the object like a remesh: levels, HD detail and mask go, and Ctrl+Z brings them back. 100k vertices take about 0.1 s on the test VM. Script: `set mirror_axis 0; mirror_weld` (axis 0 x, 1 y, 2 z; `set mirror_negative on` keeps the - side).

Duplicate (the Scene palette, or the object list's right-click menu; Ctrl+Shift+D) adds a copy of the selected object beside it, with every subdivision level, the mask and dynamic topology (HD detail is not copied, as in a saved scene), and selects it; Ctrl+Z removes it.

## Decimate

Decimate (Rebuild's Fewer, as ZBrush's Decimation Master) rebuilds the selected object with about the vertex count its Density sets while keeping its shape: edges collapse where that moves the surface least (quadric error, `geom.mesh_decimate`, `src/geom/decimate.odin`), so the triangles stay dense where the detail is and go sparse where it is flat, unlike a remesh, which spreads them evenly. It is meant for exporting a sculpt to other programs. A collapse that would fold the surface, pinch it or leave a needle is refused, so a closed object stays closed and sound (`--check-mesh` stays clean); among collapses that change the shape equally, as on a flat area, shorter edges go first. Large meshes are first thinned in parallel, a quarter of the triangles a round in 64 cells whose borders move every other round, then finished as a whole. It works on the level the object is on and, like a remesh, drops levels, HD detail and mask (Ctrl+Z brings them back). The section shows how far the surface strayed at most. On the 4-thread test VM: 1M vertices to 3k in 0.7 s; 5M to 100k in 8 s and to 10k in 3 s; 10M to 100k in 12 s. Script: `set rebuild_goal fewer; set rebuild_fewer 100000; rebuild`.

## Dynamic topology

Ctrl+T, or the switch in the Object palette's Dynamic topology section, turns dynamic topology on for the selected object, as Sculptris Pro in ZBrush and dyntopo in Blender do: each dab first splits the edges under the brush longer than Detail pixels on screen and, with Collapse short edges (on by default), collapses the ones shorter than 0.4 of that. The brush makes triangles where it goes, as many as the detail you see needs, so you can start from a coarse ball and pull out horns and folds without stretching anything. Since Detail is in pixels, zooming in makes finer triangles. On a dense mesh seen from afar the edges are already shorter than Detail, and with collapse on the brush coarsens what it touches; lower Detail or switch collapse off to keep the density. Every brush works with it, symmetry too; Grab and Mask leave the triangles as they are, and so do fully masked areas. The object needs a single subdivision level and no HD level, and turning it on or off is an undo step of its own (its earlier strokes can no longer be undone one by one). Remesh selected works on a dynamic object and turns it off.

How it works (`src/sculpt/dyntopo.odin`): the sculptor works per node as it does on a fixed mesh, but each node gets a page of the mesh's arrays (1,280 vertex slots and 2,048 triangle slots) and uses the first of them, so it grows and shrinks in place; unused triangle slots hold zeros, which draw nothing. A node whose page fills up splits in two along its longest axis, and the BVH over the nodes is rebuilt then, in well under a millisecond. Each vertex lists its triangles (up to 16), so splits and collapses only touch what is around them. Splits go longest first and cut each triangle across its longest side (Rivara's bisection): when either triangle beside an edge has a longer one, that splits first, even just outside the brush. Triangles stay well shaped however often an area is refined: no angle went below 24 degrees in our measurements, and a test strokes one ring 160 times and checks for angles under 15 degrees, folds and the whole layout every 20 dabs. A collapse is refused where it would fold or pinch the surface, give a vertex more than 12 triangles, make an edge longer than Detail, or leave its worst triangle thinner than before and under 0.3 on a scale where an equilateral triangle is 1 (2√3 times the area over the sum of the squared sides), so thin slivers do not pile up where the brush coarsens. Surfaces that are not closed work too (an imported scan, say): an edge on the border splits its one triangle, and collapses leave border vertices where they are, so the border keeps its shape. Turning it on is refused on a mesh with an edge shared by more than two triangles or with triangles facing opposite ways across an edge. A dab makes at most 2,048 splits and 2,048 collapses, and the app stops laying dabs for a frame once they have taken 10 ms, so a large brush over a coarse area keeps the frame rate and catches up over the next frames. Undo saves each node a stroke changes, whole, before its first change, and swaps it back. The GPU gets the index pages that changed along with the changed vertices; when the mesh outgrows its buffers, they are made again at the larger size.

`build/bench --dyntopo` (4 threads, this repo's cloud VM). A frame is 4 dabs plus the normal update, as in the main table. Fixed is the large-brush stroke on the usual layout, Plain the same with dynamic topology on but nothing to split, Refine with a detail that splits every edge under the brush once (each triangle into four), which is far more than a stroke on a coarse mesh asks for: from 5M up every dab stops at its 2,048 splits. Upload is the changed vertices plus the changed index pages:

Turning it on at 7M and 10M is mostly the VM's slow first touch of that memory. Turning it off packs the mesh and prepares it as any new mesh of that size.

## Files

The menu (the top bar's first button) opens and saves scenes (Open scene, Save scene, Save scene as, Save a copy, Earlier saves) and imports and exports meshes, each through the system's file dialog (SDL's); what the dialog picks runs at the start of the next frame. The outcome shows as a note at the bottom of the window for a few seconds, amber when something failed or needs attention, and goes to the log.

**Scenes** (`.sculpt`: Open scene, Save scene, Save scene as): every object with all its subdivision levels as shown and their sculpt layers, a retopologized object's quads and UVs, the mask, polypaint and polygroups of its current level, dynamic topology if on, its name and place, whether its eye is off or it is a ghost, its folder, the folders (names, folded or open, eye and ghost), Solo, and the camera. Each level is stored as positions, so it opens exactly as it was saved. Since the vertex numbering changes whenever a level is built, the levels above the base store their vertices in an order the topology alone decides: the vertices that continue the level below first, then those on its edges, by the edge's ends. Opening builds every level above the base again from it, as subdividing does, and moves its vertices where they were, so it takes about as long as subdividing to that size; the base itself keeps its node layout in the file, so it opens without being laid out again (see below). HD detail is not saved, only each object's number of HD steps; the HD section says so while an object has stored detail, and so does the note after saving. Nor is the undo history. Opening reads and uploads the whole new scene before the old one goes, so a damaged file leaves the scene as it was (both are in memory for a moment). Saving writes beside the file, makes sure every byte reached the disk (fsync), and then replaces the file with it (on Linux and Android the folder is synced too; on Windows the rename is write-through), so neither a failed save, a crash nor a power cut leaves a half-written file, and "Saved" shows only once that is done; exports, bakes and `.strokes` files are written the same way, screenshots are not. A save of a scene over about 1M vertices (32 MB) stops the app for a moment (about 0.6 s at 2M and 4.6 s at 10M on the VM), so it first shows "Saving head.sculpt..." at the bottom, saves once that is on the screen (a quarter of a second later, or at once when a scene change, another file action or closing the app comes first), and then replaces it with the outcome; a second Ctrl+S meanwhile is dropped.

**Save a copy** (Menu, or the command palette) writes the scene to another file and leaves it saving where it did: a backup, or a variation to come back to; the note says which file the scene still saves to. **Earlier saves**: saving over a scene file (Save scene, or Save scene as onto it) first keeps the file it replaces in a folder beside it, `head versions/head 2026-10-26 14.02.33.sculpt`, stamped with when that file was saved in the device's local time (a second save in the same second gets `-2`, `-3`, ...). The old file is hard-linked there, so it costs no time and no space until the new save replaces it, or copied where the file system has no links (FAT cards). The newest five are kept and older ones deleted (Settings > System > Earlier saves: Off, 3, 5 or 10; remembered as `versions_kept`); Off keeps no more and deletes none already there, and nothing else in the folder is ever touched. At 10M five versions are about 1.8 GB beside the file. If the earlier save cannot be kept (the folder cannot be made), the save still happens and its note says why in amber. Save a copy keeps no versions. **Earlier saves...** (Menu, or the command palette, once the scene's file has any) lists them under the menu button, newest first, as "Today 14:02", "Yesterday 18:40" or "12 Oct 09:15" (with the seconds when two share a minute) and their sizes; the list is read when it opens and after each save, never every frame. A tap opens that save as the scene, which still saves to its own file, so the next Save makes it the current one and keeps the one it replaces: going back loses nothing. With changes the file does not hold, the first tap turns the row red ("Discard changes and open?") and a second tap within three seconds opens it, as New scene asks. The format is little-endian binary with a version number: `scene_save` in `src/app/files.odin`, then per object `levels_write` in `src/sculpt/levels_file.odin`.

**Import** (Import mesh, `.obj` or `.ply`): OBJ `v` and `f` lines (polygons become fans of triangles; negative indices and `v/vt/vn` corners work; everything else is skipped), read in parallel chunks of 4 MB. PLY in ASCII or binary of either byte order, with any vertex properties (x, y and z are kept) and polygon faces. Then a cleanup: vertices at exactly the same place are welded (exporters split vertices along UV seams), triangles left with a repeated corner and vertices no triangle uses are dropped, and a closed surface that faces inward is turned outward. The mesh is centred and sized like a sphere (radius 1) and placed beside the other objects; its place in the file is kept for export. A surface that is not closed sculpts, also with dynamic topology, which keeps its border, but subdivision, HD and remesh need a closed one, and the note says so.

**Export** (Export selected, `.obj`, `.ply`, `.glb` or `.usda` by the name, or by the dialog's filter when the name has none): the selected object's shown level (packed, when dynamic), as OBJ with nine significant digits, which read back as the same floats, as binary PLY, as binary glTF 2.0, or as USD text, with polypaint as vertex colours when it has any (Import does not read colours back yet). It goes back where it was in the file it came from, so an imported mesh exported again lines up with the original; Move tool placement is not written.

**glTF** (`.glb`, one file) carries what Blender and other programs need to keep sculpting it: the normals, the polypaint as linear colours (16 bits a channel, so dark paint does not band), and the level's **sculpt layers as shape keys** (morph targets): each layer's displacement at strength 1, named as the layer, with the layer's strength as the key's value (0 for a hidden layer, whose strength is not kept). The base mesh written is the surface without the layers, so at those values the keys rebuild what the app shows (to rounding: 6e-8 apart at most on a 40k-vertex sphere with two layers, one at 1.5), and each key's slider then does what the layer's did, past 1 and below 0 as well. A layer is stored only where it moved the surface, so one over a small patch costs little. Checked with the Khronos glTF validator (no errors or warnings) and by importing into Blender 5.2 (vertices, triangles, shape keys and their values, the colour attribute; `scripts/export_check.py` runs both, see below); Blender turns Y up into Z up as it imports. Dynamic topology bakes the layers, so a dynamic object exports without them; polygroups and a retopologized object's quads and UVs are not in glTF exports (OBJ and USD keep the quads). A file over 4 GB, which the format cannot count (about 30 layers over the whole of a 10M mesh), is refused with a note. 10M vertices with a layer over all of them: 610 MB in about 7 s on the 4-core VM (PLY: 362 MB in about 4 s). An export over about 1M vertices first shows "Exporting head.glb..." at the bottom, as a big save does.

**USD** (`.usda`, text) carries the same as glTF, in the form Blender's, Houdini's and Maya's importers read: a `Mesh` under a `SkelRoot` named `Root`, the layers as `BlendShape`s (each the points it moves and how far, named as the layer; the prim names are the names with anything but letters, digits and `_` as `_`) bound to a skeleton with no joints whose animation gives the strengths, the paint as linear `displayColor`, normals, `subdivisionScheme` none (the surface as it is, not a cage), the polygroups as a per-face `polygroup` primvar, and a retopologized base level as its quads with UVs (`st`, per corner), as OBJ keeps them (a quad takes the group its first corner shows). The strengths are written both as the default and as a time sample at frame 1: Blender's importer reads only time samples and keys them in an action, so the shape keys take their values at frame 1, and it keeps each key's range at 0 to 1, so a layer at 1.5 shows as 1 until the key's Range Max is raised (the action holds 1.5). Checked with USD's own 30 validators (no errors) and by importing into Blender 5.2: the evaluated mesh at frame 1, layers applied, is within 8e-8 of the OBJ export; Blender turns Y up into Z up. Text spells out every number, so it is the slow one: 10M vertices with a layer over all of them is 1.9 GB in about 24 s on the 4-core VM (glTF: 7 s); an export over about 180k vertices shows "Exporting..." first.

`scripts/export_check.py FILE.glb|FILE.usda` checks an export with a validator (Khronos's for glTF, USD's own for USD) and Blender itself (`--vertices`, `--triangles`, `--keys "Layer 1=1.5,Layer 2=0"` and `--colors` say what to expect); `--setup` installs them into `build/export-tools` (node's gltf-validator package, and the `bpy` and `usd-core` wheels; bpy wants Python 3.13). A tool that is missing is reported as skipped, never as passed. They are development tools only; nothing of them ships with the app.

An object made by Retopologize exports from its base level as quads with their UVs (OBJ only; PLY stays triangles). Normal and displacement maps are baked into a folder from the Object palette (see Retopology, UVs and baking).

`build/bench --files` (4 threads, this repo's cloud VM, in memory, so without the disk). Parse is the reader alone, Clean the weld, centring and edge check after it, Sculpt-ready the setup any new mesh of that size gets (nodes, BVH, normals). Scene read includes that setup:

## Autosave and recovery

An interactive run saves a recovery copy of the whole scene, as Save scene would, every minute while there is a change to save (Settings > System > Autosave: Off, 1, 2, 5 or 10 minutes; remembered as `autosave_minutes`). It never interrupts work: a copy starts only once nothing has been pressed, typed, touched or stroked for 1.5 s, and a worker thread of low priority reads the scene and writes the file while sculpting goes on. A press, key, stroke, scene change or file action while it still reads the scene makes it stop and try again at the next pause, so it never reads a half-changed mesh; the frame that stops it waits for it a few milliseconds at most (0.7 to 8 ms at 10M with and without levels on the 4-core VM, `autosave_wait_ms` in the exit stats). Once it has read the scene it writes the file while the app goes on. A copy is the same `.sculpt` format as Save scene and takes as long to read, without HD detail (as saving) or work inside an open HD window; the System tab says so while one is open.

Each run keeps up to three copies in turn, `<session>-1.sculpt` to `-3.sculpt` with a `<session>.session` file saying when they were written and by which process, in an `autosave` folder beside `settings.txt` (`%APPDATA%\Implicit\Sculpt\autosave` on Windows, `~/.local/share/Implicit/Sculpt/autosave` on Linux). Each is written beside its name, flushed to the disk and renamed over it, so killing the app, a crash or a power cut mid-write leaves the copy before it whole. A clean exit writes a last copy if anything changed (hiding the window first), keeps the newest and marks the session closed; the last three closed sessions are kept, older ones deleted. Saving the scene counts as a copy: a run that crashes after a save with nothing new is not offered.

When a run starts and finds a session whose process is no longer running and was not closed, a card at the top asks "Recover your work?" with when it was autosaved, how many objects and vertices it held and the scene file's name: Recover opens its newest copy that reads whole (Save scene then saves to the file the scene came from, if it had one, and the next autosaves continue in this run's session), Not now leaves it for the next start (Escape too), and Discard deletes it. Crashed sessions are never deleted without asking. Menu > Open the last autosave (and the command palette) opens the newest copy of any earlier session at any time, closed ones included. On Android the app cannot tell a crash from being closed by the system, so every session not closed is offered.

Disk use is three copies of the scene a run (about 360 MB each at 10M) and the last three closed runs; a 10M scene's copy takes about 5 s to read and 2.6 s to write on the VM, at most once a minute and only after a change. Strokes while a copy is written cost the same (`build.sh release` then `build/sculpt --vertices=10000000 --bench-stroke=240 --no-vsync`, with and without `--autosave=1 --bench-after-autosave`, three runs each: brush p50 0.64 to 0.73 ms either way; frame p50 16.0 to 17.5 ms without, 17.5 to 18.0 ms with, where the 4-core VM's software GPU uses every core the writer also uses).

Flags: `--autosave=SECONDS` autosave that often (scripted runs only autosave with it or `--autosave-folder`), `--autosave-folder=DIR` keep the copies in DIR and offer the crashed ones found there, `--autosave-rest=SECONDS` the pause before a copy starts (default 1.5), `--check-autosave` hash what each copy read before and after and count a difference as `autosave_torn`, `--crash-after-autosave` exit with code 3 right after the first copy, skipping the clean exit (the crash test), `--bench-after-autosave` start `--bench-stroke` once a copy of the starting scene is being written. The exit stats give `autosaves`, `autosave_aborts`, `autosave_torn`, `autosave_wait_ms`, `autosave_sync_ms` (bringing the levels up to date on the frame loop before a copy), `autosave_serialize_ms`, `autosave_write_ms`, `autosave_mb`, `recovered` and `recover_offers`. `scripts/touch_check.py 'autosave_*'` runs the crash, recover, discard, Not now, stroke-stops-it and Off scenarios.
## Interface

The interface is touch-first, designed in Figma ("Sculpt UI"), and drawn by the app's own kit (`src/ui`). One layout serves every OS and screen, scaled by the screen's pixel density and the system's display scaling (Android's screen density, Windows' Scale setting), laid out inside the window's safe area, and every control's hit area is at least 48 points (the App Store's 44 pt and Google Play's 48 dp both met) while what is drawn inside it stays compact.

The viewport fills the window and the chrome sits round its edges, laid out as ZBrush for iPad's (`src/app/kit_bars.odin`). A strip across the top holds the menu (open, save, save as, save a copy, earlier saves, the last autosave, import, export, screenshot, New scene, Reduce motion, Settings, Stats, Help; on a window too short for all of it, it scrolls under its button), Save (a long press offers Save as, Save a copy, Earlier saves and the last autosave), Import and Export at its left; the scene's file name in the middle, with a star while it holds changes the file does not; and History, Edit pies, Help and Settings at its right. Under its left end is the selected object's readout: its name, its subdivision level, Dynamic or HD when on, its vertices and, with several objects, the scene's; a tap shows it in the tray's Object palette and a long press (or right-click) opens its menu under it (focus, duplicate, delete). Down the left edge is the brush bar: Brushes (the brush in use; a tap opens the brush browser beside it, a long press its settings), Stroke, Alpha, Material and Colour, then Focal shift, Draw size and Strength, then Undo and Redo (their tooltips name the step). Stroke, Alpha, Material and Colour open that tray section in a popover beside the bar; Focal shift, Draw size and Strength open a tall slider there, which follows how far a finger or pen moves rather than jumping to where it presses. A finger's or the pen's long press on one of those three, still held and dragged up or down, sets it on the spot, with a small readout of its value and range beside the button and nothing opened: 150 points up doubles the size, 300 take the strength from 0 to 1 and the focal shift across its range, counted from where the drag passes the slop. Let go without dragging, the long press opens the Falloff section (from Focal shift) or the Pen section (from Draw size and Strength) as it lifts, not as the press becomes long, as the mouse's right click on them does; a touch the system or a palm cancels puts the value back. A change runs the operation again from the state before it, not on its own result, so Decimate to 200k after Decimate to 500k is Decimate to 200k from the original, and a remesh is never a remesh of a remesh; a size or side runs at once, a slider when it is let go (at 10M a run takes seconds). The operation's undo step is replaced, so the History keeps one entry for it however many settings were tried, and the popover stays open with the result line to try another. A run that changes nothing (Decimate to more vertices than the object had) puts the earlier result back and says so. Anything after the operation ends the adjust: a stroke or mask, an undo, moving or selecting another object, changing its boolean mode, leaving HD or scrubbing the History. The command palette has it as Adjust last operation (greyed out when there is nothing to adjust), and opens it above the dock when the action bar is hidden. Escape, Back or a press outside closes it.

Adjust last stroke (as ZBrush's Adjust Last): after a stroke (sculpting, masking or painting), Adjust last operation in the palette, or a key given to it, opens Amount above the dock, and the Brush palette's Stroke section has the same slider as Last stroke under More options. It sets how much of the newest stroke stays, from 0% (as if it had not been drawn) through 100% (as drawn) to 150%, following the slider as it is dragged: every vertex the stroke moved, every mask or colour value it changed, and a recording layer's displacement go that share of the way from before the stroke to after it. It stays the stroke's one undo step, whose History entry then reads "Draw stroke (80%)"; undo takes the adjusted stroke back. There is no action bar group for it, which would show after every stroke. It applies while the stroke is the newest step on the level or HD window shown: another stroke, an undo, a level change or leaving HD ends it; not with dynamic topology, whose strokes change the triangles. The first adjust keeps a copy of what the stroke left of every part of the mesh it reached (12 bytes a vertex for positions or a layer's displacement, 1 for a mask, 4 for a colour, counted in the undo memory) until the step is undone or another comes. A replayed take or stroke file plays each stroke as it was drawn, at 100%.

The look comes from one set of design tokens (`src/ui/theme.odin`, "Graphite"): surfaces, text, one blue accent and the status colours, three corner radii (6, 8, 12), five type sizes in Inter and the motion durations. The brush pie, the labels over the viewport and the Stats panel use the same tokens and typeface.

Motion (`src/ui/motion.odin`) follows Anime.js: a value eases toward its target over a duration, after an optional delay, and a new target sets off from wherever it is, so nothing jumps. Presses dip and wash, hover fades in, the marker under a chosen tab or brush slides, switches move their knob with a slight overshoot, menus and popovers grow from where they open and fade, groups open by growing, the tray slides, tooltips wait and fade, and notes rise in one after another. Nothing a stroke, the camera or a drag depends on is animated. Menu > Reduce motion (`reduce_motion on` in a script) makes every animation arrive at once; it is remembered.

The kit (`src/ui`) is drawn by the renderer's own UI pass (`src/render/ui_pass.odin`, `ui.vert`/`ui.frag`): one vertex and index buffer a frame, a single-channel glyph atlas updated only where it changed, one draw per texture and clip change, with the viewport image drawn as the first quad and the viewport's overlay (the brush outline, the gizmo, the shape being dragged) laid just over it, under the panels, though it is drawn after them, once the tools have run (`ui.layer_mark`). At 1600 x 900 a frame is about 6,500 vertices with the Brush palette open and 9,000 with the Object palette; laying it out, animating and tessellating it takes about 0.65 ms p50 (0.8 ms with the Object palette) in a release build on a 12-thread Windows desktop, at 1M and at 10M vertices alike (`ui_ms_p50`, `ui_ms_p99` and `ui_vertices` on exit). Animations change only the vertices drawn, never the layout, and the tweens live in one table allocated at start. Keys, the pointer and typed text come from SDL's events (`src/app/device.odin`); fingers and the pen come from SDL's touch and pen events (`src/app/touch.odin`, `src/app/navigate.odin`), with SDL's own turning of fingers into the mouse off (see Touch and pen below). Text is Inter (SIL Open Font License) and icons are Lucide (ISC), both embedded; their licences are in `assets/fonts`.

## Command palette

Ctrl+K, `/` (on keyboards where it has its own key; Ctrl+K works on every layout) or the Search button at the top of the right bar opens the command palette beside it: a search field over a list of every command the menus, the tray's buttons and the shortcuts run, one row per brush, tray section, view, mask command, paint, group command, remesh or decimate size and New scene shape, plus each Settings tab ("Settings: Touch") and each Help tab ("Help: Gestures"). ## Statistics

F11, Menu > Stats or Settings > System shows the Stats panel at the top left, beside the brush bar. Simple, the default, says how smoothly the app runs in plain words, in four groups: Performance (frame rate; frame time and interface update time, each typical and in slower moments; the GPU's 3D time when measured), While sculpting (brush work per frame and input to the GPU, once a stroke has run), Mesh (objects, vertices, triangles, triangles drawn last frame) and Memory (the undo history's size; the memory of the whole app is not measured, so it is not shown), then Last operation (what the last remesh, smooth, file action and so on did, and how long it took). Typical is the median (p50) of the last 240 frames: half took less and half more. Slower moments is the 99th percentile (p99): 99 frames in 100 took that long or less; it is not the slowest frame. Interface update is only the time to lay out and draw the panels, one part of a frame. With VSync on, the frame time includes waiting for the screen, so it sits near the refresh time even when the app has time to spare. "What do these numbers mean?" at the bottom says the same. Advanced shows every measurement by its exact name (`frame_ms`, `cpu_ms`, `ui_ms`, `cursor_ms` for laying the brush ring on the surface, ...) with its p50 and p99, the frame-time graph, the drawing switches and what the brush costs; a measurement with no samples yet says so instead of showing 0.

## Screenshots

Menu > Save screenshot (F12) writes the viewport, as the last frame drew it and without the brush outline or gizmo, to a PNG file at the viewport's size. ## Pen and brush pie

The Brush palette's Pen section holds what a drawing tablet changes. "Pressure changes strength" and "Pressure changes size" choose what pen pressure scales; a mouse counts as full pressure. The pressure curve below them maps how hard the pen presses (along) to how much that counts as (up): a cubic Bézier from corner to corner whose two handles drag anywhere in the square, so it never falls back. Linear, Soft (light pressure goes far), Firm (it takes a press) and S are presets. A dot on the curve follows the pen. The Tilt slider (0 by default) lets a leaning pen turn the brush: the direction Draw, Clay, Flatten, Pinch and Crease push in leans toward the pen's top, by the pen's lean times the slider, at most 81 degrees, as Blender's tilt does; mirrored dabs lean the mirrored way. With tilt on, a line from the brush circle shows the lean. The readout under it shows the last pressure, what it counts as, and the lean. Tilt costs one small rotation a dab: a 2M stroke took the same brush time with it and without (1.27 to 1.33 ms p50 either way, run to run). SDL reports pen pressure and tilt on Windows (pointer messages) and on Linux (X11 and Wayland); neither is tested on a real tablet yet.

The brush pie puts every brush in a ring around the pointer, in key order clockwise from the top. Hold Space over the viewport, point toward a brush and let go to pick it, so a flick picks without aiming. A tap of Space, or a right click without dragging (a pen's side button sends one), leaves it open: click a brush, or click the middle, press Escape or tap again to close it. While it is open, nothing reaches the tools or the camera, and no press reaches a panel under it. The slice of the brush in use has a band along its outer edge.

## Pies

Four pies of your own, eight commands each, open the same way around the pointer, as Blender's Q Quick Favourites and ZBrush for iPad's quick menu do. Q opens Pie 1 and Shift+Q Pie 2 over the viewport (in the window's middle when the pointer is elsewhere, kept whole on screen); Pies 3 and 4 have no key until given one (Assign key). All four are in the command palette ("Pie 3"), which is how a tablet without a keyboard reaches them. Tap or click a slice to run its command; tap the middle, press Escape, right-click or press the pie's key again to close it, and another pie's key switches to that pie. Each slice shows the command's icon and name and a band when it is on (Wireframe, Orthographic); it is dimmed, and does nothing, when the command cannot run now, and an empty slot reads Empty; a tap on either keeps the pie open. While a pie is open no press reaches a panel under it, and the tap that opened it from the palette picks nothing from it. A fresh install has Pie 1 for the view and the object (Focus selected, Frame all, Wireframe, Flat shading, Orthographic, Studio render, Remesh, Search) and Pie 2 for the mask and hiding (Clear, Invert, Blur, Sharpen, Grow and Shrink the mask, Show all, Invert hidden); Pies 3 and 4 start empty.

The command palette's Put in a pie opens the pie editor for the picked command: four rows of eight slots, where a tap puts the command in a slot (replacing what was there), a long press or a right click empties a slot, and Reset pies puts the defaults back. Settings > Interface > Edit pies opens it to empty slots and reset only. A pie that differs from its defaults is remembered whole (`pie <pie 0-3> <slot 0-7> <command|empty>` lines, saved at once). Presets cannot go in a pie yet, and the user pies have no hold-and-flick: that is Space's brush pie.

## Brush falloff

The Brush palette's Falloff section shows how strongly the brush in use works from its centre (left) to its rim (right). By default it is the built-in smooth falloff, (1 − d²)² for the distance d in radii. Dragging either handle draws your own: a cubic curve read from the rim in, as the pressure curve is drawn, so it is always 0 at the rim and full at the centre. Presets: Smooth (the built-in), Linear (a cone), Sharp (a point in the middle, for creases and pores), Firm (most of the radius at full strength) and Flat (full strength to the rim, a hard-edged stamp). Each brush keeps its own falloff, Grab and Mask included; an alpha replaces it. Under the curve, Focal shift (-100 to 100, 0 by default, each brush its own, also on the brush bar and three fingers sideways) reshapes whichever falloff the brush has without changing its ends: the weight at d radii is the falloff's at d^p with p = 2^(−shift/50), so 100 pulls the brush to a point and −100 spreads it into a flat top with a hard edge. While it is not 0 the brush ring shows an inner ring where the brush works at half strength. A shifted falloff is a table too, so it costs what a drawn one does. The sculptor reads a drawn falloff from a 257-entry table over the squared distance, so it costs no square root: a 2M stroke's brush time was 7 to 12% higher with one than with the built-in (0.24 vs 0.25 to 0.27 ms p50, release, test VM). Script: `falloff sharp` (or another preset's name) gives every brush that preset, keeping their focal shifts, and `focal 40` gives every brush that focal shift.

## Brush alphas

An alpha, as in ZBrush (Blender calls it a brush texture), is a square grey image that shapes each dab in place of the round falloff: white moves fully, black not at all. The Brush palette's Alpha section shows the round brush and every alpha as thumbnails; tap one to use it. Six are built in: Square (flat stamps and edges), Noise (bumps of every size, for skin, stone and bark), Rings, Stripes (ridges along the image's up, so along a stroke they rake parallel grooves), Dots (rivets, scales) and Star. "Load image..." adds a PNG, JPEG, BMP, TGA or QOI file: its brightness times its opacity, padded to a square and averaged down to at most 512 pixels a side, so a grey height map and a white shape on a transparent ground both work. Every brush but Grab uses the alpha; Shift's smoothing stays round. Load image also keeps a copy of the file in the library, a folder `library/mine/alphas` beside the settings file (`<name>-library` for `--settings-file=<name>.txt`, and none for a run that keeps no settings), so the image is back after the built-ins at the next start, and so is every preset that uses it, and the brush's own alpha. The same image loaded again is found there by its bytes and not kept twice; another image of a name already there is kept as `rock-2` and on, and the file's name is made safe for every system (letters, digits, spaces, `-`, `_`, brackets). Presets, the settings file and scripts name a kept alpha `mine/<name>` (`alpha mine/rock`) and a built-in by its name; an image a script loads by its path is not kept. With a kept alpha selected, Remove from library (tap it twice) deletes its file, and the brush and every preset that used it go back to round, with a note counting those presets. A file in the library that is not an image the app reads is skipped at start, with a note naming it, and left on disk. The exit stats add `library_alphas` (kept alphas), `library_skipped` and `alpha` (the brush's alpha by reference, or `-` for round).

### Content packs

A content pack is a `.sculptpack` file: a ZIP archive, so any zip tool makes one, holding `pack.txt` and brush alphas under `alphas/` (PNG, JPEG, BMP, TGA or QOI images, right in that folder). `pack.txt` has one `key value` line each for `name` (needed), `author`, `version`, `description` and `license`; lines starting with `#` and other keys are skipped, and values are cut to 200 characters. Menu > Library (or Search) opens the Library panel in the tray's place: Install pack at its top, then Your own (the alphas Load image kept) and every pack installed, with its author, version, licence, alpha count and description, and a bin to remove it (tap it twice). Install pack picks the file with the system's file dialog (on Android every file is offered, since the picker cannot filter by `.sculptpack`, and the archive's own bytes decide) and installs it on a thread of its own, so a big pack never holds up a frame. Before anything is written the archive is checked: at most 4096 entries and 512 MB unpacked, sizes read from its directory and every entry inflated no further than it says (a zip bomb is refused), no encryption or ZIP64, names that cannot climb out of the folder or mean something else on another system (no `..`, absolute paths, drives, backslashes or Windows device names, and no two that differ only in case), every entry's checksum, a `pack.txt` with a name, and every alpha an image the app reads; one failure refuses the pack, with a note saying why. Anything else in the archive (meshes, brush presets, scripts) is left out, with a note counting it: a pack is data only and never brings code. The pack is unpacked into the library's `.incoming` folder and renamed into place as `library/<id>` (its name in lower case, letters and digits with dashes, numbered when another pack has it), so an install cut short leaves nothing half there. Its alphas join the Alpha section under the pack's name and are named `<id>/<name>` in presets, the settings and scripts (`alpha rock-set/pebble`). Installing a pack of the same name and author as one installed asks first, in the Library panel: Replace moves the old folder aside, renames the new one in, then deletes the old, and the alphas still there keep their names, so presets that use them keep working; presets on an alpha the new version dropped go round, with a note counting them. Removing a pack deletes its folder and sends the brush and presets that used its alphas back to round. Packs only add: they cannot change the built-in alphas. The script verb `install_pack PATH` installs a pack in place (replacing one of the same name and author), and the `library` command opens the panel. The exit stats add `packs`, `pack_alphas`, `packs_installed` and `packs_refused`.

The image lies on the plane across the area under the brush, its middle on the dab's centre and its sides one radius away, so a stamp sits flat on a curved surface. A vertex takes the image's value where it falls, blended between pixels, and fades as it lies further above or below that plane. Which way the image's top faces is the mode: Follow stroke turns it with the stroke, Fixed keeps it to the screen's up, and Random turns every dab a new way, for texture without a visible repeat (the turns come from the stroke's seed, as Spray's do, so a replayed stroke turns each dab the same way); Angle turns it further. The brush outline becomes the image's square, turned as the next dab will be, with a tick at its top. Symmetry mirrors the image too, so a stamp on the left reads backwards on the right as a mirror would show it.

A dab looks for vertices as far out as the image is above 0, measured when it loads: up to the square's corners, 1.41 radii, but no further than the round brush for images that fade out inside their circle, like the built-in ones but Square. With the Noise alpha a dab costs about a fifth more than Draw and a frame under a tenth more (`build/bench --brushes`, the large brush; Draw measured 0.037 and 0.312 ms a dab and 0.27 and 1.91 ms a frame at 1M and 10M in the same run, beside the alpha row in the table above), the extra being three dot products and one image lookup a vertex.

## Viewport materials, flat shading and wireframe

The Scene palette's Material section picks how objects are shaded. The classic presets are Clay (the default, as before), Red wax, White, Grey and Skin: each sets the selected object's colour, a muted one for the others, and the light's ambient, highlight and wrap (wax and skin let the light reach past the shadow line, as scattering does). Below them are physically based materials: Gold, Copper, Chrome and Steel (metals, coloured by measured reflectance), Plastic, Ceramic, Rubber and PBR clay. These use metallic and roughness with GGX highlights from the key and fill lights plus the reflection of a procedural studio that roughness blurs: a cool sky over a dark floor, a warm softbox above and beside the key light, a cool strip light behind on the right that catches edges, and a bounce card behind the camera so faces turned to the viewer reflect something. Where the normal varies within a pixel, as on a dense sculpt seen from afar, highlights widen instead of sparkling (specular anti-aliasing, as Filament does it). It is all computed in the fragment shader, so they take no memory and cost the same at any vertex count. The colour, Metallic and Roughness sliders under it edit whichever material is in use into Custom, leaving the presets as they are. Every material, classic or physically based, goes through the same display path: the lit colour is scaled by **Exposure** (in stops, -3 to 3, under More options; 0 by default), tone mapped with Khronos PBR Neutral (colours below about 0.8 pass through nearly unchanged, brighter ones roll off toward white instead of clipping) and encoded with the exact sRGB curve, which keeps the darkest values dark where a plain 2.2 power used to grey crevices out; polypaint is decoded with the same curve. **Cavity** (0.5 by default) darkens creases and **Ridge** (0.3, under More options) lightens crests, as ZBrush's materials and Blender's cavity shading do, so fine sculpted detail reads at any light angle: the shader measures how far the normal turns across each pixel, so it needs no extra pass, vertex data or memory, works with partial redraw and the idle cache, and picks out grooves and pores while leaving broad forms alone (a crest's lightening fades toward the silhouette). Because it is measured per pixel, a form drawn small (zoomed out) shows more of it than the same form close up. Flat shading turns both off. Script: `set cavity 0.6`, `set ridge 0`, `set exposure -0.5`; all three are remembered.

View > Flat shading, or Shift+G, lights each triangle with its own normal, so the facets show instead of the smoothed normals; the shader takes the triangle's normal from screen-space derivatives of the position, so it needs no extra vertex data and works with every material. While the view moves, far parts drawn from simplified copies show those copies' larger facets. View > Wireframe, or Shift+F as ZBrush's PolyFrame, draws the selected object's triangle edges over it: the same visible chunks again with line fill, pulled toward the eye by a depth bias so they sit on the surface, so it roughly doubles the selected object's draw cost while it is on. Script: `set material steel`, `flat_shading on`, `wireframe on`.

## Brush presets

A preset is a named brush, as in Nomad or Blender: a base brush with its own strength, falloff and focal shift, alpha (with its mode and angle), stroke kind, lazy mouse, Lock plane and Connected only, paint colour and cloth mode. Size, the pen settings, symmetry and front faces only stay the same for every brush, so changing brush never changes how big it is. The Brush palette's first section, Preset, names the one the brush is on even while folded ("Preset: Soft clay · changed"). On a plain brush it offers Save as preset (named "Clay 1", "Clay 2", ...), which keeps the brush as it is and puts it on the new preset, and Reset brush, which puts the plain brush's strength, falloff and focal shift back to a fresh install's. Its list picks any preset, or None for the plain brush. On a preset: its name, to type a new one (Enter or a tap elsewhere renames it; an empty name, another preset's or a brush's own is refused), Save changes and Revert (while it differs from what was saved), Save as new preset (a copy), and under More options Delete preset. The brush's own slots hold the preset's values while it is on one, and leaving it (picking a brush by its key, the dock, the pie or the list) gives the plain brush its own back, so a preset never changes a plain brush and what is remembered for it. The palette finds Save brush as preset, Save preset changes, Revert preset, Delete preset and Reset brush. The brush browser lists the presets under the brushes, each tile the base brush's icon over the preset's name (a long one is cut, and shown whole in its tooltip): a tap picks one, a long press (or right-click) shows its settings with the Preset section open. Each of the dock's 21 slots (three pages of seven) holds a brush or a preset, and a long press (or right-click) on one opens its menu above it: Brush settings (Preset settings on a preset), every brush and preset to put in the slot instead (a tap puts it there), and Reset dock, which gives back a fresh install's three pages. The same brush or preset may sit in two slots, and a deleted preset's slots go back to its brush. Up to 24 presets; they and the dock are remembered with the settings, and an alpha is remembered by name, so a loaded image's comes back only when that image is loaded again (the built-in ones always do).

## Remembered settings

An interactive run remembers, for the next one, the brush (which one, its size, each brush's strength, falloff curve and focal shift, the last as `focal <brush> <shift>` lines for the brushes where it is not 0), the pen settings (pressure, its curve, tilt), lazy mouse, the stroke, front faces only, Lock plane, Connected only, symmetry, the dynamic topology detail, the alpha (by reference, a `brush_alpha` line), its mode and angle, the material (with the Custom one), flat shading, wireframe and orthographic view, the Scene palette's shape and size for new objects, the mask steps and mask shape, and the command palette's recent rows, and the brush presets with the one the brush was on (`preset` and `brush_preset` lines, names escaped as %20), and the dock's slots (`dock <slot> brush <brush>` or `dock <slot> preset <name>`), and the keys given to commands (`key` lines; see Controls), the pies that were changed and the starred commands (`pie` and `favourite` lines; see Pies). So do the Settings panel's choices (the interface size, the brush ring, Show every option, how far the first-run tips got, the camera and touch settings with what the view turns about and the safe zone, the Stats panel, VSync, how often to autosave and how many earlier saves to keep; see Settings), and where each panel window was moved to and whether it is folded (`window` lines). They go to `settings.txt` in SDL's per-user folder (`%APPDATA%\Implicit\Sculpt` on Windows, `~/.local/share/Implicit/Sculpt` on Linux) when the app closes, when the Settings panel closes and when the app goes to the background, as plain `key values` lines after a `version` line; delete the file to start from the defaults. Runs with `--frames`, `--gpubench`, `--bench-stroke` or `--no-settings` neither read nor write it (`--settings-file=PATH` reads and writes PATH instead, scripted runs included), so scripted runs and benchmarks stay the same everywhere, and flags given on the command line win over it. Which sections are open is not remembered, nor are the scene, the speed toggles in the Stats panel or Smooth all's "On the GPU" switch.

## Cloth brush

The Cloth brush (no key; in the brush browser and the pie) turns the surface in and around the brush into cloth for the length of a stroke, as Blender's cloth brush does, so it folds and wrinkles instead of stretching. Its mode, in the Brush palette's Stroke section: Drag (what is under the brush follows the pointer on the plane facing the camera, as Grab, and the cloth around it is pulled along into folds), Gravity (the region sags toward the bottom of the screen while the button is held, settling at about half a radius at full strength; Ctrl lifts it), Pinch (gathers the cloth toward the brush into radial folds, easing in over the first 40 frames up to 55% of the way at full strength; Ctrl expands) and Expand (pushes it outward so it buckles into a ring ridge; Ctrl pinches). The simulation (`src/sculpt/cloth.odin`) is position-based dynamics in the object's space: a damped Verlet step with the mode's force, then five Jacobi rounds over every triangle edge of the region that keep the edges at their lengths, puff squeezed cloth out along its starting normals so it folds outward together, and even out each vertex's displacement with its neighbours' (bending), so folds stay smooth on dense meshes. The region's outer 30% is increasingly held where it was, and masked or hidden vertices are held completely, so the cloth stays sewn to the rest of the mesh. It runs every frame while the button is down, even with the pointer still; the stroke is one undo step. Symmetry is not applied, and it does not run with dynamic topology on. Cost on the test VM (4 threads, release): on a 1M-vertex sphere about 2.3 ms a frame with a 60 px brush; at 10M (about 170k simulated vertices) about 18 ms a frame and 50-150 ms to set up at the start of a stroke, so it is a slower brush than the others, which it leaves untouched. Script: `brush cloth`, `set cloth_mode gravity` (or `drag`, `pinch`, `expand`).

## Studio render

View > Studio render (Shift+R, as ZBrush's BPR) builds the viewport up into ambient occlusion and a soft key-light shadow while the view stays still, like a path-traced preview: crevices and creases deepen, and raised forms cast soft shadows onto what is behind them and onto other objects. Each still frame adds one light sample (`src/render/studio.odin`): it renders every object's depth from a direction into a 2048² shadow map, then for every viewport pixel reconstructs the surface point and normal from the viewport's depth and adds whether that light reaches it (3x3 filtered) to a half-float accumulation image. Three samples in four come from directions spread evenly all round the scene (an R2 sequence), weighted by how directly they face the surface, which gives the occlusion; one in four comes from around the shading's key light, jittered over a small disc, which gives its soft shadow. The image shown is the viewport darkened by both, by the Occlusion and Shadow strengths in the Scene palette's Studio render section; it settles within the Samples count (256 by default, at most 1024), after which it costs nothing. That section shows the count while it builds. Any change to the viewport, a stroke, the camera, a resize, starts it over; until the view is still again the plain viewport is copied through, so with it on a stroke costs one screen-sized copy a frame (10M stroke on the test VM: CPU frame p50 3.8-3.9 ms off and 4.8 ms on, where the llvmpipe software GPU makes that copy on the CPU; on a real GPU it is a fraction of a millisecond). Screenshots, `--dump-viewport` and the time-lapse save what the viewport shows. It needs a depth format shaders can read; where the device has none it logs a warning and stays off. Script: `studio_render on`, `set studio_samples 64`.

## History timeline and time-lapse

The History panel (the clock button beside undo and redo) opens over the brush dock and lays every undo step on one bar, oldest at the left: a block per step, coloured by what it was (brush strokes gold, mask changes blue, hiding grey, Smooth all and Clip green, rebuilds such as remesh or add and delete orange), dimmed once undone. Press or drag anywhere on the bar to go to that point (a finger or the pen goes there on a tap, or scrubs once it moves past the slop); resting the pointer on it shows the step's brush or command, its object and how long ago it was made. The outer buttons jump to the start and the newest step, the ones beside them step one at a time, and Play replays the History forward at the Steps a second speed (from the start when it stands at the end). It moves only with undo and redo, as many as it takes, so it is exactly Ctrl+Z or Ctrl+Shift+Z pressed that many times: a stroke made after scrubbing back drops the steps ahead of it, and what the undo memory limits dropped is not on the bar. Scrubbing spends at most 25 ms a frame stepping, so a long drag stays responsive; a stroke undo takes about 2 ms at 10M vertices in a release build on the test VM, so the whole History of 40 strokes there rewinds in well under a second.

A right-click, or a long press of a finger or the pen, on a done step makes it what the History brush paints back to (to before it, on that step's object), without moving through the History, and a note names it; the step must be on the level (or HD window) its object shows, and the History must not be moving; a small mark at the foot of the bar shows where the selected object's History brush point is, and resting on that step says so. A step that is not sculpting (a move of the object, a change to the scene tree, a rebuild), or out of the brush's reach, is refused with a note.

Record time-lapse... asks for a folder, rewinds the History to the start, then redoes Steps a frame steps each frame up to where the timeline stood and saves the viewport after each as `frame_00000.png`, `frame_00001.png` and so on, at full detail; with Turn above 0 the camera also turns that many degrees around the scene each frame, as a turntable, and goes back where it was afterwards. Any video tool turns the frames into a film (`ffmpeg -framerate 12 -i frame_%05d.png sculpt.mp4`). A stroke, or Stop recording, ends it early. Flags: `--timelapse=DIR` records once `--bench-stroke` ends (or at the start), and the run lasts until it is done; `--timelapse-steps=N` and `--timelapse-spin=DEG` set Steps a frame and Turn; `--bench-lifts=N` lifts the synthetic pen N times so the stroke becomes N + 1 steps.

## Stroke recorder

The Brush palette's Stroke recorder keeps strokes to play back, as ZBrush's Record and Replay Last do. The app always keeps the last stroke as it was drawn: every frame's pointer samples, pen pressure and tilt, Shift and Ctrl (and the modifier buttons), the camera and viewport size, and the brush settings. Record starts a recording that keeps every stroke until Stop recording. Replay plays the recording, or else the last stroke, back where it was drawn, with the camera it was drawn with, whatever the view is now. R over the viewport plays it so its first stroke starts under the pointer, in the current view and size, which turns a stroke or a set of strokes into a stamp to lay anywhere, on any object (a rivet, a scale, a monogram, a spiral). With Recorded brushes off the path is replayed with the brush as set now: record a path once, then lay it with Clay, then Crease. Instant plays every recorded frame at once instead of one a frame, as drawn. Escape stops a replay, and switching to Move does too.

A replay feeds the recorded frames through the same code a drawn stroke goes through (`src/app/replay.odin`, `sculpt_frame`), so lazy mouse, symmetry, Drag rectangle, Spray, Roll, Grab, Snake hook and Cloth replay as they were drawn, each replayed stroke is one undo step and shows on the History timeline, and a replay where it was drawn on the same mesh gives the same vertices, bit for bit, as the original strokes (checked frame by frame and Instant on a 200k sphere: three strokes recorded with `--record-strokes`, saved, then replayed on a new sphere, export files identical). Instant brings normals up to date between recorded frames (`sculpt.sculptor_refresh_normals`), as frame-by-frame drawing does. While a replay runs the pointer does not sculpt; the camera still moves.

Save strokes... writes the recording (or else the last stroke) to a `.strokes` file and Load strokes... reads one into the recording, to replay in another scene or share. A file keeps each stroke's brush kind, size, strength, falloff and focal shift, pressure settings and curve, lazy mouse, Front faces only, stroke mode, Spray's spread and the stroke's seed, Line and Join strokes, Lock plane and Connected only, symmetry, paint colour and cloth mode; the alpha, pen tilt strength and dynamic topology detail come from the brush as set when it is loaded, since an alpha names an image file that may not be there. Every number in a file is checked (finite, in range) before it reaches a brush, and a damaged file is refused. A frame costs 60 bytes plus 21 a pointer sample in the file and a little more in memory. Version 3 files keep whether a frame's stroke painted the mask through the Mask modifier button, and version 4 files each stroke's Spray spread and seed, so a Spray replays as drawn, version 5 files its Line and Join strokes switches, version 6 files its Lock plane and Connected only switches, and version 7 files its focal shift; versions 1 to 6 still load (strokes from before version 4 take the spread as set and seed 0, those from before 5 and 6 have the switches they lack off, and those from before 7 no focal shift). Flags: `--record-strokes`, `--save-strokes=PATH`, `--load-strokes=PATH`, `--replay-shift=DX,DY`, `--instant-replay`.

## Controls

Every shortcut, menu row, brush key and tray action button runs a command from one table (`src/app/commands.odin`: name, help, icon, whether it can run now, whether it is on), so the shortcut a menu or tooltip shows is always the one that works. A shortcut's modifiers must match exactly: Ctrl+Z undoes and Ctrl+Shift+Z redoes, and a key held with a modifier it does not list does nothing (Ctrl+B, Shift+1 or Ctrl+F are not shortcuts). Each key press keeps the modifiers held when it went down, so two quick shortcuts in one slow frame both work.

Any command's key can be changed where it is: Ctrl+Alt+click a panel control that runs it (a button, a menu row, a switch, a tab, a tool, a brush tile, a row of the command palette) and, instead of running, it opens Assign key beside the control, as ZBrush's Ctrl+Alt+click and Blender's Assign Shortcut do. The command palette has an Assign key button for the picked row too, which reaches commands that cannot run now (a greyed control takes no click) and works by touch with a keyboard attached. The popover names the command and its keys now, then takes the next key pressed, with Ctrl, Shift or Alt if wanted, as the command's only key: Redo's two keys give way to the one chosen. A key another command has is a question there and then: Use it here moves it (that command keeps any other key, else has none, and the popover says so) and Keep it there leaves it. Space, Escape, Enter, Backspace, Android's Back and the lock keys are refused with the reason, and so are bare S and U (held over the model they size the brush and set its strength) and a key pressed with Cmd or the Windows key. Remove key leaves the command with none; Reset gives it its default keys back. Changes are saved at once (`key <command> <chord|none>` lines in settings.txt); every menu, tooltip, Help > Keys and the palette show the keys as they are. A key given this way runs after the default keys in a frame where several went down. Presets have no keys yet, and a Ctrl+Alt+click on a preset tile picks it as a plain click does.

Files: Ctrl+O opens a scene, Ctrl+S saves it (where it was last saved or opened, else it asks), Ctrl+Shift+S saves it somewhere else. F12 saves a screenshot.

Tools (also on the toolbar): W picks Move (W again steps its gizmo through Move, Turn and Scale), B Sculpt (the brushes), C Curve and I Insert. Ctrl+K or `/` opens the command palette (see Command palette). Q opens Pie 1 and Shift+Q Pie 2 (see Pies). Tab shows or hides the palette tray, F11 the Stats panel, F1 opens Help (every shortcut, the mouse and touch controls, and a glossary), and Escape (or Android's back gesture) closes whatever menu is open. F points the camera at the selected object; Shift+F shows its wireframe; Shift+G switches flat shading; Shift+W shows polygroups, Ctrl+W groups the masked part (or what is shown). Delete deletes it (Ctrl+Z brings it back). Ctrl+D subdivides the selected object; D and Shift+D go up and down its levels; Ctrl+Shift+D duplicates it; Ctrl+C copies it and Ctrl+V pastes the copy below the selected object (see the Objects card). Ctrl+R remeshes it at its own vertex count. Ctrl+T turns dynamic topology on or off for it. A opens an HD window where the pointer is on an object with an HD level, or closes the open one.

Move: click or tap an object to select it (a click on empty space clears it, a drag there turns the view), and drag it to move it in the view plane, whatever the gizmo shows. The gizmo has three modes, picked by W again while the Move tool is on (Move, Turn, Scale, Move...), by the action bar's chips or by the Move tab of the inspector, and remembered (`gizmo_mode`, and the Snap latch as `gizmo_snap`):
- Move: drag an arm (red X, green Y, blue Z) to move along that axis, a square between two arms to move in their plane (it takes the colour of the axis it holds still), or the middle square to move in the view plane.
- Turn: drag a ring to turn about that axis (the world's, through the object's origin; the far half of each ring is dimmed), or the white outer ring to turn about the view's axis. A ring seen nearly edge on turns by how far the drag runs along it on screen.
- Scale: drag the middle disc or the circle round it: an arm's length further out scales by e (about 2.7), as far in by its inverse; the scale stays between 0.01 and 100.
While a drag goes, a label by the pointer says what it has done ("X +0.250", "Turn Z +45.0°", "Scale ×1.30"). Ctrl held through a drag snaps it (pressed after the press for a drag on the object's body, since Ctrl at the press starts a topological mask instead, see Posing below), and the Snap latch snaps every drag: moves to whole steps of a grid that follows the zoom (a power of ten about half an arm long on screen), turns to 15°, scales to steps of 0.1; the label names the step. Esc puts the object back mid-drag, and so does a second finger landing (a gesture). Each drag is one undo step. A tap or click on an arm, a ring or the scale disc that moves nothing opens a field over it for the value (with the on-screen keyboard on a tablet): for an arm a number sets the position along it and `+0.5` adds to it, for a ring the number is the turn in degrees, for the scale a number sets it, `+0.5` adds and `*2` (or `x2`) multiplies. Enter or Apply places it as one undo step; Esc, Cancel or a press outside closes it, and text that is no number is refused and says so. Set pivot (the action bar's Pivot chip, the Move tab or the palette), then a tap or click on any surface, puts the gizmo there, so turns and scales go about that point; the selection stays and the latch lets go. The pivot rides with the object as it moves, turns and scales, a dot marks the object's origin meanwhile, and Reset pivot puts the gizmo back on the origin; it belongs to that object only and is not saved. Handles are picked within 8 pixels with the mouse or pen and within half a touch target (24 points) with a finger, wherever they are, on the model or off it; a finger or the pen starts moving only past the slop, so a tap on a handle moves nothing. The Object palette's Transform sets position, turn and scale exactly: drag sideways on a value, or Reset transform (under More options, and in the command palette) to put the object back at the middle, unturned, at scale 1. The exit stats give `gizmo_pivot` (where the pivot is, or none), `gizmo_pivot_latch`, `gizmo_entry` (the handle whose value is open, or none), `gizmo_at`, `gizmo_mode`, `gizmo_hover`, `gizmo_last` (the handle of the last drag that changed something), `gizmo_drags`, `gizmo_snap`, `transform` (the selected object's position, turns and scale) and `transform_undo` (transform steps that can be undone); `scripts/touch_check.py 'gizmo_*'` runs the ring, finger scale, finger-sized handle, plane square, snap, chip, typed value, pivot and cancel scenarios.

Posing: with one object selected and a mask on it that leaves something shown free, the gizmo's handles pose the object's unmasked part instead of moving the object, as ZBrush's gizmo does with a mask (a drag on the object's body still moves all of it). Each vertex takes the move, turn or scale by how free it is: a half-masked vertex moves half as far, scales by half the change, and turns through half the angle at its own distance from the pivot, so the mask's soft edge bends like a joint instead of pinching. The gizmo goes to the middle of the mask's soft edge (its partly masked vertices; with a hard edge, the free vertices touching a masked one; else the free part's middle) whenever pose mode finds a mask it has not placed it for, and Set pivot still puts it anywhere until the mask changes again; a move carries the gizmo along with the part. The action bar's Gizmo group reads Pose meanwhile, the label by the pointer starts "Pose:", and each drag is one undo step ("Pose: Turn" and so on), Esc or a second finger putting the mesh back. A typed value poses too: an offset along the arm, degrees, or a scale factor (`+0.5` adds half). Hidden parts stay still. Posing is refused, with a note, in an HD window and with dynamic topology on. The exit stats give `pose_mode`, `pose_drags` (drags and values that posed) and `pose_moved` (vertices the last pose could move), and `mesh_sum` (the selected object's coordinates added up, so a scenario can tell a mesh put back exactly).

Topological mask: with the Move tool, Ctrl + a press on an object (or a finger or pen press with the rail's Mask on) selects it, and a drag from there masks it along the surface, as ZBrush's topology masking of its gizmo does: free within three quarters of the reach of the press, a smooth band to the reach, masked beyond it, the reach being the drag's length on screen at the press's depth (a circle and "Mask reach" show it). Ctrl+Alt (or Mask with Invert) makes the opposite: masked near the press, free far away. Distance is measured along the triangles' edges (Dijkstra's search from the pressed triangle's corners), so a part the other side of a thin gap stays masked however near it is in space; shapes follow the mesh's edges a little. The search settles at most 50,000 vertices a frame (about 20 ms on the test VM, release build, 655k-vertex sphere; 650k settled in 0.17 s over 9 frames) and carries on after the release until it has reached the reach set last, so a reach across a dense mesh never stalls a frame; starting one on an object with no mask costs what Mask all does (about 40 ms there), since everything far is masked at once; each gesture is one mask undo step, Esc or a second finger puts the mask back, and a tap only selects. Hidden parts keep their mask (the search crosses them). The gizmo then goes to the new mask's soft edge, so the part pressed poses at once. It works with dynamic topology on. The exit stats give `topo_masks` (gestures that masked) and `topo_reach` (the last one's reach in the object's own units).

Brush: left drag sculpts the object under the cursor, which becomes selected (Shift smooths, Ctrl inverts; the Mask brush then erases). The brush is the one the press chose for the whole stroke: Shift, the rail's Smooth or Mask, or a brush key pressed mid-stroke leave it as it began. Shift (or the rail's Smooth) pressed mid-stroke instead lays the stroke again as a straight line from where it began to the pointer, as 3DCoat's Shift line and ZBrush's Lazy Mouse line do: what the stroke did is put back from the undo copies it keeps (`sculptor_stroke_restore`) and laid again whenever the pointer moves, so it stays one undo step; a line longer than a frame's dabs (64) is laid over the next frames and finished at the release; letting Shift go lays the line to where the pointer last was with it held, then carries on freehand from there, so where a line ends depends only on the pointer's path, never on how fast the frames were, and a replay lays it the same. A straight line ignores the lazy mouse; a viewport resized mid-line leaves it as it was laid. Not with dynamic topology, whose strokes cannot be put back, nor Grab, Snake hook, Cloth or Rectangle strokes. A take recorded before this with Shift pressed mid-stroke replays as such a line; a left drag that starts on empty space turns the view instead, as in ZBrush, and keeps turning it when it crosses the model (Settings > Touch makes the mouse wait for the model instead). Keys 1 to 9 and 0 pick the first ten brushes, X toggles X symmetry, Alt+M clears the mask and Ctrl+I inverts it. Ctrl + drag from empty space masks a rectangle or lasso (Ctrl+Alt unmasks). Ctrl+Shift + drag runs the chosen gesture tool: hides by rectangle (the default) or lasso (Alt hides the inside), clips along a line (Alt: the other side) or slices along a line; a Ctrl+Shift click shows everything. Ctrl+H shows everything, Ctrl+Shift+H inverts what is hidden. The brush follows every mouse or pen sample, not just where the pointer is once a frame: dabs go along the path the pointer took on screen, a quarter of the radius apart, each where that point meets the surface. Pen pressure scales the strength, and the size too with "Pressure changes size" in the Brush palette's Pen section, through the pressure curve there; a mouse counts as full pressure. Space (hold and let go, or tap) or a right click without dragging opens the brush pie (see Pen and brush pie above). S over the viewport sizes the brush where it is (move away from or toward the circle's middle, then click or press S again; a right click or Escape puts the old size back), and U does the same for the strength; [ and ] step the size, Shift+[ and Shift+] the strength. Each brush keeps its own strength, and Shift-smoothing uses the Smooth brush's. The brush ring turns blue while a press would smooth, red while it would invert and violet while it would paint the mask, from the keys held or the modifier buttons. Lazy mouse (Stroke > More) makes the brush trail the cursor on a string that many pixels long, for steadier lines. Line (Stroke > More, `stroke_line` in settings.txt) makes every stroke a straight line from its press, redone as the pointer moves, for a pen or finger with no Shift; the Stroke section says so while it is on. Join strokes (Stroke > More, `stroke_join`) carries a stroke on from where the last one ended when it is pressed within 24 pixels of that end, on the same object with the view unchanged: the dab spacing and direction go on as if the pointer had never let go, so a line drawn in pieces has no blob or gap at the joins (each piece is still its own undo step). Replays and recordings start without a stroke to join, and undo, redo or opening a scene forgets the last stroke's end, so a press then starts its own stroke; replaying the last stroke when it joined another lays it unjoined. The exit stats count both as `stroke_lines` and `stroke_joins`. Over the model the brush ring lies on the surface, as in ZBrush: a circle of the brush's size in the plane the surface faces under it (the vertex normals the brush would reach, weighted as a dab weighs them, so it shows the way the brush pushes), seen in perspective, with a short tick out along that normal from its middle; off the model it is a flat circle on the screen (Settings > Interface turns this off). With an alpha (see Brush alphas above) the outline is the alpha's square. R over the viewport replays the recorded strokes (or else the last stroke) starting under the pointer, and Escape stops a replay (see Stroke recorder above).

**The Objects card** (the view bar's Objects button, under the navigation head) is the quick way to the objects, laid out as ZBrush for iPad's Subtools card; the Scene palette's Objects section stays as the other place to reach them, as ZBrush keeps Tool > Subtool. It opens beside the view bar in the palette tray's place: opening the tray (or Settings, Help or Macros) closes it, and the Objects button closes the tray. Its row of dots on top drags it anywhere (remembered with the other panels); holding the dots puts it back in the tray, which opens on the Scene palette's Objects. Under the title are Add (a menu: Insert puts the picked shape below the selected object, in its folder; Append at the end of the list; then Import mesh), Duplicate, New folder and More (Rename, All low and All high, which show every object at its lowest or highest subdivision level, Copy, Paste, Duplicate, Delete, Delete other and Delete all). Each object has a tall row: a picture of it, its name with its boolean switch under it (on makes it a Subtract in booleans; the row's menu picks Add, Subtract or Intersect), and at the right its polypaint toggle and its eye. A folder's row shows a folder with how many objects are in it, its name, a chevron that folds it and its eye. The pictures are drawn from the front, turned as the object is, in a light clay with its polypaint; one is drawn again once its object has stayed unchanged for 0.4 s, never during a stroke or while the view moves and at most one a frame, so sculpting costs nothing until the stroke ends and then one draw of the object (a full draw of a 10M-vertex object, about 20M triangles, once). A tap on a row selects it (Shift or Ctrl + tap, or Select several, adds it); a long press (or right-click) opens its menu: on the selected object Rename, Copy, Paste, Duplicate, Bring to top, Send to bottom, New folder, Make a ghost, Boolean process (Off, Union, Subtract, Intersect), Delete and Delete other; on another object only Boolean process, which leaves the selection alone. A folder's long press opens the folder menu, which also shows or hides the polypaint of every object in it. To move a row, hold it until its menu opens and then drag it (the menu closes): a line shows where it goes, as in the Scene palette, and near the list's ends it scrolls along; a quick swipe scrolls the list instead. With a mouse a row drags at once. The eye works as in the Scene palette (dragging down the eyes sets each row's), and the polypaint toggle leaves the object's colours out of the drawing without losing them (saved with the scene from scene file version 11, which older versions of the app do not open). The bar under the list sets how tall the list is, for this run. Copy keeps the object as the scene file stores it (for a 10M-vertex object about 370 MB, which the log notes), so Paste (one undo step) works after the object is deleted or in another scene; Bring to top and Send to bottom move it to the ends of its folder, or of the list, as one undo step each; Delete other and Delete all are one undo step that brings every object back, and are refused with a note when the copies undo keeps would pass its 1.5 GB limit. All low and All high are not undo steps, as choosing a level is not. Scripts: `copy_object`, `paste_object`, `object_to_top`, `object_to_bottom`, `delete_other_objects`, `delete_all_objects`, `all_lowest_level`, `all_highest_level`.

**The Objects card's Actions** unfold under its list (folded at first, as ZBrush's card has them) and scroll in the room the list leaves. First is Store visibility, V1 to V8: each keeps which objects and folders are shown. Choosing one keeps the eyes as they are in the one chosen before and brings back its own; one never chosen takes the eyes as they are, so nothing changes until an eye is turned. The selected object always stays in view. They are not undo steps, as eyes are not, and are saved with the scene from scene file version 12, which older versions of the app do not open. Then come these sections, each folded until tapped:
- **Split** makes part of the selected object an object of its own, as one undo step. Split hidden takes its hidden part, Split masked its masked part (each triangle masked at least half at every corner), Groups split each polygroup, and Split to parts each connected piece; each is greyed out while there is nothing of its kind. The object keeps the first part (what is shown, what is unmasked, the first group or piece), and each other part becomes an object below it, in its folder, where it was. As with Slice, the levels, HD detail, mask, hidden parts and strokes go; the polypaint, the polygroups and the shown level's sculpt layers stay. More than 64 parts is refused with a note. Under dynamic topology it is greyed out.
- **Merge**: Merge down makes the selected object and the one below it in the list one object, in the selected one's place, and Merge visible adds one new object made of every shown object at the end of the list, leaving them as they are; the folder menu's Merge folder does the same for a folder's shown objects. Each object merged in keeps polygroups of its own, numbered on from the ones before, so Groups split takes a merge apart again; polypaint comes too. Merge down drops the selected object's levels and sculpt layers and is one undo step with the delete of the object below; Merge visible is refused with a note when the new object would pass the subdivide memory limit, or when the objects have more polygroups between them than one object can keep.
- **Transpose** says how the Move tool's gizmo moves, turns and scales several selected objects together (ZBrush's Transpose Master), and how a mask poses part of one.
- **Boolean**, **Project** and **Extract** are the Object palette's Booleans, Project detail and Extract sections, here too.
- **Align** has a row of three tiles for each axis, X, Y and Z: the low sides, the middles or the high sides line up. With several objects selected they line up with the first selected; with one, it lines up with the bounds of every shown object, as ZBrush aligns a subtool. Only the position along that axis changes.
- **Distribute** spaces objects evenly along an axis by their low sides, middles or high sides: the selected ones when three or more are, or else every shown object. The outermost two stay where they are. Align and Distribute are one undo step each.

Scripts: `visibility_slot v1` to `v8`, `split_object hidden|masked|groups|parts`, `merge_down`, `merge_visible`, `align_objects x_min` (or `x_centre`, `x_max`, then `y_` and `z_`) and `distribute_objects` likewise.

Scene palette, the objects: each row shows the object's name, size and levels ("base" on the object a boolean applies to), a ghost and an eye. A tap on a row selects it; a right-click or long press opens its menu (Focus, Duplicate, Rename, Solo, Make a ghost, Hide object, New folder, Move to a folder, Take out of folder, Delete). **Folders** gather objects one level deep, as ZBrush's SubTool folders: New folder (Ctrl+G) puts the selected object in one; its row's chevron folds it, its eye and ghost apply to everything in it, a tap selects its first object, and its menu renames it, ungroups it (its objects stay, out of any folder) or deletes it with its objects. A folder's objects always sit together in the list, which is the scene's order (the first object no boolean marks is the base). Rename (F2, or the menus) opens a field for a new name. **Dragging** a row by its grip (the dotted handle at its left, with any pointer; a finger on it never scrolls the panel) moves it: a line shows where it will go, an outline when it would go into a folder (let go over the middle of a folder's row). Under a folder's last object the line steps in, keeping the object in that folder, when the pointer is right of the indent. A folder's grip moves it with all its objects, between the rows outside folders. Near the top or bottom of the tray the list scrolls along. **Several objects** can be selected: Shift + click (or Ctrl + click) on rows, Shift + click on objects with the Move tool, the Scene palette's **Select several** switch (then a tap adds or removes, for a finger), or a folder's Select its objects. The last one added carries the gizmo and is the one every other panel and tool works on; the rest are drawn most of the way to the selected colour. The gizmo, the Object palette's Transform values and typed gizmo values move, turn and scale all of them together about the same point, keeping their spacing (a scale stops where any of them reaches its limit); Reset transform puts each back at the middle by itself; Duplicate copies each, keeping their spacing, and Delete takes all of them; each is one undo step. A Shift + click that misses every object keeps the selection. A plain tap, adding an object or anything else that picks one object leaves that one alone selected; a press on one of the selection with the Move tool keeps the rest and drags them all. **Column drag**: a press on an eye or a ghost dragged up or down the column sets every row it crosses the way the pressed one was going (a finger first holds still on it until its tooltip shows, as a quick drag scrolls the panel), so hiding or ghosting a run of objects is one sweep. Folders, moving into and out of them, moving rows, renaming and deleting a folder are undo steps; deleting a folder is one step that brings back the folder and its objects together. The **eye** takes an object out of view and out of reach (H hides the selected one and selects the next; Alt+H, or Show all objects under the list, shows every object again); the **ghost** dims it and lets presses through it, to sculpt another object against it as a reference. **Solo** (Shift+S, or the object menu) shows only the selected object, and whichever is selected next, until Solo is off again; the eyes stay as they were. As ZBrush's SubTool list, the selected object is always one in view and reach: hiding or ghosting it selects the next, and a tap on the row of a hidden or ghosted object brings it back and selects it. These are view state, saved with the scene but not undo steps; an object out of view still takes part in booleans, retopology and Project detail (the Booleans section says so), and Frame all frames only the objects in view. Hidden triangles inside an object are the Visibility section's (Ctrl+H shows them).

Scene palette: pick a shape (Sphere, Cube, Cylinder, Cone, Torus, or one of the starters below) and a size (41k to 25M vertices) and Add it; the Object palette's Remesh rebuilds the selected object as an even mesh of about the size picked there that keeps its shape (see Voxel remesh above). Geodesic spheres come in steps of 10f² + 2 vertices; the Scene palette shows the exact count it will build. The cube and torus are even grids, so their triangles follow their edges; the cylinder and cone are voxel remeshed from a smooth outline, which gives even triangles over the caps (their counts land within about a fifth of the one asked). Every shape is closed, so it subdivides and remeshes like a sphere. Flag: `--shape=NAME` starts with that shape instead of spheres.

**Starters** are base meshes to begin a sculpt from, as ZBrush's and Nomad's are: Head, Bust, Figure (A-pose), Hand and Creature (four legs and a tail). They are made in code, so they need no files and carry no licence (`src/geom/starters.odin`): each is a few dozen ellipsoids and tapered tubes, fused into one closed surface by a voxel remesh (as fine as keeps the thinnest part, a finger or the tail, whole) and relaxed so the joins blend, then remeshed again at the size asked and relaxed a little more. Each faces the front (+Z) with +Y up and, all but the hand, is symmetric across X, so X symmetry works on it at once. Added at a size, a starter arrives with subdivision levels: as many as keep its base at 15,000 vertices or more, up to three, so a 1M Head is a 16k base with three levels above it, to step down to for big changes of form and up for detail (the Scene palette says how many levels it builds). A starter is never built under 15,000 vertices. On the test VM a 1M Head takes about 3 s from the tap to sculpting.

**New scene** (Menu > New scene, or the palette's "New scene: Head" and so on) replaces the scene with one Sphere, Head, Bust, Figure, Hand or Creature at the Scene palette's Add size, in the starting view, with an empty History and no file to save to (Save then asks where), as opening a scene does. When the scene has work to lose (any undo step, or more than one object), the first tap only arms that button, which turns red and reads Discard?, with a note; a second tap on it within 4 s goes ahead, and the menu stays open between the two. A palette row needs running twice in the same way.

Orbit, as ZBrush: a left drag on empty space or in the safe zone along the window's edges (see Touch and pen), a right drag anywhere, or Alt + left drag. The view turns about the middle of the last stroke, which stays where it is on screen while everything turns round it, as ZBrush's Local and Blender's Orbit Around Selection do, so the part being worked on stays in view; before any stroke, and after Focus, Frame all or Reset camera, it turns about the selected object's middle, and a point behind the eye is passed over. A small dot marks it while the view turns. Settings > Camera > Turn about can make a drag that starts on the model turn about the spot under it instead (Pointer, as Blender's Auto Depth), or every orbit turn about the middle of the view (Centre). Hold Shift while turning to snap to the nearest view square to the axes (front, back, sides, top or bottom, upright or at a quarter turn of roll), and a drag far enough jumps to the next. Pan: middle drag, or Alt or Shift + right drag. Zoom: mouse wheel, or Ctrl + right drag (up zooms in). Settings > Keys can make the buttons work as Blender or Maya has them instead. The orbit goes all the way round both ways, over the top too, with no jump and no flip at the poles: Free (the default) turns about the screen's axes, Turntable about the model's up axis (Settings > Camera, with the speeds and inverting). P (or keypad 5) switches between perspective and orthographic (parallel) projection, as wide at the orbit centre as the perspective view, so the object keeps its size on screen. Keypad 1, 3 and 7 look from the front, right and top, with Ctrl from the back, left and bottom (also in the Scene palette's Camera section). In orthographic projection the far-chunk simplification while orbiting is off. Camera history: Alt+Left (Previous view) goes back to the view before and Alt+Right (Next view) forward again, as a browser goes back and forward through pages, without touching the work or its undo; they are also in the View menu (which stays open to step several), the palette and the gesture map's choices. A view counts once the camera has stayed still 0.4 s with nothing turning it, whatever moved it (a turn, pan, zoom, pinch, Focus, Frame all, an axis view, Reset camera), and the view a scene opens with counts at once; going back from a view that has not rested yet keeps it first, so Next view returns to it, and a new view after going back drops the ones ahead. The last 32 are kept; the projection is not part of a view, and opening a scene or making a new one starts afresh (they are not saved). Script: `ortho_toggle on`, `view_axis front` (or `back`, `right`, `left`, `top`, `bottom`).

## Touch and pen

Fingers and the pen work as in ZBrush for iPad (`src/app/touch.odin`, `src/app/navigate.odin`, with every setting in Settings > Touch):
- One finger on the model sculpts, as the mouse does, once it has been down 90 ms (0.25 s while double taps are on) or moved past the slop, so a second finger landing with it makes a gesture before any clay moves. One finger on empty space turns the view, and keeps turning it over the model. Settings > Touch > On the model > Turns the view leaves sculpting to the pen.
- The pen sculpts on the model with pressure, and on empty space turns the view (or waits for the model). While the pen is near the screen or on it, a single finger does nothing (the hand holding it); the pen coming down cancels a touch in progress.
- Two fingers pan with their middle, zoom as they spread or pinch, toward the point between them, and twist to roll the view once they have turned 10 degrees (Free orbit only). Three fingers drag up and down for the brush size and sideways for its focal shift (400 points across its range), whichever way they go first; strength is a long press dragged on the brush bar's Strength. A quick tap of two fingers undoes, of three redoes (by default: see the gesture map below). Held still (landing together, within 0.15 s), two fingers undo again and again: once at 0.45 s, with a ring filling round them from 0.15 s on, then every 0.12 s with a count beside the ring, until a finger moves or lifts; three redo the same way. A hold never starts while the pen is near the screen, and once it undoes the touch neither pans nor zooms.
- Put two fingers down and lift one, and the other turns the view once it moves past the slop, about the same pivot an orbit would use, so a view filled by the model can still be turned with one finger. Only after two fingers that stayed still: the finger left rolling off the end of a pinch turns nothing. A two-finger tap still undoes unless the finger left turned the view.
- A double tap of one finger (the second tap within 0.3 s and 48 points of the first) on empty space frames the selected object, or every object when none is selected. On the model it pins the pivot to that point, with a pulse to show where: every orbit turns about it, whatever Turn about says, until the next stroke ends or the view is framed or reset. Neither tap sculpts: while one finger sculpts, a single tap's dab waits out the 0.3 s for a second tap, then lands as it was tapped (same view, brush and modifier buttons), or at once when anything else comes first (a key, the mouse, the pen, a finger elsewhere or a stroke). Taps in the safe zone along the edges never double-tap, nor do the presses that draw mask or hide shapes. A quick tap's dab keeps the modifier buttons latched or held at its press.
- The modifier wheel at the bottom left (`src/app/modifiers.odin`, `src/ui/wheel.odin`) does what Shift, Ctrl and Alt do, for a tablet with no keyboard. Its top sector is Smooth, its left Mask, its bottom Invert and its right opens the brush pie (as Space does); Smooth and Mask on together are Hide, as Shift and Ctrl held together are. Smooth smooths (Shift; held down by the other hand while the pen or mouse is mid-stroke, it lays a straight line instead, as Shift does then, and lifting it does not latch it), Invert inverts the brush (Ctrl), Mask paints the mask on the model at the Mask brush's strength and draws the Mask section's rectangle or lasso from empty space (Ctrl from empty space), and Hide (Smooth and Mask together) runs the gesture tool picked in Hide, clip and slice (Ctrl+Shift): a drag hides, clips or slices, a tap on a polygroup isolates it and a tap off one shows everything. Invert with Mask erases the mask and unmasks shapes; with Hide it flips the gesture as Alt does. With Mask on, where a tap lands chooses a mask command, as ZBrush's Ctrl click and Nomad's taps while Mask is held: off the model it inverts the mask, on a masked part it blurs the mask, on an unmasked part it sharpens it (by the Mask section's Steps), each with a toast that offers Undo; a tap paints no dot, so a mask stroke begins once it moves past the slop or is held 0.25 s. With the mouse, Ctrl and a click on empty space invert the mask too (Ctrl on the model still inverts the brush). A tap on another object selects it first; Invert (or Alt) changes nothing about which command a tap runs. A quick tap that stays within the slop latches a sector until it is tapped again (filled); a finger held on one makes it act only while held (lit), so the other hand sculpts with the pen or a finger and lifting ends it. Smooth and Mask latched or held together are Hide; otherwise one of them goes at a time, and Invert goes with any. A finger on a modifier sector is the wheel's alone: it is never the pointer, never part of a gesture, a hand resting there is no palm, and the pen landing leaves it be. A press takes the buttons' state as it goes down and keeps it until it lets go, so lifting the finger mid-stroke changes nothing; a held sector beats a latched one, the last held wins (but for Smooth and Mask held together, which are Hide), and any of Shift, Ctrl or Alt held at the press leaves the wheel out of it. The mouse and the pen click the sectors, which latches. Where a panel, a menu or a list lies over it, a finger there is the panel's. It sits under the brush bar (beside it where a short window brings the bar down to it) and rises above the bottom bar on a narrow one. Dragging the grip in its middle (a finger, the pen or the mouse) moves it anywhere in the window, and where it was put is remembered; Settings > Interface puts it at the bottom left or right (which also puts a moved wheel back), hides it (which lets go of every latch), and sets its size: Small, Medium (the default) or Large.
- Settings > Touch turns each of these off: Lift one of two fingers to turn, Double tap to frame or pin.
- The gesture map (Settings > Touch, `src/app/gesture_map.odin`) says what seven gestures run, each Nothing or one of about 30 commands a hand without a keyboard reaches for (Undo, Redo, Brush pie, Pie 1 to 4, Search, the panels, framing, Previous and Next view, the view switches, Screenshot, Symmetry X, the mask's Invert, Clear, Blur and Grow, Show all, Invert hidden, the Move and Sculpt tools): Two-finger tap (Undo), Three-finger tap (Redo), Four-finger tap (four or more fingers; Nothing), Hold two fingers (Undo), Hold three fingers (Redo), Hold four fingers (Nothing) and Pen side button (Brush pie). A hold fills its ring, then runs its command; Undo and Redo repeat while the fingers stay still, anything else runs once. The pen's side button, when not on the brush pie, runs its command where the pen is; the mouse's right click stays the brush pie. A gesture holds one command, so none collide; what overlaps is said under the map in the warning colour: four fingers the system may keep (Windows' touch gestures, some Android skins), the brush pie losing the pen's button, a hold that runs once, one command on two gestures, and a hold of your own sharing its start with Lift one of two fingers to turn. Every tooltip, the palette and Help > Gestures name the gestures the map gives a command ("Four-finger tap"), Help under YOUR GESTURES for a command it has no line for. Remembered as `gesture_map <slot> <command|none>` lines for the slots that differ; the older `tap_history 0` and `hold_history 0` lines still turn the two- and three-finger taps or holds off. The Brush pie command (Search, a gesture) opens the brush pie at the pointer for a tap.
- Long press is the secondary action, as in ZBrush for iPad and Nomad (`secondary` in `src/ui/ui.odin`): a finger or the pen held on a control for 0.45 s without moving past the slop does what a right-click on it does (the pen's side button is a right-click too), and a ring fills round the press from 0.15 s on to show it coming. On a control with no such action it shows the control's name and shortcut instead. Either way letting go is no tap, and a press that moves, changes a value or scrolls is no long press. The mouse's left button never long-presses. What each does:
  - Undo and Redo open the History panel (while there is something to undo or redo; the History button beside them always does).
  - A slot in the dock opens its menu, to show its brush's settings or put another brush or preset in it (see Brush presets).
  - A brush or preset in the brush browser picks it and shows its settings in the tray.
  - The Size and Strength sliders (in the popover Draw size and Strength open) go back to where a new brush starts: 60 px, and the brush's own starting strength. A finger that moves the value while held is adjusting it, not resetting it.
  - A bar button with a small triangle in its corner opens its settings: Brushes the brush's, Draw size and Strength the Pen section, Save the other ways to save, Studio render its section, Orthographic and Wireframe the view menu, Symmetry its X, Y and Z.
  - The Move, Curve and Insert tools on the dock pick the tool and show its settings in the tray.
  - The object's readout under the top bar opens its menu under it.
  - An object in the Scene palette opens its menu.
  - A done step on the History panel's bar makes it what the History brush paints back to (see History timeline and time-lapse); its note names the step, since the step's tooltip shows only on hover (the mouse, or a hovering pen).
- A finger or the pen changes nothing until it moves more than the slop, 10 points (Android's touch slop is 8 dp, iOS about 10 pt), so a tap never nudges the view; the mouse has none.
- The safe zone, as the SculptNavigation add-on's border: one finger, the pen or the left button pressed within 64 points of an edge of the screen (at the top, of the top bar's lower edge) turns the view even over the model, so when it is zoomed in until the model fills the screen there is still somewhere to turn it from. A faint line marks where the zone ends; panels over it keep their presses, and Ctrl keeps it for the mask and hide shapes (so does a finger held on Mask or Hide, though not a latched one). Settings > Camera sets its width (24 to 200 points), hides the line or turns it off.

Every touch, from its first finger down to its last finger up, belongs to where its first finger landed. On a panel the panels have it: that finger presses, drags and scrolls them, and other fingers of the same touch do nothing, so a hand resting on a panel never pinches the view. On the viewport the fingers navigate or sculpt as above, and lifting fingers never turns what is left into another gesture. A touch the system cancels lets go without a click, and a stroke it drew is taken back (Redo has it). Inside a panel that scrolls, a finger or pen press on a control waits to see which way it goes: up or down past the slop scrolls the panel and the control does nothing, sideways a slider takes it, and a tap within the slop is the control's tap; the mouse presses at once and scrolls with the wheel. Touchpads are not touch screens: their fingers never reach the view, and nor do the stand-in fingers SDL can make of the pen and the mouse.

`python scripts/gate.py` runs every check a change must pass (check, test, build, smoke, these scenarios, and the Windows and Android compile checks on Linux) with one line a step. `python scripts/touch_check.py` (after a debug build) drives the app with scripted fingers, pen and mouse through these cases and checks the camera, the dabs, the undo steps and the saved settings on exit: a simulation on the desktop, not a tablet (see the `sm-touch-testing` skill).
