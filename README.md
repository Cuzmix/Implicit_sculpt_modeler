# Sculpt

A performance-focused sculpting prototype in Odin, using SDL3 + SDL_GPU for rendering and its own interface kit (`src/ui`) for everything around the viewport.

## Layout

| Path | Owns |
| --- | --- |
| `src/app` | Entry point, frame loop, scene of sculptable objects, Move, Brush, Curve and Insert tools, brush alphas (the built-in ones and loaded images, which way each dab's image faces), the interface's panels (`new_ui.odin`, `kit_*.odin`), keys and pointer from SDL (`device.odin`), fingers and the pen (`touch.odin`), who owns each touch and drag and what the camera does with it (`navigate.odin`) and routing into `Viewport_Input` (pen pressure and tilt included), the Settings panel (`kit_settings.odin`), the viewport overlay and the brush pie, the History timeline and time-lapse, the menu's file actions (scene save and open, mesh import and export, file dialogs), autosave on its own thread and crash recovery (`autosave.odin`, `kit_recover.odin`) |
| `src/render` | Every GPU object the app creates: device, pipeline, viewport target, mesh buffers (16 bytes a vertex: float3 position, octahedral normal), per-mesh indirect draws of the visible chunks, simplified copies of far chunks drawn from a second index buffer while the view moves, partial redraws (while the camera and objects stay put, the last frame is kept and only the screen rectangle around what changed is cleared and redrawn), shaders |
| `src/geom` | CPU sculpt geometry (structure-of-arrays triangle mesh, BVH, test spheres, mesh simplification that keeps patch borders), view-culling math (chunk bounds and normal cones, frustum and back-face tests) and the choice of simplified groups to draw, OBJ and PLY reading and writing with cleanup of what is read, binary glTF and USD writing with morph targets and blend shapes (`gltf_write.odin`, `usd_write.odin`), quad retopology, UV layout and normal and displacement map baking, response curves (the pen pressure curve); no rendering or UI imports |
| `src/camera` | Orbit camera math (Turntable, Free (the trackball), X axis and Z axis orbits that go all the way round, roll, snapping to square views, zoom toward a point), including how a leaning pen turns the brush in the view; no rendering or UI imports |
| `src/gizmo` | Move tool gizmo math: projection, handle picking (arms, plane squares, rings, the scale disc), axis, plane, turn and scale drags, snapping, the Euler inverse; no rendering or UI imports |
| `src/sculpt` | Brush dabs on a `geom.Mesh`: mesh split into nodes that own contiguous vertex ranges, parallel brushes (Draw, Smooth, Clay, Flatten, Inflate, Pinch, Crease, Grab) with X/Y/Z symmetry, pen tilt and alphas (a grey image that shapes each dab), a per-vertex mask, per-frame normal updates, dirty vertex ranges for upload, stroke undo/redo that saves only the nodes a stroke touched (512 MB cap per object), simplified copies of groups of nodes rebuilt between strokes, subdivision levels, HD detail sculpted a window at a time above the top level, dynamic topology (brushes split and collapse edges as they go), levels in and out of the scene file |
| `src/ui` | The interface kit: immediate-mode containers and widgets (buttons, segmented controls, switches, sliders, values to drag, text fields, selects, brush tiles, list rows, areas to draw into), hit testing, the gesture arena that settles whether a finger's press is a tap, a drag or a scroll, multi-finger gesture measurement (`fingers.odin`), antialiased shapes tessellated on the CPU, text in Inter and icons in Lucide through fontstash; it imports neither SDL nor the renderer, so its tests run headless |
| `src/luau` | The binding to Luau, the language of script plugins: the part of its C API the plugins use, linked from `deps/luau` on the Windows and Linux builds only (see Script plugins) |
| `src/jobs` | Persistent worker pool (`parallel_for`) used by sculpt and mesh setup |
| `src/bench` | Headless sculpt benchmark at chosen mesh sizes (no window or GPU) |
| `src/voxel` | Voxel sculpting core: a signed distance field in a narrow band of 8³ bricks (16-bit values, tiles for the solid inside and the empty outside), Add, Subtract, Smooth, Flatten and Inflate brushes, a surface meshed by surface nets (one vertex a loop of crossings, no saddle faces in the field: closed and manifold) a 16³ node at a time into slots the GPU buffers upload in place, per-brick undo, band repair at a stroke's end, the clay's scene-file section and the conversion to a plain mesh (see Voxel sculpting below) |
| `src/sdf_trial` | Standalone SDF/voxel comparison spike (not linked into the app) |
| `src/dart_trial` | Standalone Odin vs Dart comparison of the Draw brush's hot loops (not linked into the app) |
| `tools/blender` | The Blender add-on of the Blender link (`sculpt_link`, Python under GPL-3.0-or-later, as Blender add-ons must be); not built into the app (see Blender link) |

The 3D viewport is rendered by `render` into an offscreen texture that the interface draws under its panels. Strokes undo and redo with Ctrl+Z and Ctrl+Shift+Z (or Ctrl+Y), also the buttons at the foot of the brush bar on the left; the order runs across objects. Changes that rebuild an object undo the same way: remesh, dynamic topology on or off, Delete higher and Delete lower, and adding, importing or deleting (Delete key) an object. Before such a change the object is kept as the scene file stores it (every level as positions, the mask, dynamic topology); undo rebuilds it from that and keeps the object it replaces, so redo works too. That costs about 37 bytes a base vertex plus 12 a vertex of each level above (about 370 MB for a 10M-vertex object), up to 1.5 GB in all, past which the oldest go; the Stats panel shows the total. The object's strokes from before such a change can no longer be undone one by one, and HD detail is not kept (the HD steps are). Undoing a remesh takes about 0.1 s at 100k vertices and 0.24 s at 1M on the test VM (release build). The interface never owns sculpt state: panels read and edit `App` fields through pointers each frame, and what the viewport saw reaches the camera and the active tool as a plain struct. Each object keeps its mesh in local space with a transform (position, uniform scale, rotation), so moving or turning an object never rewrites its vertices; the brush works in the object's local space, and so do symmetry and Mirror and weld. The Object palette's Transform turns the selected object (degrees about X, then Y, then Z); scenes save it (scene file version 2, which still opens version 1 files). Placing an object anew is an undo step too: each gizmo drag, each drag of a Transform value and Reset transform is one, which undo and redo put back exactly, in its place among the strokes; it outlives the object's strokes when those are dropped (a level renumbered, an HD window closed), and undo waits while a drag is under way.

## Linux

```sh
# once: system packages are listed at the top of the script
./scripts/setup_deps.sh

./build.sh            # debug build with allocation tracking -> build/sculpt
./build.sh release    # optimized build
./build.sh test       # unit tests (geom, camera, sculpt, jobs, gizmo, png_write, zip, voxel, ui, luau, app)
./build.sh check      # odin check of every package with the strict flags, then the agent-file mirror check (scripts/agents_sync.py)
./build.sh run -- --vertices=10000000
./build.sh smoke      # 300 frames in GPU debug mode; non-zero exit on assert, GPU error or leak
./build.sh bench      # headless sculpt benchmark at 500k, 1M, 5M, 7M, 10M vertices
./build.sh gpubench   # GPU and CPU frame times while orbiting and sculpting, same sizes
./build.sh computebench # Smooth all on the CPU against a GPU compute shader, same sizes
./build.sh wincheck   # compile app and bench for Windows x64 (no link) to catch Windows-only errors
```

Headless (CI or containers): run under `Xvfb` with Mesa's llvmpipe Vulkan driver (`mesa-vulkan-drivers`).

## Android

`android/` is a Gradle project that packages the app for 64-bit ARM tablets (Android 11 or newer, Vulkan): SDL's own Java activity (`SDLActivity`, from the SDL checkout in `deps/sdl3-src`) loads `libSDL3.so`, built from that same source, and `libmain.so`, which holds `src/app` compiled by Odin to one arm64 object (`-target:linux_arm64 -subtarget:android -build-mode:obj`) and linked with stb_truetype and a small C file (`android/app/jni/android_main.c`) that gives SDL its `SDL_main` and stands in for two pthread calls Android lacks. `android/app/jni/CMakeLists.txt` runs Odin itself, so Gradle or Android Studio rebuilds the app whenever a source, shader or font changes; the Odin side is always an optimised build. The app targets API 36, as Google Play requires, links for 16 KB pages and asks for no permissions.

Once, on Windows (Linux: `scripts/setup_deps.sh` already fetched SDL's source):

1. Install [Android Studio](https://developer.android.com/studio). In its first-run wizard keep the standard SDK. Then Settings > Languages & Frameworks > Android SDK > SDK Tools, tick Show Package Details, and install NDK (Side by side) `28.2.13676358` and CMake `3.22.1` (Gradle also fetches them itself on the first build if they are missing).
2. From the repo, after `scripts\setup_deps.bat`: `scripts\setup_android.bat` (clones SDL `release-3.4.18`).
3. On the tablet: Settings > About tablet (on OnePlus: About device > Version), tap Build number seven times; then Settings > System > Developer options > USB debugging on. Plug it in and allow the PC when it asks.

Then:

```bat
build.bat android      :: android\app\build\outputs\apk\debug\app-debug.apk
build.bat androidrun   :: the same, installed on the plugged-in tablet and started
```

(`./build.sh android` and `./build.sh androidrun` on Linux, with the SDK in `~/Android/Sdk` or `ANDROID_HOME`; `./build.sh androidcheck` compiles the Odin side for Android without the SDK.) Both find Android Studio's SDK (`%LOCALAPPDATA%\Android\Sdk`) and Java (`%ProgramFiles%\Android\Android Studio\jbr`) unless `ANDROID_HOME` and `JAVA_HOME` say otherwise. The project uses Gradle 9.8 and the Android Gradle plugin 9.4, which run on Java 17 to 25 (Android Studio 2026.2 ships 25; Gradle 8 stops at 24 with "Unsupported class file major version 69"). Opening `android/` in Android Studio works too: Run builds, installs and starts it. Without a cable, copy the APK to the tablet and open it there (Android asks once to allow installs from the file manager). The log goes to logcat: `adb logcat -s SDL/APP` (adb is in the SDK's `platform-tools`), and the GPU line names the tablet's Vulkan driver.

On the tablet the app is full screen, with the system bars a swipe away, and lays its panels inside the safe area SDL reports (camera cutout, rounded corners, gesture bar). The interface scales by the screen's density, so its 48 point targets are 48 dp. The pen sculpts with pressure and its side button opens the brush pie; fingers sculpt and move the view as in ZBrush for iPad (see Touch and pen). Back closes an open menu and otherwise does nothing, so it can never drop unsaved work; leave with the home gesture. Open, Import, Load image, Run script and stroke recordings go through the system's file picker, which hands back `content://` URIs; the app reads those through SDL's IO, and Import tells OBJ from PLY by the file's first bytes, since such a URI has no extension. Not yet on Android: Save and Export cannot write to a picked `content://` file, and leaving the app does not save the scene to a file; it writes an autosave instead (see Autosave and recovery), which the next start offers back if Android dropped the app in the background. A Google Play build also needs a release signing key and `bundleRelease` (an `.aab`).

## Command scripts

A command script sets a run up from text, the same way the interface would: `--run=FILE` runs a file, `--script=TEXT` one given on the command line with `;` between statements (in `build.bat`, which splits arguments at `;`, `,` and `=`, use `--run=FILE`). It runs once the window has laid out its viewport, before the run's own frames start: `--frames`, the frames of `--ui-events` (none go in before it ends), `--bench-stroke`, `--load-strokes`, `--timelapse` and `--orbit` all count from the frame it ends on. What it did is where the run starts: none of it is in the History or the camera's Previous view, the scene counts as unsaved only if it did before, and the Stats' timings and counts start afresh. Anything done by hand while a `wait` lets frames pass is part of that set-up too. `--gpubench` builds its own scenes and takes no script.

One statement a line (or `;` between them); `#` starts a comment that runs to the line's end, and `"quoted text"` is one word. Names are written in lower case with `_` or `-` between words, in any case.

- A command by its name in the command palette's registry: `remesh`, `subdivide`, `undo`, `frame_all`. One with choices takes one by name: `brush clay`, `view_axis front`, `mask invert`, `deformer lattice`, `remesh_to 500000`, `new_scene head`. One that is on or off takes `on` or `off` and then only changes it when it differs (`wireframe on`, `front_only off`); without either it turns over. Commands that ask for a file, typed text or a pick on screen (open, save, import, export, screenshot, rename, the palette and the pies), and those that depend on what a script cannot know (Replay last stroke at the pointer, Open last autosave), are not for scripts, nor are Record macro, Run macro and Run script, so no script starts another. `new_scene` goes ahead without asking twice.
- `set <setting> <value>`: a remembered setting under its name in the settings file (`set orbit_style turntable`, `set radius_px 80`, `set symmetry xz`, `set paint_color 0.2 0.4 0.9`, `set material "red wax"`, `set new_vertices 1000000` for the size Add object and New scene use, `set new_voxels on` for Add object to add voxel spheres), or a value a command reads that is not remembered: `smooth_steps`, `smooth_strength`, `mirror_axis` (0 x, 1 y, 2 z), `mirror_negative`, `extract_thickness`, `boolean_vertices` (Make boolean's Result vertices), `hd_window`, `studio_samples`, `studio_ao` (the studio render's and live occlusion's Occlusion), `live_ao_reach` and `cloth_mode`. So `set rebuild_even 200000; rebuild` remeshes the selected object to 200,000 vertices, as Rebuild > Even does. Bools take on/off, true/false, yes/no or 1/0; a number must be in the setting's range; a count must be whole.
- `wait N` lets N frames pass (to see a change drawn, or let a time-lapse start); `select N` selects the Nth object alone, counting from 1 down the Scene palette's list, the objects in folders included.
- Verbs, for what no command does with a single choice, each doing what its tool or panel does:
  - `move X Y Z` and `rotate X Y Z` set the selected object's place and its turn in degrees about X, then Y, then Z, as the Transform values do;
  - `boolean none|union|subtract|intersect` marks the selected object, as the Booleans section's tabs do;
  - `slice x|y|z` cuts the selected object in two across the middle of its bounds, as a Slice line does;
  - `knife x|y|z` (or `-x`, `-y`, `-z`) cuts away the + (or -) side of the middle of its bounds, as a Knife line does;
  - `hide x|y|z` hides the + side of its middle across that axis (`-x`, `-y`, `-z` the - side), as a hide rectangle does;
  - `mask_rect LEFT TOP RIGHT BOTTOM` masks what that part of the view shows, each edge from 0 to 1 across the view from its top left, as a mask rectangle does;
  - `project N` projects the detail of object N onto the selected one, as Project detail does;
  - `draw_curve tube|stitches|zipper` draws a wavy curve across the middle of the view with the Curve tool;
  - `insert_middle sphere|cube|cylinder|cone|torus` inserts that shape where the middle of the view meets the surface, as an Insert click does;
  - `falloff smooth|linear|sharp|firm|flat` gives every brush that falloff preset;
  - `focal N` (-100 to 100) gives every brush that focal shift;
  - `alpha NAME` picks an alpha by name (a built-in's, or `mine/NAME` or `PACK/NAME` from the library), or loads an image file as one for this run (quote a path with spaces);
  - `layer N STRENGTH [hidden]` sets the selected object's layer N (from 1, the bottom one) to that strength, from -1 to 2, shown or with `hidden` hidden, as its slider and eye do, in one undo step;
  - `install_pack PATH` installs a content pack in place, replacing an installed one of the same name and author (see Content packs);
  - `group_material N [off]` gives polygroup N (from 1) of the selected object the material `set material` chose, or with `off` the object's again, as the Material section's Group tab does;
  - `matcap FILE` loads an image of a lit sphere as the Custom material's MatCap and shades with it, as Load MatCap does;
  - `texture base_color|orm|normal FILE` loads an image as that map of the selected object, which needs UVs, as the Textures section's Load buttons do (`remove_textures` takes them all away);
  - `environment FILE` loads a panorama as the image environment and picks Image, as Load environment does, waiting for it (see Lights);
  - `preset NAME` puts the brush on a preset, one of yours by its name or a content pack's as `PACK/NAME` (`preset rock-set/stone clay`), or `none` for the plain brush, as the Preset section's list does;
  - `pack_mesh PACK/NAME` adds a content pack's mesh as a new object beside the others, as Add object does with it picked (`pack_mesh rock-set/boulder`);
  - `make_pack PATH` writes your own alphas and presets as a content pack named after the file, as Make a pack does (`make_pack "my brushes.sculptpack"`).

The whole script is checked before any of it runs: an unknown name, a choice or value that does not fit, or an unclosed quote lists every such line (`script: setup.cmd:3: brush takes one of: draw, smooth, ...`), at most 20, and the run exits with code 2 having done nothing. While it runs, a statement that does nothing (a command not available then, an operation that refuses or leaves the scene as it was, `select` past the last object) stops it: a run with `--frames` exits with code 2 saying which line and writes none of its `--export`, `--save`, `--bake` or `--save-strokes` files; an interactive run shows a note and keeps what ran before it as its set-up. An interactive run remembers the settings a script set, as it does those changed in the Settings panel. The exit stats add `script_statements`, `script_ran`, `script_frames` and `script_failed`.

Scripts replace the start-up flags that once mirrored the tools. For example, a 200k remesh then a sculpt layer is `set rebuild_even 200000; rebuild; new_layer`; Decimate is `set rebuild_goal fewer; set rebuild_fewer 20000; rebuild`; Retopologize `set retopo_quads 300; retopologize`; Mirror and weld `set mirror_axis 1; set mirror_negative on; mirror_weld`; Smooth all `set smooth_steps 3; smooth_all`; dynamic topology `dyntopo_toggle on` (and `set detail_px 14`); the morph target `morph_store`; polypaint `set paint_color 0.1 0.5 0.9; paint fill`; the camera `set orbit_style turntable`, `set orbit_pivot centre`, `set edge_orbit off`, `set finger_model orbit`; the brush ring flat on the screen `set surface_ring off`; the pen's tilt `set tilt_strength 0.5`; the alpha's turn `set alpha_mode fixed; set alpha_angle 30`; symmetry `set symmetry xz`; Line and Join strokes `set stroke_line on`, `set stroke_join on`; and the HD window `set hd_window 2000000`. Each was checked against the flag it replaced: the same mesh, scene file and settings, bit for bit. The verbs were checked the same way against theirs, with two differences: a curve or an insert now goes across the view as it is laid out rather than the window size asked for, and a slice no longer reframes the camera on the two parts.

## Macros

Record macro (in Menu > Macros, or search for it in the command palette, or give it a key in Settings > Keys) starts keeping the commands you run, by any route: a key, a button, a menu, the palette or a pie. A red "Recording macro" chip at the top of the viewport counts them and has Stop (Record macro again stops too). Stop asks for a name under the chip ("Macro 1" when left empty): Save keeps it, Discard, Escape or a tap elsewhere drops it. Each command is kept as the line of a command script (see Command scripts above) that does it again: a choice by its name (`brush clay`, `mask invert`), a switch as the state it left (`wireframe on`, so running the macro sets it rather than flips it), Sculpt HD as `hd_sculpt` or `hd_leave`, and a command that reads values from its panel (Smooth all, Rebuild, Mirror and weld, Retopologize, Extract, Make boolean, the mask's Blur to Shrink, Creases groups, Fill with colour, Add object) gets `set` lines for them first, written when they differ from the last the macro set. A command that queues its work for the next frame (Remesh, Subdivide, ...) is kept once that has changed the scene, and one that refused (a warning note) is not kept. Undo while recording takes the newest command out again when the step it undoes is that command's. Strokes, turns of the view, gizmo and slider drags and clicks on objects are not commands and are not recorded, nor are undo and redo, the view commands (axis views, focus, frame all, previous and next view), panels, the palette and the pies; commands that ask for a file, a typed name or a pick on screen (open, save, import, export, screenshot, rename, New scene) are left out and the save note counts them. So a macro acts on whatever is selected when it runs, as ZBrush's do.

A saved macro takes the first of 16 numbered slots and is Run macro N, listed in the palette and Settings > Keys by its name ("Macro: Zebra") only while the slot holds one; like any command it can be given a key, put on a pie or starred, and the binding stays with the slot. Running it runs its lines at the start of the next frame as your own work: each command is its own undo step as if done by hand, nothing is cleared, a line that does nothing stops it with a note naming the line and keeps what ran before it, and a finished run says "Ran macro Zebra: 3 steps". It is not offered while recording, while a script or another macro runs, during a stroke or drag, or while a save or file dialog waits. Each macro is a plain command script, `macro-NN.cmd` (NN the slot) in the `macros` folder beside the settings file (a settings file given with `--settings-file` has its own, `<name>-macros`), whose first line `# Macro: <name>` names it; edit it in any text editor and it is read again at the next start (on Android the folder is the app's private storage). A run that keeps no settings keeps no macros either: a macro saved then lasts until the app closes. Deleting a macro takes Run macro N off every key, pie slot, star, gesture and recent search that ran it, so a macro saved in the slot later starts with none of them.

Menu > Macros (or Search) opens the Macros panel in the tray's place, as Settings and Help open: Record macro (Stop recording while one is on) and Run script at its top, then each macro kept, by name with its keys and gestures under it ("Macro 3, no key" for none), and four buttons: Run, Key (the Assign key popover, as Ctrl+Alt+click on Run gives too), Rename (a field under the row; Enter applies it, and the file's first line changes with it) and Delete, which asks for a second tap on its bin within three seconds ("Tap the bin again to delete it") and then deletes the macro and its file. The note at its foot names the folder the files are in.

Run script (Menu > Macros, or Search) picks a command script file (`.cmd`, or `.txt`) with the system's file dialog and runs it as a macro runs, without keeping it: on what is selected, each command its own undo step, a line that does nothing stopping it with a note, and a file with an error running none of it ("Cannot run bevel.cmd: bevel.cmd:2: no command is named ..."). `wait` and `new_scene` are for start-up scripts only (`--run`), and it is not offered while a recording, a script or a macro runs. The exit stats add `macros`, `macro_recording`, `macro_entries`, `macro_left_out`, `macros_run`, `scripts_run` (script files run) and `macro_steps` (the statements macros and script files ran).

## Script plugins

On the Windows and Linux builds, a script plugin is a `.luau` file in the `plugins` folder beside the settings file (`<name>-plugins` for a settings file given with `--settings-file`), written in [Luau](https://luau.org/), the typed Lua that Roblox made and keeps for running code it does not trust. The app reads the folder at start, in file-name order, and again on Reload plugins (Menu > Macros, or Search). A plugin's top level registers commands; each command's `run` changes the scene only through `sculpt.run`, which runs command-script text (see Command scripts above) as a macro does:

```lua
sculpt.command{
    name = "Smooth and subdivide",
    help = "Smooths the selected object twice, then adds a level.",
    run = function()
        sculpt.run("set smooth_steps 2; set smooth_strength 0.5; smooth_all")
        local at = sculpt.selected()
        if at and sculpt.objects()[at].vertices < 1000000 then
            sculpt.run("subdivide")
        end
    end,
}
```

| Call | Where | What it does |
| --- | --- | --- |
| `sculpt.command{name, help, run}` | top level only | Registers a command: `name` 1 to 48 bytes (no line breaks or `/`), unique in its file; `help` at most 200 bytes, optional; `run` a function |
| `sculpt.run(text)` | in a `run` only | Runs the statements now, each its own undo step. Errors in the text, `wait`, `new_scene` and the commands a script cannot run raise an error before any of it runs; a statement that does nothing raises `line N: <statement> did nothing (why)`, keeping the steps before it |
| `sculpt.objects()` | anywhere | A list of `{name, vertices, triangles, selected, shown}`, one an object, in the scene's order |
| `sculpt.selected()` | anywhere | The selected object's number from 1, or nil |
| `sculpt.get(key)` | anywhere | A setting as `settings.txt` writes it (a string), or a value scripts set (`smooth_steps`) |
| `sculpt.note(text)` | in a `run` only | Shows a note (at most 200 bytes), which stays in place of the run's own |
| `print(...)` | anywhere | One line on the console after the plugin's file; the Macros panel shows the last |

Each command is Run plugin N, listed in Search, Settings > Keys and the Macros panel as "Plugin: <name>", and, like a macro, it can take a key (Ctrl+Alt+click on its Run button), a pie slot or a star. A command keeps its slot by its file and name (`plugin_slot <n> <file>/<name>` in the settings), so a key stays on it when other plugins come and go; a command no plugin registers any more stays listed as missing in the Macros panel, with a bin to forget it and its key. Running one waits for the next frame's start, as a macro does, and is not offered while a recording, a script, a macro, a stroke or drag, or a save or file dialog is under way; a finished run says "Ran plugin <name>: N steps", and one that stopped says where and why ("Plugin Bevel stopped after 1 step: bevel.luau:7: line 2: remesh did nothing (...)"), which the panel also shows under the file.

Each plugin runs in a Luau VM of its own, sandboxed: Luau's standard libraries less `getfenv`, `setfenv`, `debug` and `os`, so there is no file, process, network or clock access, and nothing to load code with but the plugin's own source, which the app compiles (bytecode is never read from a file); the built-ins, `sculpt` and the globals table are read-only, and a plugin's own globals stay its own. `math.random` starts from the same seed every run, so a plugin does the same each time. A plugin's top level may pass 5 million safepoints (calls and loop turns) and each run of a command 50 million, about half a second on the test VM (0.5 s in a release build, 0.7 s in a debug one), after which it stops with "ran too long", which its own `pcall` cannot catch; work inside `sculpt.run` is the app's and does not count, and a single built-in call (a string pattern, `table.sort`) runs between safepoints. A VM may hold 64 MB, past which it stops with "not enough memory". A plugin that fails to load (a syntax error, an error at its top level, either budget) shows the error under its file in the panel, its commands go missing, and the other plugins load as usual. At most 64 plugins of at most 1 MB each and 64 commands in all are read; more files are counted in the panel. A run that keeps no settings (`--frames`, the benchmarks, `--no-settings`) loads no plugins. The Android build has none: the app stores do not allow code that was not reviewed, and Luau is not built into it. The exit stats add `plugins` (loaded), `plugin_commands`, `plugin_errors` (loads and runs that failed), `plugin_runs` and `plugin_steps` (statements `sculpt.run` ran).

Luau (MIT, Roblox, built on Lua's MIT code) is built from source at the tag in `scripts/versions.env` by `scripts/build_luau.py`, which `setup_deps` runs; its licences are in `assets/licenses`.

## Benchmark

`build/bench [vertex counts...] [--meshes=N] [--threads=N] [--node=N] [--prefault=MB]` builds a sphere of each size (N of them with `--meshes`, only the first sculpted; with no sizes given it also runs 10M with a second idle sphere), prepares it for sculpting, runs the same 77-dab stroke with a large (r=0.13) and a small (r=0.04) brush, and prints a markdown table, including the undo memory of each stroke and the time to undo and redo it. A frame is 4 dabs plus the normal update and is what the app does per frame during a fast stroke. The normal update recomputes every normal of the nodes whose triangles moved, but only the border vertices of their neighbours; the normal cones that back-face culling uses wait until the stroke ends (until then those chunks are simply not back-face culled), and "Stroke end ms" is the frame where that work starts, at most 512 nodes a frame. A second table culls the sculpted sphere from three cameras (whole sphere, close-up, detail) and reports the share of triangles that would be drawn, the number of indirect draw commands, and the CPU time to cull. On cloud VMs, pass `--prefault=3000` so the VM's slow first touch of fresh memory does not dominate setup times.

`build/bench --lod [vertex counts...]` prints a table for simplified drawing instead: at each size, the time to build every group's copy as the app does (a batch a frame), the copies' memory, the triangles drawn and the CPU time to choose them from the culling table's three cameras at full detail and with copies at most 1 px off (on a 1000 px tall viewport), and the time to rebuild what the large-brush stroke made stale.

`build/bench --brushes [vertex counts...]` prints a table with one row per brush instead: the main table's stroke with the large brush, for every brush kind, then Draw with X symmetry, Draw over a sphere masked on one side and Draw with the Noise alpha (see Brushes, masking and symmetry and Brush alphas below).

`build/bench --masks [vertex counts...]` prints a table for the mask commands instead: at each size, each command on a sphere masked on one side, with how many vertices it changed and its undo (see Brushes, masking and symmetry below).

`build/bench --remesh [vertex counts...]` prints a table for voxel remesh instead: at each size, a sphere with one Grab move that pulls a wide spike out of it, remeshed back to the same vertex count (see Voxel remesh below).

`build/bench --dyntopo [vertex counts...]` prints a table for dynamic topology instead: at each size, the main table's stroke with the large brush on the usual layout, then with dynamic topology on, once with nothing to split, once refining and once more over what it refined, with undo, redo and the time to turn it on and off (see Dynamic topology below).

`build/bench --files [vertex counts...]` prints a table for files instead: at each size, a sphere written as OBJ and as PLY and parsed back, cleaned up and made ready to sculpt as Menu > Import mesh... does, then saved and read back as a scene; and a second table for scenes with subdivision levels, laid out as `--levels` lays them out (see Files below). It works in memory, without the disk.

`build/bench --hd [vertex counts...]` prints a table for HD detail instead: at each size, a sphere as the top level with an HD level one and then two steps above it. It times opening a window of about 4M vertices at the front, the small-brush stroke in it (median frame), storing it on leaving and opening the window again with the stored detail, and gives the window's memory and what the stroke stored. Then the regular levels the HD level stands in for: their memory (estimated past 16M vertices), and while they stay under that, the time to build them and the same stroke on their top level.

`build/bench --voxel [voxels across...]` prints a table for voxel sculpting instead (see Voxel sculpting below): at each size (voxels across a unit sphere; 256, 512 and 1024 by default), the clay sphere's bricks and memory, its first full meshing, then a 60-dab Add stroke across its front a frame every 3 dabs: raycast, dab and flush (remesh of the changed nodes) times, the bytes a frame uploads and how often the mesh arrays grew (a new GPU copy), the stroke's end (band repair), undo and redo with their remesh, one Smooth and one Inflate dab, the conversion to a plain mesh and back to clay, and Res− then Res+.

`build/bench --levels [vertex counts...]` prints a table for subdivision levels instead: at each size, a base sphere of at most 40k vertices with as few levels above it as reach that size. It times building the levels (all of them, and the top one alone), the same stroke on the top level, stepping down to the base (carrying the stroke down, then the base's normal update), the stroke on the base, and stepping back up (carrying that up through every level, then the top level's normal update, with the megabytes the app would upload).

## Big meshes (20M to 50M)

The sculpt core scales with what a stroke touches, not with the mesh: a brush of the same size on screen touches more vertices on a denser mesh, and the frame grows with those, while a brush of the same vertex count costs the same at 10M and at 50M. `build/bench 20000000 50000000` (4 threads, this repo's cloud VM):

| Vertices | Setup s | Mesh MB | Peak RSS MB | Frame ms, large brush (verts a dab) | Frame ms, small brush (verts a dab) | Undo ms, large |
| --- | --- | --- | --- | --- | --- | --- |
| 10M | 1.0 | 888 | 2267 | 1.34 (39k) | 0.29 (3.5k) | 8.0 |
| 20M | 3.0 | 1776 | 2700 | 2.37 (78k) | 0.45 (7k) | 14.9 |
| 50M | 9.0 | 4442 | 6751 | 6.20 (194k) | 0.99 (18k) | 39.3 |

What did grow with the mesh was culling: every frame tested each chunk (about one per 600 triangles) against the view, about 1 ms at 50M even when the view held a few hundred of them, and a stroke's partial redraw paid it every frame. Chunks now also come in groups of 64 neighbours (`CHUNK_GROUP`, in the chunks' order, which follows the BVH), each with bounds and a normal cone holding its chunks'; a group outside the view or wholly facing away is skipped without looking at its chunks, and the rest are tested one by one as before, so the same chunks are drawn. The sculptor remakes a group only when one of its chunks changed (`sculptor_chunk_groups`); under dynamic topology, whose chunks come and go, chunks are tested one by one. Culling CPU ms, chunk by chunk and by groups:

| Vertices | Whole sphere | Close-up | Detail |
| --- | --- | --- | --- |
| 10M | 0.35 → 0.19 | 0.23 → 0.05 | 0.19 → 0.014 |
| 20M | 0.80 → 0.38 | 0.50 → 0.07 | 0.36 → 0.019 |
| 50M | 2.07 → 0.95 | 1.39 → 0.12 | 1.11 → 0.03 |

Saving reserves the object's size up front instead of growing the buffer a doubling at a time, which at 50M (about 1.7 GB an object) means it never holds a second, larger copy while the buffer grows. In the app a 30M sphere is ready to sculpt in about 5 s, saves to a 1 GB .sculpt file in about 8 s and opens again in about 4.5 s on the VM, whose disk and first touches of memory are slow; a 40M top level built with `--vertices=40000 --subdivide=5` takes 11 s and about 9.5 GB with every level and the GPU's copy. To time a real GPU at these sizes: `build.bat gpubench --vertices=20000000` (or 50000000; give the GPU 2 GB of free memory at 50M).

## GPU benchmark and frame timing

`build.sh gpubench` (or `build.bat gpubench`) builds the release app and runs it on one sphere at 500k, 1M, 5M, 7M and 10M vertices (only one size with `--vertices=N`). At each size it runs six cases: the camera orbiting once around the sphere with everything on, with simplified drawing off, and with view culling off too, and a brush stroke with partial redraw and culling both on, partial redraw off, and both off. The stroke drags the 60 px Draw brush back and forth across the sphere at 30 px a frame (two dabs a frame, like a fast real stroke) and is undone after each case. Each case runs 30 warm-up frames and then measures 120; stroke cases count only the frames that sculpted. It prints three markdown tables, GPU time of the 3D viewport and CPU time per frame (p50 / p99) and triangles drawn per frame, and writes them to `build/gpubench.md`. It needs a display, and only a real GPU gives meaningful numbers. Vsync is turned off during the run where the display allows it. It runs at the default anti-aliasing (4x; the report's header says which); to time another, give it a settings file holding the line `msaa off` (or `msaa x2`): `build.bat gpubench --settings-file=build\msaa.txt`.

The Stats panel shows the same timings live:

- **Frame**: the whole frame, waits included. With the frame rate on Match display (vsync) this is the display's refresh interval whenever the frame is ready in time, and on Limit the limit's interval, so it does not show what a speed setting saves; compare CPU and GPU instead, or set the frame rate to Unlimited.
- **CPU**: the frame minus its waits.
- **GPU (3D)**: the GPU time of the 3D viewport's uploads and drawing, shown while "Time GPU work" is on. The 3D work goes in its own command buffer; with timing on, the app waits for the previous frame first and then for this one, so the time from submit to its fence is the GPU's alone. Frames then no longer overlap, so leave it off when not measuring.
- **Display wait**: time spent waiting for the display, at the start of the frame and while presenting.
- **Frame rate**: Match display, Limit or Unlimited, as in Settings > System, with the present mode in use. Limit and Unlimited use mailbox where the display offers it (no tearing), else immediate (may tear). The app reads input after the wait at the start of the frame (the display's, or the limit's), so a driver that makes the app wait there for the next screen image no longer delays that frame's input. Drivers that wait while presenting instead (Mesa does) still add up to a refresh interval of lag on Match display; Unlimited removes that.

## Smooth all and the GPU compute trial

Smooth all (Object palette, Deformation) smooths the whole selected object, as ZBrush's Deformation > Smooth: each step moves every vertex toward the average of its triangles' corners (the step the Smooth brush takes) by the Smooth strength, for the Smooth steps given. Masked areas stay (partly masked ones move part of the way), it is one undo step, and it is not offered with dynamic topology on. The Deformation section shows how long the last one took.

It is also the trial of moving a heavy sculpt operation onto the GPU. Sculpting runs on the CPU, across every core, and the GPU only draws; with "On the GPU" on, Smooth all runs instead as a compute shader (`src/render/shaders/smooth_all.comp`, `src/render/smooth_compute.odin`): the app uploads the positions, triangles, the vertex-to-triangle lookup and each vertex's weight, dispatches one pass a step between two position buffers, and reads the result back into the CPU mesh, which then updates normals, bounds, undo and the drawn mesh the usual way. The CPU path stays the default, and the fallback when the device refuses the compute pipeline. The shader does the CPU's arithmetic in the CPU's order (`precise` stops it fusing multiplies and adds), so the results match: on llvmpipe they are bit-identical, and on other GPUs they may differ in the last bits of a division.

`build.sh computebench` (or `build.bat computebench`) builds the release app and times Smooth all at 1 and 10 steps on a rough sphere at 500k, 1M, 5M, 7M and 10M vertices (only one size with `--vertices=N`), on the CPU and on the GPU, and writes the table to `build/computebench.md`. The GPU time is split into upload, compute and readback, each including the wait for the GPU. "Cold" uploads the triangles and lookup with the positions, as a press of Smooth all does; "warm" keeps them on the GPU from the run before, so only positions and weights travel, which shows what keeping the mesh on the GPU between commands would save. The last column is the largest difference between the GPU's result and the CPU's. Undo saving and normals are the same either way and are left out. It needs a display; only a real GPU gives meaningful GPU numbers.

The SDF/voxel comparison spike from step 3 builds separately: `deps/odin/odin build src/sdf_trial -o:speed -collection:deps=deps`.

The Odin vs Dart spike times the Draw brush's hot loops (finding the nodes a dab reaches, the area normal, moving the vertices, the per-frame normals) written the same way in both languages over the same cube-sphere and stroke, with one thread and with every core (Dart through worker isolates sharing the mesh in native memory). It answers whether the sculpt core could move to Dart; at 10M vertices on the 4-core cloud VM the Odin frame was 1.7 to 2.1 ms on 4 threads and the Dart frame 6.5 ms, and on one thread 2.6 to 3.3 ms against 6.4 to 10.6 ms. Build and run both (the Dart SDK comes with Flutter): `deps/odin/odin build src/dart_trial -o:speed -no-bounds-check -collection:deps=deps -out:build/dart_trial`, `build/dart_trial [sizes] [--threads=N]`, then in `src/dart_trial/dart` `dart pub get` and `dart compile exe bin/kernel.dart -o ../../../build/dart_kernel`, `build/dart_kernel [sizes] [--threads=N]`. The checksum column agrees to about six digits: Dart does its arithmetic in doubles and rounds to floats on store.

## Deformers

The Object palette's Deformers section (Surface page) bends, twists or tapers the selected object, or pulls it with a lattice (below), as ZBrush's gizmo deformers and Blender's Simple Deform do: the part the mask leaves free (all that is shown, with no mask), along one of the object's own axes (X, Y or Z) over that part's extent, from a fixed end that stays put to the far end that moves most. Bend curves that part into an arc of the same length, turning by the Amount (degrees) toward one of the two other axes (Toward; a negative amount bends the other way), and stops short of folding the inside of the bend over itself, so a thick part bends less far than a thin one (a sphere up to about 109°, a long thin part a whole turn). Twist turns it about the axis, nothing at the fixed end and the whole Amount (up to a turn either way) at the far end. Taper scales it across the axis, from as it is at the fixed end to 1 + Amount at the far end (-95% to +300%). Fixed end picks the - or + end; Auto keeps the end at the mask's soft edge, where a freed limb joins the rest (the - end with no mask). A half-masked vertex takes part of the deformation, so the mask's soft edge eases into it.

Drag Amount: the object deforms live from where the drag began, letting go is one undo step (Bend, Twist or Taper in the History), and the slider springs back to 0 for the next, which deforms the surface as it now is. The note says what it did ("Bent Sphere 1 by 40° along Y toward +X (12 ms)"), and Adjust... on the action bar sets the last one's Amount again from before it, still one step. While Amount is held nothing undoes beneath it, a stroke does not start, and a command ends the drag first as its own step. The palette's Bend, Twist, Taper and Lattice open the section on that deformer. Not in an HD window or with dynamic topology. A deformation at a lower subdivision level moves the levels above with it, and their detail keeps its size (a taper does not shrink it). Each frame of a drag deforms every free vertex again from its start: 7 to 8 ms at 1M and 55 ms (taper) to 70 ms (bend) at 10M on the 4-core VM (release), of which about 15 ms is normals.

Lattice, the section's fourth choice, is a free-form deformation cage, as Blender's Lattice modifier and Maya's lattice are: with the Move tool on (the section's Use the Move tool, or W), a box of points stands round the part the mask leaves free in place of the gizmo, 2, 3 or 4 points a side (Points a side; 3 at first), a little larger than that part. Drag a point with the mouse, a finger or the pen and it follows the pointer across the view, pulling the surface near it smoothly and the rest less the further it is (each point's pull is its Bernstein weight, so the whole surface moves together as the cage bends); letting go is one undo step (Lattice in the History), the point stays where it was dragged, and the next drag, of that point or another, carries on from the cage as it is. A press on a point takes it whatever is under it, so a point off the model drags rather than turning the view; Snap (or Ctrl held) moves it by whole grid steps, as it does the gizmo. Any other step in the History (a stroke, a mask, an undo, a move of the object, another level) makes the cage again at rest round the surface as it then is, and so does Fit the cage again; with nothing free to put a cage round, the gizmo is back. The masked part stays put and a half-masked vertex takes part of each pull. Escape or a second finger cancels a drag, as for the gizmo. Not in an HD window or with dynamic topology. The first drag of a cage notes where each vertex is in it (12 bytes a vertex, let go once the cage is made again or Lattice is no longer picked); each frame of a drag then moves every free vertex again from its start: 5 ms at 1M and 49 ms at 10M on the 4-core VM (release).

## Idle objects

Only the selected object is sculpted or moved, so the viewport draws every other object once into a cached colour + depth image and reuses it while the camera and those objects stay put (all through a brush stroke). Each frame then costs a screen-sized copy plus the selected object's triangles, however many idle objects there are. Orbiting, panning, zooming, selecting another object or changing an idle one redraws the cache. On the CPU side idle objects already cost nothing per frame (`build/bench` with `--meshes=2`).

## Simplified drawing while the view moves

While the camera orbits, pans or zooms, or an object moves, far parts of each mesh are drawn from simplified copies, then everything is drawn at full detail once the view has stayed put for a quarter of a second. The chunks a mesh is split into for culling are grouped along its BVH, four to six at a time, then groups of groups, up to one group for the whole mesh. Each group has a copy of the triangles under it with about a quarter of them, made from its children's copies by collapsing edges into existing vertices, cheapest first by quadric error. A copy never moves a vertex on its group's border, so any mix of copies and chunks meets without cracks. Each frame, the renderer draws a group's copy instead of what lies under it when the copy strays less than "Largest error" (1 px by default) from the full mesh, as seen from the camera; nearby chunks stay at full detail. On a 10M vertex sphere seen whole this draws about 500k triangles instead of 8.6M (`build/bench --lod`).

Copies are built a few milliseconds a frame, for one object at a time and never during a stroke, so a new 10M vertex mesh takes a few seconds to get all of them; until then, and for the groups an edit made stale until they are rebuilt, the chunks under them are drawn instead. Meshes under 262,144 triangles get no copies. The Stats panel turns it off ("Simplify while moving"), sets the largest error, shows how many groups are left to build and the build time per frame.

## Subdivision levels

As in ZBrush, an object can have up to 8 subdivision levels: its base mesh and finer copies, each made from the one below by one step of Loop subdivision, which splits every triangle into four and smooths the result. Each level is a whole mesh with its own sculpt data and GPU buffers, so sculpting on a level costs what it costs on a plain mesh of that size, and only the current level is drawn. Every vertex above the base stores its offset from where subdivision puts it, in a frame that turns with the surface of the level below. When the current level changes, the levels are brought up to date with the edits made on the one being left: levels above are rebuilt from their offsets, so fine detail rides on a coarse change, and levels below move each vertex by half its own change plus half the average change around it, so they follow the large shapes of a fine edit while the detail stays on top. Only the parts of each level an edit reached are visited.

Ctrl+D (or Subdivide in the Object palette's Subdivision levels) adds a level above the top one and goes to it; D and Shift+D (or Higher and Lower there) go up and down a level. When the top level has sculpt layers, they move up to the new level (see Sculpt layers), and that Subdivide is an undo step of its own with a note: Undo puts the levels back with the layers on the old top, but the object's earlier strokes can no longer be undone past it. The section shows how many vertices and how much memory the next level would take (Subdivide is refused past 12 GB), the memory all levels use, and how long the last level change took. Delete lower makes the current level the base; Delete higher drops the levels above it; both are undo steps (that object's earlier strokes can no longer be undone one by one). Undo and redo walk back across levels, switching the object to the level each stroke was made on.

## HD detail

As with ZBrush's HD geometry, an object can be sculpted up to 3 Loop steps finer than its top level without building those levels. Divide HD in the Object palette adds an HD level (on a closed mesh), and A over the object opens a window: the finer subdivision of the top-level chunks nearest the pointer, up to the window size (4M vertices by default; the section's Window slider sets 1 to 16M). The window sculpts like any level and is drawn in place of the chunks it covers; A again (or Leave HD) stores what changed and closes it. Detail is stored per top-level chunk, only for chunks that were sculpted, as each vertex's offset from where subdivision of the top level puts it, in a frame that turns with that surface, so it rides on later changes to the top level and the levels below. Outside a window it is kept but not shown, as in ZBrush.

The window's border stays where the top level is drawn around it. Brushes fade out over the last 8 top-level edges toward it, so a stroke across it leaves a slope rather than a cliff, and flat seal triangles close the join between the two meshes so it draws without pinholes. Strokes in the window undo one by one; closing it stores them and drops them from the undo history, and undoing an older stroke closes the window first. Subdivide is refused while an HD level exists (Delete HD first), Delete higher drops it with the top level, and Remesh drops it.

## Sculpt layers

Sculpt layers work as ZBrush's: the Object palette's Layers section lists the selected object's layers on its current level, newest on top. New layer adds one at full strength and starts it recording (its record button lit): while a layer records, every stroke, Smooth all and Clip also goes into the layer, as the displacement it made. Its Strength slider then dials that work from -1 (reversed) through 0 (gone) to 2 (doubled), the eye button hides or shows it, and its name can be typed over; sculpting outside the layer (record off), or in another layer, stays where it is whatever the slider does, since the surface is always the work outside the layers plus each layer's displacement times its strength. Only one layer records at a time; Recording on a layer shown at another strength first sets it to full (an undo step), and moving the recording layer's slider stops the recording. Delete takes the chosen layer's work off the surface (the select under the rows chooses it); Bake keeps it as plain sculpting and drops the layer. Adding, deleting, baking, hiding and showing are undo steps, a slider drag is one undo step however far it goes, and undoing a recording stroke takes it out of the layer too. A layer keeps 12 bytes a vertex for the nodes it moved, and nothing elsewhere; a slider change moves only those vertices. Layers belong to a subdivision level: work on other levels reaches the level as always, under its layers. Subdivide moves the top level's layers up to the new level, as ZBrush does, each displacement subdivided by the same Loop weights as the surface, so setting a moved layer to 0 gives what subdividing without it gives; the old top keeps its shape, without the layers in its list, and the recording moves up with them. Delete higher carries the deleted levels' layers down to the level it keeps, after its own: each vertex there takes half the displacement of the vertex it became above plus half the mean of that vertex's neighbours', level by level, the same way the levels pass sculpting down, so setting a carried layer to 0 takes off what it put on the kept level (its detail finer than that level goes with the levels above, as their other sculpting does). Past 32 layers on the level the rest are baked, and the note counts them. They are saved with the scene (every level's, with names, strengths and visibility; files from before layers open without any). Not in HD windows or with dynamic topology; turning dynamic topology on bakes them. Rebuilds keep them, as Nomad's layers survive a remesh: Remesh, Decimate, Mirror and weld, Slice (both parts) and Make boolean (the base) give the new mesh the layers of the level they rebuilt from, with their names, strengths, visibility and recording, and each new vertex takes each layer's displacement at the nearest point of the old surface (blended over that triangle's corners), so the shape is unchanged and moving a slider afterwards moves the new mesh as it moved the old one. Mirror and weld gives the mirrored half the kept half's displacement mirrored, and keeps the seam on the plane. A new vertex takes the layers fully within two edge lengths (of the coarser mesh) of the old surface, less the farther it is beyond that, and none beyond four (a boolean's other objects, a slice's cap), so a slider leaves no step at the seam. The layers of the object's other levels go with them, and the note says how many the rebuilt object kept and how many went. Only new vertices near what a layer displaced are searched for on the old surface, so a layer over part of the surface costs little: one over a small patch adds 36 ms to a 1M remesh (0.3 s) and 0.3 s to a 10M one (4 s), and one over the whole surface 0.4 s and 6.6 s, on the 4-core VM. Meanwhile the old level stays in memory beside the new mesh, with the search's tree and 21 bytes a new vertex: roughly 1 to 1.5 GB more at 10M while it runs (an estimate, not measured), only when there are layers. 10M vertices (`build/bench --brushes`, VM): a Draw frame while recording is the same as without (1.2 against 1.3 ms); the stroke's end adds it to the layer in 2.3 ms, and a slider change on that stroke's layer takes 4.6 ms plus 3.5 ms for normals. A script adds one with `new_layer` and sets one with `layer 2 0.5` (or `layer 2 0.5 hidden`). Exported to glTF, the layers become shape keys (see Export).

Under the Layers section's More options, on the layer the select picks: Duplicate adds a copy just above it, hidden so the surface stays as it is (its eye shows it, doubling that work), named with " copy". Invert turns the layer's work the other way at the same strength. Merge down puts what the layer and the one under it show (each displacement times its strength, so a hidden layer adds nothing) into the one under it, at full strength and shown, and drops the layer, without moving the surface. Move up and Move down change the order (an undo step, since older steps name layers by their place). Bake all keeps every layer's work as plain sculpting, as one undo step. Wide strength (remembered) lets every strength slider go from -5 to 5, ZBrush's multiplier; a strength set past -1 or 2 shows on the wide range anyway. Layers hold sculpting only, not polypaint, so there is no split of sculpt and paint. Script: `layer_edit duplicate` (or `invert`, `merge_down`, `move_up`, `move_down`, `bake_all`) on the selected layer, `set layer_wide on`.

## Brushes, masking and symmetry

Fifteen brushes, picked in the dock, the brush browser (the grid button at its end) or the brush pie, the first ten with keys 1 to 9 and 0 in this order:

| Key | Brush | What it does (Ctrl inverts) |
| --- | --- | --- |
| 1 | Draw | Pushes the surface out along the average normal under the brush (in). |
| 2 | Smooth | Moves each vertex toward the average of its neighbours. Shift smooths with any brush. |
| 3 | Clay | Builds up toward a plane just above the surface, moving only what lies below it, so dips fill first and strokes leave flat-topped layers (digs). |
| 4 | Flatten | Pulls toward the plane through the area under the brush (pushes away from it). |
| 5 | Inflate | Pushes each vertex along its own normal, so shapes swell evenly (shrinks). |
| 6 | Pinch | Pulls the surface together toward the brush's centre, along the surface (pushes apart). |
| 7 | Crease | Cuts a sharp groove: draws in with a narrow falloff and pinches toward the stroke (a sharp ridge). |
| 8 | Grab | ZBrush's Move: picks up what is under the brush where the stroke starts and drags it with the pointer, in the plane facing the camera, each vertex by its falloff weight. |
| 9 | Mask | Paints the mask (erases it). |
| 0 | Layer | Raises a flat-topped layer to one height per stroke (0.15 radii at full strength) along each vertex's normal: going over the same place again in the stroke adds nothing, and a new stroke adds one more layer, as ZBrush's and Blender's Layer brushes do (lowers). |
| | Snake hook | Pulls the surface out after the pointer for horns, tentacles and fingers: the point the stroke has reached follows the pointer in the plane facing the camera, and each step of the way, at most a quarter radius, drags what is under the brush along by its falloff. Nothing is raycast, so it leaves the surface; with dynamic topology on, the stretched triangles split as it goes. |
| | Morph | Brings the surface back toward the stored morph target, half the way a dab at full strength, so later work can be painted away in places (ZBrush's Morph brush). Without a target it does nothing. |
| | Paint | Polypaint: colours the surface with the Polypaint colour, moving nothing (takes the paint off). See Polypaint and polygroups below. |
| | Cloth | For the length of the stroke, the surface within 1.6 brush radii of where it began behaves like cloth (see Cloth brush below). |
| | History | A local undo, as ZBrush's HistoryRecall brush: brings the surface back toward how it was before an earlier step of the History, half the way a dab at full strength, only where it is brushed (see History brush below). |

History brush: by default it paints back to how the shown level (or HD window) was before the oldest step its History still holds, so in a fresh session it paints back toward what was opened. The Brush palette's History brush section, shown while the brush is held, names that step ("Before: Draw stroke, 4 steps back (the oldest held)"); Earlier and Later move it one step at a time (also in the palette, as History brush: earlier, later and use the oldest), Use the oldest goes back to the default, and a right-click or long press on a step of the History panel's bar chooses that step (see History timeline and time-lapse). A chosen step stays until it is undone or the History drops it; the next History stroke then says so and paints back to the oldest instead. The target is built when Earlier, Later or Use the oldest moves the point, or else at the first History press that finds none (a copy of the positions with the steps' saved positions laid over it, newest first: 12 bytes a vertex; on a 10M-vertex sphere about 0.1 s with four threads, the copy shared between them) and kept while its step is in the History, so the brush's own strokes, ordinary undo steps, do not move it. It reaches back neither through dynamic topology strokes (with dynamic topology on the brush does nothing and says why) nor past a change carried to this level from another (the levels bring each other up to date when the current level changes, and no step of this level holds that change): with nothing in reach it does nothing and says so. One target per level, not saved with the scene.

The Object palette's Morph target: Store keeps the selected object's surface as it is now, Delete drops it. There is one per subdivision level, kept in memory only (12 bytes a vertex: 120 MB at 10M), not saved with the scene, and none while dynamic topology is on, whose strokes add and remove vertices (turning it on drops the target). A Morph dab costs a little less than a Draw dab (10M: 0.22 against 0.31 ms in the same run). Script: `morph_store`.

Symmetry: X (the X key, or a tap on the view bar's Symmetry), Y and Z mirror every dab across the object's own planes, through its origin. Local symmetry (the view bar's button under Symmetry, or Local in the popover a long press on Symmetry opens) puts those planes, and the radial axis, through the middle of the object's box on the level being sculpted instead, as ZBrush's Local Symmetry does; the middle is measured again only after work that changes the object. Radial symmetry (Radial in that popover) lays Copies (2 to 32, 8 at first) of every dab evenly round the X, Y or Z axis, and with mirror axes on too each copy is mirrored as well, up to 256 dabs a dab; the Symmetry button shows lit while radial is on with no mirror axis. Grab carries each copy with the pointer turned and mirrored the way that copy is, Lock plane turns its plane, and Clip along a line clips every image. Every brush, voxel clay and Clip use it; the mirror-only images give the very same results as before. Settings: `symmetry`, `symmetry_local`, `radial`, `radial_count`, `radial_axis`; the exit stats' `symmetry=` reads like `x+local+radial8y`, or `none`. Each image costs about one dab.

## Polypaint and polygroups

**Polypaint** works as ZBrush's: each vertex has a colour, painted with the Paint brush in the colour picked in the Brush palette's Colour section or the Object palette's Polypaint section (Surface page), at full mesh detail (no textures or UVs). A colour has a coverage too: unpainted vertices show the material's clay, the brush lays paint over it as far as its strength and falloff reach (paint over bare clay is the paint colour from the first touch, so stroke edges fade into the clay without a dark fringe), and Ctrl takes coverage off again. The mask, hiding and Front faces only hold it back as they do any brush. Fill with colour paints everything that is not masked or hidden; Fill gradient paints it from the main colour at the object's top, as seen, to the secondary colour at its bottom (ZBrush's FillObject Grad); Clear paint takes it off the same part. Strokes and the three commands are undo steps (4 bytes a vertex of what they reach). Each subdivision level keeps its own colours: changing level carries what was painted since the level became current to the level you go to (a vertex continuing one below takes its colour, an edge vertex the average of the edge's ends, and going down a vertex takes the one above it), so a look at a coarser level and back leaves fine paint as it was, and a new level takes the colours of the one below. Colours are saved in scene files (for the current level) and exported: PLY as `red`, `green` and `blue` vertex properties, OBJ as three more numbers on each `v` line, both as the paint over white as far as it covers. On the GPU each vertex has 8 more bytes (colour and group) in a storage buffer the mesh shader reads, made only once an object has paint or groups. 10M vertices (bench, VM): a Paint stroke frame takes 1.0 ms against Draw's 1.3. Not in HD windows (whose detail leaves when they close) or with dynamic topology on (turning it on drops colours and groups; it is an undo step).

**Sculpt and paint channels**, as the reference app's sculpt and colour switches: the Colour section's Sculpt, Both and Paint (also the brush bar's channel button and the command Sculpt and paint) say what every sculpting brush changes. Sculpt moves the surface, as before; Both moves it and paints the main colour under the same falloff, alpha and symmetry in the same stroke and undo step (an inverted brush digs and still paints); Paint lays the colour and moves nothing, a Paint brush with that brush's falloff. Paint, Mask, Grab and Cloth keep to their own channel, and Shift's smoothing and the wheel's Mask only sculpt or mask. Paint needs a level's own vertices, so in an HD window or with dynamic topology on Both only sculpts and a Paint stroke is refused, and voxel clay, which has no polypaint, refuses Paint strokes too. The **secondary colour** (under the Colour section's More options) is swapped with the main one by Swap colours: V, the Colour section's button, or a long press on the brush bar's Colour. Alt, which turns the view here, does not paint with it. The channel and the secondary colour are remembered (`paint_channel`, `paint_color2`); the exit stats print `paint_channel=`, both colours, `brush_subtract=` and `painted_vertices=`.

**The Colors card** (`src/app/kit_colors.odin`; design and sources in the project notes, `notes/colors/colors-card-design.md`) is where colours are picked, laid out and named as Procreate's Colors panel with ZBrush for iPad's Color card's strengths. A tap on the brush bar's Colour (or the Colors command, or Open Colors in the Colour section) opens it beside the brush bar; it stays open while you paint, its dots drag it, and holding them puts it back in the tray's Colour section. Its header holds the main and secondary colours (a tap picks which one the pickers set, ringed in the accent; a long press swaps them), Swap colours, Fill with colour, Fill gradient, the Eyedropper and Close. Tabs along its bottom pick how to pick, as Procreate's: **Disc** (a hue ring round a disc of every saturation, across, and brightness, up), **Classic** (a saturation and brightness square, then Hue, Saturation and Brightness sliders), **Harmony** (Complementary, Split Complementary, Analogous, Triadic or Tetradic from the list at its top; a disc of hue round it and saturation out from its middle with a reticle for each colour of the scheme, which a drag on the main one moves together, the Brightness slider, and the scheme's colours as swatches; a tap on another colour's reticle or swatch makes it the colour), **Value** (HSB or RGB sliders with their values in degrees, percent or 0 to 255, and the Hexadecimal code to read or type: three or six digits) and **Palettes**. Each slider's track shows the colours it runs through and its knob the colour it sets. Under the first four are the **history**, the last seven colours picked (a pick joins it when the finger or the pen lets go, a code is typed, a swatch is tapped or the eyedropper picks; a colour picked again moves to the front; Clear empties it), and the default palette. Palettes lists the built-in palettes (Skin, Creature, Clay and stone, Greys, Vivid) and up to eight of your own (28 swatches each); + makes a new one, which becomes the default; the circle at a palette's left makes it the default, its menu duplicates it or deletes one of yours, your palette's name is a text field, a tap on its empty slot saves the current colour there, and a long press on one of its swatches sets it to the current colour or deletes it. A swatch tap anywhere makes that the colour. Every swatch is a whole touch target (48 points), so a row holds seven; the card's body scrolls when the window is too short for it. The **Eyedropper** (Shift+C, ZBrush's C) picks the colour of the surface under the pointer at once when the pointer is over the viewport: the polypaint over the material's colour, as it is rather than as lit, which is the colour to paint with. From its button (or the palette) it waits for the next press on the viewport instead: holding and dragging shows a loupe over the finger, its top half the colour under it and its bottom half the colour now, as Procreate's, and letting go picks; a release over nothing picks nothing, and Escape stops it waiting. Voxel clay and HD windows give the material's colour. The tab, the harmony, HSB or RGB, the default palette, the history and your palettes are remembered (`colors_tab`, `colors_harmony`, `colors_value_rgb`, `color_default`, `color_history`, `color_palette` lines); the exit stats print `colors_tab=`, `color_history=`, `color_palettes=`, `eyedropper=` and `window_colors=`.

**Polygroups** split a mesh into parts, as ZBrush's do: a group number per triangle, shown in flat colours with View > Polygroups (Shift+W). Ctrl+W groups the masked part as one new group and clears the mask, or with nothing masked makes what is shown one new group (with nothing hidden, the whole object becomes one group), as in ZBrush. The Object palette's Polygroups section (Select page) has the same as buttons (Group visible, Group masked), and, under More options, Groups by creases (a group for each part of the surface between edges sharper than the Angle, 35 degrees by default: a cube's six faces, a hard-surface import's panels), Groups by normals (each group keeps within the Angle of the way its first triangle faces, so even a smooth curve is cut into facets), Groups by pieces (a group for each piece joined by edges, as ZBrush's Auto groups), Groups by UVs (a group for each UV chart of a retopologized object, on any of its levels: a triangle above the base takes its chart from the one it was cut from), Merge similar (groups of as many triangles whose areas are within 1% become the lowest numbered of them: a row of copies of one shape becomes one group) and Clear groups. Each groups only what is shown; hidden triangles keep their groups. On the test VM (release build, 4 threads) at 10M vertices Groups by pieces and by normals take about 2 s each and Merge similar 0.4 s. A Ctrl + Shift click on a group shows only that group; a second Ctrl + Shift click on it when it is all that shows hides it and shows everything else; with Alt as well, the click masks the group instead. A Ctrl + Shift click on empty space, or on an object without groups, still shows everything. Every change is an undo step, groups follow level changes as colours do (a triangle going up takes the group of the triangle it was cut from, going down the group of the middle one of its four), and they are saved with the scene. Drawing them costs no triangle data: each vertex carries one group to the GPU and each triangle is drawn starting from a corner that carries its own group, whose value a flat shader input takes, so borders are sharp; a triangle none of whose corners can carry its group shows a neighbour's colour (none in the tests; at most one in a thousand is allowed). While the view moves, far parts drawn from simplified copies may show ragged group borders. Script: `group creases` (or `visible`, `masked`, `normals`, `pieces`, `uv_charts`, `merge_similar`, `clear`), `polygroups on`, `set paint_color 0.2 0.4 0.9` (0 to 1), `paint fill` and `brush paint`.

Masking works as in ZBrush: each vertex has a mask from 0 to 255, and every brush moves it only by what the mask leaves (a fully masked vertex never moves). Masked areas are drawn darker. In the Object palette's Mask section, Clear (Alt+M), Invert (Ctrl+I) and Mask all change the whole mask at once; mask strokes and these commands are undo steps like any stroke. Blur, Sharpen, Grow and Shrink move the mask's edge, as ZBrush's BlurMask, SharpenMask, GrowMask and ShrinkMask and Blender's mask filters do, a step at a time: each vertex takes from the corners of its triangles their average (Blur), their highest value (Grow) or their lowest (Shrink), so a step reaches one ring of triangles further, and Sharpen pushes each partly masked vertex toward masked or unmasked against half a Blur step, which narrows a soft edge to a sharp one that stays smooth along the triangles. Mask cavities masks the creases and dents, as ZBrush's Mask By Cavity does: each vertex is masked by how far it sits below the average of its neighbours along its normal, measured against their distance, so grooves and pores go dark and flat or bulging parts stay free; Blur after it softens the result. Mask hidden (under More options, and Mask it on the action bar while something is hidden) masks every corner of a hidden triangle fully and unmasks everything else, the one mask command that writes hidden vertices: hide a part, Mask hidden, then Show all, and the mask is that part. Steps sets how many steps a press takes (3 by default): since a step is a ring of triangles, a denser mesh needs more for the same distance. The section shows what the last command did and how long it took. The mask is carried when the object changes subdivision level (a vertex that continues one of the level below takes its mask, a new edge vertex the average of the edge's ends), so it holds on every level. An HD window starts unmasked and its mask is dropped when it closes. The mask costs no GPU memory or upload: it rides in the low 4 bits of each of the two 16-bit halves of the vertex's packed normal, which still places the normal within 0.1 degrees.

Mask by, Mask adjust and Mask region (under the Mask section's More options) are ZBrush's Masking palette's automatic masks. Mask by masks the whole selected object, replacing its mask, by one of: Peaks (the crests, more the higher they stand above what is around them), Curvature (crests and dips alike), Smoothness (the flat and gently curved parts), Depth (the nearest part of it from the view fully and the farthest not at all), Facing away (what faces away from the view; edge-on parts half), Colour intensity, Colour hue (the polypaint near the main brush colour's hue) and Colour saturation (from the polypaint), Open borders (the edges of holes and of the shown part), Group borders (where polygroups meet) and Creases (edges sharper than the Polygroups section's Angle). Strength (for the first three) sets how much the shape counts, a curve takes what the kind measures to the mask, as the falloff editor does, and Blur (0 to 5 steps) softens the result in the same undo step. Mask adjust reshapes the mask as it is through its own curve, then blurs it: a steeper curve hardens a soft edge, one above the diagonal strengthens a partial mask. Mask region fills a closed outline of mask: on each piece of the object that has any mask, every unmasked part the outline cuts off is masked fully but the largest (by area), so a ring of mask fills on its smaller side; an outline with a gap fills nothing. Each is one undo step, leaves hidden vertices' mask alone (a Blur too), and says "nothing changed" where there was nothing to go by (no polypaint, a grey main colour for hue, no polygroups, no closed outline). The colour kinds and Group borders are refused in an HD window and with dynamic topology on, as polypaint is. On the test VM (release build, 4 threads) at 10M vertices Mask by takes 60 ms (Depth) to 240 ms (Peaks), 400 ms with 5 Blur steps, 0.5 s to 0.7 s for the edge kinds, Mask adjust 60 ms and Mask region 0.8 s. They are in the command palette and the gesture list (Mask region, Mask by facing away and curvature, Mask adjust), and the settings file and scripts keep the section as `mask_by_kind`, `mask_by_strength`, `mask_by_blur`, `mask_by_curve` (its two control points, `x y x y`), `mask_adjust_blur` and `mask_adjust_curve`. Script: `mask_by peaks`, `mask_adjust`, `mask region`.

Selection sets keep masks to bring back, as ZBrush's Selection Sets do (Object palette > Selection sets). Store mask as set (also in the command palette) keeps the selected object's mask under a name, "Set 1" and on, which its row's text field changes; Restore on a row makes that set the mask again, and for the set the list picks, Add to mask takes the more masked of set and mask at each vertex, Subtract takes the set off the mask, and under More options Store over replaces the set with the mask and Delete removes it. A restore is one undo step, like a mask command, and leaves hidden parts' mask as it is; storing, renaming and deleting are not undo steps, as in ZBrush. A set is kept by the level it was stored on and restores on any level, carried there as the mask is when the level changes; deleting levels carries the sets of the deleted ones to the current level. An object keeps up to 16. A remesh or any other rebuild (Decimate, Mirror and weld, Slice, Make boolean) drops them, and its note says how many went (Undo brings them back with the old mesh); turning dynamic topology on drops them too and says so, and they cannot be stored or restored with it on or in an HD window. The palette's Restore selection set 1 to 9 can be given keys (Settings > Keys). Sets are saved in scene files (version 10, which older versions of the app do not open), as runs of equal values where that is smaller, so a mask costs at most a byte a vertex.

Mask shapes work as ZBrush's: with the Brush tool, Ctrl and a left drag that starts on empty space (not on an object) draws a rectangle, or a lasso when the Mask section says so, and letting go masks everything of the selected object inside it, through to the back side; with Alt held too it unmasks. Each shape is an undo step. The polygon is filled into a 1024 x 1024 coverage grid first, so a lasso of any length costs a lookup per vertex: at 10M vertices a shape takes about 25 ms on the test VM, 2 ms at 1M (`build/bench --masks` has the rows). A drag that starts on an object is a stroke as before, and Alt + left drag without Ctrl still orbits.

Ctrl + Shift and a left drag with the Brush tool runs the gesture tool chosen in the Object palette's "Hide, clip and slice" section (remembered between runs): Hide rectangle (the default, as ZBrush's SelectRect), Hide lasso, Clip, Slice or Knife; the brush browser's Clip and hide tiles choose it too (see Brush presets). A Ctrl + Shift click without a drag shows everything again, whichever is chosen, or on a polygroup isolates it (see Polypaint and polygroups).

Shapes wait for Apply when drawn with a finger or the pen (Settings > Touch > Shapes, "Mouse at once" by default): a mask rectangle or lasso (Ctrl, or the rail's Mask, from empty space), a hide rectangle or lasso, and a Clip, Slice or Knife line stay on screen when the drag lets go, with a bar under them: Apply (Enter), Flip (Unmask, Hide inside, Other side; not for Slice) and Cancel (Escape or Back, once no menu or popover is open). White handles sit on a rectangle's corners and a line's ends, and a ringed one in the middle moves the whole shape; each takes a press within half a touch target, by a finger, the pen or the mouse, and two fingers landing on one still pinch or turn the view, leaving the shape where it was. A press anywhere else does what it always does, so the view can be turned, panned or zoomed under the shape before applying, and Apply uses the view as it is then; a new shape replaces it, and leaving the Brush tool lets it go. A shape drawn with the mouse applies as it lets go, as before. "Always at once" and "Always after Apply" make every pointer the same. Script: `set shape_apply auto` (or `now`, `confirm`).

Hiding works as ZBrush's: the hide tools draw a rectangle or a lasso (green), and letting go keeps only the triangles whose middle is inside it shown, through to the back; hold Alt as you let go to hide what is inside instead (red). Ctrl+H (or Show all) shows everything and Ctrl+Shift+H (or Invert) swaps hidden and shown; it never hides every triangle. Hide masked hides the triangles masked at least half at every corner, and Hide unmasked the others, to work on the masked part alone; the two are exact complements, so from a fully shown object Invert turns one into the other, and what is hidden already stays hidden. Both are in the Hide, clip and slice section and the command palette, with no keys until one is assigned. Hidden triangles are not drawn and no brush, mask, mask command (but Mask hidden) or clip moves a vertex all of whose triangles are hidden, and the brush and picking look through them; vertices on the edge of a hidden part still move. Each hiding change is one undo step. Each subdivision level keeps its own hidden part. Hidden parts are not saved in scene files, and hiding is refused in an HD window or with dynamic topology on (turning dynamic topology on shows everything); an HD window does not open while anything is hidden. On the test VM (release build) hiding half of a 10M-vertex sphere takes about 0.3 s. Script: `hide y` hides the + side of the selected object's middle across Y, keeping the - side shown (`hide -y` the other way; also x or z).

The Hide, clip and slice section's More options change what is shown a step at a time, as ZBrush's Visibility palette does. The edge of the shown part is every vertex with a shown triangle and either a hidden one or an open border among the shown (the edge of a hole). Grow shows each hidden triangle with a corner on a shown one, a ring more, and Shrink hides each shown triangle with a corner on the edge, a ring less (Grow then Shrink never hides what was shown first). Grow all shows the whole of each piece with anything shown (triangles sharing a vertex are one piece, as for Split to parts); Grow to groups the whole of each polygroup with anything shown. Outer ring keeps only the shown triangles with a corner on the edge. Show masked shows the hidden triangles masked at least half at every corner, so it undoes Hide masked. Grow and Shrink are also on the action bar's Hidden group and in the gesture list. Each is one undo step, refused like the rest of hiding when it would hide everything. On the test VM at 10M vertices (half hidden) Grow takes 20 ms, Shrink 0.24 s, Outer ring 0.32 s, Grow all 1 s and Grow to groups 60 ms. Script: `grow_visible`, `shrink_visible`, `grow_all_visible`, `outer_ring`, `grow_to_groups`, `show_masked`.

Slicing works as ZBrush's SliceCurve but makes separate objects: the Slice tool draws a line (cyan) across the viewport, and letting go cuts the selected object in two along the plane through the line and the view direction, through to the back (`geom.mesh_slice`, `src/geom/slice.odin`). Each part is closed with a cap of evenly sized triangles (as long as the edges the cut crossed, up to 100,000 triangles a cap), so both stay closed and can be sculpted, remeshed or exported; holes and several separate cuts (a torus cut through) are filled correctly. The part on the right of the drag becomes a new object beside it; the other stays selected. It works on the level the object is on and rebuilds it like a remesh: levels, HD detail, mask and hiding go, and symmetry is not used. One Ctrl+Z undoes both parts. On the test VM a 1M-vertex sphere slices in about 0.4 s and a 10M one (20M triangles) in about 6 s plus 2.4 s to set the two objects up. Script: `slice x` slices the selected object across the middle of its bounds along x (or y, z).

The Knife works as ZBrush's KnifeCurve: it draws a line as Clip does, shading the side that goes (the right of the drag; Alt, or Flip on a finger's line, the other side), and letting go cuts the selected object along the plane through the line and the view direction, through to the back, throws that side away and closes the cut with a cap as Slice does (`object_knife`), so what is left stays closed. Unlike Clip, which flattens and keeps every vertex, it removes the geometry; unlike Slice, nothing becomes a new object. It rebuilds the object like a remesh, as one undo step: levels, HD detail, mask and hiding go, the level's sculpt layers come across, symmetry is not used, and dynamic topology's mesh is compacted first. A line that misses the object, or would take all of it, changes nothing. Script: `knife x` cuts away the + side of the middle along x (`knife -x` the - side; y and z too).

Clipping works as ZBrush's Clip Curve: with the Clip tool chosen, Ctrl + Shift and a left drag draws a line across the viewport, shading the side to the right of the drag (hold Alt to take the other side instead; what is held when you let go counts). Letting go flattens every vertex of the selected object on the shaded side onto the plane through the line and the view direction, through to the back, so the part past the line becomes a flat cut face. Nothing is deleted: the triangles stay, lying in the plane (Remesh selected afterwards to tidy the cut). It mirrors with the brush's symmetry, leaves masked and hidden areas (partly masked ones move part of the way), and is one undo step. Not with dynamic topology on. On the test VM a clip takes 35 ms at 10M vertices for a small cap and about 150 to 250 ms when it cuts away half the mesh, most of it saving 60 MB of positions for undo; the Object palette shows the last one's time.

Stroke (the Brush palette; Dots, Rectangle, Spray, Roll, Drag dot, not shown for Grab, Snake hook and Cloth, which drag what they pick up): Dots lays dabs along the path, as above. Rectangle (Drag rectangle), as ZBrush's DragRect, lays one stamp where the drag starts and redoes it as the pointer moves: its radius is how far the pointer is from the start and, with an alpha, the image's top faces the pointer, so an alpha can be placed, sized and turned in one drag. Each redo first puts back what the stroke did so far from the undo copies it already keeps (`sculptor_stroke_restore`), so it stays one undo step and costs one dab a frame. It works with every brush but Grab and Snake hook, and not with dynamic topology, whose strokes change the triangles (those use Dots). Spray, as ZBrush's Spray, lays a dab every half radius scattered up to the Spread slider's share of the radius from the path on screen (0 to 1.5, default 0.6), each 75 to 100% of the size and 50 to 100% of the strength and, with an alpha, turned its own way, for texture without a visible repeat. Its random numbers come from the stroke's seed and the dab's step (SplitMix64), and the seed comes from a counter each stroke takes the next of, kept by the stroke recorder, so a replayed Spray stroke lands exactly the same dabs. Roll, as ZBrush's Roll, lays a dab every diameter, the first a radius from the press, with the alpha's top along the stroke whatever the alpha's mode, so an alpha tiles like a tape rolled out (stitches, zips, chains); without an alpha it is Dots at that spacing. Drag dot, as ZBrush's DragDot, lays one stamp at the brush's size where the press is and slides it with the pointer until let go: each move puts back what the stroke did (`sculptor_stroke_restore`) and lays the stamp where the pointer meets the surface as it was, so it stays one undo step and costs one dab a frame; off the model the stamp stays where it was. Not with dynamic topology nor on voxel clay (those use Dots). Spacing (Stroke > More, with Dots; `stroke_spacing` in settings.txt, 5 to 200% of the radius, default 25%) sets how far apart Dots lays its dabs, as ZBrush's LazyStep: wider for a dotted line of stamps, narrower for a smoother one at more dabs a frame. Colour spray (with Spray, 0 to 100%, `color_spray`) makes each Spray dab's paint colour that share lighter or darker in each channel, drawn from the stroke's seed as the scatter is, for mottled polypaint that replays the same. Shift's Smooth and the rail's Smooth and Mask always stroke as Dots. Presets keep the stroke mode and the spread; settings.txt keeps them as `stroke` and `stroke_spread`. Script: `set stroke spray` (or `dots`, `drag_rect`, `roll`, `drag_dot`).

Front faces only (a switch in the Brush palette's Options, as ZBrush's BackfaceMask) makes every brush but Grab, and the mask shapes, leave the vertices whose normal faces away from the viewer, with a short fade across the ones seen edge-on, so a stroke on a thin part such as an ear, a fin or a sheet leaves its far side alone and a mask rectangle stops at the visible side. It is per vertex, not a visibility test: a front-facing part hidden behind another is still reached. With symmetry, each mirror image faces the mirrored way. Script: `front_only on`.

Lock plane (a switch in the same Options section, as ZBrush's Original plane and Nomad's lock) keeps the area the stroke's first dab found, its normal and middle, for the whole stroke, so a long Flatten or Clay stroke across changing ground flattens to one plane instead of following it, and a Draw stroke pushes one way throughout; a stroke joining one (Join strokes) keeps its plane, so a long Flatten laid in pieces stays on one. It applies to Draw, Clay, Flatten, Pinch and Crease, and to any brush with an alpha (which lies on that plane); Clay's offset and a leaning pen still apply on top, each mirror image takes the plane mirrored, and the switch greys out on the other brushes. Connected only (as ZBrush's topological auto masking) makes a dab work only on what joins the place it presses (the triangle under its centre) through the shown surface without leaving the brush, so a finger pressed against the next one, the far lip of a thin slit or a separate shell inside the brush stays untouched however near it is in space, and hidden parts join nothing; it holds for every brush but Cloth (masking and painting included, and Grab, which then picks up only the part joined to where it was pressed, ZBrush's Move Topological), and greys out for Cloth. Both are commands too (Lock plane, Connected only and Front faces only in the palette, for a key or a pie), presets keep them, and `.strokes` files store them. Lock plane costs nothing; Connected only finds what is joined on the worker threads, a BVH leaf each, and costs about as much again as the dab: a Clay stroke at 10M vertices takes 1.8 ms of brush time a frame with it against 0.7 without (release, `--bench-stroke=120`, 4-thread VM), and 8 bytes a vertex once first used. Script: `lock_plane on`, `connected on`. The same section has All depth for Grab (ZBrush's Move Infinite Depth): Grab then picks up everything within the brush's radius of the line from the eye through the press, however deep, so a grab on the front of a head moves the back of it too (All depth wins over Connected only, which greys out for Grab while it is on). And for Smooth, Smooth only: All, Valleys (only the vertices lower than their neighbours along their normal: dents fill, ridges stay) or Peaks (only those higher: bumps come down, dents stay); Shift smoothing with any brush smooths the same way, and voxel objects smooth everything. Settings `grab_depth`, `smooth_only`; presets and `.strokes` files keep both (a preset with either set is a line a build from before them skips, as one with a focal shift is for builds before that). A plain Grab with Connected only on (it is one switch for every brush) now moves only the joined part; `.strokes` files from before keep their Grab strokes as drawn.

Symmetry (X, Y and Z on the toolbar at the top; the X key toggles X) mirrors every dab across those planes through the object's origin, up to 8 images with all three; Grab drags each image the mirrored way.

## Voxel sculpting

The `voxel` package sculpts a volume rather than a surface, the way 3D-Coat's voxel room does: clay can be added anywhere, holes punched through, pieces merged, with no topology to stretch or tear. The field is a signed distance (negative inside, in voxels) kept only in a band of 3 voxels either side of the surface, in bricks of 8³ 16-bit values (4096 units a voxel, clamped at ±4 voxels); bricks that are all one clamp are tiles (a code in the chunk's table: Empty or Inside), so memory follows the surface's area, not the volume: a sphere 512 voxels across is 29k bricks and 36 MB, 1024 across is 119k bricks and 146 MB. The domain is 4096³ voxels in 128³ chunks, each made on first use with a table of its bricks and of its mesh nodes.

Brushes change the field a brick a job. Add and Subtract are a smooth union or difference with a stamp sphere whose cap protrudes a tenth of the radius out of (or into) the surface, cut to the brush's footprint: the stamp's own distances fill the band it moves into, so a dab can add more than a voxel of clay. Smooth moves each value toward the mean of its 27 neighbours, read from a window gathered before anything is written; Flatten clips to (or, inverted, fills up to) the plane under the pointer; Inflate offsets by at most a voxel a dab. A dab's serial pre-pass picks the bricks within reach, makes bricks of the tiles clay can arrive in and saves each brick once a stroke for undo; the jobs write their own bricks; the post-pass turns bricks that are all one clamp back into tiles and makes a brick of any tile beside a face the band has reached, so the surface never runs into a tile. Every new value depends only on old values, so one thread and many agree bit for bit. At a stroke's end the touched bricks (and the blends between stamps) get true distances back: voxels beside a sign change are kept, the rest solved by Godunov sweeps, one per corner-to-corner direction, each visiting the bricks in wavefronts (the bricks whose coordinates sum to the same level share no face, so a wavefront runs in parallel and reads its neighbours live, Gauss-Seidel across bricks as inside them); a brick a sweep left as it was is skipped until a neighbour changes, and the repair stops at the first sweep that moves nothing by more than a 256th of a voxel, usually the eighth.

The surface is meshed by surface nets a node (16³ voxels) at a time from a 20³ window: one vertex per loop of edge crossings in each crossed cell (the crossed edges joined through the faces they share), at the mean of the loop's crossings, its normal the field's gradient blended from the cell's corners, and a quad per crossed edge the node owns joining the four cells' vertices for that edge. The field keeps no saddle face, a 2×2 face of voxels with its two inside corners on a diagonal, which the surface would cross twice: after a field is built or read, and at a stroke's end over the bricks it touched, the inside corner nearer the surface is moved a hair outside, and again for any saddle that flip makes, so every cell face is crossed twice or not at all, every edge of the surface is in exactly two triangles and every vertex's triangles form one fan: the surface is closed and manifold, which `--check-mesh` reports. A sheet or neck thinner than a voxel loses a voxel to the flips, and a sheet one voxel thick on a diagonal dissolves. Between a stroke's dabs a saddle may stand for a few frames, with an edge in four triangles there, until the stroke ends. Each node owns a slot of vertices and a slot of indices in one mesh with a quarter headroom; a remeshed node that still fits rewrites its slot and the frame uploads only those slots; one that outgrew it moves to a hole or the end. Unused index slots are zeros (triangles on a dummy vertex), so the whole buffer can be drawn; a tenth of the slots is kept in reserve so the arrays grow (a new GPU copy) at a stroke's end rather than in the middle, and they are compacted when holes take over half. A brick dirties only the nodes that can see a change (a changed value within 3 voxels of the surface, and a neighbour node only when the change is within 2 voxels of its side). Border vertices are duplicated between nodes and agree bit for bit, so no seam shows. Each node's chunk carries the normal cone of its triangles, worked out from their face normals when the node is meshed, so the renderer skips the nodes facing away from the camera (`--no-cull` draws them all) as it does a mesh's chunks. Each vertex carries a code naming the cell it stands for as the node that owns the cell indexes it, its loop, and which neighbour of that owner made this copy; the conversion to a plain mesh (Convert to mesh, Export) welds the copies to their owners' vertices by those codes, each node in parallel, with no position sort, and gives the same mesh on one thread and many.

The mask lives in the volume too, as 3D-Coat's Freeze does: a brick may carry a mask brick of a byte a voxel (255 fully masked), and a masked voxel takes only the unmasked share of any dab's new value, so a masked patch holds still under every brush. The Mask brush (Ctrl, the rail's Mask, or the brush itself) paints the mask with the brush's falloff and strength (inverted, it erases), the mask rectangle and lasso mask every voxel of the band whose centre projects inside the shape (Front only reads the field's gradient), and Clear, Invert and Fill work on the whole clay; Cavity, Hidden, Blur, Sharpen, Grow and Shrink need a mesh and say so. Each surface vertex samples the mask field where it stands and the value rides up with the normal, so the mask shows as on a mesh. A brick that collapses to a tile drops its mask, a brick made from a tile starts unmasked, and undo saves the touched bricks' masks with their values. Convert to mesh hands the vertex masks to the mesh's sculptor, as Nomad keeps masks through a remesh; Res+ and Res− and a boolean drop the mask. Undo saves the bricks a stroke touched, 1 KiB each, as they were (or the tile they were) and swaps them with the live ones, so a step is its own inverse; 512 MB of steps are kept an object. The scene file holds the field chunk by chunk (tag `SVOX`, version 3: tile codes, then each brick packed after its byte count, a masked brick's mask packed after it; versions 1 and 2, whose bricks are raw, still read). A brick packs as one chain of its values in memory order, each sent as the change of its difference from the one before (a distance field is smooth, so most of these fit a byte) and equal values as one run (the clamp either side of the band), to 46 % of the raw bytes on a 256-across sphere, plain or sculpted (zlib at level 6 gives 48 %); a mask packs as runs; a brick or mask that would not shrink is written raw; the surface is meshed again on reading, and a damaged section is refused.

None of it has been tried on Windows or a real GPU.

In the app a voxel object is a kind of object beside the mesh ones: Add object with As voxels on (Scene palette), the Objects card's Add > Voxel sphere, or `--voxels=N`, adds a sphere of clay of radius 1, N voxels across (the Scene palette's size picks N so the surface has about that many vertices: 500k is 304 across, 1M is 432, 5M and up 1024, the most). It is picked, orbited around, moved, turned and scaled, listed, copied, duplicated, deleted, hidden, ghosted and saved as any object (scene file version 13, which older versions of the app do not open: the clay's `SVOX` section stands where a mesh's levels go). Draw, Clay and Layer add clay (Ctrl, or Invert, takes it away), Smooth, Flatten and Inflate do what they do on a mesh, with pressure, symmetry, Spray and Line strokes and the brush ring on the surface; the Mask brush, the mask shapes, Ctrl+I and Alt+M mask the clay (above); booleans work on the clay itself (see Booleans below); the other brushes, hiding, levels, dynamic topology, HD, the rebuild tools, polypaint and layers need a mesh, and say so in a note rather than run. Each stroke is one undo step in the History with the mesh strokes (512 MB of steps an object, the oldest dropped past that). The Object palette's Voxels section (Build page; a voxel object shows only Transform, Voxels and Booleans) gives the clay's size and Convert to mesh, which rebuilds the object as a mesh of its surface with the node borders welded, as one undo step, for every mesh tool; Export writes that surface. For a mesh object the same section has Voxels across (32 to 1024, whole nodes of 16; setting `voxel_across`, 0 for the resolution the object's vertex count maps to) and Convert to voxels (also in the Objects card's more menu and the command palette), which rebuilds the object as clay of its shape: the mesh is laid on the voxel lattice, rays along every voxel row find where they cross it with the exact tests the voxel remesh uses, the winding number along x says which voxels are inside (overlapping parts merge, as a remesh does), a voxel beside a crossing gets the distance a plane through the crossings on its axes would have, and the band repair solves the rest, so the surface lies within a voxel of the mesh (a unit sphere round-trips within one voxel; a torus keeps its hole). An open mesh is filled where that winding is positive, as Remesh fills it. Levels, HD detail, mask, layers, paint and the polygroups' materials go, as one undo step; a mesh without volume is refused with a note. For a voxel object the section also has Res+ and Res− (also in the command palette), 3D-Coat's names: Res+ doubles the voxels along each side (up to 1024 across) with the surface kept where it is, the finer band read from the old field between its voxel centres, and Res− halves them (down to 32), the coarser band read at the old centres and solved again by the band repair, so detail finer than the coarser voxel goes; each is one undo step that drops the clay's own stroke steps, as a rebuild does. The lattice's domain is centred on the object and halves with Res+, so clay more than a quarter of the domain from the middle (sixteen times a unit sphere's radius at 256 across, eight at 512) is refused with a note rather than cut off. The exit stats add `voxel_resolution` (the largest in the scene). The surface is closed and manifold once a stroke ends (see the field's saddle faces above), so Convert to mesh gives a mesh every mesh tool takes; `--check-mesh` checks the welded surface after finishing any stroke a `--bench-stroke` run leaves open. Exit stats: `voxel_objects`, `voxel_bricks`, `voxel_field_mb`, `voxel_surface_mb`, `voxel_undo_mb`; `--check-mesh` checks the welded surface. The dabs, remesh and upload are the numbers above: on the VM a 128-across sphere (86k vertices) takes a Draw stroke at 2.4 ms a frame of brush time and 200 KB a frame of upload in the debug build. The Objects card's picture of a voxel object is its clay's surface, drawn again once it has settled, as a mesh's is. Not yet: the bench stroke's level steps.

## Voxel remesh (DynaMesh)

Rebuild (Object palette, Shape page) replaces the selected object's topology by what it is for, picked on its tabs: Even (this remesh), Fewer (Decimate, below) or Quads (Retopologize, below), each at the count its Density slider sets (1k to 25M vertices, or 100 to 1M quads), and its button runs it. While Density is held, and for 1.5 s after, or while a mouse is over it, the selected object shows a checkerboard of the cells that density gives, as Nomad's resolution preview does: for Even the very lattice the remesh will build on (each cell becomes about one vertex; the line under the slider gives the cells' width), for Quads squares of the mean quad's size. Fewer has none, since decimation is dense where the detail is. Cells smaller than about three pixels fade to an even tint rather than shimmer. The preview measures the object's area once per change of its mesh, spread over frames at about 1 ms a frame (a 10M sphere takes about 90 ms in all on this repo's 4-core VM, so its cells show after a few dozen frames); drawing it is a few instructions in the mesh shader, and it is never in a studio render or a time-lapse. `--density-preview=N` shows it held on, for an even remesh of N vertices.

Remesh (Rebuild's Even, or Ctrl+R at the object's own vertex count) rebuilds the selected object as an even surface of about that many vertices, as ZBrush's DynaMesh does: stretched triangles from Grab or long strokes become even again, overlapping or self-intersecting parts merge into one closed surface, and anything thinner than the lattice spacing goes. It keeps the shape of the level the object is on; its levels, HD detail and mask go, and Ctrl+Z brings them back (HD detail apart).

How it works (`src/geom/remesh.odin`): the object is laid on a lattice whose spacing gives about the asked-for vertex count (at most 4,096 lattice points along any axis, DynaMesh's top resolution). A ray along each lattice row finds where it crosses the mesh and which way, using exact fixed-point tests so a ray through a shared edge or vertex counts it once, and a lattice point is inside where the winding number is positive. Rays along y and z find where the surface crosses those lattice edges. Marching cubes then joins the crossings, with one rule on ambiguous cube faces that makes the result closed and manifold (every edge between exactly two triangles), and three rounds of relaxation along the surface even out the triangles. Rays, crossings and cells are stored only where the surface is, so memory grows with the surface's area rather than the lattice's volume.

## Project detail

**Project detail** (Object palette), after ZBrush's ProjectAll: the selected object's shown level takes the shape of the object chosen in Project from, and its polypaint too with Polypaint too. Each vertex looks along its normal both ways, as far as Reach (a share of the selected object's size, 0.03 by default), for the other surface, and moves to the nearer hit by Strength; the mask holds vertices back as it holds a brush. Vertices that find nothing stay put. It is one undo step.

By default each object is read in its own space, as baking does, so a copy made by Duplicate or Retopologize, which is put beside the original, projects as if it lay on top of it; As placed uses where the two sit in the scene instead. The usual round trip: duplicate a sculpt, Remesh or Retopologize the copy (the detail goes), subdivide it a level at a time and Project detail at each level from the lowest up, so every level holds what it can of the original. A 100k-vertex retopology projected from a 1M sphere takes about 0.3 s on the VM, the source's BVH included. Not under dynamic topology on the selected object. Script: `project 1` projects from the first object onto the selected one (any object's number, counting from 1, down the Scene palette's list).

## Curve and insert tools

**Curve** (C, or Curve on the toolbar; its settings fill the tray's first palette), after ZBrush's curve brushes: drag over any surface and, on release, a new object follows the path. It is made one of three ways. **Tube** sweeps a circle of Sides sides along it, capped at both ends; Lift sets how far its middle sits out from the surface, in radii, so 0 half buries it and 1 rests it on top. **Stitches** sets leaning bars across the path. **Zipper** sets interlocking teeth from alternate sides. Width is a share of the brush's diameter where the path began, so S resizes it. The path is resampled at even steps and smoothed three times, which takes out the hand's wobble. Each part is turned to the path's frame there (along the path, out of the surface and across it), so the result follows the surface's curvature. The result is an ordinary closed object: remesh it to sculpt it, or mark it Union for the booleans.

**Insert** (I), after ZBrush's insert mesh brushes: click a surface to put a shape there at the brush's size, standing on the surface's normal and turned with the view; drag before letting go to size it instead. The shape is any primitive or starter at Vertices (a starter is never under 15,000), or a copy of any object in the scene (Copy of ... in its list), fitted to that size. Sink pushes it into the surface by that share of its half size. **Mark it as** sets its boolean mark as it is made, so a cylinder marked Subtract, with Live boolean on, cuts a hole at once.

Each curve or insert is one undo step. The geometry is in `src/geom/curve_mesh.odin`. Script: `draw_curve tube` (or `stitches`, `zipper`: a wavy path across the middle of the view) and `insert_middle cube` (or another shape, at the middle of the view).

## Booleans and Extract

**Booleans** (Object palette), after ZBrush's Live Boolean: set "The selected object is" to Union, Subtract or Intersect on any object, and the marked objects apply, in scene order, to the base, the first object left unmarked. With **Live boolean** on, the result is drawn in their place at about Live vertices (200,000 by default) and made again whenever one of them is moved, turned, sculpted or remarked, once the mouse is let go; while you drag or sculpt the selected one it shows as it is. Subtract and Intersect objects are not drawn on their own, so select them in the Scene palette's list to move them. **Make boolean mesh** replaces the base with the result at about Result vertices (1M by default) and deletes the marked objects, all as one undo step. Marks are saved in .sculpt files.

**With a voxel base** (the first unmarked object is clay) the booleans run on the field, the way 3D-Coat's voxel room and OpenVDB's CSG do (`src/voxel/combine.odin`): each marked object is read at the base's voxel centres through the two objects' placings (a mesh mark is voxelised in the base's space at the base's voxel size first, as Convert to voxels does), union keeps the smaller distance, subtract the larger of the base's and the mark's negation, intersect the larger of the two, and **Blend** (0 to 16 of the base's voxels, 0 by default) rounds the seam with the Add brush's smooth minimum, as Houdini's SDF blend does; the band is then solved again where anything changed, so the result is clay at the base's resolution, closed and manifold, with no mesh intersection that can fail and nothing to retopologise. Intersect drops every brick outside the marks' box too. Live boolean previews it on a copy of the base brought down to at most 256 voxels across by Res− steps (kept while the base is unchanged), as Nomad previews on a coarser lattice; Make boolean mesh swaps the result into the base's clay as one undo step and deletes the marks; Live and Result vertices do not apply then. A voxel mark on a mesh base takes part as its welded surface. Script: `--voxels=96 --script="duplicate_object; boolean subtract; move 0.9 0 0; select 1; make_boolean"` cuts one sphere of clay out of another. The `build/bench --voxel` Union column is a union of two spheres of the row's size on the field.

How it works for meshes (`src/geom/boolean.odin`): both meshes go through the voxel remesh together, with B's crossings counted 4,096 times A's, so one winding number says whether each lattice point is inside A, B, both or neither, and the operation picks which count as inside. Any two closed meshes therefore combine, overlapping or not, into one closed manifold surface. The voxels round edges off at their spacing, so each vertex is then put back onto the nearer input surface along its normal when one is within a voxel, which brings back the inputs' detail and flat faces; only the seam where they meet stays at voxel resolution. Two 1M-vertex spheres: about 0.35 s for a 1M union on the VM; the live preview at 200k takes about a tenth of that.

**Extract masked** makes a new object from the selected object's masked part (mask over half), as ZBrush's Extract does: a shell Thickness thick (a share of the object's size, 0.02 by default) along the normals, its open edge smoothed so it does not follow the mask's jagged outline, closed where the masked part was one piece. Script: with `--spheres=2`, `select 2; boolean union; move 0.9 0 0; select 1; make_boolean` marks the second sphere Union, moves it onto the first and makes the mesh (`live_boolean on` turns Live boolean on); `set extract_thickness 0.05; mask_rect 0 0 1 0.335; extract_masked` masks the top third of the view and extracts it.

## Retopology, UVs and baking

**Retopologize** (Object palette, Rebuild's Quads; baking is in Build > UVs and baking) makes a new object of about Quads quads (4000 by default) lying on the selected object's shown level, and puts it next to it, as ZBrush's ZRemesher does: every face a quad, closed where the sculpt is closed, facing out. The way there is simpler than ZRemesher's, and its edge flow does not follow the sculpt's curves: the sculpt is decimated by quadric error (as Decimate does, so more faces go where the shape bends), neighbouring triangles that make a near-square quad without folding pair up (about three in four do), every face is then cut into quads at its middle and its edges' middles, as a Catmull-Clark step cuts, and twelve rounds relax each vertex toward its neighbours' middle along the surface and put it back onto the sculpt along its normal. About four vertices in five end up with four quads around them. The new object is ordinary: it can be subdivided and sculpted, and its base level keeps its quads (drawn and sculpted as two triangles each) for export and baking; deleting its lower levels or turning dynamic topology on drops them. It takes about 11 s from a 10M sphere (mostly the decimation) and under a second from 1M (4 threads, VM).

It comes with **UVs**: the quads are grouped into charts that face within 55 degrees of their first quad, each chart laid flat by projecting it onto the plane facing that quad (so no quad folds over), turned to its smallest box, and the boxes packed in rows into the unit square at the largest scale that fits, with 8 texels of a 4096 map between charts; a sphere gets about a dozen charts filling 70 to 80% of the square. New UVs lays them out again after the shape changed a lot; it is an undo step, and it removes the object's texture maps in the same step, since they followed the old layout.

**Bake maps...** asks for a folder and bakes the object chosen in Bake from (by default the one the quads came from; its top level) onto the selected quad object's UVs, at Size texels square (512 to 4096, default 2048): each texel's point on the quads casts a ray each way along the quads' smooth normal, as far as Reach (2 average quad edges by default), and the nearer hit gives the displacement (distance along the normal, outward positive) and the sculpt's normal there. It writes `NAME_normal.png` (tangent space with green up, OpenGL's way; the tangent frame comes from the UVs per vertex and chart and is blended across each face, as MikkTSpace does, though not to the bit), `NAME_displacement.png` (16-bit grey: 32768 is the quads' surface, 0 and 65535 the largest distance in and out), `NAME_displacement.txt` (that distance in the OBJ's units) and `NAME.obj` (the quads with their UVs). Charts' edges are grown 8 texels outward so filtering at seams finds no background. Both objects are read in their own spaces, so moving either changes nothing. 10M-vertex sphere onto 5,000 quads at 2048: 3.7 s, with every covered texel finding the surface. Script: `set retopo_quads 5000; retopologize`. Flags: `--bake=DIR` (on exit, from the first object onto the newest), `--bake-size=N`.

The same rays bake the **bake set**, as ZBrush's Multi Map Exporter and Marmoset do, each map a switch under More options (remembered): **Base colour** (on; `NAME_base_color.png`, sRGB) is the source's polypaint over the material of the face each ray meets (its polygroup's own material, else the object's), mixed in linear light as the viewport mixes it, and the material's colour where there is no paint; **Occlusion, roughness, metal** (on; `NAME_orm.png`, linear) holds ambient occlusion in red, and the met face's material's roughness in green and metal in blue, glTF's ORM layout; **Polygroup colours** (off; `NAME_id.png`) is an ID map, each group in its viewport colour. Occlusion casts **Occlusion rays** (16; 0 turns it off, leaving red white) from each texel's point on the sculpt, spread over the hemisphere above the face it met, and counts those stopped within **Occlusion reach** (20% of the source's size); the pattern turns from texel to texel by a hash of the texel alone, so a bake is the same on any number of threads. The base colour and ORM maps grow out from texels whose rays found the sculpt (the ID map takes the colour most of its neighbours have, so no new colours appear at a chart's edge), and texels no chart reaches show the object's own material. Paint done on a lower subdivision level is carried up to the top level first. A dynamic-topology source has neither paint nor groups to bake, and the note says so.

Every bake also writes **`NAME.glb`**: the quad object as triangles (each quad along the diagonal the viewport draws it with, which the bake rasterizes too), split where its UVs are, with normals, UVs, the tangents the normal map was baked in, and one material whose textures are the maps just baked, embedded (base colour, the ORM map as metallic-roughness and, when occlusion was baked, occlusion, and the normal map), so Blender, three.js or a game engine shows the baked look straight away. The normal map and the tangents are made together: a reader that uses the file's tangents the MikkTSpace way turns the map back into the sculpt's normals to within 2 degrees (a test bakes a bumpy sphere and checks every triangle); Blender recomputes its own tangents, which agree closely but not to the bit. Without the base colour map the material takes the source's colour, without the ORM map its roughness and metal. Checked with the Khronos validator (no errors or warnings) and Blender 5.2 (UV map, three pictures, normal map wired). 2048 texels onto 5,000 quads with every map (release, 4 threads): from a 1M sphere 1.9 s without occlusion and 8.3 s with 16 rays, from 10M 5.1 s and 14 s. Script: `set bake_base_color on`, `set bake_orm on`, `set bake_id on`, `set bake_occlusion_rays 32`, `set bake_occlusion_reach 0.1`, `set bake_reach 3`; a run with `--frames` reads no settings file, so a `--bake` run takes these from its start-up script.

**Texture maps on the object.** A bake also leaves its base colour, ORM and normal maps on the quad object it baked onto (the ID map stays a file), as one undo step, and the first bake of a run turns on View > Show textures, so the result shows at once in the viewport: the maps are drawn through the object's UVs with the same split mesh, normals and tangents the `.glb` carries, so the normal map turns back into the sculpt's shading (a baked low mesh's pixels differ from its sculpt's by 0.24/255 on average, against 2.3 without the map, on a 1,500-quad sphere from a 300k stroke). The View menu's texture views (also the palette and the gesture map; setting and script `set texture_view off|textured|normal_map|uv_checker`, remembered) are **Show textures** (the base colour times the object's tint, roughness, metal and occlusion from the ORM map, which also turns on the physically based lights; occlusion dims only the ambient light and the studio's reflections, as glTF has it), **Normal map only** (the object's own material lit through the normal map, to compare with the sculpt) and **UV checker** (8 by 8 cells laid out by the UVs, tinted by column and row, which needs no maps), each picked again for clay. An object shows its maps only on its base level, with no hidden parts, no dynamic topology and no HD, while polygroup colours are off, and not while a stroke is on it (it draws as clay then, at sculpting speed: a sculpted low mesh no longer matches maps baked from its old shape anyway); the maps are decoded on a thread of their own, so the object shows as clay for a moment after a scene opens, and the viewport shows a map at most 4096 texels a side (2048 on Android), halving bigger ones. Thumbnails stay clay. The maps are stored in the scene file as the PNGs the bake wrote (scene version 18), live as long as the object's quads and UVs do (a remesh, dynamic topology or deleting lower levels drops them, and their undo brings them back with the quads), and count toward the undo memory limit when a step keeps them.

**Loading and removing maps.** The Object palette's **Textures** section (under Build, beside UVs and baking; for an object with quads and UVs) has the texture view as tabs (Clay, Maps, Normal, Checker, the View menu's choices), a line saying what the viewport holds of each map (its size, or none, loading or unreadable), and **Load base colour map...**, **Load ORM map...** and **Load normal map...** (also in the command palette as Load map), each a file picker for a PNG, JPEG, BMP, TGA or QOI image of at most 8192 texels a side, as painted in Substance Painter, Blender or Krita for these UVs; the image replaces that map alone, as one undo step, and the texture view turns on if it was off. The file is kept as it was picked (a JPEG stays a JPEG in the scene file); only its header is read at once, and an image that then does not decode leaves a note and shows without that map. The ORM map is glTF's: occlusion in red, roughness in green, metal in blue; the normal map is OpenGL's (green up), as the bake writes them. Under More options, **Remove maps** takes them all away in one undo step. Script: `texture base_color path/to/paint.png`, `texture normal detail.png`, `remove_textures`.

## Mirror and weld, duplicate

Mirror and weld in the Object palette (as ZBrush's Mirror And Weld and Blender's Symmetrize) replaces one half of the selected object with a mirror image of the other, across the object's own X, Y or Z plane (the one brush symmetry uses), keeping the + side unless "Keep the - side" is on. Triangles crossing the plane are cut at it and the two halves are welded along the cut (`geom.mesh_symmetrize`, `src/geom/symmetrize.odin`), so a closed object stays closed; vertices within 1/100,000 of the object's size of the plane move onto it so the cut makes no slivers. It works on the level the object is on and rebuilds the object like a remesh: levels, HD detail and mask go, and Ctrl+Z brings them back. 100k vertices take about 0.1 s on the test VM. Script: `set mirror_axis 0; mirror_weld` (axis 0 x, 1 y, 2 z; `set mirror_negative on` keeps the - side).

Duplicate (the Scene palette, or the object list's right-click menu; Ctrl+Shift+D) adds a copy of the selected object beside it, with every subdivision level, the mask and dynamic topology (HD detail is not copied, as in a saved scene), and selects it; Ctrl+Z removes it.

## Decimate

Decimate (Rebuild's Fewer, as ZBrush's Decimation Master) rebuilds the selected object with about the vertex count its Density sets while keeping its shape: edges collapse where that moves the surface least (quadric error, `geom.mesh_decimate`, `src/geom/decimate.odin`), so the triangles stay dense where the detail is and go sparse where it is flat, unlike a remesh, which spreads them evenly. It is meant for exporting a sculpt to other programs. A collapse that would fold the surface, pinch it or leave a needle is refused, so a closed object stays closed and sound (`--check-mesh` stays clean); among collapses that change the shape equally, as on a flat area, shorter edges go first. Large meshes are first thinned in parallel, a quarter of the triangles a round in 64 cells whose borders move every other round, then finished as a whole. It works on the level the object is on and, like a remesh, drops levels, HD detail and mask (Ctrl+Z brings them back). The section shows how far the surface strayed at most. On the 4-thread test VM: 1M vertices to 3k in 0.7 s; 5M to 100k in 8 s and to 10k in 3 s; 10M to 100k in 12 s. Script: `set rebuild_goal fewer; set rebuild_fewer 100000; rebuild`.

## Dynamic topology

Ctrl+T, or the switch in the Object palette's Dynamic topology section, turns dynamic topology on for the selected object, as Sculptris Pro in ZBrush and dyntopo in Blender do: each dab first splits the edges under the brush longer than Detail pixels on screen and, with Collapse short edges (on by default), collapses the ones shorter than 0.4 of that. The brush makes triangles where it goes, as many as the detail you see needs, so you can start from a coarse ball and pull out horns and folds without stretching anything. Since Detail is in pixels, zooming in makes finer triangles. On a dense mesh seen from afar the edges are already shorter than Detail, and with collapse on the brush coarsens what it touches; lower Detail or switch collapse off to keep the density. Every brush works with it, symmetry too; Grab and Mask leave the triangles as they are, and so do fully masked areas. The object needs a single subdivision level and no HD level, and turning it on or off is an undo step of its own (its earlier strokes can no longer be undone one by one). Remesh selected works on a dynamic object and turns it off.

How it works (`src/sculpt/dyntopo.odin`): the sculptor works per node as it does on a fixed mesh, but each node gets a page of the mesh's arrays (1,280 vertex slots and 2,048 triangle slots) and uses the first of them, so it grows and shrinks in place; unused triangle slots hold zeros, which draw nothing. A node whose page fills up splits in two along its longest axis, and the BVH over the nodes is rebuilt then, in well under a millisecond. Each vertex lists its triangles (up to 16), so splits and collapses only touch what is around them. Splits go longest first and cut each triangle across its longest side (Rivara's bisection): when either triangle beside an edge has a longer one, that splits first, even just outside the brush. Triangles stay well shaped however often an area is refined: no angle went below 24 degrees in our measurements, and a test strokes one ring 160 times and checks for angles under 15 degrees, folds and the whole layout every 20 dabs. A collapse is refused where it would fold or pinch the surface, give a vertex more than 12 triangles, make an edge longer than Detail, or leave its worst triangle thinner than before and under 0.3 on a scale where an equilateral triangle is 1 (2√3 times the area over the sum of the squared sides), so thin slivers do not pile up where the brush coarsens. Surfaces that are not closed work too (an imported scan, say): an edge on the border splits its one triangle, and collapses leave border vertices where they are, so the border keeps its shape. Turning it on is refused on a mesh with an edge shared by more than two triangles or with triangles facing opposite ways across an edge. A dab makes at most 2,048 splits and 2,048 collapses, and the app stops laying dabs for a frame once they have taken 10 ms, so a large brush over a coarse area keeps the frame rate and catches up over the next frames. Undo saves each node a stroke changes, whole, before its first change, and swaps it back. The GPU gets the index pages that changed along with the changed vertices; when the mesh outgrows its buffers, they are made again at the larger size.

`build/bench --dyntopo` (4 threads, this repo's cloud VM). A frame is 4 dabs plus the normal update, as in the main table. Fixed is the large-brush stroke on the usual layout, Plain the same with dynamic topology on but nothing to split, Refine with a detail that splits every edge under the brush once (each triangle into four), which is far more than a stroke on a coarse mesh asks for: from 5M up every dab stops at its 2,048 splits. ## Files

The menu (the top bar's second button, after Home) opens and saves scenes (Open scene, Save scene, Save scene as, Save a copy, Earlier saves) and imports and exports meshes, each through the system's file dialog (SDL's); what the dialog picks runs at the start of the next frame. The outcome shows as a note at the bottom of the window for a few seconds, amber when something failed or needs attention, and goes to the log.

**Scenes** (`.sculpt`: Open scene, Save scene, Save scene as): every object with all its subdivision levels as shown and their sculpt layers, a retopologized object's quads and UVs, the mask, polypaint and polygroups of its current level, dynamic topology if on, its name and place, whether its eye is off or it is a ghost, its folder, the folders (names, folded or open, eye and ghost), Solo, and the camera. Each level is stored as positions, so it opens exactly as it was saved. Since the vertex numbering changes whenever a level is built, the levels above the base store their vertices in an order the topology alone decides: the vertices that continue the level below first, then those on its edges, by the edge's ends. Opening builds every level above the base again from it, as subdividing does, and moves its vertices where they were, so it takes about as long as subdividing to that size; the base itself keeps its node layout in the file, so it opens without being laid out again (see below). HD detail is not saved, only each object's number of HD steps; the HD section says so while an object has stored detail, and so does the note after saving. Nor is the undo history. Opening reads and uploads the whole new scene before the old one goes, so a damaged file leaves the scene as it was (both are in memory for a moment). Saving writes beside the file, makes sure every byte reached the disk (fsync), and then replaces the file with it (on Linux and Android the folder is synced too; on Windows the rename is write-through), so neither a failed save, a crash nor a power cut leaves a half-written file, and "Saved" shows only once that is done; exports, bakes and `.strokes` files are written the same way, screenshots are not. A save of a scene over about 1M vertices (32 MB) stops the app for a moment (about 0.6 s at 2M and 4.6 s at 10M on the VM), so it first shows "Saving head.sculpt..." at the bottom, saves once that is on the screen (a quarter of a second later, or at once when a scene change, another file action or closing the app comes first), and then replaces it with the outcome; a second Ctrl+S meanwhile is dropped.

**Save a copy** (Menu, or the command palette) writes the scene to another file and leaves it saving where it did: a backup, or a variation to come back to; the note says which file the scene still saves to. **Save next** (the long press on Save, or the command palette; `save_scene_next` in a script) saves the scene as the next numbered file beside its own and keeps saving there, so each stage of a sculpt stays as a file of its own: `dragon.sculpt` becomes `dragon_002.sculpt`, `dragon_002` becomes `dragon_003`, `head_9` becomes `head_010` (the number keeps its width, at least three digits); a name already taken is skipped, and after a thousand taken it says so and saves nothing. It needs a scene file to number from (Save scene as first), and an Android picked file, which has no folder to put the next one in, cannot. Earlier saves then lists the new file's. **Earlier saves**: saving over a scene file (Save scene, or Save scene as onto it) first keeps the file it replaces in a folder beside it, `head versions/head 2026-10-26 14.02.33.sculpt`, stamped with when that file was saved in the device's local time (a second save in the same second gets `-2`, `-3`, ...). The old file is hard-linked there, so it costs no time and no space until the new save replaces it, or copied where the file system has no links (FAT cards). The newest five are kept and older ones deleted (Settings > System > Earlier saves: Off, 3, 5 or 10; remembered as `versions_kept`); Off keeps no more and deletes none already there, and nothing else in the folder is ever touched. At 10M five versions are about 1.8 GB beside the file. If the earlier save cannot be kept (the folder cannot be made), the save still happens and its note says why in amber. Save a copy keeps no versions. **Earlier saves...** (Menu, or the command palette, once the scene's file has any) lists them under the menu button, newest first, as "Today 14:02", "Yesterday 18:40" or "12 Oct 09:15" (with the seconds when two share a minute) and their sizes; the list is read when it opens and after each save, never every frame. A tap opens that save as the scene, which still saves to its own file, so the next Save makes it the current one and keeps the one it replaces: going back loses nothing. With changes the file does not hold, the first tap turns the row red ("Discard changes and open?") and a second tap within three seconds opens it, as New scene asks. The format is little-endian binary with a version number: `scene_save` in `src/app/files.odin`, then per object `levels_write` in `src/sculpt/levels_file.odin`. Since version 22 a scene starts, right after its version, with a **preview block**, as a `.blend` keeps its thumbnail, so a list of scenes can show each by reading only the start of its file, never the whole scene (also through Android's `content://` files): its length, when it was written, how many objects and vertices it holds, and a picture of the viewport as it was last drawn (without the brush ring or gizmo), at most 320 pixels on its long side, as a PNG (`src/app/scene_preview.odin`). The picture is taken while the app rests (a second after the last press, at most every two seconds, only when the scene or the view changed), copied back from the GPU without waiting for it and shrunk by averaging every pixel it covers, about 4.6 ms in a release build on the VM at 1600 x 900; a save brings it up to date first, and an autosave writes the last one taken. A length that runs past the file, or past 4 MB, is a damaged file; a picture that does not decode only shows none. The exit stats add `previews` (pictures taken), `preview_size`, `preview_kb` and `preview_ms`.

**Import** (Import mesh, `.obj`, `.ply` or `.stl`): OBJ `v` and `f` lines (polygons become fans of triangles; negative indices and `v/vt/vn` corners work; everything else is skipped), read in parallel chunks of 4 MB. PLY in ASCII or binary of either byte order, with any vertex properties (x, y and z are kept) and polygon faces. STL in text or binary (a binary file is known by its length matching its triangle count, so a binary header starting with `solid` still reads), its facet normals ignored. Then a cleanup: vertices at exactly the same place are welded (exporters split vertices along UV seams), triangles left with a repeated corner and vertices no triangle uses are dropped, and a closed surface that faces inward is turned outward. The mesh is centred and sized like a sphere (radius 1) and placed beside the other objects; its place in the file is kept for export. A surface that is not closed sculpts, also with dynamic topology, which keeps its border, but subdivision, HD and remesh need a closed one, and the note says so.

**Export** (Export selected, `.obj`, `.ply`, `.stl`, `.glb` or `.usda` by the name, or by the dialog's filter when the name has none): the selected object's shown level (packed, when dynamic), as OBJ with nine significant digits, which read back as the same floats, as binary PLY, as binary STL for 3D printing (each triangle with its normal and no colour, in the file's units, so a slicer scales it), as binary glTF 2.0, or as USD text, with polypaint as vertex colours when it has any, STL aside (Import does not read colours back yet). It goes back where it was in the file it came from, so an imported mesh exported again lines up with the original; Move tool placement is not written.

**glTF** (`.glb`, one file) carries what Blender and other programs need to keep sculpting it: the normals, the polypaint as linear colours (16 bits a channel, so dark paint does not band), and the level's **sculpt layers as shape keys** (morph targets): each layer's displacement at strength 1, named as the layer, with the layer's strength as the key's value (0 for a hidden layer, whose strength is not kept). The base mesh written is the surface without the layers, so at those values the keys rebuild what the app shows (to rounding: 6e-8 apart at most on a 40k-vertex sphere with two layers, one at 1.5), and each key's slider then does what the layer's did, past 1 and below 0 as well. The object's **material** goes as glTF's metallic-roughness material: a physically based one as it is (base colour, metallic, roughness), a classic one with no metal and the roughness whose highlight is about as wide as its own (Clay comes out at 0.47), a MatCap by the colour painted into it (a loaded image as mid grey) at its highlight's roughness, each tinted by the material's colour as the viewport tints it, and named as the material. Groups with materials of their own go as one primitive a material, all sharing the vertices and shape keys, which Blender imports as one mesh with a material slot each. With polypaint the colours are the paint over the material's colour as far as it covers, as the viewport shows them (OBJ and PLY keep the paint over white), and the material's colour goes as white, since glTF multiplies the two; Blender wires the colour attribute into the base colour. With paint and group materials, a vertex on the edge between two of them is written once for each side, so each keeps its own colour under the paint. A layer is stored only where it moved the surface, so one over a small patch costs little. Checked with the Khronos glTF validator (no errors or warnings) and by importing into Blender 5.2 (vertices, triangles, shape keys and their values, the colour attribute; `scripts/export_check.py` runs both, see below); Blender turns Y up into Z up as it imports. Dynamic topology bakes the layers, so a dynamic object exports without them; polygroups and a retopologized object's quads and UVs are not in glTF exports (OBJ and USD keep the quads). A file over 4 GB, which the format cannot count (about 30 layers over the whole of a 10M mesh), is refused with a note. 10M vertices with a layer over all of them: 610 MB in about 7 s on the 4-core VM (PLY: 362 MB in about 4 s). An export over about 1M vertices first shows "Exporting head.glb..." at the bottom, as a big save does.

**Lights** go out with glTF and USD exports, as Blender, Marmoset and KeyShot carry theirs: every light in the Lights section that is on, by its name, placed and pointing as the view shows it now, in the exported object's own space (so it lights the mesh from where it did, whatever the object's placement), in its colour (its colour temperature's, when it has one). glTF writes them as `KHR_lights_punctual` lights, a node each beside the mesh's: a sun as a directional light of pi x 683 lux at Intensity 1 (Blender's importer makes it a sun of pi watts a square metre, which lights a white surface facing it white, as the app's sun does), a point light or a spot in candela that make it that bright at the distance it matches a sun of its Intensity, with its reach as the light's range and a spot's cone and soft edge as its outer and inner cone. USD writes the same lights as a `DistantLight` and `SphereLight`s treated as points (a spot with `ShapingAPI`'s cone and softness), their intensities chosen so Blender's USD importer gives each light the same type, colour, place, direction, cone and watts as its glTF importer does (checked with Blender 5.2: identical, sun 3.14, spot 290 W). A sun with an Angle writes it as the `DistantLight`'s `inputs:angle`, the angle across in degrees as UsdLux defines it (Blender's importer reads it as half that and shows twice the angle); a lamp's Radius stays out of USD, which measures a sphere light's intensity per area of it, and glTF's lights have no size. The ambient light and the environment do not go. `scripts/export_check.py --lights "SUN=3.1416,SPOT=290.17"` checks each light's type and energy as Blender imports it.

**USD** (`.usda`, text) carries the same as glTF, in the form Blender's, Houdini's and Maya's importers read: a `Mesh` under a `SkelRoot` named `Root`, the layers as `BlendShape`s (each the points it moves and how far, named as the layer; the prim names are the names with anything but letters, digits and `_` as `_`) bound to a skeleton with no joints whose animation gives the strengths, the paint as linear `displayColor`, the material as a `UsdPreviewSurface` bound to the mesh (the same values as glTF's; with paint its diffuse colour reads `displayColor` through a primvar reader, which Blender turns into its colour attribute), group materials as a `materialBind` partition of `GeomSubset`s, one a material in use with its own `UsdPreviewSurface` (with paint, `displayColor` is then given a face corner at a time), normals, `subdivisionScheme` none (the surface as it is, not a cage), the polygroups as a per-face `polygroup` primvar, and a retopologized base level as its quads with UVs (`st`, per corner), as OBJ keeps them (a quad takes the group its first corner shows). The strengths are written both as the default and as a time sample at frame 1: Blender's importer reads only time samples and keys them in an action, so the shape keys take their values at frame 1, and it keeps each key's range at 0 to 1, so a layer at 1.5 shows as 1 until the key's Range Max is raised (the action holds 1.5). Checked with USD's own 30 validators (no errors) and by importing into Blender 5.2: the evaluated mesh at frame 1, layers applied, is within 8e-8 of the OBJ export; Blender turns Y up into Z up. Text spells out every number, so it is the slow one: 10M vertices with a layer over all of them is 1.9 GB in about 24 s on the 4-core VM (glTF: 7 s); an export over about 180k vertices shows "Exporting..." first.

`scripts/export_check.py FILE.glb|FILE.usda` checks an export with a validator (Khronos's for glTF, USD's own for USD) and Blender itself (`--vertices`, `--triangles`, `--keys "Layer 1=1.5,Layer 2=0"`, `--colors`, `--material "Gold,1,0.3"`, the first material's name, metallic and roughness, `--uv` and `--textures 3`, a UV map and how many pictures the first material's textures show (one of them feeding the normal), `--face-materials "Gold=2,Steel=10"`, how many faces each material shades, and `--lights "SUN=3.1416,POINT=145"`, each light's type and energy by name, say what to expect; the material's base colour, or what feeds it, is reported); `--setup` installs them into `build/export-tools` (node's gltf-validator package, and the `bpy` and `usd-core` wheels; bpy wants Python 3.13). A tool that is missing is reported as skipped, never as passed. They are development tools only; nothing of them ships with the app.

An object made by Retopologize exports from its base level as quads with their UVs (OBJ only; PLY stays triangles). Normal, displacement, colour, ORM and ID maps are baked into a folder from the Object palette, with a textured `.glb` of the quads (see Retopology, UVs and baking). An object with texture maps (baked or loaded) exports to `.glb`, while it shows its base level (not in HD and without dynamic topology), as that same textured file, with its sculpt layers as shape keys on the split vertices and its polypaint as vertex colours unless it has a base colour map, which then stands for it (glTF would multiply the two); polygroup materials stay out, since the maps make one material. PNG and JPEG maps go in as they are and others as PNG, the two pictures glTF holds. OBJ, PLY and USD leave the maps out.

## Home screen

Home (the top bar's first button, the command palette, or `home on` and `home off` in a script) covers the window with a page to start from, as a tablet sculpting app's home and a desktop modeller's splash screen do (`src/app/kit_home.odin`, `src/app/home.odin`). Down its left side are the new scene starters, Sphere, Head, Bust, Figure, Hand and Creature, as tiles (New scene, at the Scene palette's Add size; with work to lose, the first tap turns its name to Discard? and a second goes ahead), and Open a file.... Beside them, two tabs of scenes as pictures: **Recent**, the last 24 scenes saved or opened, newest first, each with its name, when it was saved and how many vertices it holds; and **Autosaves**, the newest autosave of each earlier session (the last few that closed, and any that ended unexpectedly, marked "did not close"), named after the scene it was of. A tap opens a scene (an autosave is recovered, as the recovery card does); with changes the scene's file does not hold, the first tap marks the tile "Discard changes and open?" and a second within four seconds opens it. The scene open now is ringed in the accent and a tap on it only closes Home. A scene whose file is gone shows a crossed-out file, and a tap takes it off Recent. A long press (or a right-click) on a tile offers Remove from Recent (the file stays) or, for an autosave, Delete this autosave (a second tap deletes it). The close button, Escape or Android's Back go back to the scene. While Home shows, only its own key and Open scene's reach past it, and the recovery card waits under it.

Each picture is the preview block at the start of the scene file (see Files), read with the file's other numbers on a thread of its own, so a slow card or a `content://` file never holds a frame, decoded there, and put into a picture atlas (`render.Pictures`, 6 by 6 cells of 320 pixels, about 15 MB) at most two a frame from the frame's own command buffer; the atlas is made when Home first shows a picture and let go when it closes, and every opening reads the pictures afresh. A file saved before version 22 shows a plain tile. An interactive run given no scene file, script or recording starts on Home (Settings > Interface > Start at Home; off, it starts straight on a sphere). The exit stats add `home` (1 while it shows), `home_opened`, `home_read` (files read), `home_pictures` (pictures put in cells), `recent_scenes`, `home_autosaves` and `scene_name` (the scene's file name, `none` for none).

## Blender link

Send to Blender and Get from Blender (Settings > System, or Search; `send_to_blender` and `get_from_blender` in scripts) pass objects to and from Blender with no file dialogs, as ZBrush's GoZ does, through a folder: `link` beside the settings file (`<name>-link` for a run given `--settings-file`), whose path Settings > System shows, with Copy path to paste into the Blender add-on. It is files in that folder and nothing else: no network and no other program started. On Android, where there is no Blender to link with, both are hidden.

**Send to Blender** writes each selected object's shown level to `<id>.ply` (binary, in the object's own space and not where an export would put it, so a mesh Blender leaves alone comes back exactly; paint goes as vertex colours, a voxel object as its surface, a dynamic one packed) and then `link.txt`, which names them: `sculpt_link 1`, `scene <token>`, `sent <number>`, and an `object <id> <level> <name> <file> <vertices> <triangles> <x> <y> <z> <rx> <ry> <rz> <scale>` line each (the name with `%`, spaces, control bytes and every byte past ASCII as `%XX`, `-` for none; the place as the object's, Y up, degrees). Then a `light <name> <kind> <x y z> <dx dy dz> <r g b> <intensity> <range> <inner> <outer> <size>` line for each of the scene's lights that is on, in the app's axes, as a glTF export gives them (`directional`, `point` or `spot`; where it is; the way it shines; linear colour; lux or candela; range, 0 for none; a spot's half angles in radians; its size, a sun's angle across in radians or a lamp's radius, 0 for none; the add-on reads the line without a size from before and leaves words after it alone), so Blender lights the objects as the app does; lights go to Blender only, and a reader that does not know the line skips it. The number rises with each send, so the other side can tell a new one; the files of objects an earlier send listed and this one does not are deleted. The token names the scene: made by its first send and kept in the scene file (version 17), so objects sent from one scene never replace another's that happen to share an id.

**Get from Blender** reads Blender's `blender.txt` (`blender_link 1` and the same lines, its meshes as `blender-<id>.ply`; id 0 for an object made in Blender) and takes each object in turn, all as one undo step:
- an object of this scene with the same triangles at the level it was sent from moves its vertices to Blender's (the level is shown first; an HD window is left, and its detail rides on the move as on a stroke; the mask and hidden parts hold vertices back, as for any deformation, and the note says how many; a recording sculpt layer takes the move);
- a voxel object or one under dynamic topology that comes back exactly as it went keeps everything and takes only Blender's placement;
- one with other triangles, a voxel object (which becomes a mesh) or one under dynamic topology (which stays on) is rebuilt from Blender's mesh, welded and turned outward when closed but never resized, as a remesh is: its levels, mask and strokes go, the shown level's layers come across, and Undo brings the old mesh back;
- one Blender made, one of another scene, one deleted here since, or one whose level is gone (or renumbered by Delete lower since the send) is added as a new object, named as Blender named it;
- Blender's placement becomes the object's.

The note names each ("From Blender: Head (moved 1,204 vertices), Hat (new topology), Cube (new object)") and warns when an object had changes made here after it was sent, which Blender's version replaced (Undo brings them back). Every file is read and checked against the manifest's counts before anything changes, so a send Blender is still writing, or a damaged file, changes nothing and is tried again by the next get. Each send is taken once: `taken.txt` in the folder notes the newest taken, so a later run does not take it again. While the History timeline plays or a stroke replays, whose undo steps a get would cut short, Get from Blender says so and does nothing. Switching back to the app's window gets a new send for this scene by itself, once no file dialog, save, stroke, History playback, replay, script or pack install is under way, and never in scripted runs (`--frames`, `--run`, `--script`). A big send or get first shows "Sending to Blender..." or "Getting from Blender...". Paint does not come back yet.

**The Blender add-on** is `tools/blender/sculpt_link` (Blender 4.2 or later). `python scripts/link_check.py --package` writes it as `build/sculpt_link.zip`; in Blender, Edit > Preferences > Get Extensions > Install from Disk installs that file. Its Link folder preference starts on the app's own folder for the system (`%APPDATA%\Implicit\Sculpt\link` on Windows, `~/.local/share/Implicit/Sculpt/link` on Linux, `~/Library/Application Support/Implicit/Sculpt/link` on macOS); paste Copy path there for any other. The 3D view's sidebar gets a Sculpt tab:
- **Get from Sculpt** brings in what the app sent: an object it made before from the same scene and id gets the new vertices in place when the counts match, so its UVs, modifiers and materials stay, or a new mesh; others become new objects. Positions stay in the object's own space and the turn from the app's Y up to Blender's Z up goes in the object's matrix, so a mesh left alone goes back exactly. Paint comes in as the colour attribute "Sculpt paint". The app's lights come too, while **Bring lights** is on (the default): each one that is on as a Blender light of its name in a "Sculpt lights" collection, updated in place by the next get and removed once a send no longer lists it, with the watts Blender's glTF importer gives the same light (a sun of Intensity 1 is pi watts a square metre), its size (a sun's Angle, a lamp's Radius), and a spot's cone and blend. **Auto get** does it by itself for each new send, looking once a second.
- **Send to Sculpt** writes the selected mesh objects: a mesh of triangles in its own order (one from the app keeps it, so the app moves its vertices), any other split into triangles over its own vertices; **Apply modifiers** sends the meshes as the modifiers leave them, which the app rebuilds its object from. A placement that is still the one the app sent goes back word for word; a moved, turned or uniformly scaled one goes in the app's axes, and a scale that differs between axes or mirrors (which the app's objects cannot have) goes into the positions, a mirrored mesh's triangles turned to keep facing out. A copy of an object from the app (Shift+D keeps its link properties) goes as a new object; the first of them keeps the link. Get from Sculpt replaces a mesh whose triangles were changed in Blender since, even at the same counts.

`scripts/link_check.py` runs the round trip with Blender itself, as `export_check.py` does exports (bpy from `export_check.py --setup`; SKIP without it): the app moves, turns and sends a sphere and saves; the add-on gets it, checks the counts, the placement and the lights (two suns at pi and 0.3 pi watts a square metre and the point light the script made), raises one vertex, moves the object, makes a cube of quads and sends both, then runs its two buttons as a person would with the add-on enabled; the app opens the scene and gets them back, and the saved result must have exactly that vertex moved, exactly where Blender put it, the sphere moved by Blender's move, and the cube as a new object. Like `export_check.py` it is outside the gate.

The exit stats add `link_sent` (objects), `link_moved`, `link_swapped`, `link_added` and `link_token` (1 when the scene has one).

## Autosave and recovery

An interactive run saves a recovery copy of the whole scene, as Save scene would, every minute while there is a change to save (Settings > System > Autosave: Off, 1, 2, 5 or 10 minutes; remembered as `autosave_minutes`). It never interrupts work: a copy starts only once nothing has been pressed, typed, touched or stroked for 1.5 s, and a worker thread of low priority reads the scene and writes the file while sculpting goes on. A press, key, stroke, scene change or file action while it still reads the scene makes it stop and try again at the next pause, so it never reads a half-changed mesh; the frame that stops it waits for it a few milliseconds at most (0.7 to 8 ms at 10M with and without levels on the 4-core VM, `autosave_wait_ms` in the exit stats). Once it has read the scene it writes the file while the app goes on. A copy is the same `.sculpt` format as Save scene and takes as long to read, without HD detail (as saving) or work inside an open HD window; the System tab says so while one is open.

Each run keeps up to three copies in turn, `<session>-1.sculpt` to `-3.sculpt` with a `<session>.session` file saying when they were written and by which process, in an `autosave` folder beside `settings.txt` (`%APPDATA%\Implicit\Sculpt\autosave` on Windows, `~/.local/share/Implicit/Sculpt/autosave` on Linux). Each is written beside its name, flushed to the disk and renamed over it, so killing the app, a crash or a power cut mid-write leaves the copy before it whole. A clean exit writes a last copy if anything changed (hiding the window first), keeps the newest and marks the session closed; the last three closed sessions are kept, older ones deleted. Saving the scene counts as a copy: a run that crashes after a save with nothing new is not offered.

When a run starts and finds a session whose process is no longer running and was not closed, a card at the top asks "Recover your work?" with when it was autosaved, how many objects and vertices it held and the scene file's name: Recover opens its newest copy that reads whole (Save scene then saves to the file the scene came from, if it had one, and the next autosaves continue in this run's session), Not now leaves it for the next start (Escape too), and Discard deletes it. Crashed sessions are never deleted without asking. Menu > Open the last autosave (and the command palette) opens the newest copy of any earlier session at any time, closed ones included. On Android the app cannot tell a crash from being closed by the system, so every session not closed is offered.

Disk use is three copies of the scene a run (about 360 MB each at 10M) and the last three closed runs; a 10M scene's copy takes about 5 s to read and 2.6 s to write on the VM, at most once a minute and only after a change. Strokes while a copy is written cost the same (`build.sh release` then `build/sculpt --vertices=10000000 --bench-stroke=240 --no-vsync`, with and without `--autosave=1 --bench-after-autosave`, three runs each: brush p50 0.64 to 0.73 ms either way; frame p50 16.0 to 17.5 ms without, 17.5 to 18.0 ms with, where the 4-core VM's software GPU uses every core the writer also uses).

Flags: `--autosave=SECONDS` autosave that often (scripted runs only autosave with it or `--autosave-folder`), `--autosave-folder=DIR` keep the copies in DIR and offer the crashed ones found there, `--autosave-rest=SECONDS` the pause before a copy starts (default 1.5), `--check-autosave` hash what each copy read before and after and count a difference as `autosave_torn`, `--crash-after-autosave` exit with code 3 right after the first copy, skipping the clean exit (the crash test), `--bench-after-autosave` start `--bench-stroke` once a copy of the starting scene is being written. The exit stats give `autosaves`, `autosave_aborts`, `autosave_torn`, `autosave_wait_ms`, `autosave_sync_ms` (bringing the levels up to date on the frame loop before a copy), `autosave_serialize_ms`, `autosave_write_ms`, `autosave_mb`, `recovered` and `recover_offers`. `scripts/touch_check.py 'autosave_*'` runs the crash, recover, discard, Not now, stroke-stops-it and Off scenarios.
## Interface

The interface is touch-first, designed in Figma ("Sculpt UI"), and drawn by the app's own kit (`src/ui`). One layout serves every OS and screen, scaled by the screen's pixel density and the system's display scaling (Android's screen density, Windows' Scale setting), laid out inside the window's safe area, and every control's hit area is at least 48 points (the App Store's 44 pt and Google Play's 48 dp both met) while what is drawn inside it stays compact.

The viewport fills the window and the chrome sits round its edges, laid out as ZBrush for iPad's (`src/app/kit_bars.odin`). A strip across the top holds Home (see Home screen), the menu (open, save, save as, save a copy, earlier saves, the last autosave, import, export, screenshot, New scene, Reduce motion, Settings, Stats, Help; on a window too short for all of it, it scrolls under its button), Save (a long press offers Save as, Save a copy, Save next, Earlier saves and the last autosave), Import and Export at its left; the scene's file name in the middle, with a star while it holds changes the file does not; and History, Edit pies, Help and Settings at its right. Under its left end is the selected object's readout: its name, its subdivision level, Dynamic or HD when on, its vertices and, with several objects, the scene's; a tap shows it in the tray's Object palette and a long press (or right-click) opens its menu under it (focus, duplicate, delete). Down the left edge is the brush bar: Brushes (the brush in use; a tap opens the brush browser beside it, a long press its settings), Stroke, Alpha, Material, Colour (a tap opens the Colors card beside the bar, below; its corner shows the main colour over the secondary one; a long press swaps them) and the paint channel (Sculpt only, Sculpt and paint, or Paint only: a tap steps through them, a long press opens the Colour section), then Focal shift, Draw size and Strength, Add and Subtract (which way the brushes work: Subtract latches the wheel's Invert, as Ctrl held does, and Add lets it go), then Undo and Redo (their tooltips name the step). The bar stays clear of the modifier wheel in the corner under it where the window has room. Stroke, Alpha and Material open that tray section in a popover beside the bar; Focal shift, Draw size and Strength open a tall slider there, which follows how far a finger or pen moves rather than jumping to where it presses. A finger's or the pen's long press on one of those three, still held and dragged up or down, sets it on the spot, with a small readout of its value and range beside the button and nothing opened: 150 points up doubles the size, 300 take the strength from 0 to 1 and the focal shift across its range, counted from where the drag passes the slop. Let go without dragging, the long press opens the Falloff section (from Focal shift) or the Pen section (from Draw size and Strength) as it lifts, not as the press becomes long, as the mouse's right click on them does; a touch the system or a palm cancels puts the value back. Every button, switch, tab and menu row that runs a command shows its shortcut and, where there is one, its touch gesture as the Settings have it ("Ctrl+Z · Two-finger tap, hold to repeat", "F · Double tap empty space", "Mask on: tap the mask"; menu rows show the gesture on hover), and the command palette's help line says it too; Escape closes any open menu, and a press outside one closes it without sculpting. File results and errors show as notes at the bottom that fade away, or go at a click. So do the operations that rebuild, add or remove objects (Delete, Remesh, Decimate, Retopologize, Mirror and weld, Slice, Make boolean, Extract, Delete higher and Delete lower, and Subdivide when the top level has sculpt layers), Smooth all and Project detail, each saying what it did and how long it took, with an Undo button at the right end: it is Ctrl+Z for that step, and it goes once the step is no longer the newest (undone, or another made since). Masking, hiding and clipping show by themselves and give no note. A long note is cut short on a narrow window; the Undo button always stays whole and on screen. The section that ran an operation shows the same line under its controls ("Last: ..."), and the Stats panel shows the last one in Last operation. A drag that starts on the viewport stays a stroke or orbit when it passes over a panel, and a press on a panel never reaches the viewport.

Adjust last operation: right after Remesh (Ctrl+R or the Remesh section), Decimate, Mirror and weld, Retopologize, Extract masked, Smooth all or a Bend, Twist or Taper, the action bar shows the operation's name and Adjust..., which opens its settings above the bar: Remesh and Decimate the sizes (41k to 25M), Mirror and weld the axis and the side kept, Retopology the quad count, Extract the thickness, Smooth all the steps and strength, a deformer its Amount. A change runs the operation again from the state before it, not on its own result, so Decimate to 200k after Decimate to 500k is Decimate to 200k from the original, and a remesh is never a remesh of a remesh; a size or side runs at once, a slider when it is let go (at 10M a run takes seconds). The operation's undo step is replaced, so the History keeps one entry for it however many settings were tried, and the popover stays open with the result line to try another. A run that changes nothing (Decimate to more vertices than the object had) puts the earlier result back and says so. Anything after the operation ends the adjust: a stroke or mask, an undo, moving or selecting another object, changing its boolean mode, leaving HD or scrubbing the History. The command palette has it as Adjust last operation (greyed out when there is nothing to adjust), and opens it above the dock when the action bar is hidden. Escape, Back or a press outside closes it.

Adjust last stroke (as ZBrush's Adjust Last): after a stroke (sculpting, masking or painting), Adjust last operation in the palette, or a key given to it, opens Amount above the dock, and the Brush palette's Stroke section has the same slider as Last stroke under More options. It sets how much of the newest stroke stays, from 0% (as if it had not been drawn) through 100% (as drawn) to 150%, following the slider as it is dragged: every vertex the stroke moved, every mask or colour value it changed, and a recording layer's displacement go that share of the way from before the stroke to after it. It stays the stroke's one undo step, whose History entry then reads "Draw stroke (80%)"; undo takes the adjusted stroke back. There is no action bar group for it, which would show after every stroke. It applies while the stroke is the newest step on the level or HD window shown: another stroke, an undo, a level change or leaving HD ends it; not with dynamic topology, whose strokes change the triangles. The first adjust keeps a copy of what the stroke left of every part of the mesh it reached (12 bytes a vertex for positions or a layer's displacement, 1 for a mask, 4 for a colour, counted in the undo memory) until the step is undone or another comes. A replayed take or stroke file plays each stroke as it was drawn, at 100%.

The look comes from one set of design tokens (`src/ui/theme.odin`, "Graphite"): surfaces, text, one blue accent and the status colours, three corner radii (6, 8, 12), five type sizes in Inter and the motion durations. The brush pie, the labels over the viewport and the Stats panel use the same tokens and typeface.

Motion (`src/ui/motion.odin`) follows Anime.js: a value eases toward its target over a duration, after an optional delay, and a new target sets off from wherever it is, so nothing jumps. Presses dip and wash, hover fades in, the marker under a chosen tab or brush slides, switches move their knob with a slight overshoot, menus and popovers grow from where they open and fade, groups open by growing, the tray slides, tooltips wait and fade, and notes rise in one after another. Nothing a stroke, the camera or a drag depends on is animated. Menu > Reduce motion (`reduce_motion on` in a script) makes every animation arrive at once; it is remembered.

The kit (`src/ui`) is drawn by the renderer's own UI pass (`src/render/ui_pass.odin`, `ui.vert`/`ui.frag`): one vertex and index buffer a frame, a single-channel glyph atlas updated only where it changed, one draw per texture and clip change, with the viewport image drawn as the first quad and the viewport's overlay (the brush outline, the gizmo, the shape being dragged) laid just over it, under the panels, though it is drawn after them, once the tools have run (`ui.layer_mark`). At 1600 x 900 a frame is about 6,500 vertices with the Brush palette open and 9,000 with the Object palette; laying it out, animating and tessellating it takes about 0.65 ms p50 (0.8 ms with the Object palette) in a release build on a 12-thread Windows desktop, at 1M and at 10M vertices alike (`ui_ms_p50`, `ui_ms_p99` and `ui_vertices` on exit). Animations change only the vertices drawn, never the layout, and the tweens live in one table allocated at start. Keys, the pointer and typed text come from SDL's events (`src/app/device.odin`); fingers and the pen come from SDL's touch and pen events (`src/app/touch.odin`, `src/app/navigate.odin`), with SDL's own turning of fingers into the mouse off (see Touch and pen below). Text is Inter (SIL Open Font License) and icons are Lucide (ISC), both embedded; their licences are in `assets/fonts`.

## Thumbnail

View > Thumbnail (the view menu, the command palette, or `thumbnail on` in a script) opens a small window under the object's readout showing the whole scene from the camera, as a sculptor steps back from the work: ZBrush's thumbnail view, and the painter's habit of flipping the picture to see its proportions afresh (`src/app/thumbnail.odin`, `src/render/thumbnail_view.odin`). **Silhouette** (the default) draws every object black on a light ground, so the outline reads without the shading; **Shaded** draws it as the viewport does; **Flip** mirrors it left to right. It is drawn at twice its size and smoothed, so the silhouette's edge is clean. Each picture draws every object whole, without the viewport's culling or simplified copies, so it is drawn again only when the scene or the view changed, once a stroke or a turn of the view is over, and at most ten times a second: while you work it costs nothing. Drag it by its dots; a long press on them or Close shuts it. Whether it is open, Shaded and Flip are remembered (`thumbnail`, `thumbnail_shaded`, `thumbnail_flip`). The exit stats print `thumbnail`, `thumbnail_draws`, `thumbnail_ms` (the CPU time of the last), `thumbnail_px`, `thumbnail_flip` and `thumbnail_shaded`. A release build's 120-frame stroke on a 2M sphere ran at the same frame time with it open as without (52 and 51 ms p50 on the VM's software GPU).

## Command palette

Ctrl+K, `/` (on keyboards where it has its own key; Ctrl+K works on every layout) or the Search button at the top of the right bar opens the command palette beside it: a search field over a list of every command the menus, the tray's buttons and the shortcuts run, one row per brush, tray section, view, mask command, paint, group command, remesh or decimate size and New scene shape, plus each Settings tab ("Settings: Touch") and each Help tab ("Help: Gestures"). Type part of a name, or a word another app uses for it (dynamesh, zremesher, subtool, freeze, polygroup, bpr, ...): rows whose name is the text come first, then names starting with it, then names with a word starting with each word typed, then those other words, then, from three letters, names holding the letters in order (`wfr` finds Wireframe). Among equals, a row run recently comes first, then one that can run now. Each row shows its icon, its shortcut, and a check when it is on; one that cannot run now (Duplicate object with nothing selected) is dimmed, does nothing, and its help line below starts "Not now". Up and Down pick a row (the list, eight rows or as many as the window's height leaves room for, scrolls to follow; with no keyboard, typing more narrows it), Enter or a tap runs it and closes the palette, and Escape, Android's Back, Ctrl+K again or a press outside closes it. With nothing typed the list starts with the starred rows, in the order they were starred, then the last eight rows run, which are remembered (`palette_recent`, by name) and cleared by Settings > Reset everything; a starred row shows a small star after its name. Under the help line three buttons act on the picked command, whether it can run now or not: Star (Starred when it is; up to 16 commands, remembered as `favourite` lines), Put in a pie (see Pies) and Assign key (see Controls). While the palette is open its field has the keys, so letters never run their shortcuts, and on a tablet the keyboard comes up with autocorrect and capitals off (for every text field, layer names too); hiding the keyboard (Back while it is up) closes the palette. Two commands that act where the pointer is (A's HD window and R's replay) are not listed.

## Statistics

F11, Menu > Stats or Settings > System shows the Stats panel at the top left, beside the brush bar. Simple, the default, says how smoothly the app runs in plain words, in four groups: Performance (frame rate; frame time and interface update time, each typical and in slower moments; the GPU's 3D time when measured), While sculpting (brush work per frame and input to the GPU, once a stroke has run), Mesh (objects, vertices, triangles, triangles drawn last frame) and Memory (the undo history's size; the memory of the whole app is not measured, so it is not shown), then Last operation (what the last remesh, smooth, file action and so on did, and how long it took). Typical is the median (p50) of the last 240 frames: half took less and half more. Slower moments is the 99th percentile (p99): 99 frames in 100 took that long or less; it is not the slowest frame. Interface update is only the time to lay out and draw the panels, one part of a frame. On Match display (or Limit), the frame time includes waiting for the screen (or the limit), so it sits near the refresh time even when the app has time to spare. "What do these numbers mean?" at the bottom says the same. Advanced shows every measurement by its exact name (`frame_ms`, `cpu_ms`, `ui_ms`, `cursor_ms` for laying the brush ring on the surface, ...) with its p50 and p99, the frame-time graph, the drawing switches and what the brush costs; a measurement with no samples yet says so instead of showing 0.

## Screenshots

Menu > Save screenshot (F12) writes the viewport, as the last frame drew it and without the brush outline or gizmo, to a PNG file at the viewport's size. The encoder is this repo's own (`src/png_write`; Odin's `core:image/png` only reads): each row filtered with Sub or Up, deflated with greedy matches and the fixed codes, so a 1214 x 862 viewport is about 200 KB and takes about 25 ms in a release build. `--dump-viewport=PATH` does the same on exit, or writes a binary PPM when the path ends in `.ppm`, which `scripts/ppm.py` reads.

## Pen and brush pie

The Brush palette's Pen section holds what a drawing tablet changes. "Pressure changes strength" and "Pressure changes size" choose what pen pressure scales; a mouse counts as full pressure. The pressure curve below them maps how hard the pen presses (along) to how much that counts as (up): a cubic Bézier from corner to corner whose two handles drag anywhere in the square, so it never falls back. Linear, Soft (light pressure goes far), Firm (it takes a press) and S are presets. A dot on the curve follows the pen. The Tilt slider (0 by default) lets a leaning pen turn the brush: the direction Draw, Clay, Flatten, Pinch and Crease push in leans toward the pen's top, by the pen's lean times the slider, at most 81 degrees, as Blender's tilt does; mirrored dabs lean the mirrored way. With tilt on, a line from the brush circle shows the lean. The readout under it shows the last pressure, what it counts as, and the lean. Tilt costs one small rotation a dab: a 2M stroke took the same brush time with it and without (1.27 to 1.33 ms p50 either way, run to run). SDL reports pen pressure and tilt on Windows (pointer messages) and on Linux (X11 and Wayland); neither is tested on a real tablet yet.

The brush pie puts every brush in a ring around the pointer, in key order clockwise from the top: each slice shows its number near the middle and the brush's name further out, a long name stepping down to the small size where its neighbours sit beside it, so no two names meet. Hold Space over the viewport, point toward a brush and let go to pick it, so a flick picks without aiming. A tap of Space, or a right click without dragging (a pen's side button sends one), leaves it open: click a brush, or click the middle, press Escape or tap again to close it. While it is open, nothing reaches the tools or the camera, and no press reaches a panel under it. The slice of the brush in use has a band along its outer edge.

## Pies

Four pies of your own, eight commands each, open the same way around the pointer, as Blender's Q Quick Favourites and ZBrush for iPad's quick menu do. Q opens Pie 1 and Shift+Q Pie 2 over the viewport (in the window's middle when the pointer is elsewhere, kept whole on screen); Pies 3 and 4 have no key until given one (Assign key). All four are in the command palette ("Pie 3"), which is how a tablet without a keyboard reaches them. Tap or click a slice to run its command; tap the middle, press Escape, right-click or press the pie's key again to close it, and another pie's key switches to that pie. Each slice shows the command's icon and name and a band when it is on (Wireframe, Orthographic); it is dimmed, and does nothing, when the command cannot run now, and an empty slot reads Empty; a tap on either keeps the pie open. While a pie is open no press reaches a panel under it, and the tap that opened it from the palette picks nothing from it. A fresh install has Pie 1 for the view and the object (Focus selected, Frame all, Wireframe, Flat shading, Orthographic, Studio render, Remesh, Search) and Pie 2 for the mask and hiding (Clear, Invert, Blur, Sharpen, Grow and Shrink the mask, Show all, Invert hidden); Pies 3 and 4 start empty.

The command palette's Put in a pie opens the pie editor for the picked command: four rows of eight slots, where a tap puts the command in a slot (replacing what was there), a long press or a right click empties a slot, and Reset pies puts the defaults back. Settings > Interface > Edit pies opens it to empty slots and reset only. A pie that differs from its defaults is remembered whole (`pie <pie 0-3> <slot 0-7> <command|empty>` lines, saved at once). Presets cannot go in a pie yet, and the user pies have no hold-and-flick: that is Space's brush pie.

## Brush falloff

The Brush palette's Falloff section shows how strongly the brush in use works from its centre (left) to its rim (right). By default it is the built-in smooth falloff, (1 − d²)² for the distance d in radii. Dragging either handle draws your own: a cubic curve read from the rim in, as the pressure curve is drawn, so it is always 0 at the rim and full at the centre. Presets: Smooth (the built-in), Linear (a cone), Sharp (a point in the middle, for creases and pores), Firm (most of the radius at full strength) and Flat (full strength to the rim, a hard-edged stamp). Each brush keeps its own falloff, Grab and Mask included; an alpha replaces it. Under the curve, Focal shift (-100 to 100, 0 by default, each brush its own, also on the brush bar and three fingers sideways) reshapes whichever falloff the brush has without changing its ends: the weight at d radii is the falloff's at d^p with p = 2^(−shift/50), so 100 pulls the brush to a point and −100 spreads it into a flat top with a hard edge. While it is not 0 the brush ring shows an inner ring where the brush works at half strength. A shifted falloff is a table too, so it costs what a drawn one does. The sculptor reads a drawn falloff from a 257-entry table over the squared distance, so it costs no square root: a 2M stroke's brush time was 7 to 12% higher with one than with the built-in (0.24 vs 0.25 to 0.27 ms p50, release, test VM). Script: `falloff sharp` (or another preset's name) gives every brush that preset, keeping their focal shifts, and `focal 40` gives every brush that focal shift.

## Brush alphas

An alpha, as in ZBrush (Blender calls it a brush texture), is a square grey image that shapes each dab in place of the round falloff: white moves fully, black not at all. The Brush palette's Alpha section shows the round brush and every alpha as thumbnails; tap one to use it. Six are built in: Square (flat stamps and edges), Noise (bumps of every size, for skin, stone and bark), Rings, Stripes (ridges along the image's up, so along a stroke they rake parallel grooves), Dots (rivets, scales) and Star. "Load image..." adds a PNG, JPEG, BMP, TGA or QOI file: its brightness times its opacity, padded to a square and averaged down to at most 512 pixels a side, so a grey height map and a white shape on a transparent ground both work. Every brush but Grab uses the alpha; Shift's smoothing stays round. Load image also keeps a copy of the file in the library, a folder `library/mine/alphas` beside the settings file (`<name>-library` for `--settings-file=<name>.txt`, and none for a run that keeps no settings), so the image is back after the built-ins at the next start, and so is every preset that uses it, and the brush's own alpha. The same image loaded again is found there by its bytes and not kept twice; another image of a name already there is kept as `rock-2` and on, and the file's name is made safe for every system (letters, digits, spaces, `-`, `_`, brackets). Presets, the settings file and scripts name a kept alpha `mine/<name>` (`alpha mine/rock`) and a built-in by its name; an image a script loads by its path is not kept. With a kept alpha selected, Remove from library (tap it twice) deletes its file, and the brush and every preset that used it go back to round, with a note counting those presets. A file in the library that is not an image the app reads is skipped at start, with a note naming it, and left on disk. The exit stats add `library_alphas` (kept alphas), `library_skipped` and `alpha` (the brush's alpha by reference, or `-` for round).

### Content packs

A content pack is a `.sculptpack` file: a ZIP archive, so any zip tool makes one, holding `pack.txt`, brush alphas under `alphas/` (PNG, JPEG, BMP, TGA or QOI images, right in that folder), brush presets in `brushes.txt`, base meshes under `meshes/` (OBJ or PLY files, right in that folder, at most 64), and MatCaps under `matcaps/` (images of a lit sphere, right in that folder, at most 32, each at most 1024 x 1024) with materials in `materials.txt`. `pack.txt` has one `key value` line each for `name` (needed), `author`, `version`, `description` and `license`; lines starting with `#` and other keys are skipped, and values are cut to 200 characters. Menu > Library (or Search) opens the Library panel in the tray's place: Install pack and Make a pack at its top, then Your own (the alphas Load image kept) and every pack installed, with its author, version, licence, how many alphas, presets, meshes and materials it holds, and its description, and a bin to remove it (tap it twice). Install pack picks the file with the system's file dialog (on Android every file is offered, since the picker cannot filter by `.sculptpack`, and the archive's own bytes decide) and installs it on a thread of its own, so a big pack never holds up a frame. Before anything is written the archive is checked: at most 4096 entries and 512 MB unpacked, sizes read from its directory and every entry inflated no further than it says (a zip bomb is refused), no encryption or ZIP64, names that cannot climb out of the folder or mean something else on another system (no `..`, absolute paths, drives, backslashes or Windows device names, and no two that differ only in case), every entry's checksum, a `pack.txt` with a name, every alpha an image the app reads, every MatCap one too and no larger than 1024 x 1024, and every mesh one that reads and cleans as Import would (the note names a bad mesh's line); one failure refuses the pack, with a note saying why. `brushes.txt` holds `preset` lines exactly as `settings.txt` writes them (see Brush presets), at most 256, whose alpha is `-`, a built-in's name or the name of one of the pack's own alphas without its extension; a line that is damaged, repeats a name, takes a brush's own name or names an alpha the pack lacks is skipped, and the note counts those lines. A second mesh of one name (Boulder.obj and Boulder.ply) and anything in a folder below `meshes/` are left out, and so is anything else in the archive (scripts, shaders), with a note counting it: a pack is data only and never brings code. The pack is unpacked into the library's `.incoming` folder and renamed into place as `library/<id>` (its name in lower case, letters and digits with dashes, numbered when another pack has it), so an install cut short leaves nothing half there. Its alphas join the Alpha section under the pack's name and are named `<id>/<name>` in presets, the settings and scripts (`alpha rock-set/pebble`). Its presets join the brush browser, the dock's slot menu and the Preset section's list under the pack's name, and are named `<id>/<name>` in scripts (`preset rock-set/stone clay`). They are read-only: picking one copies its values onto the brush as any preset does, and the Preset section offers Revert and Save as new preset (a preset of your own named after it, "Stone clay 1") but not Save changes, Rename or Delete. The brush and the dock slots on a pack's preset are remembered (`brush_pack_preset <id> <name>` and, after the slot's own `dock` line, `dock_pack <slot> <id> <name>`, which older versions skip). Installing a pack of the same name and author as one installed asks first, in the Library panel: Replace moves the old folder aside, renames the new one in, then deletes the old, and the alphas still there keep their names, so presets that use them keep working; presets on an alpha the new version dropped go round, with a note counting them; the brush and dock slots on one of its presets stay on the preset of that name in the new version, or go back to the plain brush when it has none. Removing a pack deletes its folder, sends the brush and presets that used its alphas back to round, the brush on one of its presets back to the plain brush and those slots back to their brush. Packs only add: they cannot change the built-in alphas. Its meshes are listed with their vertex and triangle counts in the pack's `meshes.txt`, so a start lists them without reading them again. Menu > New scene lists each pack's meshes under its name after the six shapes (a tap starts a scene of that mesh alone, cleaned, centred and sized as Import does, with the same second tap to discard work); Scene > Add object lists them after the shapes ("Boulder (Rock Set)", with no size to pick) and the Objects card's Add menu under the pack's name, each adding the mesh beside the others as one undo step, named after its file. Replacing a pack keeps Add object's pick on the new copy of a mesh of the same name; removing it puts the pick back on the shape, and objects already made from its meshes stay. `materials.txt` has one `material <name> <r> <g> <b> <metallic> <roughness> <matcap>` line a material, at most 64: the name escaped as preset names are (`%20` for a space), the colour in linear light from 0 to 1 (as the Custom material keeps it), metallic from 0 to 1, roughness from 0.04 to 1, and the MatCap `-` for the lights, a built-in's word (`red-wax`, `clay`, `grey`, `skin`, `pearl` or `toon`) or the name of one of the pack's own without its extension, which wins over a built-in's word. A line that is damaged, has a value out of range, repeats a name, takes a preset material's name or Custom, or names a MatCap the pack lacks is skipped and counted in the note. A MatCap no line names becomes a material of its own, white and named after its file, so a folder of MatCap pictures is a pack as it stands. The pack's materials come after Custom in the Material section's list ("Moss (Rock Set)"), and are named `<id>/<name>` in scripts (`set material rock-set/moss`) and the settings, whose `material` line keeps the one new objects take (older versions skip it and start on Clay), as `custom_material` keeps Custom's MatCap when it is a pack's. A MatCap's texture is made the first time something shows it and let go once something else is made and nothing shows it, so a library of many uses GPU memory only for those in use; one whose file no longer reads leaves a note and the lights. A scene file (version 16) keeps a pack's material or MatCap by name with its values, an object's and a polygroup's alike, and opened where that pack is not installed the object has a Custom material of the same colours with the lights, with a note counting those objects. Replacing a pack moves objects, the material new objects take and Custom's MatCap to the new version's of the same name; removing it, or a replace without it, leaves those objects a Custom material of the same colours (with the lights where the MatCap went), Custom with the lights and new objects on Clay, with a note counting the objects. Make a pack writes your own alphas (the ones Load image kept) and your own presets as a `.sculptpack`, named after the file you save it as ("Bolt clay.sculptpack" is the pack "Bolt clay"), with stored entries any zip tool opens; a preset on one of your alphas names it by its file, one on a built-in by its name, and one on another pack's alpha goes round in it, since that alpha is not yours to pass on, with a note counting those presets. With no alpha or preset of your own it is disabled. The script verb `install_pack PATH` installs a pack in place (replacing one of the same name and author), `make_pack PATH` makes one, and the `library` command opens the panel. The exit stats add `packs`, `pack_alphas`, `pack_presets`, `pack_meshes`, `pack_materials`, `pack_matcaps`, `pack_matcap_textures` (made this run), `packs_installed` and `packs_refused`, and `selected_material` names the selected object's material.

The image lies on the plane across the area under the brush, its middle on the dab's centre and its sides one radius away, so a stamp sits flat on a curved surface. A vertex takes the image's value where it falls, blended between pixels, and fades as it lies further above or below that plane. Which way the image's top faces is the mode: Follow stroke turns it with the stroke, Fixed keeps it to the screen's up, and Random turns every dab a new way, for texture without a visible repeat (the turns come from the stroke's seed, as Spray's do, so a replayed stroke turns each dab the same way); Angle turns it further. The brush outline becomes the image's square, turned as the next dab will be, with a tick at its top. Symmetry mirrors the image too, so a stamp on the left reads backwards on the right as a mirror would show it.

A dab looks for vertices as far out as the image is above 0, measured when it loads: up to the square's corners, 1.41 radii, but no further than the round brush for images that fade out inside their circle, like the built-in ones but Square. With the Noise alpha a dab costs about a fifth more than Draw and a frame under a tenth more (`build/bench --brushes`, the large brush; Draw measured 0.037 and 0.312 ms a dab and 0.27 and 1.91 ms a frame at 1M and 10M in the same run, beside the alpha row in the table above), the extra being three dot products and one image lookup a vertex.

## Viewport materials, flat shading and wireframe

The Scene palette's Look section (also "look", "matcap", "shading" or "style" in the command palette, and `viewport_look sculpt_studio` or `viewport_look classic` in a script) puts on a whole look at once, the way Nomad's and Blender's viewport shading presets do, while each part stays its own control. **Sculpt studio** is soft grey clay (the Studio grey material) under a key light from the upper left, the fill all but off and the rim light behind on, deeper Cavity (0.7), styled shading (below), Occlusion while working, and the studio render at full Occlusion, Shadow 0.6 and Shadow softness 8.6°, so soft shadows fall from the jaw onto the neck once the view is still, on a flat dark grey backdrop. It matches renders of grey studio sculpts: on a 3.8M-triangle head the lit face is about 200 of 255, the neck in the jaw's shadow 40 to 70, the backdrop 42. **Classic** is the look the app always had: Clay, the starting lights, the gradient, plain shading, both occlusions off. A preset sets the material new objects take and the selected objects' (as a pick in Material does), the scene's lights and the starting ones, and the rest; it is not an undo step. Its tab shows lit while the style and the studio render are as it set them. Beside the tabs: Key light (the first light's Intensity), Ambient, Shadow and Shadow softness; under More options Occlusion, Styled shading with Rim and Underside, and the Background's brightness. A fresh install, and settings from before there were presets, start in Sculpt studio once; after that the settings keep what was chosen. Runs with `--no-settings`, `--frames` or a settings file of their own keep Classic, so scripts, tests and benchmarks look as before.

The Scene palette's Material section picks how the selected objects are shaded. The classic presets are Clay (the code's default and Classic's), Red wax, White, Grey, Skin and Studio grey (Sculpt studio's, a soft grey with a faint broad sheen): each sets the selected object's colour, a muted one for the others, and the light's ambient, highlight and wrap (wax and skin let the light reach past the shadow line, as scattering does). Below them are physically based materials: Gold, Copper, Chrome and Steel (metals, coloured by measured reflectance), Plastic, Ceramic, Rubber and PBR clay. These use metallic and roughness with GGX highlights from the lights (see Lights) plus the reflection of a procedural studio that roughness blurs: a cool sky over a dark floor, a warm softbox above and beside the key light, a cool strip light behind on the right that catches edges, and a bounce card behind the camera so faces turned to the viewer reflect something. Where the normal varies within a pixel, as on a dense sculpt seen from afar, highlights widen instead of sparkling (specular anti-aliasing, as Filament does it). It is all computed in the fragment shader, so they take no memory and cost the same at any vertex count. The colour, Metallic and Roughness sliders under it edit whichever material is in use into Custom, leaving the presets as they are. Every colour in the panels (the material's, Polypaint's and the Paint brush's) is a swatch beside its hex code over Red, Green and Blue sliders from 0 to 255, all in the values a screen shows (sRGB, as image editors and Blender's hex field give them), so a code copied from elsewhere gives the same colour here. A tap on the hex field empties it to type a code over its hint, the code it had: `#RRGGBB` or `#RGB`, with or without the `#`, in either case; the colour follows as soon as the code is whole, and Enter or a tap elsewhere ends it. The material's colour is kept as linear light, which is what the shader lights, so its sliders and swatch go through the sRGB curve (moving one channel converts only that channel); paint is kept as shown. Settings and scene files hold the same numbers as before. Every material, classic or physically based, goes through the same display path: the lit colour is scaled by **Exposure** (in stops, -3 to 3, under More options; 0 by default), tone mapped with Khronos PBR Neutral (colours below about 0.8 pass through nearly unchanged, brighter ones roll off toward white instead of clipping) and encoded with the exact sRGB curve, which keeps the darkest values dark where a plain 2.2 power used to grey crevices out; polypaint is decoded with the same curve. **Cavity** (0.5 by default) darkens creases and **Ridge** (0.3, under More options) lightens crests, as ZBrush's materials and Blender's cavity shading do, so fine sculpted detail reads at any light angle: the shader measures how far the normal turns across each pixel, so it needs no extra pass, vertex data or memory, works with partial redraw and the idle cache, and picks out grooves and pores while leaving broad forms alone (a crest's lightening fades toward the silhouette). Because it is measured per pixel, a form drawn small (zoomed out) shows more of it than the same form close up. Flat shading turns both off. Script: `set cavity 0.6`, `set ridge 0`, `set exposure -0.5`; all three are remembered.

**Each object has its own material**, kept in the scene file (version 14; version 16 keeps a content pack's material by name, see Content packs). The Material section shows the selected object's, and a pick or a moved slider goes to every selected object and becomes the material new objects take (Add object, import, New scene); the others keep theirs. An object made from another takes its material: a duplicate or paste, both parts of a slice, split pieces, an extracted shell, a retopologized copy, an Insert of an object; Merge visible takes the first merged object's. A material change is no undo step (as in ZBrush, where materials are outside Undo History), but the scene counts as changed, and undoing or redoing something else (a remesh, a slice) leaves materials as they are. A scene saved before version 14 opens with every object in the material new objects take, which is how it showed. **Dim the others** (under More options, on by default, remembered) shows the objects that are not selected in their material's muted colour, as the app always has, so the one being sculpted stands out; off, each shows its own colour. A Custom MatCap material uses the one loaded image, which the scene does not store: loading another changes every object using it. Script: `set material steel` gives the selection steel too (the settings file's `material` line only sets what new objects take), `set dim_others off`.

**Each polygroup can have a material of its own**, as ZBrush's polygroup materials and Blender's material slots give one: gold trim on a steel plate, in one object. When the selected object has polygroups (Object palette, Polygroups), the Material section shows Object and Group tabs. Group's **Pick a group** (also in the command palette) waits for a press on the selected object and takes the group under it; group 0, the faces in no group, is always the object's own. A pick from the list (the lit presets and Custom) or a moved colour, and under More options Metallic and Roughness, give that group its own material; **Use the object's material** gives it back. An object has at most 15 groups with their own, and a MatCap cannot shade a group, since a draw has one matcap picture, the object's. The renderer looks each triangle's group up in a small table sent with the frame's uniforms (16 slots: slot 0 the object's own), so it adds no vertex data, costs the same at any vertex count, and partial redraws and the idle cache stay exact; HD windows, the boolean preview and the thumbnails show the object's material. Like the object's material it is outside Undo and kept in the scene file (version 15; an older file opens with none), but a group command that renumbers the groups (Visible, Masked, Creases, Clear) takes the materials with them in the same undo step: each goes to the group that now holds most of its faces, and is dropped when that is group 0. Rebuilds that keep the groups keep them; dynamic topology, which has no groups, drops them. Split gives each piece its groups' materials (a piece of one group with its own takes it as the object's), and Merge keeps every part's look, a merged object's groups taking its material. Script: `set material gold` then `group_material 3` gives group 3 gold, `group_material 3 off` takes it away.

**MatCaps** come last in the list, as ZBrush's MatCap materials and Blender's MatCap shading: Red wax, Clay, Grey, Skin, Pearl and Toon MatCap. A matcap is a picture of a lit sphere that stands in for the lights: the shader looks the picture up by where the surface's normal points as the camera sees it (with Blender's correction, so the sides of a wide-angle view do not smear), so the light, colour, sheen and rim painted into it cover the whole mesh with one texture fetch a pixel. The light therefore turns with the camera, never with the object. The six built-in ones are painted in code at start-up (`src/app/matcaps.odin`: a key light from the upper left, sky and ground light, a highlight, a broad sheen, a rim, light scattered along the shadow's edge for wax and skin, and three hard-edged tones for Toon), 256 x 256 each with a full mip chain, 1.4 MB of GPU memory for all six, and the app ships no image files. The picture is multiplied by the material colour (white for the presets), so polypaint and the mask show as they do on the other materials, and Cavity, Ridge and Exposure work on them too; Metallic and Roughness are hidden, since the picture holds the sheen. Under More options, **Load MatCap...** takes any PNG, JPEG, BMP, TGA or QOI picture of a lit sphere (the sphere filling the square, as matcap libraries share them; grey, 16-bit and alpha pictures work, alpha is ignored) and makes it the Custom material in white; moving the colour then tints it. The Custom material remembers its matcap, and the image loaded last is loaded again on the next start (a `matcap_image` line; a missing file leaves a note and the lights). Script: `set material "clay matcap"`, `matcap path/to/sphere.png`.

Styled shading, for the look of a studio's grey sculpt renders, changes two things on the lit materials (classic and physically based; MatCaps carry their own light): the ambient light falls off toward surfaces facing down, to Underside's share facing straight down (0.15 at first), so a chin shades the neck and a brow the eyes; and the classic rim is narrower and gathers on the upper silhouettes, at Rim's strength (0.35 at first). Down is the light rig's, so it turns with the lights. Off, the shading is exactly as before. Script: `set styled on`, `set rim 0.5`, `set underside 0.2`; all three remembered with the settings.

View > Flat shading, or Shift+G, lights each triangle with its own normal, so the facets show instead of the smoothed normals; the shader takes the triangle's normal from screen-space derivatives of the position, so it needs no extra vertex data and works with every material. While the view moves, far parts drawn from simplified copies show those copies' larger facets. View > Wireframe, or Shift+F as ZBrush's PolyFrame, draws the selected object's triangle edges over it: the same visible chunks again with line fill, pulled toward the eye by a depth bias so they sit on the surface, so it roughly doubles the selected object's draw cost while it is on. A long press on Wireframe picks what it shows, as ZBrush's PolyFrame does: Lines (the edges, on at first), Fill (the selected object's polygroups in their colours, as Polygroups shows them on every object) or both. Script: `set material steel`, `flat_shading on`, `wireframe on`, `set polyframe_fill 1`.

The view menu's Field of view (15 to 100 degrees, 40 at first; a long press on Orthographic) sets the lens: wider strengthens the perspective, narrower flattens it toward a long lens's. The eye moves along its line as it changes, so the model keeps its size on screen; Reset camera keeps it, and an orthographic view does not change with it. Script: `set fov 0.7` (radians); remembered with the settings.

Floor grid (the right bar, Shift+P, as ZBrush's Floor) draws grid lines under everything shown, and on the walls behind it as you look when its section (a long press, or Scene > Floor grid) turns them on: Floor, Back (square to Z) and Side (square to X), each on the scene's box, the walls on whichever side faces away from the eye, so the grid never stands in front of the model. A brighter line comes every fifth cell, and with Axes in colour the lines through the origin show as the axes, X red, Y green and Z blue. Fit cells to the scene (on at first) makes a cell a round 1, 2 or 5 times a power of ten near an eighth of the scene's size; off, Cell size sets it. Each plane is one full-screen triangle whose pixels find where their ray meets the plane (`src/render/shaders/floor.frag`): the lines stay one pixel wide and smooth at any distance or slant, the minor ones fade where their cells grow too small to tell apart, all of them fade out a little way round the scene, and each point writes its own depth, so a mesh in front hides the grid and the grid crosses a mesh behind it. It is drawn after the meshes in every pass and never into the idle cache, so partial redraws stay exact. The scene's box is taken again only when the work, an object's place or what shows changes, never during a stroke or a drag, so the floor holds still while you sculpt. Script: `floor_grid on`, `set floor_z 1`, `set floor_fit 0`, `set floor_cell 0.5`; remembered with the settings.

Background (Scene > Background) sets what the viewport shows behind everything: one colour, or with Gradient (on at first) a top colour that shades into a bottom one down the viewport, a soft grey from #454547 to #17171A. With the gradient, Top and Bottom pick which edge's colour the picker below edits, as a swatch, a hex code and Red, Green and Blue sliders. The gradient is dithered under half a step of 8 bits, so it shows no bands, and the same pixel always gets the same value, so partial redraws stay exact. Screenshots, the time-lapse and the studio render show it as the viewport does; thumbnails and the navigation head stay transparent. Script: `set background_gradient off`, `set background_top 0.17 0.17 0.17`, `set background_bottom 0 0 0.1`; remembered with the settings. The exit stats give `background_gradient`, `background_top` and `background_bottom` (as hex codes).

Transparency (the right bar) draws every shown object but the selected one see-through, at 30%, so the selected one shows through whatever stands before it, as ZBrush's Transp does. The see-through objects blend over everything drawn before them and leave the depth alone, so the idle cache is not used while it is on, and with anti-aliasing a stroke's frames redraw the whole view rather than a rectangle. The studio render's occlusion and shadows see only the solid ones. Script: `transparency on`; remembered with the settings.

## Lights

The scene has its own lights, up to eight, as in Blender, Marmoset and KeyShot, edited in the Scene palette's Lights section as ZBrush's Light palette is. Each light is a **Sun** (from a direction, as from far away), a **Point** (from a place, every way, brighter close up) or a **Spot** (from a place, into a cone), switched on or off, with its own Intensity and colour, and an Ambient light lifts every side evenly. Each one **moves with** the camera, as ZBrush's and Blender's studio lights do, so a form reads the same way however it is turned, or stays in the **scene**, so the lit side stays put while the camera goes round, which is how a form is judged on a turntable. A new scene starts with four suns moving with the camera: Light 1 (the key, upper left) and Light 2 (a weak fill, lower right) on, Light 3 (a rim from behind on the upper right) and Light 4 (a bounce from below) waiting off, so the default look is the one the app always had, pixel for pixel.
- **The light sphere** at the top is a ball lit by the lights as the camera sees them, with a numbered marker for each light that is on: filled when the light is in front of the model, a ring when it is behind. The picked light is circled. A point light or a spot shows where it stands as seen from the orbit's centre.
  - A press on a marker (within a finger's reach) picks that light. A drag on the sphere moves the picked light to the finger, the pen or the mouse, keeping it in front or behind, and switches it on; a point light or a spot moves round the orbit's centre at the distance it was, a spot still aimed at the centre.
  - A tap on the picked light sends it behind the model, or brings it back in front, at the same place on the sphere: from behind, a light catches the model's edges. A tap on the empty sphere puts the picked light there.
- **Markers in the viewport**, while the section shows, stand for every light, as Blender, KeyShot and Marmoset draw their lamps: a dark plate with the light's kind's icon ringed in its colour, faded when it is off, the picked one ringed in the accent. A point light or a spot stands where it is, a spot with a line to where it is aimed; a sun, which has only a direction, stands on a large circle round the orbit's centre (0.42 of the view's shorter side) where the light sphere would show it, on a lighter plate when it is behind the model. A marker whose place is off screen, behind the camera or under the bars or the palette is held smaller at the edge of the room left, on the line from the middle toward it. A press on a marker (within a finger's reach, for any tool; it never sculpts) picks that light, and a drag moves it: a sun round the circle, keeping the side it was on, as on the light sphere; a point light or a spot across the view at the depth it had, a spot still aimed at the point it was. The picked point light or spot also has the Move tool's handles about its marker, as Blender's lamps take its axis moves and Marmoset's lights their gizmo: an arm along each of the scene's axes (red x, green y, blue z) moves it along that axis alone, and a square between two arms across their plane, the third axis held exactly; the marker in the middle still moves it across the view. A mouse or pen hovering lights the handle it would take; a press on one is the lights' for any tool, as a marker's is. A marker held at the edge has none, since its light is not where it shows. Each drag is one undo step ("Move light").
- **Place highlight** (a switch under Intensity), as Marmoset's light placement and KeyShot's highlight tool: while it is on, a press on the model moves the picked light so its highlight, seen from the camera, lands under the finger, the pen or the mouse, following it while held. The light comes from the view direction mirrored about the surface there: a sun turns; a point light or a spot moves round that spot at the distance it was from it (a sun's place, the camera's distance), a spot aimed at it. It switches the light on, and each press is one undo step ("Place highlight"). A press off the model still turns the view.
- **The list** under it shows each light, as the Scene palette lists objects: its kind's icon (a sun, a bulb, a ceiling lamp), its name (Light 1 to Light 8, numbered as on the sphere), what it is and moves with, and an eye that switches it on or off. A tap picks the light the controls below edit. **Add** Sun, Point or Spot puts a new light after the others and picks it (up to eight): a sun moving with the camera, shining from the upper right in front; a point light or a spot standing in the scene up and to the right of the orbit's centre, as far away as the camera, a spot aimed at the centre, as a new lamp is placed in Blender or KeyShot. Then **Intensity** (0 to 2) and, under More options, its **name** (typed, up to 23 bytes; the typing is one undo step, "Rename light", and an empty name shows the light's number), its colour (a swatch, hex code and Red, Green and Blue, as every colour is), **Colour temperature** (a switch: on, the light shines in the colour of a black body at **Temperature**, 1700 K to 12000 K, 6500 K when switched on, as a lamp is set in Blender, KeyShot or Marmoset; picking a colour switches it off), its kind (**Sun**, **Point**, **Spot**; a point light or a spot adds **Distance**, how far it stands from the orbit's centre, from a twentieth of the camera's distance to twenty times it, moving it along the line from the centre while it points the same way), its size (a sun's **Angle**, 0° to 60° across, the real sun's being about half a degree; a point light's or a spot's **Radius**, in scene units, the slider reaching half the camera's distance; each kept while the light is the other kind, as Blender keeps a sun's angle and a lamp's radius; a bigger light gives broader, softer highlights, a smooth or glossy surface most, by Karis's representative point with the highlight's energy kept, and 0, the default, shades exactly as a light without a size; a spot adds **Cone**, 1° to 160°, and **Soft edge**, the share of the cone from its edge in that fades), what it **Moves with** (Camera or Scene; switching keeps it exactly where it is on screen) and **Delete** (the lights after it move up). Adding and deleting are undo steps of their own ("Add light", "Delete light").
- Under More options, after the picked light's controls, **Ambient** (0 to 2, 1 by default) scales the material's ambient light and, on the physically based materials, the studio's diffuse light; their reflections stay.
- Under More options, **All fixed to the scene** moves every light, and the environment, to the scene, or back to the camera, keeping each light exactly where it is on screen; the environment keeps where it was for a camera turned about the up axis (Turn all takes the camera's own turn in or out).
- **Turn all** (-180° to 180°) and **Height all** (-90° to 90°), under More options, swing every light moving with the camera and the studio the physically based materials reflect round together, about the view's up axis or up and down; lights in the scene stay where they are.
- **Use as starting lights** makes the lights the ones every new scene, and every scene saved before scenes kept lights, starts with (remembered with the settings); **Reset lights** puts the scene's lights back as a fresh install has them.

A point light or a spot is as bright as a sun of its Intensity at the distance it was first placed (the orbit's distance then), and falls off with the square of the distance from there, as a real lamp does, so moving it closer brightens the model. Its reach (`light1_reach`, in scene units, 0 for none) fades it smoothly to nothing there, so a far light never pops off. A spot shines along the way it points, inside its cone, its edge faded over the soft edge with a smoothstep. Every change in the section, from a press to its release, is one undo step ("Lights" on the History timeline), and the lights are saved in the scene file (version 19, with each light's colour temperature and name from version 20; an older file opens with the starting lights, a version 19 one's lights with no temperature and no names, and a damaged lights section is refused like any damaged scene). Autosave notices a change to them.

Every light that is on casts the studio render's shadows (see Studio render), each as wide as its own size; with every light off it shows the occlusion alone. MatCaps carry their own light and ignore the lights. A light lights both the classic and the physically based materials, at three times its Intensity on the latter. The shader loops over eight lights sent per draw and hashed into both frame keys, so partial redraw and the idle cache stay exact; lights that are off cost one comparison. Script: `set light1_on on`, `set light1_kind point` (`sun`, `point`, `spot`), `set light1_space scene` (`camera`, `scene`; the numbers are then read in the scene's axes), `set light1_x -0.5`, `set light1_y 0.6`, `set light1_z 0.6` (toward the light, in front of the model for z above 0 when it moves with the camera, made unit length where it is used), `set light1_px 1`, `set light1_py 0.5`, `set light1_pz 2` (where a point light or spot is: from the orbit's centre in the lights' frame when it moves with the camera, in the scene otherwise; left at 0 0 0, it is placed along its direction as far away as the camera), `set light1_strength 1.3`, `set light1_ref 2` (the distance at which it is as bright as a sun), `set light1_reach 10`, `set light1_cone 35`, `set light1_blend 0.3`, `set light1_color 1 0.8 0.6` (linear light, 0 to 1), `set light1_kelvin 3200` (0 for the colour as picked; below 1700 it is 1700), `set light1_angle 5` (a sun's size, degrees across, 0 to 60), `set light1_radius 0.2` (a point light's or spot's, 0 to 1000 scene units), the same for `light2` to `light8`, `set light_count 6` (0 to 8), `set light_ambient 0.5`, `set light_turn 90`, `set light_height 20`; `set lights_fixed on` moves every light to the scene with its numbers read in the scene's axes turned by Turn all, as it did before each light had its own space; the older `set light_key` and `set light_fill` set Light 1's and Light 2's Intensity. Scripts set the scene's lights; the settings file keeps the starting lights under the same names, a starting light's name as `light1_name`, with `environment_fixed`, and a settings file from before reads its lights as the starting lights (one from before the four lights keeps its key and fill strengths, one with the old `lights_fixed` its lights in the scene where they were). The exit stats add `light_pick`, `lights_on`, `light1` (its view-space direction), `light1_on`, `light_flips`, `light_count`, `light1_kind`, `light1_space`, `light_moves` (the drags of a marker or its handles and Place highlight presses made), `light1_name` (spaces as underscores), `light1_kelvin` and `light1_at` (where a point light or spot stands in the scene; 0,0,0 for a sun).

**Image environments.** The Scene palette's Environment section (after Lights) swaps the procedural studio for a panorama, as Blender's LookDev HDRIs do: Built-in (the studio above, the default) or Image, **Load environment...** (a Radiance `.hdr` file, or a PNG, JPEG, BMP, TGA or QOI picture read as sRGB; equirectangular, twice as wide as tall within a pixel, from 64 x 32 to 8192 a side, pictures at most 4096 wide on Android) and **Strength** (-4 to +4 stops). Under More options, **Background** shows the panorama behind the scene in place of the flat or gradient background, and **Blur** (0 to 1, 0.3 by default) how soft it shows. The physically based materials (and textured objects) then reflect the panorama, sharper or blurrier with their roughness, and take their diffuse light from it; the Lights section's lights still add theirs (switch them off there for the panorama alone). The classic materials and MatCaps are not lit by it. The panorama turns with the Lights section's Turn all (Height all does not tilt it, as a world rotation only spins) and, with All fixed to the scene, stays with the scene so the camera orbits inside it; otherwise it stays put on screen as the studio does. A file is decoded on a thread, halved by 2 x 2 averages until it is at most 2048 wide (1024 on Android); a Radiance file is read and halved row by row, so an 8k one never sits in memory whole, while a picture is decoded whole once its header shows it is within the limit (on Android the file picker offers every file, since it has no type for `.hdr`, and the bytes decide); Radiance files with flat or run-length rows are read, the old 1 1 1 run form and XYZE files are refused, and every value is clamped to a half float's largest (65504), so a blazing sun cannot become infinite. On the GPU it becomes an RGBA16F texture with a full mip chain and a copy half its size prefiltered once into six levels (roughness 0, 0.2 ... 1: 64 GGX samples a texel, each read from the mip that matches its solid angle, so few samples show no noise), about 27 MB for a 2048 panorama and 7 MB on a tablet (the section's status line says how much), and its diffuse light as nine spherical harmonics worked out on the CPU. A reflection is one texture fetch a pixel and the diffuse light nine multiply-adds, so the cost does not grow with the mesh; partial redraw and the idle cache stay exact (both frame keys hash which panorama and how it shows, and the background pixel depends only on its own ray). In a constant white panorama a white rough material with the lights off shows white (1 + the Fresnel term, about 1.016, before the tone map). With Built-in every image is the same as before, bit for bit. A file that is not a panorama, damaged or refused by the GPU leaves a note and changes nothing, and while a file decodes the one before keeps showing; one picked while another decodes waits its turn, the newest winning. Remembered like a loaded MatCap: `environment_source built_in|image`, `environment_fixed`, `environment_strength`, `environment_background`, `environment_blur` and an `environment_image` line naming the file, read again (and waited for) at the next start; a file gone since leaves a note and Built-in. It is a view setting, not kept in the scene file. Script: `environment path/to/sky.hdr` (waits for it and picks Image), `set environment_source built_in`, `set environment_background on`, `set environment_blur 0.5`, `set environment_strength -1`. Exit stats: `environment`, `environment_size`, `environment_background`, `environment_mb`.

## Frame rate

Settings > System > Frame rate says how often the app draws. Match display, the default, waits for the screen's refresh (vsync), so the app runs at whatever the screen runs at, 60, 120 or 144 Hz, and never draws a frame the screen would not show. Limit draws at most 30, 60, 90, 120, 144, 165 or 240 frames a second (`--frame-limit=N` for any other), shown as soon as they are ready (mailbox where the screen offers it, so without tearing), to save the battery or to keep an uneven rate steady. Unlimited draws as fast as it can, for measuring speed (`--no-vsync`). The wait for the limit comes before the frame reads its input, as the wait for the screen does, so a limited frame still shows the newest pointer position. Below the choice the panel says what the screen refreshes at and how frames reach it, so a screen set to 60 Hz in the system's display settings shows as such.

Android runs an app's screen at 60 Hz unless the app asks for more, even on a 120 Hz tablet, so on Android Match display and Unlimited ask for the highest rate the screen offers at its resolution (`ANativeWindow_setFrameRate`, from `android/app/jni/android_main.c`), and Limit asks for the limit, which lets a screen that can run slower save power; the system makes the final choice (a battery saver may still hold it at 60). The panel shows the highest rate when the screen runs below it. A settings file from before the choice keeps VSync off as Unlimited.

Rest when idle (on by default, below the frame rate) saves the battery between strokes. Once a second has passed in which no frame changed anything (no input, nothing held down, the same panels, nothing redrawn in the viewport, no stroke, replay, script, studio samples, thumbnails, Home's pictures or a thumbnail view waiting to be drawn), the app waits for the next event before each frame instead of drawing the same frame again, waking at least every 100 ms so timers and work finished on other threads still show. Any touch, key or pen event ends the rest at once, and the frame it wakes reads that input, so the first stroke after a rest is not late. Whether a frame changed anything is judged from what was drawn (a hash of the interface's triangles, and the viewport's partial redraw), so a fading panel or a moving progress bar keeps it awake without a list of what might animate. Scripted runs never rest unless `--idle-sleep` asks; the exit stats print `idle_rests` and `idle_rest_ms`. On the 4-core VM, 300 frames of an untouched scene with `--idle-sleep` took 18.7 s of rest after the first second, and used about a thirtieth of the CPU time per second of the frames before it.

## Anti-aliasing

Settings > System > Anti-aliasing (Off, 2x or 4x; 4x by default, 2x on Android) smooths the stepped edges of outlines, creases seen side on and wireframe lines with multisampling (MSAA): each pixel keeps 2 or 4 coverage and depth samples, the surface is shaded once a pixel, and the samples are averaged into the image the interface shows. Shading inside a surface is not multisampled; the specular anti-aliasing of the physically based materials and the matcaps' mip chains keep that from sparkling. It is an exact technique, so the same view gives the same image every time and partial redraw stays exact; there is no temporal or post-process blur over fine sculpted detail. The samples are kept from frame to frame (partial redraw loads them to redraw a rectangle, and the idle cache is multisampled too and copied sample for sample), so 4x costs about four times the viewport's colour and depth memory, about 130 MB more at 1920 x 1080 with the cache, and the bandwidth to load, store and average them each frame: on the order of a few tenths of a millisecond of GPU time at 1080p on a desktop GPU (not measured yet; `gpubench` reports it). With multisampling a partial redraw draws the meshes one pixel past the rectangle it clears, as some rasterizers (llvmpipe) test the scissor at each sample and would otherwise leave a seam; the depth test keeps what is already there. Thumbnails and the navigation head stay single-sampled. The studio render, which reads the camera's depth, draws a single-sampled copy of it once per still view. Where the GPU cannot use the count asked for it uses the other of 2x and 4x (Vulkan promises 4x), and where the viewport cannot be made at that count (out of memory) it turns anti-aliasing off, logs it and carries on. Script: `set msaa off` (or `x2`, `x4`); remembered with the settings.

## Brush presets

A preset is a named brush, as in Nomad or Blender: a base brush with its own strength, falloff and focal shift, alpha (with its mode and angle), stroke kind, lazy mouse, Lock plane and Connected only, paint colour and cloth mode. Size, the pen settings, symmetry and front faces only stay the same for every brush, so changing brush never changes how big it is. The Brush palette's first section, Preset, names the one the brush is on even while folded ("Preset: Soft clay · changed"). On a plain brush it offers Save as preset (named "Clay 1", "Clay 2", ...), which keeps the brush as it is and puts it on the new preset, and Reset brush, which puts the plain brush's strength, falloff and focal shift back to a fresh install's. Its list picks any preset, or None for the plain brush. On a preset: its name, to type a new one (Enter or a tap elsewhere renames it; an empty name, another preset's or a brush's own is refused), Save changes and Revert (while it differs from what was saved), Save as new preset (a copy), and under More options Delete preset. The brush's own slots hold the preset's values while it is on one, and leaving it (picking a brush by its key, the dock, the pie or the list) gives the plain brush its own back, so a preset never changes a plain brush and what is remembered for it. The palette finds Save brush as preset, Save preset changes, Revert preset, Delete preset and Reset brush.

**The brush browser** (`src/app/kit_brushes.odin`) is laid out as ZBrush for iPad's Brushes palette: Brushes on the brush bar opens it beside the bar and the dock's grid button above the dock. Its header holds Categories (which hides or shows the column at its left), the title, Search and Close. Down its left are the current brush's card (a large tile of it, whose tap or long press shows its settings, its name and what it is: a brush, a library preset, one of yours or a pack's, or a tool; and a heart that keeps it in Favorites) and the categories, each with how many it holds: Recent (the last twelve brushes, presets and tools picked, from the browser, the dock, a key or a pie, the last first), Favorites (in the order the heart added them), All, Clay (Draw, Clay, Layer, Inflate and the library's Standard, Clay buildup and Blob), Crease (Crease, Pinch, Sharp crease, Slash), Smooth (Smooth, Flatten, Hard polish, Trim and the three Smooth presets), Move (Grab, Snake hook, Move, Move connected, Move all depth), Cloth, Mask (the Mask brush, Mask rectangle and Mask lasso), Paint, Clip and hide (Hide rectangle, Hide lasso, Clip, Slice and Knife, as the reference app's SelectRect, SelectLasso, ClipCurve, SliceCurve and KnifeCurve), Curve and insert (the two tools), History (Morph, History), My presets, and each content pack's presets under its name. The built-in library is the brushes ZBrush for iPad's library opens on, each a preset over one of ours with the strength, focal shift, alpha and options that make it. In the middle the category's items are large tiles, three to a row and alphabetical (Recent and Favorites in their own order): a lit ball of clay (the paint colour for Paint, dark grey for the masks) with the brush's icon pressed into it, and its name under it (a long one is cut, and shown whole in its tooltip); what is chosen is ringed in the accent (the brush or preset held, the tool, and the mask shape and gesture the modifiers draw, so two can be at once). A tap picks one and closes the browser, a long press (or right-click) shows its settings (a preset's with the Preset section open, a tool's in the tray). A mask shape or a gesture tile makes it what Ctrl + drag on empty space, or Mask on the wheel, draws for the mask shapes, and what Ctrl + Shift + drag, or Hide on the wheel, runs for the rest, leaving the brush held alone and saying so in a note; neither goes in a dock slot. Down the right is an A to Z index: a tap or a drag on a letter scrolls the tiles to the first one starting with it (or with the next letter that has one); letters that start none are faint. Search turns the title into a field that lists, from every category, what has the typed text in its name, in any case. The grid opens scrolled to the brush held and scrolls with a drag or the wheel, as the categories do when they are taller than the room. The category, whether the categories are hidden, Recent and Favorites are remembered (`brush_category`, `brush_sidebar_hidden`, and `brush_recent` and `brush_favorite` lines that name each item by its kind and name, `brush/Clay` or `library/Trim`, so they outlive a preset deleted before one; one naming nothing lists nothing); the exit stats print `brush_category=`, `brush_recent=`, `brush_favorites=`, `brush_sidebar=`, `brush_search=` and `brush_browser_picks=`.

Each of the dock's 21 slots (three pages of seven) holds a brush or a preset, and a long press (or right-click) on one opens its menu above it: Brush settings (Preset settings on a preset), every brush and preset to put in the slot instead (a tap puts it there), and Reset dock, which gives back a fresh install's three pages. The same brush or preset may sit in two slots, and a deleted preset's slots go back to its brush. The built-in ones are read-only as a pack's are: Save as new preset makes one of your own from one ("Blob 1"), and their names are refused for your own (a preset of yours from before them by such a name is kept as "Trim 1" and so on, with the brush and dock slots on it); the Preset section's list has them after yours, scripts name them by name (`preset Smooth valleys`), and settings.txt keeps a brush or a dock slot on one by name. Up to 24 presets of your own; they and the dock are remembered with the settings, and an alpha is remembered by name, so a loaded image's comes back only when that image is loaded again (the built-in ones always do).

## Remembered settings

An interactive run remembers, for the next one, the brush (which one, its size, each brush's strength, falloff curve and focal shift, the last as `focal <brush> <shift>` lines for the brushes where it is not 0), the pen settings (pressure, its curve, tilt), lazy mouse, the stroke, front faces only, Lock plane, Connected only, All depth, Smooth only, symmetry (the axes, Local, and Radial with its copies and axis), the paint channel and both colours, the dynamic topology detail, the alpha (by reference, a `brush_alpha` line), its mode and angle, the material new objects take (with the Custom one and the MatCap image loaded last) and Dim the others, the viewport's Exposure, Cavity and Ridge, the lights, flat shading, wireframe and what it shows, orthographic view and the field of view, the floor grid, the background and Transparency, the Scene palette's shape and size for new objects, the mask steps and mask shape, and the command palette's recent rows, the scenes Home lists under Recent (`recent_scenes`, paths escaped as %20, newest first; written as soon as a scene is saved or opened), and the brush presets with the one the brush was on (`preset` and `brush_preset` lines, names escaped as %20), and the dock's slots (`dock <slot> brush <brush>` or `dock <slot> preset <name>`), and the keys given to commands (`key` lines; see Controls), the pies that were changed and the starred commands (`pie` and `favourite` lines; see Pies). ## Cloth brush

The Cloth brush (no key; in the brush browser and the pie) turns the surface in and around the brush into cloth for the length of a stroke, as Blender's cloth brush does, so it folds and wrinkles instead of stretching. Its mode, in the Brush palette's Stroke section: Drag (what is under the brush follows the pointer on the plane facing the camera, as Grab, and the cloth around it is pulled along into folds), Gravity (the region sags toward the bottom of the screen while the button is held, settling at about half a radius at full strength; Ctrl lifts it), Pinch (gathers the cloth toward the brush into radial folds, easing in over the first 40 frames up to 55% of the way at full strength; Ctrl expands) and Expand (pushes it outward so it buckles into a ring ridge; Ctrl pinches). The simulation (`src/sculpt/cloth.odin`) is position-based dynamics in the object's space: a damped Verlet step with the mode's force, then five Jacobi rounds over every triangle edge of the region that keep the edges at their lengths, puff squeezed cloth out along its starting normals so it folds outward together, and even out each vertex's displacement with its neighbours' (bending), so folds stay smooth on dense meshes. The region's outer 30% is increasingly held where it was, and masked or hidden vertices are held completely, so the cloth stays sewn to the rest of the mesh. It runs every frame while the button is down, even with the pointer still; the stroke is one undo step. Symmetry is not applied, and it does not run with dynamic topology on. Cost on the test VM (4 threads, release): on a 1M-vertex sphere about 2.3 ms a frame with a 60 px brush; at 10M (about 170k simulated vertices) about 18 ms a frame and 50-150 ms to set up at the start of a stroke, so it is a slower brush than the others, which it leaves untouched. Script: `brush cloth`, `set cloth_mode gravity` (or `drag`, `pinch`, `expand`).

## Studio render

View > Studio render (Shift+R, as ZBrush's BPR) builds the viewport up into ambient occlusion and soft shadows from every light while the view stays still, like a path-traced preview: crevices and creases deepen, and raised forms cast soft shadows onto what is behind them and onto other objects. Each still frame adds one light sample (`src/render/studio.odin`): it renders every object's depth from a direction into a 2048² shadow map, then for every viewport pixel reconstructs the surface point and normal from the viewport's depth and adds whether that light reaches it (3x3 filtered) to a half-float accumulation image. Three samples in four come from directions spread evenly all round the scene (an R2 sequence), weighted by how directly they face the surface, which gives the occlusion; one in four comes from one of the lights, jittered over its disc, which gives the soft shadows. Each of those picks a light by its share of the lights' brightness (a dim fill gets few samples), and counts at a pixel by how much of the light there that light gives, the ambient light included, so a shadow takes away only the light it blocks: a pixel lit mostly by the key darkens fully in the key's shadow, one lit by a dim fill and the ambient light only a little in the fill's. A sun's disc is as wide as its Angle, a point light or spot is a sphere of its Radius whose rays stop at it, and a light of size 0 takes Shadow softness. The image shown is the viewport darkened by both, by the Occlusion and Shadow strengths in the Scene palette's Studio render section; it settles within the Samples count (256 by default, at most 1024), after which it costs nothing. That section shows the count while it builds. Any change to the viewport, a stroke, the camera, a resize, starts it over; until the view is still again the plain viewport is copied through, so with it on a stroke costs one screen-sized copy a frame (10M stroke on the test VM: CPU frame p50 3.8-3.9 ms off and 4.8 ms on, where the llvmpipe software GPU makes that copy on the CPU; on a real GPU it is a fraction of a millisecond). Screenshots, `--dump-viewport` and the time-lapse save what the viewport shows. Shadow softness (under More options, 0.6° to 29°, 3.4° by default) is the radius of a light without a size of its own, how wide its shadow's soft edge spreads; a change starts the samples over. A change to Occlusion or Shadow once the samples are done shows at once. Whether it is on, its Occlusion, Shadow and Shadow softness are remembered with the settings. It needs a depth format shaders can read; where the device has none it logs a warning, the section says so, and the plain viewport shows (or live occlusion, when that is on). Script: `studio_render on`, `set studio_samples 64`, `set studio_softness 0.15` (radians).

Where the device allows, the samples are traced instead of shadow-mapped (`src/render/trace.odin`): each still frame casts one ray per pixel from the surface toward that sample's light against the real triangles, so occlusion and the lights' shadows keep detail finer than a shadow map's texel (about 1/1000 of the scene), and nothing in a shadow map can shadow a surface itself. Occlusion rays are cosine-weighted about the surface and unbounded; light rays aim at the picked light over its disc, and toward a point light or spot end at its sphere, so what stands beyond the lamp casts nothing; the shadow-mapped fallback casts a point light's shadow along one direction from the scene's middle. Each ray's directions are turned by a hash of its pixel, so the image settles as fine grain rather than bands. Every mesh keeps a tree over each chunk's triangles (leaves of up to 12, about 11-12 bytes a triangle on the GPU) and a tree over its shown chunks. A chunk's tree is built on the CPU, on all threads, only when its triangles change (remesh, levels, HD, dynamic topology, a voxel stroke; hiding does not count, since hidden triangles are skipped). It is refit on the GPU when only vertices moved (any stroke), and the chunks' tree is rebuilt only when their boxes moved or which are hidden changed. All of it happens at the first sample of a still view, so a stroke never waits for it. Cost on the test VM (4 threads, release, llvmpipe): the 3.8M-triangle head scan builds in 0.18 s (44 MB), a 500k one in 26 ms. See-through objects cast nothing. Meshes the device will not let a compute shader read, a tablet's mesh over 128 MB a buffer, or `--no-trace` keep the shadow maps, which give the same image as before. The traced result agrees with the shadow-mapped one to within 12 of 255 on all but a few silhouette pixels, where the shadow map's offsets had darkened edges. Bounded occlusion rays (a Reach, as Blender's AO Distance) are later work. The exit stats add `trace` (samples traced), `trace_mb`, `trace_build_ms` and `trace_chunks_built`.

Occlusion while working (the same section, under the studio render's controls; also a command, found as "ssao" or "ambient occlusion" in the palette) darkens creases and contact every frame, while sculpting and turning the view too, where the studio render waits for a still view. It is screen-space ambient occlusion, GTAO as Blender's EEVEE and Intel's XeGTAO compute it (`src/render/live_ao.odin`). For each pixel it reads the camera's depth along two directions out to Reach (under More options: a share of the scene's radius, 0.1 by default, 0.01 to 0.4, at most 48 pixels on screen), finds how high the surroundings rise either side, and integrates the cosine-weighted sky that leaves. The two directions turn, and the steps along them shift, in a 4 x 4 pattern that a 4 x 4 blur then averages away, weighted by depth so it does not bleed across silhouettes. That gives 32 directions a pixel with no noise left over and nothing that changes from frame to frame. It darkens the finished image with the studio render's Occlusion strength and curve, so it works on MatCaps as well as on the lit materials, the view does not jump when the studio render takes over, and the background is untouched. With the studio render on as well, it shows until the studio has built up 16 samples, a quarter of a second at 60 frames a second, so a stroke keeps its occlusion where the studio starts over. With partial redraw, a stroke's frame reruns the occlusion only over the rectangle the viewport redrew, padded by how far it reads, and keeps the rest. The result is the same to the bit as a full pass, with anti-aliasing off or 4x (which draws a single-sampled copy of the camera's depth, again only over that rectangle). Tablets work it out at half size each way and upsample it in the blur. Open surfaces keep their shading, and the seam where two spheres meet darkens about as much as the converged studio render darkens it (within about 10 of 255 across it). Script: `set live_ao on` (remembered with the settings), `set live_ao_reach 0.2`, `set studio_ao 1`. The exit stats add `live_ao`, `live_ao_full`, `live_ao_partial` and `live_ao_skipped` (frames it ran whole, over a rectangle, and not at all).

## Render mode

Scene > Render's Render mode (also a command, found as "render", "path trace" or "cycles" in the palette) path traces the view while it stays still, as Blender's rendered viewport does with Cycles: every light in the scene casts a soft shadow, light bounces between surfaces (a chin lights the neck from below, a coloured object tints its neighbour), and the materials are taken as physically based surfaces. It builds up a sample a pixel a still frame and shows from the fourth sample on; until then the viewport shows as it otherwise would (the studio render's or live occlusion's image when on). Any change, a stroke, the camera, a light, a material, starts it over, so it costs nothing while sculpting. It stops at Samples (1024 by default, 16 to 4096) and follows each path for up to Bounces surfaces (6 by default, 1 to 12; 1 is direct light only). Denoise (on by default) smooths the grain each time a sample is in, with the edge-avoiding À-Trous wavelet filter (Dammertz et al. 2010, `render_atrous.frag`): the first sample goes through each pixel's centre and keeps what it met's colour, normal and distance as guides, and five passes of a 5 x 5 kernel with taps 1 to 16 pixels apart blur the light with the colour divided out, each tap counting less where the guides say it is another surface or its light differs by more than the samples' noise explains, so creases, texture, paint and shadow edges stay sharp. It takes a pass fewer each time the samples grow four times past 64, down to two. The head at 16 samples looks finished where the raw image is grain. The section shows how many samples it has built and how long one takes. How it lights (`src/render/path.odin`, `render_trace.comp`):
- The lights are the viewport's, in the world, at their own size (a sun's Angle, a lamp's Radius, in the Lights section); a light of size 0 takes the studio's Shadow softness instead, a sun spanning a cone that wide and a point or spot light a sphere that wide seen from the scene's middle, each as bright as the viewport makes it where its light arrives. At each bounce one light is picked by its share of the brightness and sampled toward its shadow ray, and the surface's own reflection direction is weighed against it (multiple importance sampling), so small lights and wide ones both settle quickly.
- A path that leaves the scene takes the environment: the image environment at its Strength, or the built-in studio (the soft sky, the softbox, strip and card the materials reflect) at the ambient light's strength.
- Physically based materials keep their metallic and roughness (GGX with visible-normal sampling); the classic shading becomes a dielectric whose roughness matches its highlight's width, and a MatCap object its colour, half rough. Polypaint, polygroup colours and polygroups' own materials show as in the viewport. See-through objects are left out.
The scene is copied on the GPU into one set of buffers at the first sample of a still view, reusing each mesh's trees from the traced studio render, with a tree over every object's chunks built on the CPU; render mode needs a device that can trace (as the studio does) and write 32-bit float images from a compute shader, and otherwise the section says so. Tablets refuse a scene over 256 MB of copies. A frame takes a band of rows of one sample, as many as keep frames under about 50 ms, so the interface stays responsive. The image is the same every run. Half resolution (on by default on tablets, off on the desktop) traces half the viewport's size each way, a quarter of the pixels, and lays each traced pixel's light smoothly over the viewport, blended by how much of it met the scene so silhouettes stay soft over the viewport's own background: about three times as fast (0.2 s a sample against 0.55 s for three spheres on the test VM), a little softer. Render mode is off at every start; Samples, Bounces, Denoise and Half resolution are remembered. Cost on the test VM (llvmpipe software GPU, 1600 x 900): about 0.5 s a sample for three spheres, 0.8-0.9 s for a 500k-triangle head (20 MB of copies), 2.5 s for the 3.8M-triangle head scan (154 MB); a real GPU is far faster. An image environment is also sampled by its brightness, so a sun in the panorama lights the scene in a few samples where it used to show as scattered bright specks: each surface a path meets takes, besides a light, a direction the panorama's bright parts are likelier to give, in proportion to how much light the environment gives against the lights, weighed against the bounces that find it so nothing counts twice. Render mode reads the image at its full size, not the blurred copy the viewport reflects. The built-in studio is broad enough that bounces find it well, so it is sampled this way only when every light is off. Script: `render_mode on`, `set render_samples 64`, `set render_bounces 3`, `set render_denoise off`, `set render_half on`. The exit stats add `render`, `render_samples`, `render_ms` (a sample's time), `render_mb` (the scene copies) and `render_failed`.

## History timeline and time-lapse

The History panel (the clock button beside undo and redo) opens over the brush dock and lays every undo step on one bar, oldest at the left: a block per step, coloured by what it was (brush strokes gold, mask changes blue, hiding grey, Smooth all and Clip green, rebuilds such as remesh or add and delete orange), dimmed once undone. Press or drag anywhere on the bar to go to that point (a finger or the pen goes there on a tap, or scrubs once it moves past the slop); resting the pointer on it shows the step's brush or command, its object and how long ago it was made. The outer buttons jump to the start and the newest step, the ones beside them step one at a time, and Play replays the History forward at the Steps a second speed (from the start when it stands at the end). It moves only with undo and redo, as many as it takes, so it is exactly Ctrl+Z or Ctrl+Shift+Z pressed that many times: a stroke made after scrubbing back drops the steps ahead of it, and what the undo memory limits dropped is not on the bar. Scrubbing spends at most 25 ms a frame stepping, so a long drag stays responsive; a stroke undo takes about 2 ms at 10M vertices in a release build on the test VM, so the whole History of 40 strokes there rewinds in well under a second.

A right-click, or a long press of a finger or the pen, on a done step makes it what the History brush paints back to (to before it, on that step's object), without moving through the History, and a note names it; the step must be on the level (or HD window) its object shows, and the History must not be moving; a small mark at the foot of the bar shows where the selected object's History brush point is, and resting on that step says so. A step that is not sculpting (a move of the object, a change to the scene tree, a rebuild), or out of the brush's reach, is refused with a note. The panel's Marker button does the same for a tap: while it is lit, a tap (or click) on a done step sets the History brush point there instead of going there, and the button goes out after one mark; a second press turns it off unused.

Settings > System > Undo steps kept (No limit, the default, or 20 to 500; `undo_steps` in the settings file and scripts) keeps only that many of the newest steps: once a step more is made, the oldest goes, and its strokes go from their object's undo memory too, so the memory comes back. A step of several entries (a move of several objects at once) counts once and goes whole, so "Step N of M" on the bar, which counts entries, can read more than the limit. Nothing is dropped while a stroke, a drag or the History itself is moving. **Delete older history** (the History panel, or the command palette) forgets every step that can be undone and frees their memory; the steps undone ahead of the bar stay, so Redo still works. It takes two taps: the first turns the button red ("Tap again to delete") for three seconds. A note says how many steps went and how much memory came back; it cannot be undone, and the History brush point goes with them.

Record time-lapse... asks for a folder, rewinds the History to the start, then redoes Steps a frame steps each frame up to where the timeline stood and saves the viewport after each as `frame_00000.png`, `frame_00001.png` and so on, at full detail; with Turn above 0 the camera also turns that many degrees around the scene each frame, as a turntable, and goes back where it was afterwards. Any video tool turns the frames into a film (`ffmpeg -framerate 12 -i frame_%05d.png sculpt.mp4`). A stroke, or Stop recording, ends it early. Flags: `--timelapse=DIR` records once `--bench-stroke` ends (or at the start), and the run lasts until it is done; `--timelapse-steps=N` and `--timelapse-spin=DEG` set Steps a frame and Turn; `--bench-lifts=N` lifts the synthetic pen N times so the stroke becomes N + 1 steps.

## Stroke recorder

The Brush palette's Stroke recorder keeps strokes to play back, as ZBrush's Record and Replay Last do. The app always keeps the last stroke as it was drawn: every frame's pointer samples, pen pressure and tilt, Shift and Ctrl (and the modifier buttons), the camera and viewport size, and the brush settings. Record starts a recording that keeps every stroke until Stop recording. Replay plays the recording, or else the last stroke, back where it was drawn, with the camera it was drawn with, whatever the view is now. R over the viewport plays it so its first stroke starts under the pointer, in the current view and size, which turns a stroke or a set of strokes into a stamp to lay anywhere, on any object (a rivet, a scale, a monogram, a spiral). With Recorded brushes off the path is replayed with the brush as set now: record a path once, then lay it with Clay, then Crease. Instant plays every recorded frame at once instead of one a frame, as drawn. Escape stops a replay, and switching to Move does too.

A replay feeds the recorded frames through the same code a drawn stroke goes through (`src/app/replay.odin`, `sculpt_frame`), so lazy mouse, symmetry, Drag rectangle, Spray, Roll, Grab, Snake hook and Cloth replay as they were drawn, each replayed stroke is one undo step and shows on the History timeline, and a replay where it was drawn on the same mesh gives the same vertices, bit for bit, as the original strokes (checked frame by frame and Instant on a 200k sphere: three strokes recorded with `--record-strokes`, saved, then replayed on a new sphere, export files identical). Instant brings normals up to date between recorded frames (`sculpt.sculptor_refresh_normals`), as frame-by-frame drawing does. While a replay runs the pointer does not sculpt; the camera still moves.

Save strokes... writes the recording (or else the last stroke) to a `.strokes` file and Load strokes... reads one into the recording, to replay in another scene or share. A file keeps each stroke's brush kind, size, strength, falloff and focal shift, pressure settings and curve, lazy mouse, Front faces only, stroke mode, Spray's spread and the stroke's seed, Line and Join strokes, Lock plane and Connected only, All depth and Smooth only, spacing and colour spray, symmetry, paint colour, cloth mode and the stroke's strength scale (Touch strength, for a finger's stroke); the alpha, pen tilt strength and dynamic topology detail come from the brush as set when it is loaded, since an alpha names an image file that may not be there. Every number in a file is checked (finite, in range) before it reaches a brush, and a damaged file is refused. A frame costs 60 bytes plus 21 a pointer sample in the file and a little more in memory. Version 3 files keep whether a frame's stroke painted the mask through the Mask modifier button, and version 4 files each stroke's Spray spread and seed, so a Spray replays as drawn, version 5 files its Line and Join strokes switches, version 6 files its Lock plane and Connected only switches, version 7 files its focal shift, version 8 files its strength scale, so a finger's stroke replays as light as it was drawn whatever points now, and version 9 files local and radial symmetry, and version 10 files the paint channel, and version 11 files All depth and Smooth only, and version 12 files spacing and colour spray; versions 1 to 11 still load (strokes from before version 4 take the spread as set and seed 0, those from before 5 and 6 have the switches they lack off, those from before 7 no focal shift, those from before 8 full strength, those from before 9 no local or radial symmetry, those from before 10 only sculpt, those from before 11 have Grab's round reach and Smooth on everything, and those from before 12 the default spacing and no colour spray). Flags: `--record-strokes`, `--save-strokes=PATH`, `--load-strokes=PATH`, `--replay-shift=DX,DY`, `--instant-replay`.

## Controls

Every shortcut, menu row, brush key and tray action button runs a command from one table (`src/app/commands.odin`: name, help, icon, whether it can run now, whether it is on), so the shortcut a menu or tooltip shows is always the one that works. A shortcut's modifiers must match exactly: Ctrl+Z undoes and Ctrl+Shift+Z redoes, and a key held with a modifier it does not list does nothing (Ctrl+B, Shift+1 or Ctrl+F are not shortcuts). Each key press keeps the modifiers held when it went down, so two quick shortcuts in one slow frame both work.

Any command's key can be changed where it is: Ctrl+Alt+click a panel control that runs it (a button, a menu row, a switch, a tab, a tool, a brush tile, a row of the command palette) and, instead of running, it opens Assign key beside the control, as ZBrush's Ctrl+Alt+click and Blender's Assign Shortcut do. The command palette has an Assign key button for the picked row too, which reaches commands that cannot run now (a greyed control takes no click) and works by touch with a keyboard attached. The popover names the command and its keys now, then takes the next key pressed, with Ctrl, Shift or Alt if wanted, as the command's only key: Redo's two keys give way to the one chosen. A key another command has is a question there and then: Use it here moves it (that command keeps any other key, else has none, and the popover says so) and Keep it there leaves it. Space, Escape, Enter, Backspace, Android's Back and the lock keys are refused with the reason, and so are bare S and U (held over the model they size the brush and set its strength) and a key pressed with Cmd or the Windows key. Remove key leaves the command with none; Reset gives it its default keys back. Changes are saved at once (`key <command> <chord|none>` lines in settings.txt); every menu, tooltip, Help > Keys and the palette show the keys as they are. A key given this way runs after the default keys in a frame where several went down. Presets have no keys yet, and a Ctrl+Alt+click on a preset tile picks it as a plain click does.

Files: Ctrl+O opens a scene, Ctrl+S saves it (where it was last saved or opened, else it asks), Ctrl+Shift+S saves it somewhere else. F12 saves a screenshot.

Tools (also on the toolbar): W picks Move (W again steps its gizmo through Move, Turn and Scale), B Sculpt (the brushes), C Curve and I Insert. Ctrl+K or `/` opens the command palette (see Command palette). Q opens Pie 1 and Shift+Q Pie 2 (see Pies). Tab shows or hides the palette tray, F11 the Stats panel, F1 opens Help (every shortcut, the mouse and touch controls, and a glossary), and Escape (or Android's back gesture) closes whatever menu is open. F points the camera at the selected object; Shift+F shows its wireframe; Shift+P the floor grid; Shift+G switches flat shading; Shift+W shows polygroups, Ctrl+W groups the masked part (or what is shown). Delete deletes it (Ctrl+Z brings it back). Ctrl+D subdivides the selected object; D and Shift+D go up and down its levels; Ctrl+Shift+D duplicates it; Ctrl+C copies it and Ctrl+V pastes the copy below the selected object (see the Objects card). Ctrl+R remeshes it at its own vertex count. Ctrl+T turns dynamic topology on or off for it. A opens an HD window where the pointer is on an object with an HD level, or closes the open one.

Move: click or tap an object to select it (a click on empty space clears it, a drag there turns the view), and drag it to move it in the view plane, whatever the gizmo shows. The gizmo has three modes, picked by W again while the Move tool is on (Move, Turn, Scale, Move...), by the action bar's chips or by the Move tab of the inspector, and remembered (`gizmo_mode`, and the Snap latch as `gizmo_snap`):
- Move: drag an arm (red X, green Y, blue Z) to move along that axis, a square between two arms to move in their plane (it takes the colour of the axis it holds still), or the middle square to move in the view plane.
- Turn: drag a ring to turn about that axis (the world's, through the object's origin; the far half of each ring is dimmed), or the white outer ring to turn about the view's axis. A ring seen nearly edge on turns by how far the drag runs along it on screen.
- Scale: drag the middle disc or the circle round it: an arm's length further out scales by e (about 2.7), as far in by its inverse; the scale stays between 0.01 and 100.
While a drag goes, a label by the pointer says what it has done ("X +0.250", "Turn Z +45.0°", "Scale ×1.30"). Ctrl held through a drag snaps it (pressed after the press for a drag on the object's body, since Ctrl at the press starts a topological mask instead, see Posing below), and the Snap latch snaps every drag: moves to whole steps of a grid that follows the zoom (a power of ten about half an arm long on screen), turns to 15°, scales to steps of 0.1; the label names the step. Esc puts the object back mid-drag, and so does a second finger landing (a gesture). Each drag is one undo step. A tap or click on an arm, a ring or the scale disc that moves nothing opens a field over it for the value (with the on-screen keyboard on a tablet): for an arm a number sets the position along it and `+0.5` adds to it, for a ring the number is the turn in degrees, for the scale a number sets it, `+0.5` adds and `*2` (or `x2`) multiplies. Enter or Apply places it as one undo step; Esc, Cancel or a press outside closes it, and text that is no number is refused and says so. Set pivot (the action bar's Pivot chip, the Move tab or the palette), then a tap or click on any surface, puts the gizmo there, so turns and scales go about that point; the selection stays and the latch lets go. The pivot rides with the object as it moves, turns and scales, a dot marks the object's origin meanwhile, and Reset pivot puts the gizmo back on the origin; it belongs to that object only and is not saved. Handles are picked within 8 pixels with the mouse or pen and within half a touch target (24 points) with a finger, wherever they are, on the model or off it; a finger or the pen starts moving only past the slop, so a tap on a handle moves nothing. The Object palette's Transform sets position, turn and scale exactly: drag sideways on a value, or Reset transform (under More options, and in the command palette) to put the object back at the middle, unturned, at scale 1. The exit stats give `gizmo_pivot` (where the pivot is, or none), `gizmo_pivot_latch`, `gizmo_entry` (the handle whose value is open, or none), `gizmo_at`, `gizmo_mode`, `gizmo_hover`, `gizmo_last` (the handle of the last drag that changed something), `gizmo_drags`, `gizmo_snap`, `transform` (the selected object's position, turns and scale) and `transform_undo` (transform steps that can be undone); `scripts/touch_check.py 'gizmo_*'` runs the ring, finger scale, finger-sized handle, plane square, snap, chip, typed value, pivot and cancel scenarios.

Posing: with one object selected and a mask on it that leaves something shown free, the gizmo's handles pose the object's unmasked part instead of moving the object, as ZBrush's gizmo does with a mask (a drag on the object's body still moves all of it). Each vertex takes the move, turn or scale by how free it is: a half-masked vertex moves half as far, scales by half the change, and turns through half the angle at its own distance from the pivot, so the mask's soft edge bends like a joint instead of pinching. The gizmo goes to the middle of the mask's soft edge (its partly masked vertices; with a hard edge, the free vertices touching a masked one; else the free part's middle) whenever pose mode finds a mask it has not placed it for, and Set pivot still puts it anywhere until the mask changes again; a move carries the gizmo along with the part. The action bar's Gizmo group reads Pose meanwhile, the label by the pointer starts "Pose:", and each drag is one undo step ("Pose: Turn" and so on), Esc or a second finger putting the mesh back. A typed value poses too: an offset along the arm, degrees, or a scale factor (`+0.5` adds half). Hidden parts stay still. Posing is refused, with a note, in an HD window and with dynamic topology on. The exit stats give `pose_mode`, `pose_drags` (drags and values that posed) and `pose_moved` (vertices the last pose could move), and `mesh_sum` (the selected object's coordinates added up, so a scenario can tell a mesh put back exactly).

Topological mask: with the Move tool, Ctrl + a press on an object (or a finger or pen press with the rail's Mask on) selects it, and a drag from there masks it along the surface, as ZBrush's topology masking of its gizmo does: free within three quarters of the reach of the press, a smooth band to the reach, masked beyond it, the reach being the drag's length on screen at the press's depth (a circle and "Mask reach" show it). Ctrl+Alt (or Mask with Invert) makes the opposite: masked near the press, free far away. Distance is measured along the triangles' edges (Dijkstra's search from the pressed triangle's corners), so a part the other side of a thin gap stays masked however near it is in space; shapes follow the mesh's edges a little. The search settles at most 50,000 vertices a frame (about 20 ms on the test VM, release build, 655k-vertex sphere; 650k settled in 0.17 s over 9 frames) and carries on after the release until it has reached the reach set last, so a reach across a dense mesh never stalls a frame; starting one on an object with no mask costs what Mask all does (about 40 ms there), since everything far is masked at once; each gesture is one mask undo step, Esc or a second finger puts the mask back, and a tap only selects. Hidden parts keep their mask (the search crosses them). The gizmo then goes to the new mask's soft edge, so the part pressed poses at once. It works with dynamic topology on. The exit stats give `topo_masks` (gestures that masked) and `topo_reach` (the last one's reach in the object's own units).

Brush: left drag sculpts the object under the cursor, which becomes selected (Shift smooths, Ctrl inverts; the Mask brush then erases). The brush is the one the press chose for the whole stroke: Shift, the rail's Smooth or Mask, or a brush key pressed mid-stroke leave it as it began. Shift (or the rail's Smooth) pressed mid-stroke instead lays the stroke again as a straight line from where it began to the pointer, as 3DCoat's Shift line and ZBrush's Lazy Mouse line do: what the stroke did is put back from the undo copies it keeps (`sculptor_stroke_restore`) and laid again whenever the pointer moves, so it stays one undo step; a line longer than a frame's dabs (64) is laid over the next frames and finished at the release; letting Shift go lays the line to where the pointer last was with it held, then carries on freehand from there, so where a line ends depends only on the pointer's path, never on how fast the frames were, and a replay lays it the same. A straight line ignores the lazy mouse; a viewport resized mid-line leaves it as it was laid. Not with dynamic topology, whose strokes cannot be put back, nor Grab, Snake hook, Cloth or Rectangle strokes. A take recorded before this with Shift pressed mid-stroke replays as such a line; a left drag that starts on empty space turns the view instead, as in ZBrush, and keeps turning it when it crosses the model (Settings > Touch makes the mouse wait for the model instead). Keys 1 to 9 and 0 pick the first ten brushes, X toggles X symmetry, V swaps the main and secondary colours, Shift+C picks the colour under the pointer (the Eyedropper), Alt+M clears the mask and Ctrl+I inverts it. Ctrl + drag from empty space masks a rectangle or lasso (Ctrl+Alt unmasks). Ctrl+Shift + drag runs the chosen gesture tool: hides by rectangle (the default) or lasso (Alt hides the inside), clips along a line (Alt: the other side) or slices along a line; a Ctrl+Shift click shows everything. Ctrl+H shows everything, Ctrl+Shift+H inverts what is hidden. The brush follows every mouse or pen sample, not just where the pointer is once a frame: dabs go along the path the pointer took on screen, a quarter of the radius apart (Spacing under Stroke > More changes that), each where that point meets the surface. Pen pressure scales the strength, and the size too with "Pressure changes size" in the Brush palette's Pen section, through the pressure curve there; a mouse counts as full pressure. Space (hold and let go, or tap) or a right click without dragging opens the brush pie (see Pen and brush pie above). S over the viewport sizes the brush where it is (move away from or toward the circle's middle, then click or press S again; a right click or Escape puts the old size back), and U does the same for the strength; [ and ] step the size, Shift+[ and Shift+] the strength. Each brush keeps its own strength, and Shift-smoothing uses the Smooth brush's. The brush ring takes the colour the reference app gives its cursor for what a press will do: red to sculpt, pink to sculpt inverted, blue to smooth, yellow to paint the mask and white to hide (a selection), from the keys held or the modifier wheel, and more opaque while pressing. Lazy mouse (Stroke > More) makes the brush trail the cursor on a string that many pixels long, for steadier lines. Line (Stroke > More, `stroke_line` in settings.txt) makes every stroke a straight line from its press, redone as the pointer moves, for a pen or finger with no Shift; the Stroke section says so while it is on. Join strokes (Stroke > More, `stroke_join`) carries a stroke on from where the last one ended when it is pressed within 24 pixels of that end, on the same object with the view unchanged: the dab spacing and direction go on as if the pointer had never let go, so a line drawn in pieces has no blob or gap at the joins (each piece is still its own undo step). Replays and recordings start without a stroke to join, and undo, redo or opening a scene forgets the last stroke's end, so a press then starts its own stroke; replaying the last stroke when it joined another lays it unjoined. The exit stats count both as `stroke_lines` and `stroke_joins`. Over the model the brush ring lies on the surface, as in ZBrush: a circle of the brush's size in the plane the surface faces under it (the vertex normals the brush would reach, weighted as a dab weighs them, so it shows the way the brush pushes), seen in perspective, with a short tick out along that normal from its middle; off the model it is a flat circle on the screen (Settings > Interface turns this off). With an alpha (see Brush alphas above) the outline is the alpha's square. R over the viewport replays the recorded strokes (or else the last stroke) starting under the pointer, and Escape stops a replay (see Stroke recorder above).

**The Objects card** (the view bar's Objects button, under the navigation head) is the quick way to the objects, laid out as ZBrush for iPad's Subtools card; the Scene palette's Objects section stays as the other place to reach them, as ZBrush keeps Tool > Subtool. It opens beside the view bar in the palette tray's place: opening the tray (or Settings, Help or Macros) closes it, and the Objects button closes the tray. Its row of dots on top drags it anywhere (remembered with the other panels); holding the dots puts it back in the tray, which opens on the Scene palette's Objects. Under the title are Add (a menu: Insert puts the picked shape below the selected object, in its folder; Append at the end of the list; then Import mesh), Duplicate, New folder and More (Rename, All low and All high, which show every object at its lowest or highest subdivision level, Copy, Paste, Duplicate, Delete, Delete other and Delete all). Each object has a tall row: a picture of it, its name with its boolean switch under it (on makes it a Subtract in booleans; the row's menu picks Add, Subtract or Intersect), and at the right its polypaint toggle and its eye. A folder's row shows a folder with how many objects are in it, its name, a chevron that folds it and its eye. The pictures are drawn from the front, turned as the object is, in a light clay with its polypaint; one is drawn again once its object has stayed unchanged for 0.4 s, never during a stroke or while the view moves and at most one a frame, so sculpting costs nothing until the stroke ends and then one draw of the object (a full draw of a 10M-vertex object, about 20M triangles, once). A tap on a row selects it (Shift or Ctrl + tap, or Select several, adds it); a long press (or right-click) opens its menu: on the selected object Rename, Copy, Paste, Duplicate, Bring to top, Send to bottom, New folder, Make a ghost, Boolean process (Off, Union, Subtract, Intersect), Delete and Delete other; on another object only Boolean process, which leaves the selection alone. A folder's long press opens the folder menu, which also shows or hides the polypaint of every object in it. To move a row, hold it until its menu opens and then drag it (the menu closes): a line shows where it goes, as in the Scene palette, and near the list's ends it scrolls along; a quick swipe scrolls the list instead. With a mouse a row drags at once. The eye works as in the Scene palette (dragging down the eyes sets each row's), and the polypaint toggle leaves the object's colours out of the drawing without losing them (saved with the scene from scene file version 11, which older versions of the app do not open). The bar under the list sets how tall the list is, for this run. Copy keeps the object as the scene file stores it (for a 10M-vertex object about 370 MB, which the log notes), so Paste (one undo step) works after the object is deleted or in another scene; Bring to top and Send to bottom move it to the ends of its folder, or of the list, as one undo step each; Delete other and Delete all are one undo step that brings every object back, and are refused with a note when the copies undo keeps would pass its 1.5 GB limit. All low and All high are not undo steps, as choosing a level is not. Scripts: `copy_object`, `paste_object`, `object_to_top`, `object_to_bottom`, `delete_other_objects`, `delete_all_objects`, `all_lowest_level`, `all_highest_level`.

**The Objects card's Actions** unfold under its list (folded at first, as ZBrush's card has them) and scroll in the room the list leaves. First is Store visibility, V1 to V8: each keeps which objects and folders are shown. Choosing one keeps the eyes as they are in the one chosen before and brings back its own; one never chosen takes the eyes as they are, so nothing changes until an eye is turned. The selected object always stays in view. They are not undo steps, as eyes are not, and are saved with the scene from scene file version 12, which older versions of the app do not open. Then come these sections, each folded until tapped:
- **Split** makes part of the selected object an object of its own, as one undo step. Split hidden takes its hidden part, Split masked its masked part (each triangle masked at least half at every corner), Groups split each polygroup, and Split to parts each connected piece; each is greyed out while there is nothing of its kind. The object keeps the first part (what is shown, what is unmasked, the first group or piece), and each other part becomes an object below it, in its folder, where it was. As with Slice, the levels, HD detail, mask, hidden parts and strokes go; the polypaint, the polygroups and the shown level's sculpt layers stay. More than 64 parts is refused with a note. Under dynamic topology it is greyed out.
- **Merge**: Merge down makes the selected object and the one below it in the list one object, in the selected one's place, and Merge visible adds one new object made of every shown object at the end of the list, leaving them as they are; the folder menu's Merge folder does the same for a folder's shown objects. Each object merged in keeps polygroups of its own, numbered on from the ones before, so Groups split takes a merge apart again; polypaint comes too. Merge down drops the selected object's levels and sculpt layers and is one undo step with the delete of the object below; Merge visible is refused with a note when the new object would pass the subdivide memory limit, or when the objects have more polygroups between them than one object can keep.
- **Transpose** says how the Move tool's gizmo moves, turns and scales several selected objects together (ZBrush's Transpose Master), and how a mask poses part of one.
- **Boolean**, **Project** and **Extract** are the Object palette's Booleans, Project detail and Extract sections, here too.
- **Align** has a row of three tiles for each axis, X, Y and Z: the low sides, the middles or the high sides line up. With several objects selected they line up with the first selected; with one, it lines up with the bounds of every shown object, as ZBrush aligns a subtool. Only the position along that axis changes.
- **Distribute** spaces objects evenly along an axis by their low sides, middles or high sides: the selected ones when three or more are, or else every shown object. The outermost two stay where they are. Align and Distribute are one undo step each.

Scripts: `visibility_slot v1` to `v8`, `split_object hidden|masked|groups|parts`, `merge_down`, `merge_visible`, `align_objects x_min` (or `x_centre`, `x_max`, then `y_` and `z_`) and `distribute_objects` likewise.

Scene palette, the objects: each row shows the object's name, size and levels ("base" on the object a boolean applies to), a ghost and an eye. A tap on a row selects it; a right-click or long press opens its menu (Focus, Duplicate, Rename, Solo, Make a ghost, Hide object, New folder, Move to a folder, Take out of folder, Delete). **Folders** gather objects one level deep, as ZBrush's SubTool folders: New folder (Ctrl+G) puts the selected object in one; its row's chevron folds it, its eye and ghost apply to everything in it, a tap selects its first object, and its menu renames it, ungroups it (its objects stay, out of any folder) or deletes it with its objects. A folder's objects always sit together in the list, which is the scene's order (the first object no boolean marks is the base). Rename (F2, or the menus) opens a field for a new name. **Dragging** a row by its grip (the dotted handle at its left, with any pointer; a finger on it never scrolls the panel) moves it: a line shows where it will go, an outline when it would go into a folder (let go over the middle of a folder's row). Under a folder's last object the line steps in, keeping the object in that folder, when the pointer is right of the indent. A folder's grip moves it with all its objects, between the rows outside folders. Near the top or bottom of the tray the list scrolls along. **Several objects** can be selected: Shift + click (or Ctrl + click) on rows, Shift + click on objects with the Move tool, the Scene palette's **Select several** switch (then a tap adds or removes, for a finger), or a folder's Select its objects. The last one added carries the gizmo and is the one every other panel and tool works on; the rest are drawn most of the way to the selected colour. The gizmo, the Object palette's Transform values and typed gizmo values move, turn and scale all of them together about the same point, keeping their spacing (a scale stops where any of them reaches its limit); Reset transform puts each back at the middle by itself; Duplicate copies each, keeping their spacing, and Delete takes all of them; each is one undo step. A Shift + click that misses every object keeps the selection. A plain tap, adding an object or anything else that picks one object leaves that one alone selected; a press on one of the selection with the Move tool keeps the rest and drags them all. **Column drag**: a press on an eye or a ghost dragged up or down the column sets every row it crosses the way the pressed one was going (a finger first holds still on it until its tooltip shows, as a quick drag scrolls the panel), so hiding or ghosting a run of objects is one sweep. Folders, moving into and out of them, moving rows, renaming and deleting a folder are undo steps; deleting a folder is one step that brings back the folder and its objects together. The **eye** takes an object out of view and out of reach (H hides the selected one and selects the next; Alt+H, or Show all objects under the list, shows every object again); the **ghost** dims it and lets presses through it, to sculpt another object against it as a reference. **Solo** (Shift+S, or the object menu) shows only the selected object, and whichever is selected next, until Solo is off again; the eyes stay as they were. As ZBrush's SubTool list, the selected object is always one in view and reach: hiding or ghosting it selects the next, and a tap on the row of a hidden or ghosted object brings it back and selects it. These are view state, saved with the scene but not undo steps; an object out of view still takes part in booleans, retopology and Project detail (the Booleans section says so), and Frame all frames only the objects in view. Hidden triangles inside an object are the Visibility section's (Ctrl+H shows them).

Scene palette: pick a shape (Sphere, Cube, Cylinder, Cone, Torus, or one of the starters below) and a size (41k to 25M vertices) and Add it; the Object palette's Remesh rebuilds the selected object as an even mesh of about the size picked there that keeps its shape (see Voxel remesh above). Geodesic spheres come in steps of 10f² + 2 vertices; the Scene palette shows the exact count it will build. The cube and torus are even grids, so their triangles follow their edges; the cylinder and cone are voxel remeshed from a smooth outline, which gives even triangles over the caps (their counts land within about a fifth of the one asked). Every shape is closed, so it subdivides and remeshes like a sphere. Flag: `--shape=NAME` starts with that shape instead of spheres. As voxels makes the Add button add a sphere of clay instead, of the resolution whose surface has about the size's vertices (see Voxel sculpting); the Objects card's Add menu has Voxel sphere too.

**Starters** are base meshes to begin a sculpt from, as ZBrush's and Nomad's are: Head, Bust, Figure (A-pose), Hand and Creature (four legs and a tail). They are made in code, so they need no files and carry no licence (`src/geom/starters.odin`): each is a few dozen ellipsoids and tapered tubes, fused into one closed surface by a voxel remesh (as fine as keeps the thinnest part, a finger or the tail, whole) and relaxed so the joins blend, then remeshed again at the size asked and relaxed a little more. Each faces the front (+Z) with +Y up and, all but the hand, is symmetric across X, so X symmetry works on it at once. Added at a size, a starter arrives with subdivision levels: as many as keep its base at 15,000 vertices or more, up to three, so a 1M Head is a 16k base with three levels above it, to step down to for big changes of form and up for detail (the Scene palette says how many levels it builds). A starter is never built under 15,000 vertices. On the test VM a 1M Head takes about 3 s from the tap to sculpting.

**New scene** (Menu > New scene, or the palette's "New scene: Head" and so on) replaces the scene with one Sphere, Head, Bust, Figure, Hand or Creature at the Scene palette's Add size, in the starting view, with an empty History and no file to save to (Save then asks where), as opening a scene does. When the scene has work to lose (any undo step, or more than one object), the first tap only arms that button, which turns red and reads Discard?, with a note; a second tap on it within 4 s goes ahead, and the menu stays open between the two. A palette row needs running twice in the same way.

Orbit, as ZBrush: a left drag on empty space or in the safe zone along the window's edges (see Touch and pen), a right drag anywhere, or Alt + left drag. The view turns about the middle of the last stroke, which stays where it is on screen while everything turns round it, as ZBrush's Local and Blender's Orbit Around Selection do, so the part being worked on stays in view; before any stroke, and after Focus, Frame all or Reset camera, it turns about the selected object's middle, and a point behind the eye is passed over. A small dot marks it while the view turns. Settings > Camera > Turn about can make a drag that starts on the model turn about the spot under it instead (Pointer, as Blender's Auto Depth and Nomad's pivot on camera move; with Off the model, turn about the air on, a drag on empty space turns about the point under it as deep as the middle of the view, as Nomad's Allow air pivot, rather than about the last stroke), every orbit turn about the middle of the selected objects (Selected objects, as Blender's Orbit Around Selection in Object Mode and Nomad's Selection pivot) or of everything shown (Whole scene, as Nomad's Scene pivot), or about the middle of the view (View centre, as Blender with Orbit Around Selection off). Show the pivot dot (on by default) hides the dot, as Nomad can; a double tap's pin still pulses. Hold Shift while turning to snap to the nearest view square to the axes (front, back, sides, top or bottom, upright or at a quarter turn of roll), and a drag far enough jumps to the next. Pan: middle drag, or Alt or Shift + right drag. Zoom: mouse wheel, or Ctrl + right drag (up zooms in). The wheel zooms toward the middle of the view, or with Settings > Camera > Wheel zooms toward the pointer on, toward what is under the pointer, which stays there (Blender's Zoom to Mouse Position), as a pinch keeps what is between the fingers. Settings > Keys can make the buttons work as Blender or Maya has them instead. The orbit goes all the way round both ways, over the top too, with no jump and no flip at the poles: Turntable (the default) turns about the model's up axis, Trackball about the screen's axes, and X axis and Z axis sideways about the world's X or Z axis (Settings > Camera, with the speeds and inverting). P (or keypad 5) switches between perspective and orthographic (parallel) projection, as wide at the orbit centre as the perspective view, so the object keeps its size on screen. Keypad 1, 3 and 7 look from the front, right and top, with Ctrl from the back, left and bottom (also in the Scene palette's Camera section). In orthographic projection the far-chunk simplification while orbiting is off. Camera history: Alt+Left (Previous view) goes back to the view before and Alt+Right (Next view) forward again, as a browser goes back and forward through pages, without touching the work or its undo; they are also in the View menu (which stays open to step several), the palette and the gesture map's choices. A view counts once the camera has stayed still 0.4 s with nothing turning it, whatever moved it (a turn, pan, zoom, pinch, Focus, Frame all, an axis view, Reset camera), and the view a scene opens with counts at once; going back from a view that has not rested yet keeps it first, so Next view returns to it, and a new view after going back drops the ones ahead. The last 32 are kept; the projection is not part of a view, and opening a scene or making a new one starts afresh (they are not saved). Script: `ortho_toggle on`, `view_axis front` (or `back`, `right`, `left`, `top`, `bottom`).

## Touch and pen

Fingers and the pen work as in ZBrush for iPad (`src/app/touch.odin`, `src/app/navigate.odin`, with every setting in Settings > Touch):
- One finger on the model sculpts, as the mouse does, once it has been down 90 ms (0.25 s while double taps are on) or moved past the slop, so a second finger landing with it makes a gesture before any clay moves. One finger on empty space turns the view, and keeps turning it over the model. Settings > Touch > On the model > Turns the view leaves sculpting to the pen.
- The pen sculpts on the model with pressure, and on empty space turns the view (or waits for the model). While the pen is near the screen or on it, a single finger does nothing (the hand holding it); the pen coming down cancels a touch in progress.
- Two fingers pan with their middle, zoom as they spread or pinch, toward the point between them, and twist to roll the view once they have turned 10 degrees (Trackball orbit only). Three fingers drag up and down for the brush size and sideways for its focal shift (400 points across its range), whichever way they go first; strength is a long press dragged on the brush bar's Strength. A quick tap of two fingers undoes, of three redoes (by default: see the gesture map below). Held still (landing together, within 0.15 s), two fingers undo again and again: once at 0.45 s (its own time, not the Hold delay, so fingers resting before a pinch do not undo), with a ring filling round them from 0.15 s on, then every 0.12 s with a count beside the ring, until a finger moves or lifts; three redo the same way. A hold never starts while the pen is near the screen, and once it undoes the touch neither pans nor zooms.
- Put two fingers down and lift one, and the other turns the view once it moves past the slop, about the same pivot an orbit would use, so a view filled by the model can still be turned with one finger. Only after two fingers that stayed still: the finger left rolling off the end of a pinch turns nothing. A two-finger tap still undoes unless the finger left turned the view.
- A double tap of one finger (the second tap within 0.3 s and 48 points of the first) on empty space frames the selected object, or every object when none is selected. On the model it pins the pivot to that point, with a pulse to show where: every orbit turns about it, whatever Turn about says, until the next stroke ends or the view is framed or reset. Neither tap sculpts: while one finger sculpts, a single tap's dab waits out the 0.3 s for a second tap, then lands as it was tapped (same view, brush and modifier buttons), or at once when anything else comes first (a key, the mouse, the pen, a finger elsewhere or a stroke). Taps in the safe zone along the edges never double-tap, nor do the presses that draw mask or hide shapes. A quick tap's dab keeps the modifier buttons latched or held at its press.
- The modifier wheel at the bottom left (`src/app/modifiers.odin`, `src/ui/wheel.odin`) does what Shift, Ctrl and Alt do, for a tablet with no keyboard. Its top sector is Smooth, its left Mask, its bottom Invert and its right opens the brush pie (as Space does); Smooth and Mask on together are Hide, as Shift and Ctrl held together are. Smooth smooths (Shift; held down by the other hand while the pen or mouse is mid-stroke, it lays a straight line instead, as Shift does then, and lifting it does not latch it), Invert inverts the brush (Ctrl), Mask paints the mask on the model at the Mask brush's strength and draws the Mask section's rectangle or lasso from empty space (Ctrl from empty space), and Hide (Smooth and Mask together) runs the gesture tool picked in Hide, clip and slice (Ctrl+Shift): a drag hides, clips or slices, a tap on a polygroup isolates it and a tap off one shows everything. Invert with Mask erases the mask and unmasks shapes; with Hide it flips the gesture as Alt does. With Mask on, where a tap lands chooses a mask command, as ZBrush's Ctrl click and Nomad's taps while Mask is held: off the model it inverts the mask, on a masked part it blurs the mask, on an unmasked part it sharpens it (by the Mask section's Steps), each with a toast that offers Undo; a tap paints no dot, so a mask stroke begins once it moves past the slop or is held 0.25 s. With the mouse, Ctrl and a click on empty space invert the mask too (Ctrl on the model still inverts the brush). A tap on another object selects it first; Invert (or Alt) changes nothing about which command a tap runs. A quick tap that stays within the slop latches a sector until it is tapped again (filled); a finger held on one makes it act only while held (lit), so the other hand sculpts with the pen or a finger and lifting ends it. Smooth and Mask latched or held together are Hide; otherwise one of them goes at a time, and Invert goes with any. A finger on a modifier sector is the wheel's alone: it is never the pointer, never part of a gesture, a hand resting there is no palm, and the pen landing leaves it be. A press takes the buttons' state as it goes down and keeps it until it lets go, so lifting the finger mid-stroke changes nothing; a held sector beats a latched one, the last held wins (but for Smooth and Mask held together, which are Hide), and any of Shift, Ctrl or Alt held at the press leaves the wheel out of it. The mouse and the pen click the sectors, which latches. Where a panel, a menu or a list lies over it, a finger there is the panel's. It sits under the brush bar (beside it where a short window brings the bar down to it) and rises above the bottom bar on a narrow one. Dragging the grip in its middle (a finger, the pen or the mouse) moves it anywhere in the window, and where it was put is remembered; Settings > Interface puts it at the bottom left or right (which also puts a moved wheel back), hides it (which lets go of every latch), and sets its size: Small, Medium (the default), Large, 2XL or 3XL; what its sectors show: Icons (the default), Icons and names, or Names (the reference app's sets name keyboard keys, but here Mask and Invert are both Ctrl, so the sectors name what they do instead); and its turn (Wheel turn, -180 to 180 degrees in steps of 15, so the hand finds each sector where it suits). Two fingers on the ring, spread or pinched, resize it to the nearest size, and twisted turn it: once the line between them grows or shrinks by twice the slop or turns 15 degrees, they stop holding their sectors (two held still still hide), latch nothing as they lift, and the wheel follows the whole spread and twist from where they came down. The second finger may land on the brush pie's sector or the grip; a lone finger there is still the pie's or the grip's.
- Settings > Touch turns each of these off: Lift one of two fingers to turn, Double tap to frame or pin.
- The gesture map (Settings > Touch, `src/app/gesture_map.odin`) says what eight gestures run, each Nothing or one of about 50 commands a hand without a keyboard reaches for (Undo, Redo, Brush pie, Pie 1 to 4, Search, the panels and the Objects card, framing, Previous and Next view, the view switches, Screenshot, Symmetry X, the mask's Invert, Clear, Blur, Sharpen, Grow and Shrink, Show all, Invert hidden, Hide masked and unmasked, grouping, polygroups, Solo, Show all objects, New folder, Subdivide, the levels, Remesh, Dynamic topology, Adjust last, the Move and Sculpt tools), or, through its last row, Any command..., whatever the Search lists: that opens the Search titled "Choose what ... runs", and the command picked there goes on the gesture instead of running. One-finger tap (Nothing): a quick tap of one finger on empty space (on the model a tap sculpts); with Double tap to frame or pin on it waits 0.3 s for a second tap first, and a pen coming near meanwhile drops it, as the hand's; with the Move tool it runs in place of clearing the selection. Two-finger tap (Undo), Three-finger tap (Redo), Four-finger tap (four or more fingers; Nothing), Hold two fingers (Undo), Hold three fingers (Redo), Hold four fingers (Nothing) and Pen side button (Brush pie). A hold fills its ring, then runs its command; Undo and Redo repeat while the fingers stay still, anything else runs once. The pen's side button, when not on the brush pie, runs its command where the pen is; the mouse's right click stays the brush pie. A gesture holds one command, so none collide; what overlaps is said under the map in the warning colour: four fingers the system may keep (Windows' touch gestures, some Android skins), the brush pie losing the pen's button, a hold that runs once, one command on two gestures, and a hold of your own sharing its start with Lift one of two fingers to turn. Every tooltip, the palette and Help > Gestures name the gestures the map gives a command ("Four-finger tap"), Help under YOUR GESTURES for a command it has no line for. Remembered as `gesture_map <slot> <command|none>` lines for the slots that differ; the older `tap_history 0` and `hold_history 0` lines still turn the two- and three-finger taps or holds off. The Brush pie command (Search, a gesture) opens the brush pie at the pointer for a tap.
- Long press is the secondary action, as in ZBrush for iPad and Nomad (`secondary` in `src/ui/ui.odin`): a finger or the pen held on a control for the Hold delay (Settings > Touch, 0.3 s by default, shorter than Android's 0.4 s and iOS's 0.5 s since a long press here is a tool used again and again) without moving past the slop does what a right-click on it does (the pen's side button is a right-click too), and a ring fills round the press from halfway (0.15 s at most) to show it coming. On a control with no such action it shows the control's name and shortcut instead. Either way letting go is no tap, and a press that moves, changes a value or scrolls is no long press. The mouse's left button never long-presses. What each does:
  - Undo and Redo open the History panel (while there is something to undo or redo; the History button beside them always does).
  - A slot in the dock opens its menu, to show its brush's settings or put another brush or preset in it (see Brush presets).
  - A brush or preset in the brush browser picks it and shows its settings in the tray.
  - The Size and Strength sliders (in the popover Draw size and Strength open) go back to where a new brush starts: 60 px, and the brush's own starting strength. A finger that moves the value while held is adjusting it, not resetting it.
  - A bar button with a small triangle in its corner opens its settings: Brushes the brush's, Draw size and Strength the Pen section, Save the other ways to save, Studio render and Floor grid their sections, Orthographic the view menu, Wireframe what it shows, Symmetry its X, Y and Z.
  - The Move, Curve and Insert tools on the dock pick the tool and show its settings in the tray.
  - The object's readout under the top bar opens its menu under it.
  - An object in the Scene palette opens its menu.
  - A done step on the History panel's bar makes it what the History brush paints back to (see History timeline and time-lapse); its note names the step, since the step's tooltip shows only on hover (the mouse, or a hovering pen).
- A finger or the pen changes nothing until it moves more than the slop, 10 points (Android's touch slop is 8 dp, iOS about 10 pt), so a tap never nudges the view; the mouse has none.
- The safe zone, as the SculptNavigation add-on's border: one finger, the pen or the left button pressed within 64 points of an edge of the screen (at the top, of the top bar's lower edge) turns the view even over the model, so when it is zoomed in until the model fills the screen there is still somewhere to turn it from. A faint line marks where the zone ends; panels over it keep their presses, and Ctrl keeps it for the mask and hide shapes (so does a finger held on Mask or Hide, though not a latched one). Settings > Camera sets its width (24 to 200 points), hides the line or turns it off.

Every touch, from its first finger down to its last finger up, belongs to where its first finger landed. On a panel the panels have it: that finger presses, drags and scrolls them, and other fingers of the same touch do nothing, so a hand resting on a panel never pinches the view. On the viewport the fingers navigate or sculpt as above, and lifting fingers never turns what is left into another gesture. A touch the system cancels lets go without a click, and a stroke it drew is taken back (Redo has it). Inside a panel that scrolls, a finger or pen press on a control waits to see which way it goes: up or down past the slop scrolls the panel and the control does nothing, sideways a slider takes it, and a tap within the slop is the control's tap; the mouse presses at once and scrolls with the wheel. Touchpads are not touch screens: their fingers never reach the view, and nor do the stand-in fingers SDL can make of the pen and the mouse.

`python scripts/gate.py` runs every check a change must pass (check, test, build, smoke, these scenarios, and the Windows and Android compile checks on Linux) with one line a step. `python scripts/touch_check.py` (after a debug build) drives the app with scripted fingers, pen and mouse through these cases and checks the camera, the dabs, the undo steps and the saved settings on exit: a simulation on the desktop, not a tablet (see the `sm-touch-testing` skill).
